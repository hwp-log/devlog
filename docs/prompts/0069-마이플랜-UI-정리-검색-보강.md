# 0069 회고: 마이플랜 UI 정리, 항공편 검색 기능 보강

- 기간: 2026-06-04
- 관련 커밋: `bf126eb`

## 1. 한 줄 요약

항공편 검색 폼의 입력 빈틈(한글 통과, 과거 날짜)을 차단하고, 상세 페이지 UI(항공편 카드·타임라인·비용)를 목업 기준으로 정렬했다.

## 2. 왜 / 목적 / 이유

### IATA 입력을 영문 A–Z로 제한

- **왜**: 기존 검증은 `길이 === 3`뿐이라 "나리타"(한글 3글자)도 통과했다. 버튼이 켜지고 API 호출이 실제로 나가며, Skyscanner는 IATA 매칭에 실패해 빈 결과를 돌려준다. 월 20건 쿼터가 소모되고, 사용자는 "이 노선엔 직항이 없다"는 잘못된 결론을 얻는다. 길이 검증은 형식 검증이 아니었다.
- **목적**: 잘못된 입력이 API까지 도달하지 않는 상태.
- **이유**: 검증 단계를 하나 더 추가하는 대신, 입력 시점에 영문 외 문자를 제거하고 대문자로 변환했다(`replace(/[^A-Za-z]/g, '').toUpperCase().slice(0, 3)`). 잘못된 입력 상태가 아예 만들어질 수 없다.

### 과거 날짜 검색 차단

- **왜**: 첫 e2e에서 시작일이 어제(6/3)인 채 검색해 빈 결과가 나왔다. 항공 검색은 과거 날짜에 결과가 없으므로, 막지 않으면 쿼터만 소모되고 "직항 없음"으로 오해하게 된다.
- **목적**: 검색 전에 "지난 날짜는 검색할 수 없습니다"로 안내하고 버튼을 비활성하는 상태.
- **이유**: 오늘 날짜 기준값 `todayStr()`은 로컬 기준으로 만들었다. `toISOString()`은 UTC라 KST 00~09시에 어제 날짜를 반환해 차단이 뚫린다 — 0068의 fmtTime과 같은 부류의 함정으로, plan 검수에서 발견해 로컬 조립으로 교체했다.

### 상세 UI를 목업 기준으로 정렬

- **왜**: 항공편 카드가 목업의 가로형 route 레이아웃과 달리 텍스트 나열로 구현돼 있었고, 섹션 제목 위치(카드 안/밖)와 섹션 순서가 화면마다 제각각이었다. 검수가 문구만 보고 레이아웃 대조를 빠뜨린 것이 원인 중 하나였다.
- **목적**: 섹션 라벨 → 흰 카드의 일관된 리듬, 모든 금액 우측 정렬, 목업과 동일한 위계.
- **이유**: 목업 HTML을 레포(`mock/myplan_mockup.html`)에 넣어 Claude Code가 직접 참조하게 했다. 목업이 도구의 손에 닿지 않으면 "목업 없음 → 즉흥 구현"이 반복된다. 항공편은 [출발 공항][소요·직항·편명][도착 공항][가격] 4열 카드, 타임라인은 마커+항목별 카드+우측 금액, 비용은 아이콘+이름/우측 금액/풀폭 막대 구조로 교체했다.

### 색 체계 정리

- **왜**: 타임라인에 마커 색(초록/파랑/빨강)과 카테고리 아이콘 색이 동시에 들어가 화면이 과해졌다.
- **목적**: 색이 정보를 전달하는 차분한 화면.
- **이유**: 의미 있는 색 하나만 남겼다. 카테고리 아이콘 색은 비용 섹션과 같은 색으로 연결되는 정보라 유지하고, 순번 숫자가 이미 시작/끝을 말해주는 마커는 파랑 단일로 통일했다.

## 4. 코드 작성 & 수정

IATA 입력 — 길이 검증에서 입력 정제로:

```ts
// app/(protected)/my-plan/new/FlightSearchSection.tsx
// Before — 길이만 보고 형식은 보지 않음 ("나리타"도 통과)
onChange={(e) => setOriginIata(e.target.value.toUpperCase().slice(0, 3))}

// After — 영문 외 문자는 입력 자체가 안 됨
onChange={(e) =>
  setOriginIata(e.target.value.replace(/[^A-Za-z]/g, '').toUpperCase().slice(0, 3))
}
```

오늘 날짜 기준값 — UTC가 아닌 로컬 기준:

```ts
// app/(protected)/my-plan/new/FlightSearchSection.tsx
// toISOString()은 UTC 기준이라 KST 00~09시에 어제 날짜를 반환 — 로컬로 조립
function todayStr() {
  const d = new Date();
  return `${d.getFullYear()}-${String(d.getMonth() + 1).padStart(2, '0')}-${String(d.getDate()).padStart(2, '0')}`;
}

const isPastDate = !!startDate && startDate < todayStr();
```

날짜 안내 문구 — 누락 원인별 분기:

```ts
const dateWarning = !startDate
  ? '계획 날짜를 먼저 입력하세요'
  : isPastDate
  ? '지난 날짜는 검색할 수 없습니다'
  : tripType === 'ROUND_TRIP' && !endDate
  ? '왕복 검색을 위해 계획 종료일을 먼저 입력하세요'
  : null;
```

## 5. 결과 / 배운점

**결과**

- IATA 칸에 한글·숫자가 입력되지 않고, 과거 날짜에서는 버튼 비활성과 안내가 노출된다.
- 상세 페이지가 목업과 일치: 항공편 4열 가로 카드, 섹션 제목 카드 밖 통일(항공편/여행 일정/카테고리별 비용), 타임라인 항목별 카드 + 카테고리 아이콘 + 우측 금액, 비용 섹션 아이콘 + 풀폭 막대.
- 목업 파일이 레포에 들어가 이후 UI 작업에서 경로 참조만으로 재사용 가능.

**배운점**

1. 길이 검증은 형식 검증이 아니다. 그리고 가장 싼 형식 검증은 검증 단계 추가가 아니라 입력 정제 — 잘못된 상태가 만들어질 수 없게 하는 쪽이 분기도 안내도 필요 없다.
2. 같은 함정은 반복된다. 0068에서 잡은 `toISOString()` UTC 함정이 같은 날 todayStr()에서 다시 나왔다. 한 번 잡은 패턴은 검수 항목으로 만들어야 다음에 막힌다.
3. 참조 자원은 도구의 손에 닿는 곳에 둔다. 목업이 레포 밖에 있는 동안 "목업 없음 → 즉흥 구현"이 발생했고, `mock/`에 넣은 뒤로는 프롬프트에 경로만 적으면 됐다.
4. UI 다듬기는 수렴하지 않고 루프를 돈다. 어디서 끊을지도 설계 결정이다 — 같은 화면을 오래 보면 기준점이 사라지므로(디자인 피로), 커밋으로 끊고 새 눈으로 다시 본다.

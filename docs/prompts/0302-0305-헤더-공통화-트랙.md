## 1. 한 줄 요약

Story·SpotFinder가 각자 인라인으로 갖던 헤더를 공용 `AppHeader` 컴포넌트로 통일하고(1단계), Story 파일 트리를 `(protected)` 그룹으로 이동해 layout을 공유함으로써 페이지 이동 시 헤더 remount를 제거(2단계)했으며, 활성 메뉴 표시를 밑줄에서 "슬라이드하는 점"으로 바꾸고(0304), Story 목록만 풀블리드로 펼쳤다(3단계).

---

## 2. 왜 / 목적 / 이유

> 판단 근거는 코드에 드러나지 않음. 아래는 변경 내용으로부터의 추정. 실제 의도는 기록되지 않았다.

- **왜 (추정)**: Story와 SpotFinder가 각자 인라인 헤더를 갖고 있어 중복이었고, 페이지 이동 시 헤더가 remount되면서(깜빡임·활성 표시 리셋) 일관성이 깨졌음. 공용 헤더로 통일 + layout 공유로 remount 제거가 목표.
- **목적 (추정)**: (1) 헤더를 단일 컴포넌트(AppHeader)로 통일해 중복 제거 (2) layout 공유로 페이지 전환 시 헤더가 유지되게(remount 방지) (3) 활성 표시를 부드러운 slide로 (4) Story 목록은 넓게 펼쳐 카드 그리드 활용.
- **이유**: 기록 없음

```tsx
// AppHeader.tsx — 3열 그리드 헤더
<header className="glass-header sticky ...">
  <div className="grid grid-cols-[1fr_auto_1fr]">   {/* 좌: Logo / 중앙: NavLinks / 우: 그룹 */}

    <NavLinks />

// HeaderGate로 래핑, widthClassName prop: Story=max-w-7xl mx-auto / SpotFinder=풀블리드
```
- 두 layout(protected·story)이 각자 인라인 헤더를 지우고 AppHeader 사용.

### 0303 — 파일 이동 (헤더 공통화 2단계)
파일 21개: `app/story/*` → `app/(protected)/story/*` 이동(대부분 순수 rename, 내용 0 변경) · `app/story/layout.tsx` 삭제(-39) · import 경로 갱신

```
app/story/...  →  app/(protected)/story/...   (15+개 파일 이동)
app/story/layout.tsx 삭제  →  Story가 (protected)/layout 공유
@/app/story/... 절대참조 → @/app/(protected)/story/...  갱신
  (대표: CardReveal·StoryCard·TagSearchBar·PublicCostSection)
```
- 핵심: Story가 자체 layout을 버리고 `(protected)/layout`을 공유 → **헤더가 페이지 이동 시 remount 안 됨.**

### 0304 — 활성 표시 밑줄→점 + slide
파일 1개: `app/(protected)/_components/NavLinks.tsx`

```tsx
// 각 링크의 조건부 밑줄 제거 → 단일 점 하나가 활성 메뉴로 슬라이드
<nav className="relative">
  {links}
  <span className="absolute h-1.5 w-1.5 rounded-full bg-primary"
        style={{ transform: `translateX(calc(activeCenter - 50%))`,
                 transition: 'transform 250ms' }} />   {/* 6px 점, 활성 위치로 translateX 슬라이드 */}
</nav>
// 활성 위치: itemRefs로 offsetLeft 측정 → lastCenter 보존(HeaderGate 토글=remount 넘어 슬라이드 유지)
// enabled 게이트로 최초 로드 점프 방지. 재측정: resize · document.fonts.ready
// (라우트 전환 시 transition-none으로 즉시 이동 처리)
```

## 5. 결과 / 배운점

### 결과
- Story·SpotFinder 헤더가 단일 AppHeader로 통일 — 인라인 중복 제거.
- Story가 `(protected)/layout` 공유 → 페이지 이동 시 헤더 remount 없음(깜빡임·활성 리셋 해소).
- 활성 표시가 밑줄 → 슬라이드 점으로. remount를 넘어 위치 보존(lastCenter).
- Story 목록만 풀블리드 + 그리드 컬럼 확장(최대 6열).

### 배운점
- (추정) layout 공유로 remount를 제거한 게 헤더 일관성의 핵심 — 파일 이동(0303)이 "구조로 문제를 푼" 사례. [사용자 확인]

---

## 결정 (Decisions)

- **헤더를 AppHeader 단일 컴포넌트로 통일** — 인라인 중복 제거. (왜: 기록 없음)
- **Story를 (protected) 그룹으로 이동해 layout 공유** — 페이지 이동 시 헤더 remount 제거가 목적. 파일 이동(구조 변경)으로 해결. [왜 이 방식인지: 사용자 확인]
- **활성 표시 = 슬라이드 점** — 밑줄 대신 단일 점이 translateX로 이동, remount 넘어 위치 보존. (왜: 기록 없음)
- **/story만 풀블리드** — 정확 매칭 분기로 목록만 넓게, 상세·작성은 max-w 유지. (왜: 기록 없음)

## 작업 4의 발견 — inline 'use server' 이슈

**현상**: page.test.tsx에서 redirect 테스트 작성 → form submit 자체가 throw로 죽음 → loginAction 본문 실행 안 됨.

**원인**:
- inline 'use server' 함수가 Next.js 컴파일 시 Server Action 프록시로 변환됨
- jest jsdom 환경에서 프록시 호출 불가 → form action에 throw 문자열 박힘 (Next.js 안전장치)
- 작업 1~3이 통과한 이유: form submit이 실제로 일어나지 않는 테스트였음 (DOM 존재 여부만 검증)
- 작업 4에서 처음으로 form submit + 결과 검증 시도 → 이슈 표면화

**해결**:
- loginAction을 별도 파일(actions.ts)로 분리
- 'use server' 파일 지시문 사용 (Server Module 패턴)
- actions.test.ts에서 loginAction을 직접 import + 호출 → jest 환경에서 정상 작동

**의미**:
- "Failing for the right reason" 원칙 적용 — 의도 외 실패 발견 시 멈추고 원인 분석
- 카테고리 점프 시 환경 이슈는 사이클 진행 중에야 표면화 (plan 단계에서 사전 예측 불가)

## Server / Client 분리 프레임

이번 작업의 본질적 통찰. Next.js 16 + React 19의 핵심 설계 원칙.

- **Server Component**: 서버에서 렌더링되는 UI (page.tsx)
- **Client Component**: 브라우저에서 실행되는 UI + 훅 사용 (LoginForm.tsx)
- **Server Action**: 서버에서 실행되는 함수, 클라이언트→서버 RPC (actions.ts의 loginAction)

**규칙**:
- Server → Client props 전달 시 직렬화 가능한 데이터만 (함수는 Server Action만)
- 'use client' 파일에서는 Server Action을 직접 정의 불가 → import만 가능
- Server Action 정의는 'use server' 모듈 또는 함수 단위로

규칙 어기면 프로덕션은 어떻게든 작동하지만 테스트 환경에서 깨짐. 명시적일수록 테스트 가능성 ↑.

## useActionState 학습

React 19 표준 훅. Server Action 결과를 자동으로 state에 매핑.

```typescript
const [state, formAction] = useActionState(action, null);
```

**핵심 동작**:
- 첫 번째 인자: 이전 호출의 반환값 (prevState). 첫 호출은 초기값(null).
- 두 번째 인자: 새 액션 트리거 함수 (form action에 박음).
- 액션 응답이 자동으로 state에 저장 → 화면 자동 리렌더링.

**디버깅 시 주의**:
- Next.js 자동 로그는 prevState만 표시 (한 박자 늦은 흔적).
- 이번 호출의 결과는 화면(state) 또는 console.log 직접 추가로 확인.

```typescript
// 디버깅 패턴 (검증 후 제거)
const result = await signIn(...);
console.log('[DEBUG] result:', result);
```

## 도입한 패턴

### 1. Server Component + Client Component 분리

페이지의 정적 부분은 Server Component, 상호작용 부분은 Client Component.
'use client' 경계 최소화. 데이터 페칭은 Server에서, 상태 관리는 Client에서.

### 2. Server Action 모듈 (actions.ts)

```typescript
// 'use server' 파일 지시문
'use server';
import { redirect } from 'next/navigation';
import { signIn } from '@/lib/auth/actions';

export async function loginAction(_prevState, formData) { ... }
```

- 'use server' 파일 최상단 = Server Module
- 안에 정의된 export 함수 = 모두 Server Action
- 0017 lib/auth/actions.ts와 같은 패턴 (위치/책임만 다름)

### 3. useActionState + Server Action 연결

```typescript
'use client';
import { useActionState } from 'react';

interface LoginFormProps {
  action: (prevState, formData) => Promise<ActionState>;
}

export function LoginForm({ action }: LoginFormProps) {
  const [state, formAction] = useActionState(action, null);
  return (
    <form action={formAction}>
      ...
      {state && 'error' in state && <p role="alert">{state.error}</p>}
    </form>
  );
}
```

- Server Action을 props로 받음
- useActionState로 감싸서 state 관리
- 타입 가드(`'error' in state`)로 narrow 처리

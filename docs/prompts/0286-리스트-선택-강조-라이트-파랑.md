## 1. 한 줄 요약

SpotFinder 리스트 선택 행 배경의 라이트 값을 무채 `bg-black/[0.08]` → `bg-primary/10`(옅은 브랜드 파랑)으로 변경 — 데탑 좌측 리스트·모바일 시트 행 동기 페어 2곳, 다크(`dark:bg-white/[0.16]`)는 무변.

---

## 2. 왜 / 목적 / 이유

- **왜**: 라이트에서 선택 항목 강조가 약한 회색이라, 리스트↔지도 연동이 핵심인 화면에서 지금 선택된 것이 눈에 안 들어왔다.
- **목적**: 선택 항목 배경을 라이트에서 primary 틴트(파랑)로.
- **이유**: 지도 마커가 파랑이라, 리스트 선택도 파랑이면 리스트의 이 항목=지도의 이 마커가 색으로 연결돼 도구 연동성이 산다. 다크는 현행 유지가 충분(채도 문제로 다크에 옅은 파랑을 강제할 이유 없음).

---

## 3. 작성한 프롬프트

```
[배경]
좌측 리스트의 선택 항목 강조가 라이트에서 약한 회색이라 눈에 안 들어옴.
리스트↔지도 연동이 핵심 기능인 화면이라 선택 강조가 명확해야 함.

선택 항목 배경을 라이트에서만 브랜드 파랑 계열(옅은 파랑)로. 좌측 바 없이 배경만.
다크는 현행 유지 — 절대 변경 금지.

[하지 말 것]

```

## 4. 코드 작성 & 수정

### `components/SpotFinderMapNaver.tsx` — 선택 행 2곳 (데탑 :1029 / 모바일 시트 :1141)

```tsx
// 변경 전
? 'border-transparent bg-black/[0.08] dark:bg-white/[0.16]'
// 변경 후
? 'border-transparent bg-primary/10 dark:bg-white/[0.16]'
```

- `bg-primary/10` = 기존 `--color-primary` 매핑(globals.css @theme inline) 위 Tailwind 불투명 수식 — 신규 토큰 불요.
- 0285의 배지 `bg-black/[0.08]`(:284)은 리스트 아님 — 무변.

## 5. 결과 / 배운점

### 결과
- 빌드 성공, `npm test` 기존 실패(6스위트/8테스트) 외 증가 없음.
- 컴파일 CSS 확인: `color-mix(in oklab, var(--primary) 10%, transparent)` + color-mix 미지원 구형 브라우저용 solid 폴백(`var(--primary)`) 페어 생성 — 토큰 경유라 4단계 토큰 정비와도 정합.
- 텍스트 대비: primary 10% over 흰 열 배경 ≈ 연한 하늘색, 그 위 제목 fg(#191a1c)·배지 fg2 — 가독 충분(어두운 글자 위계 무변).
- 브라우저 수동 확인 잔여(사용자): 라이트 선택 행 파랑 틴트 체감 강도(10%가 약하면 /15 상향 여지), 다크 무변 확인.

### 배운점
- 선택(지속 상태)은 색(파랑)으로, hover(일시 상태)는 무채(회색)로 — 상태마다 위계를 다르게 줘야 선택이 유일하게 튄다. 둘을 같은 색으로 하면 지금 선택된 게 뭔지 헷갈린다.
- 라이트/다크가 강조 방식을 다르게 가져가는 건 안티패턴이 아니라, 채도 원칙상 오히려 정석.

## 결정 (Decisions)

- **선택 상태 색은 테마별로 다른 전략** — 라이트 = primary 틴트(§9 지속 상태 색 배정), 다크 = 흰 저투명 명도 부상(0272 실측 확정 유지). 같은 상태라도 배경 명도에 따라 신호 수단이 달라진다.
- 틴트는 `bg-primary/10` 불투명 수식 채택 — theme.ts 신규 토큰 기각(기존 primary 토큰 파생으로 충분, 0284 기준: 단일 소비처는 variant/수식).

# 0337~348 회고: 글쓰기 시안 적용

작성일 2026-07-26 / 소요 약 9시간 / 커밋 0337~0348

## 핵심 판단

- **요약 문서를 사양서로 쓰다가 값을 세 군데 틀렸다.** 문서는 "무엇을 하려 했나"의
  기록이고 시안 파일은 "무엇이 됐나"의 기록인데, 구현은 후자를 따라야 했다.
- **1px 선이 안 보인 원인은 색이 아니라 낮 시간 모니터 반사광이었다.** 대비를 네 번
  올려도 안 됐고, 스크린샷 픽셀을 디코드해 "값은 정확히 반영되고 있다"를 먼저 확인한
  뒤에야 두께가 답이라는 게 나왔다.
- **트리맵 색이 투명하게 나온 건 토큰 이름 불일치가 아니라 빌드 캐시였다.** 내 가설대로
  코드를 고쳤으면 없는 문제를 만들었을 것이다.
- **라벨 굵기가 달라 보인 건 실제 차이가 아니라 동시대비 착시였다.**

## 한 줄 요약

Claude Design으로 받은 글쓰기 화면 시안을 7단계로 나눠 적용하고, 실화면과 대조해
남은 차이를 메웠다.

## 왜 / 목적 / 이유

**왜** — 글쓰기 화면이 입력 상자와 카드로 채워져 있어 "폼을 채우는 화면"으로 읽혔다.
글을 쓰는 도구인데 도구가 글보다 눈에 띄었다.

**목적** — 상자를 걷고 밑줄로 바꿔, 화면에서 가장 눈에 띄는 것이 사용자가 쓴 글이
되게 한다. 브런치·미디엄이 취하는 방향.

**이유** — 시안을 한 번에 적용하면 어디서 깨졌는지 알 수 없다. 토큰 정의 → 위계 →
구조 → 표현 순으로 커밋을 쪼개 각 단계에서 실화면을 확인했다.

## 결과 / 배운 점

### 원본과 요약의 차이

0338에서 값이 세 군데 틀렸다. 헤드라인을 20px에서 13px로 줄였고, 제목을 23px 대신
30px로 했고, 필요 없는 가로선을 넣었다. 전부 이전 세션에서 만든 요약 문서를 보고 한
것이었다.

원인은 문서 자체가 틀린 게 아니라 **문서가 요청 시점의 값을 기록했다는 것**이다.
"L1 제목 30px"은 시안을 요청할 때 쓴 숫자였고, 돌아온 시안은 23px이었다. 문서는
요청을 남겼고 시안은 결과를 남겼는데, 나는 요청을 사양으로 읽었다.

이후 모든 단계에서 프롬프트를 쓰기 전에 시안 파일에서 해당 블록 값을 직접 추출했다.
이 규칙이 이후 다섯 단계에서 값 오류를 0으로 만들었다.

### 원인을 확정하기 전에 고치지 않기

세 번의 사건이 같은 형태였다.

**구분선** — 툴바 그룹 구분선이 안 보였다. `--border` 토큰이 긴 수평선 전제의
헤어라인이라 1px 세로 조각에서는 대비가 부족했다. 전용 토큰을 만들어 라이트에서
해결했는데 다크에서는 알파를 0.28 → 0.44 → 0.60 → 0.75로 네 번 올려도 흐릿했다.

여기서 CC가 스크린샷 픽셀을 직접 디코드해 **선이 `#96a8bd` 그대로, 배경 대비 7.7:1로
정확히 켜져 있음**을 확인했다. 색은 이미 아이콘 밝기 직전까지 갔는데 안 보이는 것이었다.
원인은 낮 시간 모니터 반사광이 어두운 배경을 들어올려 실효 대비가 붕괴한 것이었고,
그 영향을 가장 먼저 받는 게 1px짜리 얇은 선이었다. 두께를 2px로 올려 해결했다.

주변을 어둡게 하니 원래 값으로도 잘 보였다. 진단이 맞았다.

**트리맵 색** — 예산 트리맵의 타일 색이 전부 투명하게 나왔다. 나는 `chart1Bg` →
`--chart1-bg` 변환이 어긋났을 거라 추정했다(숫자+대문자 조합이 처음이었다).
CC에게 세 지점(변환 결과·렌더된 변수·globals 참조)을 나란히 대조하게 했더니
**세 곳 모두 일치**했고, 진짜 원인은 Turbopack 빌드 캐시였다. 하드리프레시로 끝났다.

내 가설대로 이름 규칙을 고쳤으면 멀쩡한 코드를 바꾸고 없는 문제를 만들었을 것이다.

**라벨 굵기** — 제목·본문 라벨이 태그·플랜보다 굵어 보였다. 조사해보니 네 라벨의
클래스가 바이트 단위로 동일했다. 굵은 이웃(23px 제목·툴바) 옆에서는 같은 500도 굵게
읽히고, 가는 이웃(14px 입력) 옆에서는 가늘게 읽히는 동시대비였다.

착시를 굵기로 좇으면 라벨 층이 두 종류가 된다. 실제 결함이었던 카운터 span의
`font-normal` 하나만 고쳤다.

### form 경계

등록 버튼을 여행동선 아래로 옮기면서 버튼이 `form` 밖으로 나가는 문제가 생겼다.
두 안이 있었다.

- (가) SpotMap을 form 안으로
- (나) 버튼에 `form="id"` 속성으로 연결

CC 감사에서 **SpotMap의 지도 검색 input이 Enter에 `preventDefault()`가 없다**는 게
나왔다. (가)로 갔으면 지도에서 장소를 검색하다 Enter를 누르는 순간 스토리가 발행됐을
것이고, 재현도 어려운 버그로 남았을 것이다.

(나)를 채택했다. payload 무변경, SpotMap 무접촉, 표준 HTML `form` 속성만으로 해결.

### 남은 것

- 시안 값과 상세 화면 제목 크기(30px)가 어긋나 있다. 편집은 23px 유지, 정합은
  상세 토큰 이관 사이클에서.
- `fill1~5` 토큰이 트리맵을 파스텔로 결정하면서 용처를 잃었다.

  // max-sm:hidden(0461·0462) — 모바일 한 줄(5버튼+더보기)엔 그룹이 없어 구분선 미표시.

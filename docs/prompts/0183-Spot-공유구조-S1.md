# 0183 회고: Spot 공유 구조 S1 — StorySpot·SpotMovie 확장·백필·이중쓰기

작성일: 2026-07-13 / 소요: 약 3시간 / 커밋: 0aa2a09

## 1. 한 줄 요약
스팟을 스토리의 자식에서 공유 자산으로 바꾸기 위한 expand 단계 — 조인 테이블 2개 신설, 21행 1:1 무손실 백필, 쓰기 경로 이중기록을 프로덕션 DB에 무중단 적용했다.

## 2. 왜 / 목적 / 이유
- **왜(문제)**: 한 장소에 여러 작품·여러 스토리가 붙는 현실을 `Spot.storyId`·`Spot.movieId` 단수 FK가 표현하지 못했다. 같은 장소가 스토리마다 중복 생성됐다.
- **목적(목표 상태)**: 장소(per-place)와 방문 기록(per-visit)과 작품 연결(per-link)을 분리한 다대다 구조. 우측 패널의 "작품 N편 · 스토리 N편"이 가능한 데이터 모델.
- **이유(채택 근거)**: expand-migrate-contract 패턴을 채택 — 한 번에 갈아엎지 않고 확장(S1)→읽기 전환(S2)→쓰기 전환(S3)→수축(S4)으로 분할해 각 단계가 롤백 가능하게. 백필은 1:1 무병합(중복 통합은 사람 판단이 필요하므로 후속 admin 작업으로 분리).

## 3. 작성한 프롬프트
CC에 S1 착수 지시 후, SQL 전문을 사전 보고받아 승인 게이트를 걸었다. 승인 시 조정 2건:
```
SQL 승인. 단 적용 전 2건 반영:
1) spot_movies 백필의 created_at을 CURRENT_TIMESTAMP 대신 s."created_at"으로 승계.
   이유: 대표 작품 선정 규칙이 "최신 연결 작품"이라 백필 행이 동률이면 비결정적이 됨.
2) 적용 직전 `SELECT * FROM spots;` 결과를 파일로 덤프(원격 직결 대비 복구 재료).
이후 4단계 우회로 B(DDL+백필)·C(RLS) 적용 → 무손실 검증 쿼리 결과 보고.
```

## 4. 작성·수정한 코드

8파일: 마이그레이션 1 · 스키마 1 · RLS SQL 2 · 쓰기 경로 3 · 읽기 타입 1.

```sql
-- prisma/migrations/20260713130000_add_spot_sharing_joins/migration.sql
-- 0183 S1 (expand): story_spots + spot_movies 조인 추가.
-- 기존 spots 컬럼(story_id/movie_id/order/review/photo_url) 유지 — S4에서 제거(contract).

-- 1) Spot.story_id nullable화 (공유 준비 — 제거는 S4. FK/CASCADE/인덱스 불변)
ALTER TABLE "spots" ALTER COLUMN "story_id" DROP NOT NULL;

-- 2) story_spots: 스토리↔장소 (per-visit: order/review/photo_url 이관처)
CREATE TABLE "story_spots" (
    "id" TEXT NOT NULL, "story_id" TEXT NOT NULL, "spot_id" TEXT NOT NULL,
    "order" INTEGER NOT NULL, "review" TEXT, "photo_url" TEXT,
    "created_at" TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
    "updated_at" TIMESTAMP(3) NOT NULL,
    CONSTRAINT "story_spots_pkey" PRIMARY KEY ("id")
);
CREATE UNIQUE INDEX "story_spots_story_id_spot_id_key" ON "story_spots"("story_id", "spot_id");
CREATE INDEX "story_spots_story_id_order_idx" ON "story_spots"("story_id", "order");
-- (FK 2개: stories·spots 모두 ON DELETE CASCADE)

-- 3) spot_movies: 장소↔작품 다대다 (UNIQUE(spot_id, movie_id) + FK 2개 CASCADE)

-- 4) 백필 (1:1 무병합). id는 cuid 불필요 → gen_random_uuid()::text. ON CONFLICT = 재실행 안전
INSERT INTO "story_spots" (...)
SELECT gen_random_uuid()::text, s."story_id", s."id", s."order", s."review", s."photo_url",
       s."created_at", CURRENT_TIMESTAMP
FROM "spots" s WHERE s."story_id" IS NOT NULL
ON CONFLICT ("story_id","spot_id") DO NOTHING;

-- 승인 반영 1: created_at = s.created_at 승계 (대표 작품 "최신 연결" 정렬 결정성 보장)
INSERT INTO "spot_movies" (...)
SELECT gen_random_uuid()::text, s."id", s."movie_id", s."created_at"
FROM "spots" s WHERE s."movie_id" IS NOT NULL
ON CONFLICT ("spot_id","movie_id") DO NOTHING;
```

```sql
-- prisma/sql/story-spots-rls.sql
CREATE POLICY "story_spots_insert" ON "story_spots" FOR INSERT TO authenticated
WITH CHECK (EXISTS (SELECT 1 FROM stories
  WHERE stories.id = story_spots.story_id AND stories.user_id = (select auth.uid())));
```

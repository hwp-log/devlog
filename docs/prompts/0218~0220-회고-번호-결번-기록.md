# 회고 번호 결번·불일치 기록

작성일: 2026-08-10
목적: 커밋·회고 번호가 비어 있거나 어긋난 구간을 기록한다. 나중에 "이 번호 어디 갔지?"를 다시 추적하지 않기 위함.

모든 항목은 `git show` 실측으로 확인했다. 추측은 넣지 않았다.

## 1. 결번 — 0218 · 0219 · 0220

### 상태

커밋이 존재하지 않는다.

```
1a5d264  0221  비선택 마커 라벨 테두리 강화
9345834  0217  클러스터 마커를 브랜드 핀 형태로·클릭 줌 심화   ← 0218·0220 내용이 여기 뭉쳐 있음
b53e1ce  0216  전체 칩 fitBounds에서 제주 제외
```

`0217` 다음이 바로 `0221`이다.

### 이유

2026-07-15 새벽, 클러스터 마커를 브랜드 로고의 핀 형태로 바꾸면서 디자인을 여러 번 고쳤다. 각 조정 단계에 번호를 붙이기로 하고 진행했으나, **중간 커밋을 찍지 않고 수정만 반복하다가 마지막에 한 번에 커밋**했다. 그 커밋에 `0217`을 붙였다.

| 예정 번호 | 작업 | 결과 |
|---|---|---|
| 0217 | 클러스터를 로고 핀 형태로 + 클릭 줌 심화 | 커밋됨 (아래 내용 전부 포함) |
| 0218 | 클릭 줌 심화 (z16 착지) | 별도 커밋 없음. 주석만 남음 |
| 0219 | 핀 흰 구멍 확대 (숫자 가독성) | **흔적 없음** — 되돌려서 코드에 안 남음 |
| 0220 | 핀 흰 구멍 제거, 숫자를 흰 글씨로 | 별도 커밋 없음. 주석만 남음 |

### 0219는 아예 없다

`git show 9345834`의 diff에도, 현재 파일 어디에도 `0219` 문자열이 없다. grep 0건이다.

작업 중 "구멍 확대 → 도넛처럼 보여 되돌림" 단계가 있었는데, **되돌렸기 때문에 코드에 흔적이 남지 않았다.** 번호만 소비되고 사라졌다.

### 코드에 남은 빈 번호 주석 (원문)

**0218 — 3곳**

```
// 예외 — 스팟 클릭(handleSpotSelect)은 ③ 골목 단위(SPOT_CLICK_ZOOM) 착지(0218). 그 외 프로그램 이동은 ② 유지.

// 분해 임계(11)와 분리: 11=분해 시작 / 16=클릭 착지(>11이라 분해 확정, 벤더 checkByZoomAndMinClusterSize).

```

**0220 — 2곳** (현재 HEAD에도 그대로 있다)

```
// 클러스터 핀 — Logo.tsx 기하 참조(머리 원 + 삼각 꼬리 + 바닥 그림자). 흰 구멍은 제거(0220) — 숫자는 흰 글씨로 머리에 직접.
```

0218 주석 3곳은 0223에서 해당 코드가 재작성되며 사라졌다. **0220 주석 2곳은 지금도 HEAD에 남아 있다.**

### 회고 처리

**0218~0220은 별도 회고를 쓰지 않는다.** diff가 없어 "작성·수정한 코드" 항목을 채울 수 없다.

해당 내용은 **`0213-0217` 회고에서 다룬다.** 그 회고의 코드 섹션이 0217 커밋 diff이고, 거기에 네 단계 결과가 모두 들어 있다.

## 2. 코드-주석 번호 불일치 — 0216 → `0217:`

**0216 커밋이 넣은 주석 4곳이 전부 `0217:`로 적혀 있다.** 커밋 메시지·회고 번호는 0216이다.

```
// 0217: 전체 뷰 fitBounds에서 제주(33도대) 제외 — 육지 최남단(해남 34.29)과 제주 최북(33.56) 사이.
const MAINLAND_LAT_MIN = 34.0;

// 0217: fitBounds 입력 — "전체" 칩(selectedMovieId=null)일 때만 제주 제외(과축소·흔들림 제거).
const boundsSpots = useMemo(...)

fitMapToSpots(mapInstance, boundsSpots); // 0217: 전체 칩 시 제주 제외된 육지 bounds
fitMapToSpots(mapInstance, boundsSpots); // 0217: 전체 상태 리사이즈 재적합도 제주 제외 유지
```

**지금도 HEAD에 그대로 남아 있다.** 다음 번호를 미리 쓴 것으로 보이나, 이유는 확인되지 않았다.

## 3. 값 불일치 — 0217의 `SPOT_CLICK_ZOOM = 11`

이번 세션에서 확인된 것 중 가장 실질적인 어긋남이다.

```
0217 커밋 메시지    "도심에서 마커 라벨이 겹쳐 안 읽혔다. 클릭 목표 줌을 16으로 심화"
0217 주석 (3곳)     "골목 단위(z16)까지 확대", "16=클릭 착지", "SPOT_CLICK_ZOOM=16 착지"
0217 실제 선언       const SPOT_CLICK_ZOOM = 11;
```

**즉 0217 시점에 클릭 줌은 심화되지 않았고, 동작은 이전(`STAGE2_MAX_ZOOM = 11`)과 동일했다.** 커밋 메시지 첫 줄이 "클릭 줌 심화"인데 실제로는 그 부분이 아무것도 바뀌지 않았다.

이 값 문제는 0222~0223에서 클릭 줌을 재작성하며 해소됐다. `SPOT_CLICK_ZOOM`이라는 이름은 현재 존재하지 않고, `SPOT_CLICK_ZOOM_MIN = 11` / `MAX = 16` 연속 계산으로 대체됐다.

## 4. 값 불일치 — 0222의 `CLICK_ZOOM_DENSE = 13`

```
0222 커밋 메시지    "최근접 이웃이 1km 안에 있으면 z15"
0222 주석          "z15 = 349m↑ 쌍 겹침 해소"
0222 실제 상수      CLICK_ZOOM_DENSE = 13
```

설계에서 z15로 정했으나 코드엔 13이 들어갔다. 0223에서 이 상수 자체를 지우고 연속 계산으로 갈아엎었기 때문에, **잘못된 값이 드러날 기회 없이 사라졌다.**

→ `0221-0223` 회고 "배운 것 2"에 기록.

## 6. 단독 회고 없음 — 0210 (2026-08-12 추가)

### 상태

**결번이 아니다.** 커밋은 존재한다.

```
fe6ac67  2026-07-14 23:02  feat: 0210 다녀온 이야기 카드에서 스토리 상세로 이동
```

다만 0210을 표제로 하는 회고 파일이 없다. 내용은
`0213-0217-첫인상-지도이동-브랜드핀.md` §각주 — 0210에 다뤄져 있다.

### 왜 파일명에 편입하지 않았나

`0213-0217`을 `0210,0213~0217`로 바꾸면 0210이 그 트랙의 구성원으로 읽힌다.
실제로는 **다른 트랙의 각주**다 — 파일명을 정확하게 만들려다 내용을 부정확하게
만드는 교환이 되므로, 파일명은 두고 이 문서에 사실만 남긴다.

### 왜 지금까지 안 보였나

`0206-0212`라는 파일명이 0210을 범위 안에 품고 있어서, 번호를 훑어도 빈자리로
보이지 않았다. **연속 범위 표기가 불연속 실범위를 가린 것.** 2026-08-12 파일명
정리에서 그 파일이 `0206,0211~0212`로 좁혀지며 드러났다.

## 공통 원인과 대응

### 형태가 같다

2~5번은 전부 **"설계 단계에서 정한 것과 코드에 박힌 것이 다른데 아무도 대조하지 않았다"**이다.

| 건 | 문서상 | 실제 코드 |
|---|---|---|
| 0212 | 커밋 0212 | 주석 `0214:` |
| 0216 | 커밋 0216 | 주석 `0217:` |
| 0217 | z16 심화 | `SPOT_CLICK_ZOOM = 11` |
| 0222 | z15 | `CLICK_ZOOM_DENSE = 13` |

### 왜 안 걸렸나

승인할 때 **보고서와 커밋 메시지는 읽었지만, diff의 그 줄을 직접 보지 않았다.** 보고서가 "z16으로 했습니다"라고 적혀 있으면 그대로 통과한다. 그리고 세 건은 다음 커밋이 그 코드를 갈아엎어서 드러날 기회조차 없었다.

특히 0217은 **커밋 메시지 첫 줄이 사실이 아닌 채로 남아 있다.** 회고를 쓰며 diff를 다시 읽지 않았다면 영영 몰랐을 것이다.

### 앞으로

- 상수 하나·주석 한 줄짜리 변경일수록 **diff에서 그 줄을 직접 본다.** 보고서 요약으로 대체하지 않는다
- 커밋 직전 `git diff --cached`로 번호·값을 눈으로 확인한다
- 회고를 쓸 때 반드시 `git show`로 대조한다. 이번에 네 건이 이 과정에서 나왔다

## 번호 체계 원칙

- 회고 번호는 커밋 순서와 일치시킨다
- 여러 커밋을 한 편으로 묶을 때는 범위로 표기한다 (`0213-0217`)
- **범위 표기는 실제 담긴 번호와 일치해야 한다** (2026-08-12 추가) —
  연속은 `~`, 불연속은 `,`로 끊는다: `0391~0393,0395`.
  연속 범위로 뭉개면 그 안의 빈 번호가 가려진다 (§6 0210이 그 사례).
  파일명·H1·본문 `범위:` 줄 셋을 같은 값으로 맞춘다
- 작업 중 예정 번호를 정했더라도, **커밋하지 않으면 그 번호는 쓰지 않는다.** 다음 커밋이 이어받거나 결번으로 남긴다
- 결번·불일치가 생기면 이 문서에 남긴다

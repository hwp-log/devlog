## 2. 왜 / 목적 / 이유

> 근거: `docs/0228-0273-회고-재료-인수인계.md` 묶음 7.

### 회고 공백의 발견
- **왜**: 회고 최신 번호가 0162인데 커밋은 0272까지 와 있었다 — **110커밋 공백**. "기억"으로는 회고가 안 쌓인다는 것을 확인했다.
- **목적**: 회고가 쌓이는 구조를 만든다.
- **이유**: 보고 형식에 박아야 안 까먹는다 — 완료 보고에 "회고 초안 작성했습니다" 또는 "회고 대상 아님(사유)" 중 하나가 반드시 들어가고, 누락은 보고 미완으로 간주한다. §8 자가점검과 같은 메커니즘이다.

### 번호 이중 대조를 규칙으로
- **왜**: 이번 묶음에서 CC의 번호 헷갈림이 반복됐다 — `025X` 자리표시자 미치환 사고, 0268 결번.
- **목적**: 번호를 추측하지 못하게 만든다.
- **이유**: `ls docs/prompts/`(기존 회고 최신 번호)와 `git log --oneline`(대상 커밋 범위)을 **둘 다** 대조해야 확정할 수 있다. 결번·자리표시자 이력은 지우지 말고 그대로 명기한다.

### 역할 분담을 확정한 것
- **왜**: 종전 §7은 "회고는 CC가 작성·커밋하지 않는다 / 사용자가 선질문을 거쳐 조립한다"였다.
- **결정**: 커밋 = 사용자 수동 / 회고 초안 = CC / 회고 감시 = Claude(대화 세션).
- **이유**: 사실 섹션(한 줄 요약·프롬프트·코드·커밋 목록)은 CC가 채우고, **"왜/목적/이유"와 "배운점"은 `[사용자 확인 필요]` 표시 + 초안까지만** 쓴다 — **git log에 "왜"는 없다. 지어내지 말고 비워두는 것이 정답**이다.

### 회고-코드 동기 (부패 방지)
- **왜**: 기존 커밋 범위를 나중에 고치면(버그 수정·revert·값 변경) 회고의 사실 서술이 조용히 어긋난다.
- **이유**: 이 묶음 자체가 사례다 — 0250·0264~0266이 revert됐고, 0267의 앰버 토큰이 0269에서 삭제됐다. 정정 불가·불명확하면 그 사실을 보고에 명시한다(조용한 어긋남 금지).

### 작업의 교훈을 규칙으로 올린 것
- **§5 뷰포트 높이 (묶음 2 승격)**: svh 실기기 과소 / 중첩 flex grow 금지 / 짝 상수 콜로케이션 / Tailwind JIT 리터럴.
- **§9 상태 표시의 위계 (묶음 6 승격)**: 공존 상태는 둘 다 표시하되 강조 차등, 일시 상태는 무채 명도·지속 상태에만 색.
- **이유**: 작업의 교훈을 하네스 문서로 승격하는 사이클.

## 4. 코드 작성 & 수정

### 1. §7 — "회고 작성 주체" → "회고 작성 정책" (전면 재작성)

```diff
- ## 7. 회고 작성 주체
-
- - 회고(`docs/prompts/NNNN`)와 선질문 답변은 CC가 작성·커밋하지 않는다.
-   회고는 사용자가 선질문을 거쳐 조립하고, CC는 요청 시 "읽고 보고만"으로
-   코드 블록 확증만 담당한다.
- - 완료 보고에 회고 파일 생성·커밋을 포함하지 않는다 (docs 커밋은 사용자 몫).
```

```markdown
## 7. 회고 작성 정책

### 작성 시점 (트리거)
- **작업 단위 완료 보고에 회고 초안 작성 여부를 반드시 포함한다** —
  "회고 초안 작성했습니다" 또는 "회고 대상 아님(사유)" 중 하나.
  누락은 보고 미완으로 간주.
- 작업 단위 = plan 1개 승인~검증 완료의 묶음. 소작업 여러 개가 한
  기능이면 마지막 완료 시점에 범위를 묶어 1편.

### 양식·번호
- `docs/prompts/0999-회고-작성-예시.md`를 먼저 읽고 그 구조·톤을 따른다
  (5섹션 경량 양식).
- 파일명: `docs/prompts/NNNN-한국어-제목.md`.
  번호는 추측 금지 — ① `ls docs/prompts/`로 기존 회고 최신 번호,
  ② `git log --oneline`로 대상 커밋 범위를 둘 다 대조해 확정한다.
  결번·자리표시자 이력("025X"=0252, 0268 결번 등)은 그대로 명기.

### 역할 분담
- 사실 섹션(한 줄 요약·프롬프트·코드·커밋 목록)은 CC가 채운다.
- **"왜/목적/이유"·"배운점"은 `[사용자 확인 필요]` 표시 + 초안 수준까지만.**
  git log에 "왜"는 없다 — 지어내지 말고 비워두는 것이 정답이다.
- 초안은 커밋하지 않고 보고 — 사용자 검토·수정 후 사용자가 커밋.

### 회고-코드 동기 (부패 방지)

  정정 불가·불명확 시 그 사실을 보고에 명시한다 (조용한 어긋남 금지).
```

**이 절이 뒤집은 것**: 종전 규칙은 CC의 회고 작성 자체를 금지했다. 0273은 그 금지를 걷어내고 **"사실은 CC / 왜는 사용자 / 커밋은 사용자"** 3분할로 바꿨다.

### 2. §5 — 뷰포트 높이 절 신설 (묶음 2 승격)

```diff
- - 뷰포트 높이:
-   - **고정 레이아웃 기본은 `svh`** (주소창 노출 상태 기준, 스크롤 없는 정적 화면 안전)
-   - `vh` 폴백 유지 (CSS 캐스케이드로 자동 처리, svh 미지원 브라우저)
```

```markdown
### 뷰포트 높이 (0253~0256 실측 교훈 반영)
- 고정 레이아웃 기본은 `svh`, `vh` 폴백 유지. `dvh`는 명시적 이유 있을 때만.
- **실기기 iOS Safari의 svh는 헤드리스·시뮬보다 작다** (주소창·툴바 몫).
  svh 기반 높이엔 `max()` 하한을 짝으로 고려한다.
- **중첩 flex 스크롤 컨테이너에 flex-grow 사이징 금지** — iOS Safari가
  grow를 계산하지 않아 한 줄 높이로 붕괴한 실측 이력(0253).
  스크롤 영역 높이는 명시 calc로 결정한다.
- 서로 파생 관계인 높이 상수(시트↔목록 등)는 콜로케이션 + 상호 참조
  주석으로 짝을 명시한다 ("한쪽만 바꾸면 클립 잘림").
- Tailwind arbitrary 값은 완전 리터럴만 JIT 스캔됨 — 상수 추출 불가 시
  주석으로 동기 관계를 남긴다.
```

네 줄이 각각 묶음 2의 커밋 하나씩에 대응한다 — `max()` 하한(0254), 명시 calc(0253), 짝 상수(0254~0257), JIT 리터럴(0247 `SHEET_MAX_H` 주석).

### 3. §9 — 상태 표시의 위계 추가 (묶음 6 승격)

```markdown
- 상태 표시의 위계: 복수 상태(선택·호버 등)가 공존할 땐 둘 다 표시하되
```

## 5. 결과 / 배운점

### 결과
- CLAUDE.md가 50줄 늘고 10줄 줄었다(§5 재편·§7 전면 재작성·§9 추가).
- 회고 작성이 "기억나면 쓰는 것"에서 **완료 보고의 필수 항목**이 됐다.
- 번호 확정에 이중 대조가 강제됐다.
- **이 회고 묶음(0228~0273 7편) 자체가 §7의 산물이다** — 사실은 CC가 채우고, 커밋은 사용자가 한다. 인수인계 파일(`docs/0228-0273-회고-재료-인수인계.md`)이 "왜"의 원기억 역할을 맡은 것도 §7의 역할 분담을 따른 결과다.

### 배운점

- **잊지 않는 문제는 기억이 아니라 구조(보고 형식·이중 대조)로 푼다.**
- **작업의 교훈을 하네스 문서로 승격하는 사이클.** 코드 주석에만 두면 다음 화면에서 같은 실측을 반복한다.
- **AI에게 "모른다고 말할 자리"를 규칙으로 준다.** `[사용자 확인 필요]` 표기 하나가 "지어내기"와 "비워두기"를 구분해 준다 — git log에 "왜"는 없다.

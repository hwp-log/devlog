# 0055 회고: 맵 사이드 카드 재구성 및 추가 메뉴

- 작성일: 2026-05-30
- 소요: 약 3시간 (1~4단계 + 단계별 검수)
- 관련 커밋: feat: 0055 사이드 카드 재구성 및 추가 메뉴

## 1. 한 줄 요약

지도 사이드 카드를 "여행동선 짜기" 메뉴로 재구성하고, 흩어져 있던 불리언 플래그(`isAddMode`·`isEditing`)를 `mode` 상태머신 하나로 통합했다. 지도를 직접 클릭하면 마커가 추가되며 바로 편집 카드가 열리고, 저장 없이 취소하면 빈 마커가 자동으로 사라진다. 큰 작업이라 4단계로 나눠 진행하고 한 커밋으로 묶었다.

## 2. 왜 / 목적 / 이유

### a) mode 상태머신 통합

- **왜**: 기존엔 `isAddMode`·`isEditing` 같은 불리언이 따로 흩어져 있었다. 불리언 2개면 조합이 4가지인데, 그중 "추가 중이면서 동시에 편집 중"(true+true) 같은 현실에 없는 상태가 코드상 만들어질 수 있었다.
- **목적**: 한 번에 딱 한 상태만 갖게 해서, 불가능한 조합이 아예 태어나지 못하게.
- **이유**: 신호등이 빨강·노랑·초록 중 하나만 켜지듯, `mode`를 `menu`/`pinning`/`edit`/`view` 네 값 중 하나만 갖는 상태머신으로 만들면 "편집이면서 동시에 찍는 중" 같은 조합이 생길 수 없다. 잘못된 상태를 거르는 게 아니라, 태어나지 못하게 막는 것.

### b) 직접 클릭 입구 통합

- **왜**: 기존엔 지도 우상단 [마커 추가] 버튼으로 `isAddMode`를 켜야 지도 클릭이 먹었다. 새로 만든 메뉴의 [지도에서 찍기]랑 입구가 둘로 갈렸다.
- **목적**: [지도에서 찍기]를 누르면 곧장 지도 클릭이 먹게, 입구를 하나로.
- **이유**: 입구가 둘이면 처음 온 사용자가 어느 게 진짜인지 헷갈린다. 하나로 합쳐 동선을 단순하게 만들었다.

### c) 콜백 ref 우회 (stale closure)

- **왜**: 지도 클릭 핸들러는 `useEffect([])`에서 딱 한 번만 등록돼서, 그 안에 갇힌 `localSpots`·`addSpot`이 등록 시점의 옛날 값으로 얼어붙는다(stale closure). 마커가 추가돼도 핸들러는 옛날 목록을 본다.
- **목적**: 클릭할 때 항상 최신 `localSpots`·`addSpot`을 쓰게.
- **이유**: 1차(`pendingClick` state + effect 호출)는 `set-state-in-effect` 규칙에, 2차(렌더 중 `ref.current =` 직접 할당)는 "렌더 중 ref 쓰기 금지" 규칙에 막혔다(React 19 lint). 결국 "deps 없는 `useEffect`로 `ref.current`를 매 렌더 갱신 → 클릭 핸들러는 ref를 통해 최신 콜백 호출"로 우회했다. **이 우회 이유를 회고에 남기는 게 중요한데**, 안 남기면 나중에 코드를 보고 "왜 이렇게 빙빙 돌렸지?" 하고 잘못 건드려 stale closure 버그를 되살릴 수 있다.

### d) 추가 직후 편집 진입 + 취소 시 빈 마커 삭제

- **왜**: 직접 클릭으로 추가하면 이름 빈 마커가 생기는데, 조회 카드로 열리면 "수정"을 한 번 더 눌러야 작성할 수 있었다. 또 저장 없이 취소하면 이름 빈 마커가 그대로 남았다.
- **목적**: 추가하면 곧장 작성(편집) 카드로 열고, 취소하면 추가 자체를 없던 일로.
- **이유**: `SpotPopup`에 `initialEditing` prop을 줘서 추가 직후 편집 상태로 시작하게 했다. 취소할 땐 "`initialEditing`이 true이면서 저장된 이름이 빈" 경우만 = 방금 추가한 미저장 마커로 보고 삭제한다. 이름이 이미 있는 기존 마커의 편집 취소는 그대로 조회로 복귀시켜, 멀쩡한 마커가 실수로 지워지지 않게 했다.

## 3. 작성한 프롬프트

4단계로 나눠 진행했다. 각 단계 = plan 요청 → 검수 → 구현 → 검수. 커밋은 4단계가 다 끝난 뒤 한 번.

**1단계 (상태 그릇 + 사이드 펼침)**
```
mode useState<'menu'|'pinning'|'edit'|'view'>('menu') 추가.
사이드 카드: canAddSpot이면 항상 펼침.
activeSpot 있으면 SpotPopup, 없으면 menu placeholder.
★★★ 상태관리. 작성·수정·조회 3경로 회귀 확인. plan 요청.
```

**2단계 (메뉴 3버튼)**
```
placeholder를 메뉴 UI로 교체. 버튼 3개(검색·지도찍기·여행순서).
검색·여행순서는 0056·0057이라 비활성, [지도에서 찍기]만 활성 → setMode('pinning').
pinning이면 "지도를 클릭하세요" 안내 + 뒤로. plan 요청.
```

**3단계 (직클 연결)**
```
우상단 [마커 추가] 버튼 제거. 지도 클릭을 mode==='pinning' 기준으로(modeRef).
클릭 → addSpot → activeSpot 설정. 기존 isAddMode/하단폼/handleSaveSpot 제거.
★★★ 기존 흐름 들어내기라 회귀 위험 큼. plan 요청.
```

**4단계 (편집 진입 + 취소 삭제)**
```
SpotPopup에 initialEditing prop. 직클 시 setMode('edit') → initialEditing={true}.
마커 클릭 시 setMode('view') (버그 수정).
취소 시 initialEditing + 이름 빈 마커면 삭제. plan 요청.
```

## 4. 코드 작성 & 수정

핵심만 추렸다.

**mode 상태머신 + 사이드 분기** (`components/SpotMap.tsx`)
```typescript
const [mode, setMode] = useState<'menu' | 'pinning' | 'edit' | 'view'>('menu');

// 사이드 내용 분기 — 한 번에 한 갈래만
{activeSpot ? (
  <SpotPopup /* ... */ initialEditing={mode === 'edit'} />
) : canAddSpot ? (
  mode === 'pinning' ? <안내 + 뒤로 /> : <메뉴 3버튼 />
) : null}
```

**콜백 ref 우회** (`components/SpotMap.tsx`)
```typescript
// mode 최신값 추적용 ref
const modeRef = useRef(mode);
useEffect(() => { modeRef.current = mode; }, [mode]);

// 매 렌더 후 최신 addSpot·localSpots를 담은 콜백을 ref에 갱신
const addSpotFromMapRef = useRef<((lng: number, lat: number) => void) | null>(null);
useEffect(() => {
  addSpotFromMapRef.current = (lng, lat) => {
    const id = addSpot('', lng, lat);
    setActiveSpot({ id, name: '', lat, lng, order: localSpots.length + 1 });
    setMode('edit');
  };
});

// 클릭 핸들러는 한 번만 등록되지만, ref를 거쳐 항상 최신 콜백 호출
map.on('click', (e) => {
  if (modeRef.current !== 'pinning') return;
  addSpotFromMapRef.current?.(e.lngLat.lng, e.lngLat.lat);
});
```

**취소 시 빈 마커 삭제** (`components/SpotPopup.tsx`)
```typescript
const [isEditing, setIsEditing] = useState(initialEditing);

function cancelEdit() {
  // 직클로 방금 추가된 미저장 마커: 취소 = 삭제
  if (initialEditing && !displayName.trim()) {
    if (pendingPhotoPreview) URL.revokeObjectURL(pendingPhotoPreview);
    onDelete?.();
    onClose?.();
    return;
  }
  // 이름이 있는 기존 마커 편집 취소: 조회로 복귀 (기존 로직 유지)
  // ...
}
```

## 5. 결과 / 배운 것

### 결과
- 사이드 카드를 "여행동선 짜기" 메뉴로 재구성. 화면 5경로 검증 통과.
- 흩어진 불리언 플래그를 `mode` 상태머신으로 통합, 불가능한 조합 제거.
- 직접 클릭 입구를 하나로 통합, 추가 직후 편집 진입, 취소 시 빈 마커 삭제.
- `tsc`·`lint` 에러 0 (남은 경고는 기존 `<img>` 관련뿐).

### 배운 것

1. **상태머신** = 한 번에 한 상태만. 불리언 여러 개가 만드는 "불가능한 조합"을 원천 차단한다. 면접에서 "상태 관리 어떻게 했어요?"의 핵심 답이 된다.
2. **stale closure**는 `useEffect([])` 안에 갇힌 값이 옛날 것으로 얼어붙는 문제다. 콜백 ref(매 렌더 갱신)로 "주소는 고정, 내용물은 최신"을 만들어 우회했다. 단, 형태가 빙빙 돈 건 lint 규칙(React 19) 때문이라, 그 이유를 회고에 남겨야 미래에 안 헷갈린다.
3. **큰 작업은 잘게 쪼개되 한 커밋으로.** 4단계로 나눠 단계별 검수로 위험을 줄이고, 결과물은 하나의 의미 단위(0055)로 묶어 히스토리를 깔끔하게.
4. 기능을 만들 땐 정상 동선뿐 아니라 **"취소·되돌리기" 같은 빠져나가는 길도 함께 설계**해야 한다. 안 그러면 "추가했다 취소 → 빈 마커 잔류" 같은 쓰레기가 남는다.

## 2. 왜 / 목적 / 이유

(초안 — 요구·확정 근거에서 추린 초안 수준)

- **①**: flex-wrap에서 auto 마진이 더보기를 다음 줄로 밀어 5+1 두 줄이 됨 — 좌측 연속 배치로 전환.
- **②**: 버블이 모바일의 실질 주 경로인데 접힌 항목 접근로가 없었음. H2를 버블에 유지하는 전제 — 노션은 키보드 위 상시 툴바로 블록 변환을 하지만 우리는 툴바가 문서 상단 비고정이라 글 중간에서 스크롤이 필요(사용자 확정). **데스크톱 버블에도 추가(CC 판단)**: 데스크톱도 툴바가 in-flow 비고정이라 같은 스크롤 이탈 문제 + 두 환경 버블 구성 한 벌 유지 + 폭 증가 미미(+42px).
- **③**: 두 오버레이 동시 노출은 혼란(요구사항). 방식 선택 근거 — extensions가 useMemo []로 고정돼 콜백 교체가 불가한 구조라, 호출 시점에 ref를 읽는 지연 참조(0457 이미지 콜백·0378 SpotPopup closeHandleRef 선례)가 현재 구조에 맞는 쪽.

### ② `TiptapEditor.tsx` BubbleMenu 끝 + `ToolbarMore.tsx` 트리거

```tsx
{/* 구분선 — ToolbarDivider는 max-sm:hidden이라 모바일 표시가 필요한 버블엔 인라인 div */}

```

ToolbarMore 트리거에 `sm:min-h-0 sm:min-w-0` 추가 — 데스크톱 버블에서 다른 버튼과 28px 정합(툴바 쪽은 sm:hidden 래퍼라 무영향).

### ③ 동시 표시 방지 — 3파일 배선

```tsx
// SlashCommand.tsx — 시그니처 확장 + allow 게이트 + 닫힘 핸들 노출
createSlashCommand(onImagePick, isSuppressed?, closeHandleRef?)
allow: (…) => { if (isSuppressed?.()) return false; … }
onStart: closeHandleRef.current = destroy  /  destroy(): closeHandleRef.current = null

// TiptapEditor.tsx — ref 2개 + 공용 핸들러(툴바·버블 두 인스턴스)
const moreOpenRef = useRef(false); const slashCloseRef = useRef<(() => void) | null>(null);
createSlashCommand(() => fileInputRef.current?.click(), () => moreOpenRef.current, slashCloseRef)
function handleMoreOpenChange(open) { moreOpenRef.current = open; if (open) slashCloseRef.current?.(); }

// ToolbarMore.tsx — 열림 통지(클린업 경유라 닫힘·언마운트(버블 숨김) 모두 false 보장)
useEffect(() => { if (!open) return; onOpenChange?.(true); return () => onOpenChange?.(false); }, [open, onOpenChange]);
```

린트 여담: useMemo 고정 객체 브리지 시도는 `react-hooks/immutability`(훅 산출물 변경 금지)에 걸려 기각 — 가변 비렌더 상태는 useRef가 정위치. `react-hooks/refs` 오탐(지연 참조)은 해당 호출 줄에만 근거 주석 + `eslint-disable-next-line`(StoryWriteForm의 exhaustive-deps disable 선례) — 이 줄의 기존 오탐 1건도 함께 침묵됨을 주석에 명시.

## 5. 결과 / 배운점

### 결과 (검수 ①~④)
- **① 한 줄 수치**: 6×44 + gap 5×4 = 284px ≤ 294(360px 가용)/324(390px) — 계산상 한 줄. 실화면 확인은 사용자.
- **② 버블 폭**: 모바일 ≈245 → **≈299px(+54)** (gap4+구분선2+gap4+⋯44), 데스크톱 ≈171 → ≈213px(+42). shift(8)로 뷰포트 이탈 없음. **iOS 자체 선택 콜아웃**: 수직 겹침 조건은 기존 버블과 동일(placement top·offset 8 — 콜아웃도 선택 위), 폭 +54만큼 수평 겹침 확률 소폭 증가 — 실기기 확인 항목.
- **③ 버블발 패널 위치**: ⋯ 트리거 기준 `bottom-end`+flip+shift(8) — 보통 버블 아래(선택 영역을 덮을 수 있음, 플로팅 특성), 하단 공간 부족 시 위로 플립, 화면 밖 이탈 없음.
- **④ 동시 표시 잔존 경로**: 패널→"/" 차단(allow) / 슬래시→툴바 ⋯ 차단(열 때 destroy) / 슬래시→버블 ⋯는 경로 부재(슬래시 중엔 캐럿이라 버블 안 뜸). **잔존 1건(범위 밖)**: 데스크톱 FormatMenu(서식 팝오버)+슬래시 동시는 기존부터 가능 — 요구가 "더보기 패널" 한정이라 미변경, 별도 결정 필요 시 같은 배선 재사용 가능.
- tsc·eslint(변경 3파일 0건)·테스트 기준선(6 스위트/8 테스트) 일치.

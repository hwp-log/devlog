## 1. 한 줄 요약

방문자 수를 세려고 Google Analytics 4(GA4)와 Vercel Web Analytics를 함께 도입.
GA4는 이벤트·전환 분석용, Vercel은 방문 수 집계용으로 역할을 나눴다. 도입
과정에서 GA 패키지(@next/third-parties)가 전역 타입을 건드려 기존 파일 한 곳에
타입 에러가 났고 타입 명시 한 줄로 해소했다(런타임 동작 변경 없음).

---

## 2. 왜 / 목적 / 이유

왜: Dotrip은 배포돼 운영 중이었으나 방문자 수를 세는 수단이 없었다.
지원 중이라 사람이 들어오는지 확인할 필요가 생겼다.

왜 GA 하나로 끝내지 않았나: GA4는 방문 신호를 google-analytics.com이라는
구글 소유 주소로 보낸다. 광고 차단기는 이 주소를 차단 목록에 갖고 있어
광고 차단기를 켠 방문자는 집계에서 빠진다. 로컬에서 실측한 결과가 그랬다 -
GA 스크립트 자체는 로드돼 `window.gtag`(GA가 심어두는 전송 함수)는
function으로 초기화됐지만 실제 수집(collect) 요청은 0건이었다.

Vercel Web Analytics는 신호를 우리 서비스 자신의 경로(`/_vercel/insights`)로
보낸다. 차단 목록은 외부 추적 도메인을 겨냥하므로
자기 도메인 경로는 걸리지 않는다. 그래서 GA를 그대로 두고 Vercel
Analytics를 같이 붙였다. 방문 수는 Vercel에서 보고 이벤트·전환은
GA에서 보기로 했다.

## 4. 코드 작성 & 수정

### 배경 — 세 커밋의 인과

작업은 GA4 도입(0622)에서 시작했다. `@next/third-parties`는 설치만 된
상태에서는 빌드가 통과했고 `layout.tsx`에 import 한 줄을 넣자 그 패키지가
손대지도 않은 기존 파일에 타입 에러가 났다. 이것을 먼저 치운 것이
0621이다. GA4를 붙인 뒤 광고 차단기 문제를 실측으로 확인해 Vercel Analytics를
병행한 것이 0623이다. 아래 서술도 이 순서를 따른다.

### 0621 (c17feeb) — jsdom 타입 충돌

`lib/story/clean-empty-sections.ts`는 jsdom(브라우저 없이 HTML을 파싱하는
라이브러리)으로 스토리 본문의 빈 구간을 정리한다. 기존 코드는 jsdom이 만든
가짜 window에서 document를 구조 분해로 꺼냈다.

```diff
-    const { document } = new JSDOM(html).window;
+    // Document 명시: @next/third-parties가 전역 Window에 [key: string]: any 인덱스
+    // 시그니처를 병합해 DOMWindow(Omit<Window,...>)의 구체 속성 추론이 무너짐.
+    // 타입만 복원하는 주석이며 런타임 동작은 이전과 같다.
+    const document: Document = new JSDOM(html).window.document;
```

주석의 "인덱스 시그니처"는 "어떤 이름의 속성이든 허용한다"는 규칙을 말한다.
"DOMWindow(Omit<Window,...>)"는 jsdom이 전역 Window에서 몇 가지를 빼내
자기 타입을 만든다는 뜻이다.

에러의 원인은 @next/third-parties의 타입 선언이다. 이 패키지는 전역 Window
타입에 "어떤 이름의 속성이든 any로 허용한다"는 규칙을 덧붙인다. jsdom의
window 타입은 전역 Window를 가공해 만드는데 그 규칙이 끼어들자 document의
구체 타입 추론이 무너졌다. 구조 분해 대신 `document: Document`로 타입을
직접 적어 복원했다. 타입 주석만 바뀌었고 런타임 동작은 이전과 같다.

### 0622 (6edcf9e) — GA4 정식 도입

`@next/third-parties`의 GoogleAnalytics 컴포넌트를 루트 레이아웃에 추가했다.

```diff
+import { GoogleAnalytics } from "@next/third-parties/google";
```

```diff
+  // GA4 — Vercel Production에만 NEXT_PUBLIC_GA_ID가 있어 Preview·로컬 방문은 수집 안 됨
+  const gaId = process.env.NEXT_PUBLIC_GA_ID;
```

```diff
       </body>
+      {gaId && <GoogleAnalytics gaId={gaId} />}
     </html>
```

`{gaId && ...}`는 gaId에 값이 있을 때만 뒤의 컴포넌트를 그린다는 뜻이다.
값이 없으면 그 자리에 아무것도 렌더되지 않는다.

측정 ID는 환경 변수 `NEXT_PUBLIC_GA_ID`에서 읽고 없으면 컴포넌트 자체를
렌더하지 않는다. 이 변수를 Vercel의 Production 환경에만 둬서 Preview 배포와
로컬 개발 중의 방문은 수집되지 않는다. 코드에 분기를 넣는 대신 변수를 두는
위치로 수집 범위를 제어한 것이다.

`NEXT_PUBLIC_`으로 시작하는 변수는 빌드할 때 값이 코드에 박힌다. 실행 중에
읽는 것이 아니므로 Preview 빌드에는 애초에 값이 들어가지 않는다.

### 0623 (ebb9191) — 광고 차단기 → Vercel 병행

로컬 실측에서 GA 수집이 광고 차단기에 막히는 것을 확인하고
`@vercel/analytics`를 함께 넣었다.

```diff
+import { Analytics } from "@vercel/analytics/next";
```

```diff
         </div>
+        {/* Vercel Web Analytics — 자기 도메인 경로(/_vercel/insights)로 전송해 광고 차단기에 안 걸림. dev 모드는 수집 안 함 */}
+        <Analytics />
       </body>
```

배치 위치가 GA와 다르다. GA는 `</body>` 뒤, Vercel은 `<body>` 안이다. 각
패키지의 공식 문서가 지정한 자리를 그대로 따랐고 편의로 맞추지 않았다.

Vercel Analytics는 설정값 없이 `<Analytics />` 한 줄이면 되고 dev 모드에서는
스스로 수집하지 않는다. GA의 조건 렌더는 손대지 않고 그대로 유지했다.

## 5. 결과 / 배운점

### 결과

- 같은 방문에서 GA 수집 0건, Vercel 1건으로 실측 확인됨
  (0623 커밋 메시지의 근거와 동일)
- GA4는 Production 한정 수집으로 동작, Vercel Analytics는 dev 외 환경에서 수집
- 0621 타입 에러 해소 — 런타임 동작 변경 없음
- Vercel 대시보드 첫 기록: Visitors 1, Page Views 3, `/story` 1건.
  Referrers는 비어 있다 — 주소를 직접 입력해 들어갔기 때문이다

### 배운점

**패키지 하나가 손대지 않은 파일을 깨뜨릴 수 있다.** GA를 붙이는데
스토리 정리 파일이 터졌다. 원인은 세 칸 건너에 있었다 — GA 패키지가
전역 Window에 "아무 이름이나 넣어도 된다"를 추가했고 jsdom이 그 Window를
가공해 자기 타입을 만드는데 그때 구체 속성이 함께 뭉개졌다. 전역을
건드리는 선언은 그 파일 안에서 끝나지 않는다.

그래서 이번 작업 이후 패키지를 새로 넣을 때 전역 타입 선언을 먼저
확인하기로 했다. 0623에서 실제로 그 절차를 밟았고 `@vercel/analytics`는
구체 속성 다섯 개뿐이라 안전하다는 것을 설치 전에 알았다.

**멈추고 물어본 것이 원인을 남겼다.** CC가 "타입 주석 한 줄을 추가해도
되느냐"고 물었을 때 허락하지 않고 중단을 골랐다. 허락했으면 빌드는
살았겠지만 왜 깨졌는지는 모른 채 넘어갔을 것이다. 조사 결과 방아쇠가
패키지 설치가 아니라 import 한 줄이라는 것까지 나왔다.

**붙였다고 도는 것이 아니다.** GA를 배포하고 나서 Network 탭에 요청이
0건이었다. 배포도 코드도 환경변수도 정상이었는데 광고 차단기가 막고
있었다. `window.gtag`는 function으로 초기화됐지만 수집 요청만 나가지
않는 상태였다. 스크립트를 받아오는 것과 신호를 보내는 것은 다른 일이다.

그리고 이 발견이 0623을 만들었다. 내 브라우저에서만 막히는 문제가
아니라 차단기를 쓰는 모든 방문자가 집계에서 빠진다는 뜻이었다. 그래서
GA를 떼는 대신 Vercel Analytics를 같이 붙였다. 자기 도메인 경로로
보내는 방식이라 차단 목록에 걸리지 않는다.

**계측이 붙었다고 숫자를 믿을 수 있는 것도 아니다.** Vercel Analytics는
쿠키 없이 접속 정보를 조합해 방문자를 세므로 기기나 브라우저를 바꾸면
같은 사람도 여러 명으로 잡힌다. 그래서 앞으로 배포 확인은 한 대의
컴퓨터에서만 하기로 했다. 내 방문을 하루 한 건으로 고정해두면 그보다
많은 날은 다른 사람이 왔다는 뜻이 된다.

---

## 결정 (Decisions)

- **GA와 Vercel Analytics 병행 유지.** GA를 떼지 않고 역할을 나눴다 —
  방문 수는 Vercel(광고 차단기에 안 막힘), 이벤트·전환은 GA.
- **GA 수집 범위는 Production 한정.** `NEXT_PUBLIC_GA_ID` 변수를 Vercel
  Production에만 두는 방식으로 제어. 변수가 없으면 컴포넌트가 렌더되지
  않는다.
- **0621 타입 충돌은 타입 명시 한 줄로 해소.** @next/third-parties가 전역
  Window에 병합한 인덱스 시그니처가 원인. 구조 분해를 풀고 `document:
  Document`로 직접 적었다. 런타임 무변경이며 원인을 코드 주석으로 남겼다.
- **패키지 도입 전 전역 타입 선언 확인을 절차로 추가.** 0621을 겪고 만든
  것이고 0623에서 바로 적용했다. 확인 방법은 최소 재현이다 — 그 선언만
  담은 파일을 만들어 프로젝트 tsc로 돌려본다.
- **배포 확인은 한 대의 컴퓨터에서만.** 방문자 판정이 접속 정보 조합
  방식이라 기기를 바꾸면 같은 사람이 여러 명으로 잡힌다. 내 몫을 하루
  한 건으로 고정해야 그보다 많은 날을 외부 유입으로 읽을 수 있다.

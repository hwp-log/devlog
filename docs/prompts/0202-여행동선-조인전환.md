# 0202 회고: 스토리 상세 여행동선을 조인 기준으로 전환

작성일: 2026-07-14 / 소요: 약 30분 / 커밋: 8426ad9

## 1. 한 줄 요약
S3-a 재사용 스토리에서 여행동선이 통째로 사라진 원인 — 상세가 S2 미전환분(구컬럼 FK)이었다. 조인 기준으로 전환했다.

## 2. 왜 / 목적 / 이유
- **왜**: 재사용 스토리는 owned Spot이 0이라 `story.spots.length > 0`이 false → 섹션 미렌더. 데이터는 story_spots 조인에 전부 있었다(SQL 확증).
- **목적**: storySpots 조인으로 전환. per-visit(order·review·photoUrl·rating)은 조인에서, per-place(name·좌표)는 spot에서.
- **이유**: S2에서 SpotFinder만 전환하고 상세를 남긴 것이 원인 — 당시엔 모든 스팟이 스토리 소속이라 무해했으나 S3-a가 전제를 깼다. 편집 페이지(0201 전환)와 같은 패턴으로 일관.

## 3. 작성한 프롬프트
[읽고 보고만] 원인 조사(구컬럼 조회 여부·타 화면 전수·SQL 확증) → 전환 지시 + 미전환 소비처 전수 재조사 요구.

## 4. 작성·수정한 코드
1파일 23+/8-. 조인 전환과 함께 **작품 표시도 이 커밋에서 조인으로 바뀌었다**(아래 주의).

```ts
// app/story/[id]/page.tsx — spots include → storySpots { orderBy, select: { …, spot: {…} } }
// 조건도 story.storySpots.length > 0으로, rating(0199)도 상세에 노출

// 작품은 spot_movies 조인(복수) — 레거시 spot.movie(단수)는 재사용 seed 스팟에서 null이라 누락됨
spot: { include: { spotMovies: {
  orderBy: { createdAt: 'desc' },
  select: { movie: { select: { id: true, title: true } } },
} } },

// 작품: spot_movies 최신 연결순(0185 대표 규칙) → 대표 1개 + extraMovieCount("+N"). SpotFinder와 동일 정책.
const movies = ss.spot.spotMovies.map((sm) => sm.movie);
movieId: movies[0]?.id ?? null,
movieTitle: movies[0]?.title ?? null,
extraMovieCount: Math.max(0, movies.length - 1),
```

> **커밋 경계 주의**: 0203 커밋 메시지가 "여행동선 작품 표시 조인 전환"을 함께 표방하지만,
> 실제 `page.tsx` 작품 조인은 **이 커밋(8426ad9)에 들어 있다.** 0203 커밋(49af65b)의 diff는
> `SpotPopup.tsx` 편집 잠금 하나뿐이다. 메시지가 앞 커밋의 일을 중복 서술한 경우.

## 5. 결과 / 교훈
- 1파일 23+/8-. 재사용·기존 스토리 모두 정상.
- 교훈: **부분 전환은 조건이 바뀌면 터진다.** "SpotFinder만 전환"이 남긴 빚을 S3-a가 청구했다. 읽기 소비처는 화면 단위가 아니라 전수 조사로.

## 1. 한 줄 요약

상세 모달이 뚝 나타나던 것을 마운트 자동 재생 `@keyframes`로 슬라이드 업 시켰고(0263, 현행 유지), 그 짝인 닫기 슬라이드 다운은 닫힘 상태·`animationend` 폴백·이중 back 차단까지 설계했으나 실기기에서 검은 띠·하단 멈칫·지도 미표시가 얽혀 3커밋을 일괄 revert하고 **"닫기는 즉시"**로 확정했다.

---

## 2. 왜 / 목적 / 이유

> 근거: `docs/0228-0273-회고-재료-인수인계.md` 묶음 4.

### 열기 트랜지션 (0263)
- **왜**: 상세 모달이 뚝 나타났다 — iOS 시트 표준(아래에서 위로 슬라이드)이 없었다.
- **목적**: iOS 시트 표준인 슬라이드 업을 적용한다.
- **이유(구현 방식)**: 이 모달은 **조건부 렌더**라 `transition`을 쓸 수 없다 — 마운트 직후 최종 스타일로 첫 페인트가 끝나기 때문. 그래서 마운트되면 자동 재생되는 `@keyframes`를 썼다. 상태도 `requestAnimationFrame`도 없는 최소 방식.
- **기존 keyframe 재사용을 기각한 이유**: `ph-enter`는 다른 용도 전용이라 재사용하면 의미가 결합되고, `opacity`가 포함돼 있어 iOS 불투명 슬라이드와 어긋난다.
- **320ms / cubic-bezier(0.32, 0.72, 0, 1)**: 시트 토글(0245)과 같은 값 — 질감 통일.

### 닫기 트랜지션 (0264~0266) → 전량 revert
- **왜**: 열기의 짝으로 닫기도 슬라이드 다운을 넣었다.
- **설계는 정교했다**: 닫힘 상태(`detailClosing`) + `animationend` + 400ms 타임아웃 폴백 + closing 중 재열기 차단 + **이중 `back()` 방지**(페이지 이탈!)까지 경합 경로를 전부 막았다.
- **그런데 실기기에서 세 증상이 얽혔다**: 검은 띠 · 하단 멈칫 · 지도 미표시. 0265에서 원인을 `height:100svh`가 `inset-0`을 무력화하는 **over-constrained**로 지목하고, 0266에서 히어로를 노치까지 확장했지만 정리되지 않았다.
- **결론**: 새벽에 3커밋 일괄 revert. **"닫기는 즉시"로 확정** — 닫기는 이탈이라 빠른 게 어색하지 않다.
- **킵 조건**: 재도전한다면 실기기 실측부터.

## 4. 코드 작성 & 수정

### 1. 0263 — 마운트 자동 재생 keyframe (현행 유지)

```css

   ph-enter 재사용 기각: TagSearchBar 롤링 전용 + opacity 포함이라 의미 결합·질감 상이 */
@keyframes detail-up {
  from { transform: translateY(100%); }
  to { transform: translateY(0); }
}
```

### 2. 0264 — 닫기 상태 + 폴백 + 이중 back 차단 (revert됨: `2d0a1ea`)

```css
/* app/globals.css — revert됨: 2d0a1ea */
/* 0264: 상세 모달 ✕ 닫기 슬라이드 다운 (detail-up의 짝 — 사용처에서 forwards 필수: 종료~언마운트 프레임 사이 되튐 방지) */
@keyframes detail-down {
  from { transform: translateY(0); }
  to { transform: translateY(100%); }
}
```

```tsx
// components/SpotFinderMapNaver.tsx — revert됨: 2d0a1ea
const [detailClosing, setDetailClosing] = useState(false); // 0264: ✕ 슬라이드 다운 재생 중 (popstate 닫힘은 즉시라 미경유)

// 0264: closing 중 재열기 무시 — 모달이 내려가며 시트가 노출·탭 가능해지는 320ms 동안
// 이중 pushState/이중 back 차단(선택 변경만 통과, 무해).
function openDetail(spot: SpotFinderSpot) {
  if (detailClosing) return;
  window.history.pushState({ detail: spot.id }, '', '?detail=' + spot.id);
  setDetailOpen(true);
}
// 0264: ✕ 닫기 완료(공용 — animationend·타임아웃 폴백). closing 해제 후 back() → popstate가 detailOpen을 끔.
function finishCloseDetail() {
  setDetailClosing(false);
  window.history.back();
}
// 0264: animationend 미발화(백그라운드 탭 등) 대비 폴백 400ms(320+여유). closing 해제 시 cleanup이 타이머 취소 —
// popstate로 먼저 닫힌 경우 이중 back(페이지 이탈!) 방지의 핵심.
useEffect(() => {
  if (!detailClosing) return;
  const t = setTimeout(finishCloseDetail, 400);
  return () => clearTimeout(t);
}, [detailClosing]);
```

```tsx
// 렌더 — revert됨: 2d0a1ea
<div
  className={`lg:hidden fixed inset-0 z-[60] bg-bg ${detailClosing
    ? 'animate-[detail-down_320ms_cubic-bezier(0.32,0.72,0,1)_forwards]'
    : 'animate-[detail-up_320ms_cubic-bezier(0.32,0.72,0,1)]'}`}
  style={{ height: '100svh' }}
  onAnimationEnd={(e) => { if (detailClosing && e.animationName === 'detail-down') finishCloseDetail(); }}
>
```

`animationName` 검사로 detail-up 종료·자손 버블 오발화를 걸러낸 것까지 설계돼 있었다.

### 3. 0265 — over-constrained 진단 (revert됨: `441cee5`)

```tsx
// components/SpotFinderMapNaver.tsx — revert됨: 441cee5
{/* 0265: height 100svh 제거 — inset-0의 bottom:0을 height가 무력화(over-constrained)해 실기기 svh 과소 시
    모달이 화면보다 ~80px 짧음 → ① 상단/하단 경계 노출 ② translateY(100%)=자기높이만큼 하강이라 종료 후에도
    하단 스트립이 남아 back 지연 동안 "멈칫"으로 보임 — 두 실기기 증상의 공통 원인. inset-0 단독 = 컨테이너
    완전 채움(본문 calc(100%-210px)도 성립, dvh 불요). */}
```

같은 커밋에서 닫힘 감지를 React 합성 이벤트에서 **ref 네이티브 리스너**로 바꿨고, 실측으로 앞선 가설을 스스로 정정한 기록도 남겼다:

```ts
// revert됨: 441cee5
// 0264→0265: 닫힘 감지 = 모달 요소 "직접" 네이티브 animationend + 폴백 400ms 통합(React 위임 의존 제거 — 방어적 단순화).
// 0265 실측 정정: 크롬·WebKit 모두 원래 animationend 경로로 닫히고 있었음(폴백 2000ms 실험으로 확정).
// 실기기 "멈칫"의 실원인은 모달 height:100svh 잔여 스트립 — end→popstate 사이 back 지연(크롬 실측 39ms) 동안
// 잔여 ~80px이 forwards로 정지 노출된 것.
useEffect(() => {
  if (!detailClosing) return;
  const el = detailModalRef.current;
  const onEnd = (e: AnimationEvent) => { if (e.animationName === 'detail-down') finishCloseDetail(); };
  el?.addEventListener('animationend', onEnd);
  const t = setTimeout(finishCloseDetail, 400);
  return () => { el?.removeEventListener('animationend', onEnd); clearTimeout(t); };
}, [detailClosing]);
```

### 5. revert 후 남은 상태

- `detail-down` keyframe·`detailClosing` 상태·네이티브 리스너·이중 back 차단 — 전부 사라졌다. 오늘 코드에는 `detail-up` 하나만 있다(`app/globals.css:73`).
- 0265가 지목했던 `style={{ height: '100svh' }}`도 revert와 함께 **되돌아와 현재 코드에 남아 있다**(`SpotFinderMapNaver.tsx:1253`).

## 5. 결과 / 배운점

### 결과
- 열기 슬라이드 업은 오늘까지 그대로 쓰인다. 상태 없이 keyframe 하나로 끝낸 최소 구현.
- 닫기는 **즉시**로 확정. 백로그 C절에 "재도전 시 실기기 실측부터"로 킵.
- 정교한 경합 방어(폴백·이중 back 차단)를 전부 만들어 놓고도, 증상이 얽히자 붙들지 않고 되돌렸다.

### 배운점

- **조건부 렌더 + 애니메이션은 마운트와 언마운트의 해법이 다르다.** 마운트 쪽은 `@keyframes` 자동 재생으로 상태 없이 끝나지만, 언마운트 쪽은 닫힘 상태를 두고 재생이 끝날 때까지 언마운트를 지연해야 한다. 이번 결과도 그 비대칭 그대로다(열기 채택, 닫기 기각).
- **`height`와 `inset-0`은 함께 쓰면 over-constrained다.** 실기기 svh 과소와 결합하면 실기기에서만 터진다.
- **새벽에 증상 3개가 얽히면 파고들지 말고 확실한 지점으로 되돌린다.**
- **닫기는 이탈이라 즉시여도 어색하지 않다.**

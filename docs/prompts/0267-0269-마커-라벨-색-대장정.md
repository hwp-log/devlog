## 1. 한 줄 요약

다크 지도에서 미선택 마커 라벨이 묻히는 문제를 앰버(#ffb84d) 토큰 신설로 풀었다가 — 흰 글자 시도 기각, 구글 나이트 모드 공식 스타일 발견, 카라멜·회색 목업과 실기기 비교 2회를 거쳐 — **회색 그라데이션 + 흰 테두리 0.5 + 미세 입체**로 되돌아오고 앰버 토큰을 삭제해, 선택 파랑을 화면의 유일한 색으로 남겼다.

---

## 2. 왜 / 목적 / 이유

> 근거: `docs/0228-0273-회고-재료-인수인계.md` 묶음 5.

- **왜**: 미선택 마커 라벨(회색 pill)이 다크 지도에 묻혀 촬영지를 지나쳤다.
- **목적**: 지도 위에서 "찾는 대상"이 배경과 구분되게 만든다.

### 결정 여정 (왕복 자체가 서사)

1. **0267 — 앰버 채택.** `#ffb84d` + 다크 잉크 `#2b1d00`으로 토큰을 신설했다. 대비 9:1.
2. **흰 글자 시도 → 즉시 기각.** 실기기에서 씻겨 보이는 것을 확인했다 — 대비 1.9:1.
3. **구글 나이트 모드 공식 스타일 발견.** 구글 지도 나이트 모드의 POI 라벨이 `#d59563` — 다크 지도에서 "찾는 대상"을 앰버 계열로 띄우는 것이 구글의 명문 문법이었다. 면접용 레퍼런스.
4. **카라멜(#d59563) 목업 → 회색 목업 → 실기기 비교 2회.**
5. **0269 최종 = 회색.** 앰버 토큰을 삭제하고, 배경은 `#33383d → var(--surface2)` 그라데이션, 테두리 `white/0.5`, 미세 입체(`inset 0 1px 0 white/0.14` + 그림자 0.4). **선택 파랑을 화면의 유일한 색으로** 남겼다.

### 입체감 레벨
- PPT 광택 수준(inset 0.45)을 기각하고 "살짝"(0.14)으로 확정. 멘토의 "shadow가 과하다" 피드백을 반영해 절제했다.

### 왜 결국 회색이었나
- **"느낌이 갈리면 시스템 일관성이 캐스팅보트"**로 정리했다.

### 2. 0269 — 회색 확정 + 미세 입체, 토큰 삭제

```ts
// components/SpotFinderMapNaver.tsx (0269)
// 0269 확정: 미선택 = 회색 pill(목업 스펙) — 밝은 테두리(흰 0.5)+상단 inset 하이라이트가 다크 지도 지명과의 구분을 담당
// (앰버 0267~0268은 실기기 비교로 기각 — 토큰도 삭제). 선택 = primary 파랑, 그림자 문법만 통일.
// 그라데이션 밝은 톤 #33383d 리터럴 근거: surface2(#26292b)의 흰색 혼합 파생으로는 목업의 청색 성분(+5B)이 재현 안 됨
// — color-mix 파생(0268 관례) 불가 판정, 목업 확정값을 그대로 사용.
const pillColor = selected
  ? `background:linear-gradient(to bottom,color-mix(in srgb,${PRIMARY} 82%,#fff),${PRIMARY});color:#fff;border:1px solid ${PRIMARY};box-shadow:inset 0 1px 0 rgba(255,255,255,0.2),0 2px 6px rgba(0,0,0,0.4);`
  : 'background:linear-gradient(to bottom,#33383d,var(--surface2));color:var(--fg2);border:1px solid rgba(255,255,255,0.5);box-shadow:inset 0 1px 0 rgba(255,255,255,0.14),0 2px 6px rgba(0,0,0,0.4);';
```

```ts
// lib/theme.ts (0269) — 앰버 토큰 삭제
- markerLabel: '#ffb84d',
- markerLabelInk: '#2b1d00',
```

**되돌아왔지만 원상복귀는 아니다.** 0267 이전의 미선택 pill은 `background:var(--surface2)` 단색 + 테두리 `white/0.3`이었다. 0269는 같은 회색 계열이되 그라데이션 + 테두리 0.5 + 상단 하이라이트가 붙었다 — 색을 안 쓰고 **명도·입체로** 구분성을 만든 것이다.

### 3. 현재 코드에서의 상태

0269 리터럴은 오늘도 살아 있다. 이후 라이트 테마가 들어오면서(0292) `isDark` 분기가 감싸졌을 뿐, **다크 값은 "0269~0270 확정 리터럴 바이트 원복"**으로 명시돼 있다.

```ts
// components/SpotFinderMapNaver.tsx:75~84 (현재)
// 0269 확정(다크): 미선택 = 회색 pill — 밝은 테두리(흰 0.5)+상단 inset 하이라이트가 다크 지도 지명과의 구분 담당.
// 선택 = primary 파랑 그라데이션(상단 흰 혼합 광택). 라이트(0292): 선택·비선택 모두 완전 플랫 —
const pillColor = selected
  ? (isDark
    ? `background:linear-gradient(to bottom,color-mix(in srgb,${PRIMARY} 82%,#fff),${PRIMARY});…`
    : `background:${PRIMARY};color:#fff;border:1px solid ${PRIMARY};box-shadow:none;`)
  : (isDark
    ? 'background:linear-gradient(to bottom,#33383d,var(--surface2));color:var(--fg2);border:1px solid rgba(255,255,255,0.5);box-shadow:inset 0 1px 0 rgba(255,255,255,0.14),0 2px 6px rgba(0,0,0,0.4);'
    : 'background:var(--card);color:var(--fg2);border:1px solid var(--border);box-shadow:none;');
```

`lib/theme.ts`에 `markerLabel`은 없다 — 0269의 삭제가 유지되고 있다.

## 5. 결과 / 배운점

### 결과
- 미선택 라벨은 **색 없이** 다크 지도에서 구분된다(명도 + 테두리 + 미세 입체).
- 선택 파랑이 SpotFinder 지도의 유일한 색으로 남았다.
- 커밋 메시지에 기각 이력을 새겼다 — `"앰버 검토 끝에 기존 회색 배경 유지"`. 나중에 "왜 회색인가"를 물었을 때 답이 커밋에 있다.

### 배운점

- **"느낌이 갈리면 시스템 일관성이 캐스팅보트."** 수치화되지 않는 선택의 탈출 규칙이다.
- **실기기 시인성이 이론(WCAG 수치)을 이긴다.** 흰 글자 사건이 그 사례다.
- **색은 감이 아니라 비교 실측으로 정한다.** 목업 3회 + 실기기 비교 2회로 결정했다.
- **커밋 메시지에 기각 이력을 남긴다.** "앰버 검토 끝에" 한 마디가 미래의 "왜 이 값?"에 답한다.

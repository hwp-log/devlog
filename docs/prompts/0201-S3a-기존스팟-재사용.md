# 0201 회고: S3-a 기존 스팟 재사용 — 근접 후보 제시·사람 판단

작성일: 2026-07-14 / 소요: 약 1.5시간 / 커밋: 3b80c99

## 1. 한 줄 요약
스토리 작성 시 반경 200m의 기존 촬영지를 후보로 제시하고, 선택하면 새 Spot 없이 조인만 추가한다 — 실측(14m=같은 곳, 4m=다른 곳)이 "자동 통합 불가·사람 판단 필수"를 증명했다.

## 2. 왜 / 목적 / 이유
- **왜**: 사용자가 "롯데월드타워"를 만들었는데 시딩 "롯데월드몰"과 사실상 같은 곳(14m) — 쓰기가 여전히 새 Spot을 만들어 중복이 쌓였다. B1의 마지막 미완성 조각.
- **목적**: 근접 후보 UI + existingSpotId 분기(있으면 StorySpot·SpotMovie만 추가, 없으면 현행 생성). 좌표 이동·삭제 시 재사용 자동 해제.
- **이유**: 실측 — 롯데월드몰↔타워 14m(같은 곳), 구룡포 가옥거리↔공원계단 4m(다른 곳). **거리로는 동일성 판별 불가** → 기계는 후보만, 사람이 결정. 이름 매칭도 게이트 금지("몰"≠"타워"라 이 케이스를 놓침 — 좌표만으로 후보, 이름은 표시만). haversineM은 geo.ts로 추출(server-only 제거, 복제 없는 재사용).

## 3. 작성한 프롬프트
S3-a만(dual-write 중단·RLS는 S3-b) + plan 실측 선행(반경 근거·두 스팟 실거리·표지 3개 storyId=null 발생 여부).

## 5. 결과 / 교훈
- 10파일 279+/74-. 스키마 무변. storyId=null이 안 생겨 표지 3개(s.story! 단언·RLS·description) 전부 무관 확증 — blast radius 최소.

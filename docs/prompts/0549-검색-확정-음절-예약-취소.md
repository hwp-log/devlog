# 0549 검색 확정 음절 예약 취소

**작성일**: 2026-08-07
**소요 시간**: 기록 없음
**관련 커밋**: fix - 0549 검색 확정 음절 예약 취소 - 다음 조합 시작 시 대기 타이머 폐기 (740024d)

---

## 1. 한 줄 요약

MyPlan 검색에서 "경주" 입력 중 "경"이 단독 검색되던 문제 — 원인 조사(위임 우회 아님, TagSearchBar 구조) 후 `handleCompositionStart`에 대기 타이머 취소 1지점 추가로 해결. MyStory 검색에도 동일 적용(회귀 없음 분석 포함).

---

## 2. 왜 / 목적 / 이유

- **현상**: "경주"를 치면 "경"으로 한 번 검색돼 경북·경기까지 나왔다가 다음 글자에서 정리됨(0548 실사용).
- **조사 확정(0549 선행 조사)**: 한글은 다음 자음(ㅈ)에서 앞 음절이 확정되며 그 음절의 compositionend가 발생 → 66~69행이 **정식으로** `scheduleSearch("경")` 등록. 이어지는 조합 동안 handleChange는 스케줄만 안 걸 뿐 **이미 등록된 타이머를 취소하는 코드가 없어** 음절 간격 >300ms면 발화. 0086이 잡은 건 자모 중간("ㅈ"·"저") 억제이고 확정 음절은 해결 범위 밖이었음(0086 회고에 해당 케이스 언급 없음). MyStory도 같은 구조로 "경"이 나가지만 검색 대상(태그 contains)이라 체감이 안 됐을 뿐.
- **해법 선택**: 원인이 시간이 아니라 취소 누락 — 디바운스 값 변경이 아니라 "다음 음절 조합 시작 = 직전 확정 음절의 예약 폐기".

## 4. 코드 작성 & 수정

`app/(protected)/story/_components/TagSearchBar.tsx` — 1지점:

```tsx
const handleCompositionStart = () => {
  isComposing.current = true;
  // 0549: 직전 확정 음절의 예약 검색 폐기 — "경주"의 ㅈ에서 compositionend("경")가 정식
  // 스케줄되는데, 다음 음절 조합 시작이 그 타이머를 안 지우면 음절 간격 >300ms에 "경"이 나간다.
  // 0086은 자모 중간("ㅈ"·"저") 억제, 0549는 확정 음절 예약 취소 — 층이 다르다.
  // 마지막 확정값은 compositionEnd가 다시 스케줄하므로 정상 검색.
  if (timerRef.current) clearTimeout(timerRef.current);
};
```

디바운스 300ms·isComposing 분기·Enter 무관 전부 무변.

## 5. 결과 / 배운점

### 결과
- `npx tsc --noEmit` 통과.
- MyStory 회귀 분석: 마지막 확정값은 compositionEnd 재스케줄로 검색됨(blur 종료 포함), X 클리어는 조합 밖 경로라 무접촉. 부수 이득 — 클리어 예약('') 직후 한글 입력 시작 시 '' 검색 1회가 절약됨.
- 영문 등 비조합 입력: composition 이벤트 미발생 → 영향 0.

### 배운점
초안 — IME 처리는 두 층이다 — "조합 중 억제"(스케줄 등록 차단)와 "확정 음절 예약 취소"(등록된 타이머 폐기)는 별개 문제고, 전자를 해결한 기억이 후자의 존재를 가렸다

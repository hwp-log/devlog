- 소요: 약 4시간

## 1. 한 줄 요약

공개 플랜을 여는 상세 페이지(`cost-plan/[id]`)를 신규로 만들고, 정밀 금액·항공 시간·날짜는 서버 쿼리 단계에서 빼고 가공값(비중·구간)만 클라로 내려보내도록 구현했다. 마이플랜 상세의 부품(FlightLeg·PlanTimeline)은 재사용하고, 페이지 셸만 전용으로 새로 작성했다.

---

## 2. 왜 / 목적 / 이유

### 가공 공개를 서버 쿼리 단계에서

- 왜: 작성자의 정밀 지출은 사생활 정보다. 단순히 화면에서 안 보여주는 건 클라에 데이터가 도착한 뒤 가리는 것이라, 응답 payload를 개발자도구 네트워크 탭에서 열면 정밀 금액이 그대로 보인다. 화면 숨김은 가린 것이지 안 준 게 아니다.
- 목적: 공개 상세에서 정밀 금액·항공 시간·날짜가 클라(payload)에 아예 도착하지 않는 상태. 화면에 없을 뿐 아니라 네트워크에도 없다.
- 이유: 서버 쿼리의 select 단계에서 정밀 값을 빼고, 서버에서 `summarizePlanCost`로 비중·구간만 산출해 가공값만 내려보낸다. 0092 `fetchPublicPlans`의 "정밀 미조회·가공 반환" 패턴을 따랐다. 표시 방식(비율)은 타 서비스에서 검증된 패턴.

### 전용 셸 신규(분기 아님)

- 왜: 마이플랜 상세(PlanDetail)와 공개 상세는 쿼리부터 다르다. 마이플랜은 `ownerId`로 본인 것만 + 정밀 전체, 공개는 `isPublic: true`로(소유권 무관) + 가공값만. 한 컴포넌트에 `isOwner` 분기를 곳곳에 넣으면 편집 로직과 공개 뷰가 한 파일에 엉켜 읽기 어렵다.
- 목적: 부품은 두 페이지가 공유하되, 페이지 셸(상단 액션·렌더 순서)은 각자 전용으로 둔 상태.
- 이유: 부품(FlightLeg·PlanTimeline·PublicCostSection)은 그대로 import해 재사용하고, 셸만 `CostPlanDetail`로 새로 작성. 0091에서 공개 뷰는 isOwner 분기를 없애고 무조건 가공으로 간 선택과 같은 방향.

### FlightLeg showDetails / PlanTimeline 부분 타입

- 왜: 같은 부품을 공개 상세에서 쓰려면, 항공 카드는 금액·시간을 가려야 하고 타임라인은 amount 없는 부분 데이터를 받아야 한다. 부품이 정밀 값을 필수로 받으면 가공 데이터로는 깨진다.
- 목적: 같은 부품이 마이플랜(정밀)과 공개(가공) 양쪽에서 동작하는 상태.
- 이유: FlightLeg에 `showDetails?: boolean`(기본 true) 추가 — 기본값이라 마이플랜 호출은 불변, 공개만 false로 시간·날짜·금액 가림. PlanTimeline의 입력 타입을 Prisma 전체 타입에서 부분 타입(amount 없어도 되는)으로 넓혀, 구조적 타이핑으로 마이플랜은 그대로 호환.

> 부수: ① flight select에 금액 컬럼이 빠져 `summarizePlanCost`가 항공 비중을 0%로 계산하던 버그를 수정(금액은 서버 summary 계산에만 쓰고 `publicFlight`엔 0으로 미전송). ② `createdAt` 표시에 `{ timeZone: 'Asia/Seoul' }` 명시(0070·0091 함정 — Vercel UTC 환경에서 KST 자정~09시 작성분이 전날로 표시).

## 4. 코드 작성 & 수정

### 신규: `app/(protected)/cost-plan/[id]/page.tsx` (server)

가공 공개의 핵심. 정밀 값을 select에서 빼거나 서버 계산에만 쓰고, 클라로는 가공값만 넘긴다.

```tsx
// app/(protected)/cost-plan/[id]/page.tsx (신규)
export default async function Page({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params;

  const plan = await prisma.myPlan.findFirst({
    where: { id, isPublic: true },   // 소유권 무관, 공개만. 없으면 notFound
    select: {
      title: true, description: true, region: true, movie: true,
      createdAt: true,
      spots: { /* 타임라인 장소·동선용 (금액 제외) */ },
      costs: { /* summary 계산용 — 서버에서만 */ },
      flight: { select: { /* ...공항·편명...*/ totalAmount: true } },
      //                          ↑ summary 계산에만 사용, publicFlight엔 0
      owner: { select: { nickname: true } },
    },
  });
  if (!plan) notFound();

  // 서버에서 정밀 → 가공
  const summary = summarizePlanCost(plan.costs, plan.flight, currency);
  const publicFlight = { /* ...공항·편명... */ totalAmount: 0 };  // 금액 0 미전송
  const createdAtLabel = plan.createdAt.toLocaleDateString('ko-KR', {
    timeZone: 'Asia/Seoul',   // Vercel UTC 함정 회피 (0070·0091)
  });

  // 클라로는 가공값만
  return <CostPlanDetail summary={summary} publicFlight={publicFlight}
                         createdAtLabel={createdAtLabel} /* ... */ />;
}
```

> (select 필드 목록·spots 구조 등 실제 전문은 02b41f0 커밋 코드로 교체)

## 5. 결과 / 배운점

- 검증 4겹 통과: ① 화면에 정밀 금액·시간·날짜 안 보임 ② 네트워크 payload에 정밀 총액 미전송(`253844` 검색 0건) ③ 비공개 플랜 id 직접 접근 시 404 ④ 항공 비중 45%가 마이플랜 상세와 일치(가공 정확성).
- 처음엔 항공 비중이 0%로 빠졌다. flight select에 금액 컬럼이 없어 `summarizePlanCost`가 0으로 계산한 버그. 금액을 서버 summary 계산에만 넣고 `publicFlight`엔 0으로 두어 해결 — "비중은 맞추되 정밀 금액은 안 새게".
- 배운점: 민감 정보 보호는 화면에서 숨기는 것(클라 도착 후 가림)과 서버에서 안 보내는 것(payload 미전송)이 다른 차원이다. F12로 payload를 열 수 있으므로, 진짜 보호는 서버 쿼리의 select 단계에서 일어나야 한다. "화면 숨김"은 보안이 아니라 표시 제어일 뿐이다.

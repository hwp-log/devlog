# 0285 회고: 상세 히어로 폴백 라이트 스크림 — 사진 유무 분기

**작성일**: 2026-07-19
**소요 시간**: 약 30분
**관련 커밋**: `4946be1` fix: 0285 상세 히어로 폴백 스크림 라이트 대응 - 사진 없는 경우 밝은 스크림·어두운 제목

---

## 1. 한 줄 요약

SpotFinder 상세 히어로에 사진 유무 분기(`hasPhoto`)를 추가 — 폴백(플레이스홀더)일 때만 라이트에서 밝은 스크림(bgDeep 파생) + 어두운 제목(fg, 그림자 제거) + 어두운 배지(검정 저투명)로 전환하고, 사진 위와 다크는 전량 현행 보존.

---

## 2. 왜 / 목적 / 이유

- **왜**: 히어로 스크림(rgba(13,13,20) 그라데이션)이 라이트/다크 공용 하드코딩이라, 사진 없는 폴백에서 밝은 플레이스홀더 위에 검정 띠가 떠 이물질처럼 보였다.
- **목적**: 폴백(사진 없음)에 한해 라이트일 때 밝은 스크림 + 어두운 제목으로 전환.
- **이유**: 사진 위 어두운 스크림 + 흰 글자는 업계 표준(넷플릭스·유튜브) — 사진 색이 제각각이라 가독성 보장을 위해 유지. 이물질의 원인은 사진 위가 아니라 폴백 위 검정 스크림이라 거기만 라이트로.

---

## 4. 코드 작성 & 수정

### `components/SpotFinderMapNaver.tsx` — SpotDetailContent 히어로 분기

```tsx
// 0285: 사진 유무 분기 — 사진 위는 다크 스크림 + 흰 글자가 테마 중립 표준(무분기 유지).
const hasPhoto = !!spot.thumbnailUrl;

// 스크림 — 폴백 라이트 = rgb(246,246,248) = bgDeep(#f6f6f8) 파생, 스톱 구조(0.85/0.15/0.35)는 시안 실측 유지
className={`absolute inset-0 ${hasPhoto
  ? 'bg-[linear-gradient(to_top,rgba(13,13,20,0.85)_0%,rgba(13,13,20,0.15)_45%,rgba(13,13,20,0.35)_100%)]'
  : 'bg-[linear-gradient(to_top,rgba(246,246,248,0.85)_0%,...)] dark:bg-[linear-gradient(to_top,rgba(13,13,20,0.85)_0%,...)]'}`}

// 제목 — 폴백 라이트 = fg + 그림자 제거 / 사진·다크 = 흰 글자 + 그림자 현행
${hasPhoto
  ? 'text-white [text-shadow:0_2px_10px_rgba(0,0,0,0.60)]'
  : 'text-fg dark:text-white dark:[text-shadow:0_2px_10px_rgba(0,0,0,0.60)]'}

// 작품 배지 — 폴백 라이트 = 검정 저투명 0.08(0272·0284 명도 부상 관례) + fg2
${hasPhoto
  ? 'bg-white/[0.18] text-white'
  : 'bg-black/[0.08] text-fg2 dark:bg-white/[0.18] dark:text-white'}
```

## 5. 결과 / 배운점

### 결과
- 빌드 성공, `npm test` 기존 실패(6스위트/8테스트) 외 증가 없음.
- 컴파일 CSS에서 3계열 클래스(사진 케이스 원본·폴백 dark: variant·폴백 라이트) 전부 생성 확인 — 사진 케이스와 폴백 다크는 **동일한 선언**(`linear-gradient(#0d0d1459 0%,#0d0d1426 55%,#0d0d14d9 100%)`)으로 컴파일돼 다크·사진 무변 확증.
- 검증 함정 1건: minifier가 rgba→hex 변환(`rgba(13,13,20,.85)`→`#0d0d14d9`) + `to top` 제거·스톱 순서 반전 정규화를 해서 rgba 문자열 grep이 0건으로 나옴 — 값 등가였고 hex로 재검색해 확인. (0284의 "구 서버 점유" 건에 이어 검증 도구 측 함정 2례째.)
- 브라우저 수동 확인 잔여(사용자): 라이트에서 사진 없는 스팟 상세 — 밝은 스크림 + 어두운 제목/배지, 사진 있는 스팟 — 현행 동일, 다크 양 케이스 — 현행 동일.

### 배운점
- 가독성 판단의 기준은 바탕을 예측할 수 있느냐였다. 사진 위(예측 불가)는 어두운 스크림으로 강제 통일, 폴백(우리가 배경색 앎)은 바탕 밝기에 글자를 맞춤. 같은 화면 안에서도 이 조건에 따라 처리가 갈린다.
- 도구는 미관보다 가독성이 우선 — 사진 위 스크림을 억지로 라이트로 바꾸는 건 비표준이라 채택 안 함.

---

## 결정 (Decisions)

- **사진 위 오버레이 텍스트는 테마 무분기** — 어두운 스크림 + 흰 글자가 임의 색 사진 위 가독성 표준. 테마 분기는 배경이 우리 서피스(플레이스홀더)일 때만.
- **폴백 라이트 스크림 색 = bgDeep rgb 파생(246,246,248)** — Tailwind arbitrary는 완전 리터럴만 JIT 스캔이라 var() 불가, 파생 근거는 주석으로 동기(§5 관례).
- 분기 값이 Tailwind 클래스 한 곳 소비라 **dark: variant 페어** 채택(0284 결정 기준 — 새 토큰은 CSS+inline 양쪽 소비일 때만).

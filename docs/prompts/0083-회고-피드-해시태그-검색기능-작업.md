# 0083 회고: 피드 해시태그 검색기능 작업기록 추가

- 작성일: 2026-06-09
- 소요: 약 3시간
- 관련 커밋: 5369451

## 1. 한 줄 요약

스토리 카드의 태그를 검색하는 기능. 해시태그의 본질(클릭 가능한 검색 링크)을 분석해 피드는 검색창·상세는 태그 클릭으로 진입점을 나누고, 부분일치 ILIKE + 실시간 디바운스로 피드 검색창을 구현했다.

## 2. 왜 / 목적 / 이유

### 진입점 분리 — 피드는 검색창, 상세는 태그 클릭

- 왜: 카드에 태그가 표시되지만 검색 기능이 없었다. 처음엔 피드 카드의 `#태그`를 클릭하면 검색되게 하려 했으나, 카드 전체가 이미 상세로 가는 `<Link>`라 태그 클릭이 카드 클릭과 충돌했다.
- 목적: 태그로 스토리를 찾되, 각 화면의 기본 구조를 깨지 않는다.
- 이유: 충돌은 오버레이(stretched-link, `::after` + z-index) 패턴으로 풀 수 있었지만, 그건 카드 전체 링크라는 멀쩡한 구조를 비트는 오버엔지니어링이었다. 인스타그램이 태그를 클릭하게 하는 건 글(상세) 맥락이고, 거기엔 카드 전체 링크 충돌이 없다. 그래서 충돌을 우회 기술로 *푸는* 대신, 클릭을 충돌 없는 곳(상세 페이지)으로 두고 피드는 구조에 맞는 검색창으로 — 화면 구조에 맞게 진입점을 분리했다. (이번 작업에선 피드 검색창을 구현했고, 상세 태그 클릭은 다음 작업으로 둔다.)

### 부분일치 + 사용자 입력 이스케이프

- 왜: 100% 일치가 아니라 일부 단어만 들어가도 검색돼야 한다("범죄" → `#범죄도시`).
- 목적: 부분 문자열 매칭(대소문자 무시)으로 태그를 찾는다.
- 이유: 태그가 별도 Tag 테이블(M:N)이라 `tags: { some: { name: { contains: q, mode: 'insensitive' } } }`로 join. Prisma의 `contains`는 PostgreSQL에서 `LOWER() ILIKE '%q%'`로 변환된다(web_search로 확증). 사용자 입력의 `%`·`_`는 ILIKE 와일드카드라, 그대로 넣으면 오작동한다. `escapeILike`로 `% _ \`를 이스케이프하고, `%` 입력 시 결과 0개가 나오는 것으로 실측 확인했다(escape가 안 먹었으면 전체가 나왔을 것).

### 실시간 디바운스 검색

- 왜: 엔터 제출보다 타이핑하면 바로 결과가 보이는 게 자연스럽다.
- 목적: 입력 중 자동 필터, 단 서버 요청 폭주는 방지.
- 이유: `onChange` → `setTimeout(300ms)` + cleanup으로 디바운스, `router.replace`로 URL 갱신(히스토리 누적 방지). 부수 효과로 한글 IME 조합도 자연히 흡수됐다 — 조합 중에는 `onChange`가 계속 발동해 타이머가 매번 리셋되므로, 조합이 끝나고 조용해진 뒤에만 검색이 나간다. "마지막 입력 후 조용할 때만 실행"이라는 디바운스의 본질이 IME 조합 완료를 기다려줘서 `onCompositionEnd` 같은 별도 처리가 불필요했다.

## 3. 작성한 프롬프트

검색 1차 구현:

```

피드(app/story/page.tsx)는 서버 컴포넌트로 findMany 조회 중.

[하지 말 것]
❌ 상세 페이지 태그 클릭 (다음 작업)
❌ 제목·본문 검색 (태그만, 나중 확장 여지)

- 사용자 입력 % _ escape (ILIKE 와일드카드 오작동 방지)
- 검색창 = 클라이언트 컴포넌트, 입력 → ?q= URL 갱신
```

## 4. 코드 작성 & 수정

```tsx
// app/story/page.tsx — 서버 컴포넌트, 검색 필터
import { TagSearchBar } from './_components/TagSearchBar';

// % _ \ 를 이스케이프해 ILIKE 와일드카드 오작동 방지
function escapeILike(s: string) {
  return s.replace(/[%_\\]/g, '\\$&');
}

export default async function StoryPage({
  searchParams,
}: {
  searchParams: Promise<{ q?: string }>; // Next.js 16: searchParams는 Promise
}) {
  const { q } = await searchParams;
  const keyword = q?.trim() ?? '';
  const escaped = escapeILike(keyword);

  const stories = await prisma.story.findMany({
    where: keyword
      ? { tags: { some: { name: { contains: escaped, mode: 'insensitive' } } } }
      : undefined, // 빈 검색어면 전체
    include: { user: true, tags: true, _count: { select: { likes: true } } },
    orderBy: { createdAt: 'desc' },
  });
  // ...h1과 같은 줄에 <TagSearchBar q={keyword} />, 결과 없음 메시지 분기
}
```

```tsx
// app/story/_components/TagSearchBar.tsx — 클라이언트, 실시간 디바운스
'use client';
import { useRouter } from 'next/navigation';
import { useState, useEffect, useRef } from 'react';
import { Search, X } from 'lucide-react';

export function TagSearchBar({ q }: { q: string }) {
  const router = useRouter();
  const [value, setValue] = useState(q);
  const isFirstRender = useRef(true);

  useEffect(() => {
    if (isFirstRender.current) { isFirstRender.current = false; return; } // 마운트 시 스킵
    const normalized = value.trim().replace(/\s/g, ''); // 공백 제거
    const timer = setTimeout(() => {
      const url = normalized ? `/story?q=${encodeURIComponent(normalized)}` : '/story';
      router.replace(url); // push 아닌 replace — 히스토리 누적 방지
    }, 300); // 디바운스
    return () => clearTimeout(timer);
  }, [value, router]);

  // input: w-70, focus:ring-2 + transition-[box-shadow] duration-200 cubic-bezier(0.4,0,0.2,1)
  // placeholder="제목, 지역명을 입력해보세요", X 버튼으로 클리어
}
```

## 5. 결과 / 배운점

- 피드에 실시간 태그 검색창을 구현했다. "드라마" 입력 시 7개, "오징어" 시 `#오징어게임` 부분일치 등 시드 데이터로 결과가 다양하게 나온다.
- 배운점 1: 기능을 만들기 전에 본질(해시태그 = 클릭 가능한 검색 링크)을 분석하니, "피드 카드에 태그 클릭을 넣는다"는 오버엔지니어링을 통째로 피하고 화면 구조에 맞게 진입점을 나눌 수 있었다.
- 배운점 2: 사용자 입력을 ILIKE에 직접 넣으면 `%`·`_` 와일드카드 오작동이 생긴다. 이스케이프 후, `%` 입력 시 결과 0개로 실측 확인해야 escape가 실제로 먹는지 안다(코드만 보고 단정하지 않는다).
- 배운점 3: 디바운스는 "마지막 입력 후 조용할 때만 실행"이라, 연속 입력인 한글 IME 조합을 자연히 흡수한다. 별도 `onCompositionEnd` 처리 없이 깔끔하게 동작한 이유다.
- 다음: 상세 페이지 태그 클릭(설계 완료, 구현 대기), 검색 대상을 제목까지 확장하는 여지.

## 1. 한 줄 요약

상세 모달의 이중 스크롤러를 하나로 정리해 본문 스크롤을 복구하고(0260), 0250에서 revert했던 마커→목록 동기를 `scrollIntoView` 없이 `ul.scrollTop` 직접 대입 + rect 좌표 + 가시성 게이트로 재구현했으며(0261), 모바일 행에서 [상세] 버튼을 없애고 **썸네일 탭=지도 선택 / 텍스트 탭=상세**로 나눴다(0262).

## 2. 왜 / 목적 / 이유

> 근거: `docs/0228-0273-회고-재료-인수인계.md` 묶음 3.

### 상세 모달 이중 스크롤러 (0260)
- **왜**: 상세 모달의 내용이 끝까지 스크롤되지 않았다. 모달 루트에도 `overflow-y-auto`가, 본문에도 스크롤 컨테이너가 있는 **이중 스크롤러** 구조였다.
- **목적**: 스크롤러를 하나로 확정해 내용 끝까지 접근 가능하게 한다.
- **이유**: 실기기 iOS에서 body에서 시작한 터치가 바깥 스크롤러로 체이닝되지 않아 스크롤 자체가 불가능했다(코드 주석 근거). 그리고 높이는 묶음 2에서 얻은 원칙대로 **flex grow가 아니라 명시 calc**으로 줬다 — 같은 Safari 붕괴 패턴의 재발 방지.

### 마커→목록 동기 재구현 (0261)
- **왜**: 0250을 revert한 뒤 "마커를 탭해도 목록이 안 따라온다"는 공백이 남아 있었다.
- **목적**: 같은 기능을 Safari에서 확실히 동작하는 방식으로 다시 만든다.
- **이유**: `scrollIntoView`의 조상 순회가 0250 revert의 원인이었다. 그래서 **`scrollIntoView`를 금지하고** 스크롤포트(`ul`)의 `scrollTop`을 직접 계산해 대입했다.
- 좌표를 `offsetTop`이 아니라 **rect 기반**으로 잡은 이유: `offsetParent`가 시트 루트라 `offsetTop`이 함정이었다(실측).
- `hiddenBottom`을 **computed `paddingBottom`에서 읽은** 이유: `env()`는 JS로 직접 못 읽지만 computed 값에는 이미 해석돼 있다.
- **가시성 게이트**를 둔 이유: 이미 보이는 행을 탭했을 때 목록이 튀면 안 된다(행 탭 무점프).

### 행 동작 재배치 (0262)
- **왜**: 모바일 행의 [상세] 버튼이 시각 소음이었다.
- **목적**: 버튼을 없애고 행 자체를 두 개의 의미 영역으로 나눈다 — 썸네일 탭=지도 선택, 텍스트 탭=상세.
- **이유**: 텍스트 탭에서도 `handleSpotSelect`를 먼저 부른다 — 모달이 `selectedSpot`을 렌더하므로 선행 세팅이 없으면 빈 모달이 뜬다.
- **데스크탑에는 이식하지 않았다**: 데탑은 3열이라 클릭 한 번으로 지도 이동 + 상세가 동시에 일어난다. **"동작 통일이 아니라, 제약별로 같은 의도"**.

### 2. 0261 — `alignRowInList` (0250의 귀환)

```ts
// components/SpotFinderMapNaver.tsx:252 (0261 — 현재 코드에도 동일하게 존재)
// 0261: 목록 정렬 스크롤 — scrollIntoView 금지(조상 순회가 0250 revert 원인),
// 좌표는 rect 기반(offsetParent가 시트 루트라 offsetTop 함정 — 실측).
// hiddenBottom = 스크롤포트 하단의 비가시 존(모바일 pill 뒤 72+env) — ul의 computed paddingBottom에서 읽음
// (env는 JS로 못 읽지만 computed엔 해석됨. 데탑 0·peek 0 자동).
// 가시 게이트: 행이 가시영역에 온전히 보이면 no-op(행 탭 무점프). 정렬: center(데탑)/top(모바일 — 0257 걸침 보존).
// 상한 클램프는 scrollTop 대입의 브라우저 표준 동작에 위임, 하한만 0.
// 즉시 이동(대입) — 시트 전환(320ms)·구형 iOS smooth 편차와 경합 없음.
// display:none 쪽(반대 브레이크포인트)은 rect 전부 0 → 현재 scrollTop 재대입 = no-op(분기 불요).
function alignRowInList(li: HTMLLIElement | null, align: 'top' | 'center') {
  const ul = li?.closest('ul');
  if (!li || !ul) return;
  const ulR = ul.getBoundingClientRect();
  const liR = li.getBoundingClientRect();
  const rowTop = liR.top - ulR.top + ul.scrollTop;
  const hiddenBottom = parseFloat(getComputedStyle(ul).paddingBottom) || 0;
  const visibleH = ul.clientHeight - hiddenBottom;
  if (visibleH > 0 && rowTop >= ul.scrollTop && rowTop + liR.height <= ul.scrollTop + visibleH) return;
  ul.scrollTop = Math.max(0, align === 'center' ? rowTop - (visibleH - liR.height) / 2 : rowTop);
}
```

| | 0250 (revert) | 0261 (채택) |
|---|---|---|
| 스크롤 수단 | `li.scrollIntoView({block:'nearest'})` | `ul.scrollTop = …` 직접 대입 |
| 좌표 | 브라우저 위임 | `getBoundingClientRect()` 차분 |
| 비가시 존 | 고려 없음 | computed `paddingBottom`에서 읽음 |
| 무점프 | `'nearest'`에 위임 | 가시성 게이트로 명시 |
| 타이밍 | `setTimeout` 340ms (전환 대기) | 즉시 대입 (경합 없음) |

## 5. 결과 / 배운점

### 결과
- 상세 모달이 단일 스크롤러가 되어 본문 끝까지 접근 가능해졌다.
- 0250에서 되돌렸던 기능이 0261에서 돌아왔고, `alignRowInList`는 오늘 코드에도 그대로 있다(`SpotFinderMapNaver.tsx:252`).
- 모바일 행에서 파란 버튼이 사라지고 행 전체가 두 개의 터치 의미로 나뉘었다. `renderSpotThumb`/`renderSpotText` 분할도 현재까지 유지된다.

### 배운점

- **브라우저 API에는 실측으로만 드러나는 함정이 있다.** `scrollIntoView`(조상 순회), `offsetParent`/`offsetTop`(시트 루트가 기준이 됨), `env()`(JS로 직접 못 읽지만 computed에는 해석돼 있음) — 이번 묶음에서 셋을 한꺼번에 만났다.
- **반응형은 같은 동작의 복제가 아니라, 화면별 제약에 맞는 같은 의도다.** 모바일은 3열을 못 쓰니 행을 둘로 나눴고, 데탑은 3열이라 나눌 필요가 없다.
- **되돌린 기능은 같은 방식으로 재도전하지 않는다.** 0261은 0250을 고친 게 아니라 다른 수단(직접 `scrollTop`)으로 다시 만든 것이다.

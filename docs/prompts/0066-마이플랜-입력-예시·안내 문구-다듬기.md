# 0066 회고: 마이플랜 입력 예시·안내 문구 다듬기

- 날짜: 2026.06.03
- 소요: 약 3시간
- 관련 커밋:
  - `feat: 0066 마이플랜 입력 예시·안내 문구 다듬기`

## 1. 한 줄 요약
계획에 영감·지역·영화 칸을 더해 '일정표'를 '나만의 촬영지 이야기'로 만들고, 상세에 배지·영감 박스로 보여줬다. DB에는 nullable 칸 3개를 기존 데이터가 깨지지 않는 additive 방식으로 추가했다.

## 2. 왜 / 목적 / 이유

### 2-1. 왜 영감·지역·영화 칸을 넣었나 (제품/정체성)
- **왜(동기/문제):** 제목·날짜·비용만 있으면, 어느 여행 앱에나 있는 '일정표'일 뿐이다. "내 이태원 클라스 코스"라는 정체성이 빠진다.
- **목적(가치):** 계획에 정체성(어떤 작품·어느 지역·무슨 영감)을 담아, 일반 일정표가 아니라 "나만의 촬영지 이야기"가 되게 한다.
- **이유(브랜드 + 결정):** Dotrip = Dot(점) + trip. 영감·지역·영화가 그 '점'이고, 점이 모여야 나만의 여행 이야기(선)가 된다. 또한 이 칸들은 나중에 제품의 다른 부분과 잇는 연결점이다 — 영화는 Movie 테이블/검색으로, 지역은 지도로.

### 2-2. 왜 nullable + additive 마이그레이션인가 (데이터)
- **왜(동기/문제):** 이미 저장된 계획들이 있는데, 칸을 NOT NULL로 추가하면 기존 행이 값이 없어 깨진다.
- **목적(가치):** 기존 데이터를 그대로 둔 채 칸만 안전하게 늘린다.
- **이유(결정):** 세 칸을 모두 nullable(`String?`)로 추가. Prisma 7에서는 `migrate dev`가 shadow DB 때문에 실패해서, `migrate diff`로 SQL을 먼저 뽑아 ADD COLUMN만 있는지 확인하고 → `db execute`로 적용 → `migrate resolve --applied`로 이력 등록하는 수동 경로를 썼다.

[목표] MyPlan에 영감·지역·영화 칸 추가 + 상세에 배지·영감 박스 표시.

[검수 모드] 마이그레이션 SQL이 ADD COLUMN(nullable)만인지 / '' -> null 정규화

(핵심만 — 실제 코드는 repo 기준으로 확인)

model MyPlan {
  // ...

  movie       String? // 영화
}
```

ALTER TABLE "MyPlan" ADD COLUMN "movie" TEXT;
```

## 5. 결과 / 배운점
- **결과:** 영감·지역·영화 입력·표시 완성(빈 칸은 숨김). 기존 계획 데이터 손실 없이 칸 추가.
- **배운점:**
  - 메타 칸은 장식이 아니라 **제품 정체성을 담는 '점'** — 브랜드 개념(Dot+trip)을 데이터 모델 결정으로 이은 사례.
  - 칸 추가는 **nullable + additive**로 — 기존 데이터를 깨지 않는 마이그레이션.
  - Prisma 7은 `migrate dev`가 shadow DB로 막힐 때 **diff → execute → resolve** 수동 경로로 우회.
  - 입력값은 **빈 문자열 → null 정규화** — "값 없음"을 ''가 아니라 null로 일관되게.
  - 면접 포인트: 브랜드 개념을 스키마 결정으로 연결한 점 + 운영 중 데이터를 깨지 않는 마이그레이션 판단.

# 0352~363 회고: 양식 5종과 콜아웃 블록

작성일 2026-07-26 / 소요 약 5시간 / 커밋 0352~0363

## 핵심 판단

- **몇 시간 전 내가 만든 병합을 스스로 걷어냈다.** 계기는 "나도 수시로 헷갈렸다"였고,
  검색해보니 업계는 그 문제를 아예 안 만들었다. 선례 없는 발명을 하고 있었다.
- **회색 placeholder를 실제 텍스트로 바꿨다.** 나타났다 사라지는 안내는 거슬리고,
  진짜 글자로 두면 사용자가 지우거나 고칠 수 있다.
- **저장 HTML 규약을 먼저 정한 것이 나머지를 전부 결정했다.**
- **`isolating`이 규약을 지키면서 삭제 경로까지 막았다.** 속성을 걷는 대신 경계 키
  처리로 풀었다.
- **정렬은 절대값이 아니라 관계다.** 본문에 테두리를 두르면서 시작선이 어긋났지만
  층이 달라졌으므로 어색하지 않았다.
- **파괴적 확인의 기본 포커스는 안전한 쪽에 둬야 하고, 모바일엔 Ctrl+Z가 없다.**

## 한 줄 요약

Tiptap 커스텀 노드로 콜아웃 블록을 만들고, 글 양식을 5종으로 늘리면서 예시를 회색
안내가 아닌 실제 텍스트로 프리필하게 바꿨다.

## 왜 / 목적 / 이유

**왜** — 글쓰기에 익숙하지 않은 사람이 빈 화면을 마주하면 무엇을 어떻게 쓸지 막막하다.
양식을 제공하되 강요하지 않는 방식이 필요했다.

**목적** — 네 가지 글 유형(에세이·정보 리뷰·일차별 코스·촬영지 순례)의 골격을 예시와
함께 제공하고, 자유형으로 언제든 빠져나갈 수 있게 한다.

**이유** — 예시를 회색 placeholder로 두면 지우면 다시 나타나고 쓰면 사라진다. 그 깜빡임이
거슬린다는 판단이 있었고, 브런치처럼 실제 텍스트로 넣으면 사용자가 보면서 고치거나
지울 수 있다.

## 결과 / 배운 점

### 만든 것을 몇 시간 뒤에 걷어내기

0355에서 양식 교체 로직을 만들었다. "빈 섹션만 걷어내고 사용자가 쓴 섹션은 보존"하는
병합이었고, 예시 원문과 정규화 비교해서 손대지 않은 섹션만 치우는 방식이었다.

구현은 잘 됐는데 실제로 써보니 결과가 예측이 안 됐다. 양식을 바꾸면 일부만 바뀌어서
"뭐가 남고 뭐가 바뀌었지?"가 매번 헷갈렸다.

검색해보니 **업계는 이 문제를 아예 만들지 않았다.** Confluence는 이미 존재하는 페이지에
템플릿을 적용할 수 없다고 문서에 명시돼 있고, Cloud는 템플릿을 바꾸면 새 페이지를 만들며
기존 것을 버릴지 묻는다. Google Docs는 기능 자체가 없다. 템플릿은 생성 시점에만 적용된다.

즉 우리가 만든 병합은 **선례가 없는 발명**이었고, 그래서 예측이 안 됐던 것이다.

0359에서 전체 교체로 바꾸고 병합 판정을 걷어냈다. 만든 걸 지우는 게 아까웠지만,
**내가 헷갈렸으면 사용자도 헷갈린다**는 게 결정적이었다.

### 저장 구조를 먼저 정하기

콜아웃 노드를 만들 때 저장 HTML 규약을 먼저 확정했다.

```html
<div data-callout="tip"><p>제목</p><p>본문…</p></div>
```

첫 문단이 제목, FAQ만 두 번째 문단이 질문. 이모지는 데이터에 없고 `data-callout` 값에서
CSS `::before`로 파생.

이 결정이 나머지를 전부 정했다.

- `div[data-callout]` 셀렉터 하나로 **재편집(parseHTML)·발행 정리(jsdom)·상세 렌더(CSS)**가
  같은 문법을 공유한다
- `content: 'paragraph+'`라 이미지·heading이 콜아웃 안으로 못 들어가고, 그래서 썸네일
  추출(첫 `<img>` 파싱)과 heading 구간 분할이 구조적으로 안전하다
- 이모지가 문서 텍스트에 없어 검색·복사·정리 로직이 오염되지 않는다

콘텐츠가 HTML 문자열로 저장되는 구조에서 이 규약이 어긋나면 저장된 글이 깨지고 되돌리기
어렵다. 먼저 정하고 시작한 게 맞았다.

### isolating이 막은 것

콜아웃에 `isolating: true`를 줘서 경계 병합을 막았다. 첫 문단이 제목이라는 규약이
병합으로 조용히 무너지는 걸 방지하는 목적이었다.

그런데 그게 **삭제 경로까지 막았다.** 콜아웃 안에서 전체 선택 후 Delete를 하면 텍스트만
지워지고 빈 껍데기가 남았다. "안 지워진다"의 실체가 그거였다. 드래그 핸들은 콜아웃 위에
뜨지만 클릭만으로는 노드가 선택되지 않아(NodeSelection이 dragstart에서만 설정됨)
삭제 경로가 아니었다.

`isolating`을 걷는 대신 경계 키 처리를 추가했다(0363). 첫 문단 맨 앞에서 Backspace를
누르면 빈 콜아웃은 즉시 삭제되고, 내용이 있으면 전체 선택 상태로 전환돼 한 번 더 눌러야
지워진다. 2단이 실수 방지선이 되고, 모바일은 "내용 소진 → 빈 콜아웃 → 삭제"로 백스페이스
만으로 도달할 수 있다.

`isolating`을 제거하는 안은 콜아웃 내용이 밖으로 유출되고 제목 규약이 붕괴해서 기각했다.

**여기서 하나 더 나왔다.** 2단 삭제의 1회차는 노드 선택 상태로 전환되는데, ProseMirror
기본에는 그 상태의 스타일이 없다. 그대로 두면 "한 번 눌렀는데 아무 일도 안 일어남"으로
읽혀 원래 문제로 되돌아간다. 콜아웃 한정으로 선택 표시를 추가했다.

### 파괴적 확인의 두 가지

교체를 전체 교체로 바꾸면서 확인 단계가 필요해졌다. 모달 대신 팝오버가 같은 자리에서
확인 화면으로 전환되는 방식을 택했다 — 레이어가 한 겹으로 유지되고 모바일에서 답답하지
않다.

두 가지를 정정했다.

**포커스는 "취소"에 둔다.** "바꾸기"에 포커스가 있으면 Enter를 습관적으로 누르는 순간
글이 날아간다. 확인 단계를 넣은 이유가 사라진다.

**"Ctrl+Z로 되돌릴 수 있어요"를 뺐다.** 모바일엔 Ctrl+Z가 없어 그 문구가 거짓이 된다.
"지금 쓴 내용은 사라져요."로 끝내면 모든 환경에서 참이고, 되돌리기를 약속하지 않으니
확인 단계의 무게도 유지된다.

### 흐름을 뒤집은 결정

기본 양식을 촬영지 순례형에서 자유형으로 바꿨다(0361). 근거는 "프리필이 깔려 있으면
다른 양식이나 슬래시 기능을 찾지 않게 된다"였다. 빈 화면에서 접근법을 먼저 보여주고,
갈증이 생기면 스스로 양식을 고르게 하는 방향.

빈 문서일 때만 3줄 안내가 뜬다.

```
① '/'를 입력해 여러 기능을 사용해보세요.
② '서식'을 클릭하여 글쓰기 템플릿을 이용해보세요.
③ 아니면 나만의 방식으로 즐겁게 작성해보세요 :)
```

**한계는 인지하고 있다.** 한 글자라도 쓰면 안내가 사라지는데, 갈증은 쓰기 시작한 뒤에
온다. 진짜 온보딩(첫 방문에만 표시)은 상태 저장이 필요해 범위 밖으로 미뤘다.

### 상자를 걷었다가 다시 두른 것

0341에서 입력 상자를 전부 걷고 밑줄로 갔는데, 정작 본문 영역이 어디서 시작하고 끝나는지
모호해졌다. 하단에 가로선 하나를 그어봤지만 그 선이 태그 필드의 윗선처럼도 읽혔다.

결국 툴바와 본문을 한 상자로 감쌌다(0360). 이때 대가를 하나 치렀다. 드래그 핸들이 텍스트
왼쪽 바깥 −20px에 뜨므로, 테두리를 두르면 본문에 왼쪽 안쪽 여백을 줘야 하고 그러면
**본문 시작선이 제목·태그와 어긋난다.** 0341에서 맞춰놓은 정렬을 포기하는 것이었다.

실제로 보니 어색하지 않았다. 본문이 "제목·태그와 같은 층의 필드"가 아니라 **별도 영역**으로
읽히면서 다른 시작선이 자연스러워졌기 때문이다. 티스토리·네이버 에디터가 같은 구조다.

**정렬은 절대값이 아니라 관계다.** 같은 층이면 맞춰야 하고, 층이 다르면 달라도 된다.

### 한글 IME가 만든 이중 등록

태그에 "수리남"을 치고 Enter를 누르면 `#수리남`과 `#남`이 함께 추가됐다(0362).

조합 중 Enter는 `keydown`을 두 번 발생시킨다. 1회차(조합 커밋)가 태그를 추가하면서
input을 비우면, IME가 조합 중이던 마지막 음절 "남"을 빈 input에 다시 커밋하고,
2회차 Enter가 그걸 또 추가한다.

`e.nativeEvent.isComposing` 가드 한 줄로 끝났다. `keyCode === 229`는 비표준·deprecated고,
`compositionstart/end` 추적은 상태 변수가 늘고 Safari 이벤트 순서 엣지가 있다.
React 합성 이벤트에는 `isComposing`이 없어 `nativeEvent` 경유가 필수다.

**한국어 서비스에서 Enter로 확정하는 입력은 전부 이 가드가 필요하다.** 전체 grep으로
확인한 결과 태그 input이 유일했지만, 앞으로 같은 패턴을 만들 때 재적용 대상이다.

## 대표 코드

```ts
// app/(protected)/story/new/Callout.ts  (발췌 — 저장 규약과 경계 키 처리만)
export const Callout = Node.create({
  name: 'callout',
  group: 'block',
  content: 'paragraph+', // 이미지·heading 진입 불가 — 썸네일 추출·구간 분할에 구조적 무영향
  defining: true, // 붙여넣기·교체 시 구조 보존
  isolating: true, // 경계 밖 병합(Backspace로 콜아웃 해체) 방지

  parseHTML() {
    return [{ tag: 'div[data-callout]' }];
  },

  renderHTML({ HTMLAttributes }) {
    return ['div', mergeAttributes(HTMLAttributes), 0];
  },

  // 경계 Backspace/Delete(0363) — isolating이 경계 병합을 막으면서 "안에서 노드를 지울" 경로까지
  // 없앴다(내부 전체 선택 삭제는 빈 껍데기 잔존, 첫 문단 앞 Backspace는 no-op — 0355·0363 실측).
  // 규칙: 캐럿이 경계 위치(첫 textblock 맨 앞 Backspace / 마지막 textblock 맨 끝 Delete)일 때 —
  //   · 콜아웃이 비었으면(제목 포함 텍스트 전무) 즉시 통삭제
  //   · 내용이 있으면 NodeSelection(하이라이트)으로 전환 — 한 번 더 누르면 기본 deleteSelection이
  //     삭제(실수 통삭제 방지 2단). 모바일은 백스페이스 연타만으로 빈 콜아웃→통삭제에 도달.
  // 그 외 위치는 false(내부 문단 병합·글자 삭제 등 기본 동작 무간섭). isolating은 유지 —
  // 경계 병합 해체(B안)는 첫 p=제목 위치 규약을 조용히 붕괴시켜 기각.
  addKeyboardShortcuts() {
    const boundaryDelete = (dir: 'backward' | 'forward') => () => {
      /* …중략 — 콜아웃 depth 탐색·경계 판정… */
      const before = $from.before(depth);
      if (callout.textContent.trim().length === 0) {
        return this.editor.commands.deleteRange({ from: before, to: before + callout.nodeSize });
      }
      return this.editor.commands.command(({ tr }) => {
        tr.setSelection(NodeSelection.create(tr.doc, before));
        return true;
      });
    };
    return {
      Backspace: boundaryDelete('backward'),
      Delete: boundaryDelete('forward'),
    };
  },
});
```

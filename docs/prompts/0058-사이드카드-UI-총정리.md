## 1. 한 줄 요약

맵 사이드카드의 제목·버튼 색·빈 공간 안내를 한 번에 다듬어, 기능 추가 없이 "보기에 일관되고 처음 쓰는 사람도 흐름을 아는" 상태로 정리했다. 핵심 결정은 버튼 색을 sky(파랑)에서 slate(회색)로 낮춘 것 — 색을 "꾸밈"이 아니라 "의미 전달 수단"으로만 쓰겠다는 원칙을 세웠다.

---

## 2. 왜 / 목적 / 이유

### 핵심 A — 버튼 색 sky → slate 통일

- **왜(동기/문제)**: menu 버튼 3개가 sky(파랑) 계열이었는데, 그 파랑은 *특별한 의미가 없는데도* 시선을 끌었다. 색이 여러 개면 뇌가 "이 색은 무슨 뜻이지?" 하고 자꾸 해석하려 드는데, 의미 없는 색은 그냥 노이즈다.
- **목적(도달할 상태)**: 의미 없는 색 노이즈를 제거해 화면을 조용하게. 색을 봤을 때 *진짜 의미가 있는 것에만* 시선이 가도록.
- **이유(채택 근거)**: 색을 "꾸밈"이 아니라 *정보 전달 수단*으로만 쓰는 원칙. 그래서 의미 없는 색(버튼 파랑)은 slate로 낮추고, *의미 있는 색은 살렸다* — 마커의 도착지 빨강(#ef4444)은 "여기가 끝점"이라는 뜻이 있어 그대로 뒀다(0057에서 확정). 즉 "색 통일"이 목적이 아니라 "의미 없는 색만 죽이고 의미 있는 색은 남긴다"가 목적이고, slate 통일은 그 수단이다.

> 면접용 한 문장: "색에 의미가 없으면 노이즈라고 보고, 의미 없는 버튼 색은 회색으로 낮추되 방향성을 뜻하는 마커 색(도착=빨강)은 살려, 색을 정보 설계 관점에서 다뤘다."

### 핵심 B — 빈 공간에 "처음 쓰는 사람"용 안내

- **왜**: 사이드카드의 빈 공간이 그냥 비어 있어, 처음 쓰는 사람은 "여기서 뭘 해야 하지"를 몰랐다. menu·pinning·search 세 화면 모두 빈 공간이 생겼다.
- **목적**: 화면마다 "지금 막혀 있는 지점"에 맞는 안내를 띄워, 다음에 뭘 할지 한눈에 알게.
- **이유**: 빈 공간 안내는 "지금 이 화면에서 뭘 하면 되는지"를 알려주는 이정표다. 그래서 화면마다 막힌 지점이 다르면 문구도 달라야 한다 — menu는 *전체 흐름*(아직 아무것도 안 함), search는 *검색 결과를 어떻게 쓰는지*, pinning은 *지도를 클릭*. 톤·아이콘은 통일(생김새)하되 문구 내용은 화면별로 다르게(내용) 풀었다.

### 위계 — 같은 slate 계열 + 진하기 차등

- **왜**: 버튼·가이드·빈 상태가 다 같은 회색이면 뭐가 중요한지 시선이 안 간다.
- **이유**: 버튼은 "지금 누를 것"(주역), 가이드는 "참고 설명"(조연)이라, 가이드를 버튼보다 한 단계 연하게 둬 시선이 버튼으로 먼저 가게 했다. *통일=같은 색 계열, 위계=진하기 차이.* (버튼 제목 slate-700 > 가이드 스텝 slate-500 > 팁·빈 상태 slate-300~400)

## 5. 결과 / 배운점

### 결과
- 페이지 제목 "여행동선", menu 카드 "나만의 경로 짜기"로 교체 (작성·보기 방 양쪽 제목, 가이드는 작성 방에만).
- menu 버튼 3개 slate 통일 — grep으로 파랑(sky) 잔존 0개 확인.
- menu 빈 공간에 3스텝(①②③) + 전구 팁, reorder에 ⠿·× 가이드 2줄.
- 마커 많아도 목록만 스크롤되고 가이드·뒤로 버튼은 카드 하단 고정.

### 배운점
1. **색은 "꾸밈"이 아니라 "정보 전달 수단"이다.** 의미 없는 색은 노이즈라 죽이고(버튼 파랑→회색), 의미 있는 색은 남긴다(도착=빨강). "다 통일"이 목적이 아니라 "의미 없는 색만 제거"가 목적이었다.
2. **통일과 위계는 다른 축이다.** 통일=같은 slate 계열(생김새), 위계=진하기 차이(중요도). 버튼>가이드>빈상태 순으로 연하게 둬, 다 회색이어도 시선이 버튼으로 먼저 가게 했다.
3. **빈 공간 안내는 화면마다 막힌 지점이 달라 문구도 달라야 한다.** menu=전체 흐름, search=검색 결과 활용, pinning=지도 클릭. 톤·아이콘은 통일하되 내용은 화면별로.
4. **flex 안에서 일부만 스크롤하려면 `min-h-0`이 필요하다.** flex 자식은 기본이 "내용만큼 무조건 자란다(min-height:auto)"라, 목록이 길면 카드를 뚫고 늘어난다. `min-h-0`으로 "줄어들어도 됨"을 허락해야 `overflow-y-auto`가 작동한다.
5. **"UI 총정리"처럼 범위가 넓은 작업은 한 회차에 담을 것을 N개로 못 박아야 안 늘어난다.** 빈 마커 청소·npm audit은 성격이 달라(버그성·의존성) 의도적으로 0059·0060으로 분리했다.

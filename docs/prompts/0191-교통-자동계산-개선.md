# 0191 회고: 교통 자동계산 개선 — 거리 기반 수단 판정·비승객역 필터

작성일: 2026-07-14 / 소요: 약 1.5시간 / 커밋: e7d392e

## 1. 한 줄 요약
"도보 250분"·"폐역 안내"를 만드는 0178 로직을 고치고, 파생이 불가능해진 수단(도보/차로)을 Spot.transitMode로 저장했다.

## 2. 왜 / 목적 / 이유
- **왜**: 시딩 백필 전 샘플 실측에서 영진해변 "강릉역 도보 250분", 동부마을 "진영역(폐역) 106분", 석병1리 "화물역 319분"이 나왔다. 0178 때 스팟 6개(전부 도심)로만 검증해 안 보였던 한계.
- **목적**: ① 2km 초과 시 차로 계수 ② 폐역·화물·신호장·조차장 필터 ③ 90분 초과 null(잘못된 정보보다 없는 정보) ④ transitMode 저장.
- **이유(저장 전환)**: 0179 주석이 예고한 "파생 불가능 시점"에 도달 — "강릉역"(차로)과 "시청역"(도보)이 이름으로 구분되지 않는다. §8②는 "파생 가능한 것을 중복 저장하지 마라"이지 불가능한 것까지 금지가 아니다. 임계 2km는 지하철 검색 반경 재사용(새 상수 발명 없음).

## 3. 작성한 프롬프트
백필 보류 지시("도보 250분은 거짓") → 개선 plan 요구(임계값 근거·필터 필드 실측·개선 전후 대조 7곳). 편집 payload에 transitMode 포함 지시(소실 방지).

## 5. 결과 / 교훈
- 11파일 74+/26-. 개선 전후: 250분→차로 27분 / 폐역→진영역 16분 / 화물역→공항 30분 / 도비도항→null / 도심 무변.
- **CC가 스스로 잡은 것**: 편집 payload 누락 시 스토리 수정마다 mode가 null로 지워지는 회귀 — "편집이 데이터를 지운다" 유형. **새 컬럼 추가 시 편집 왕복 경로 확인**이 이 프로젝트의 반복 패턴으로 확정.
- 교훈: **좁은 데이터로 검증하면 로직의 거짓이 숨는다.** plan 단계 실호출 강제가 프로덕션 진입 전에 잡았다.

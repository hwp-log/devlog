# 0617 회고: CI 환경변수 더미값 추가

**작성일**: 2026-08-28
**소요 시간**: 약 1시간
**관련 커밋**: ci: 0617 CI에 DIRECT_URL 더미값 추가 (`9faf35f`)

---

## 1. 한 줄 요약

0616에서 붙인 CI의 첫 실행이 npm ci의 postinstall(`prisma generate`)에서 실패했다. `prisma.config.ts` 27행 `env("DIRECT_URL")`이 값을 못 찾아 config 로드 시점에 죽은 것이다. 판독 2건(존재 검사 여부·빌드 시점 DB 호출 경로)으로 더미값이면 충분함을 확정하고 ci.yml의 ci job에 env 블록 4줄을 추가해 해소했다.

---

## 2. 왜 / 목적 / 이유

왜: 에러 문구가 "Cannot resolve environment variable"이지 연결 실패가
아니었다. 접속을 시도한 적이 없고 값의 존재만 검사한 것이다. 처음 든
생각은 "CI에 DB 자격증명을 줘야 하나"였는데 문구는 그 단계까지 가지도
않았다고 말하고 있었다.

목적: CI를 그린으로 만드는 것. 그러려면 prisma generate가 통과해야 한다.
이 명령은 스키마를 읽어 타입 코드를 만드는 작업이라 DB에 접속하지 않는다.
`DIRECT_URL`이 원래 쓰이는 자리는 마이그레이션이고 CI는 마이그레이션을
돌리지 않는다. 그렇다면 존재 검사만 통과시키면 된다.

이유 — 판독을 먼저 시킨 까닭: 대응이 두 갈래였다. 더미값이면 되는가,
진짜 자격증명이 필요한가. 이건 고르는 문제가 아니라 확인하는 문제라
"읽고 보고만" 판독을 먼저 시키고 그 결과로 갈래를 정했다.

## 4. 코드 작성 & 수정

변경 파일 1개: `.github/workflows/ci.yml` (+4줄)

```diff
   ci:
     runs-on: ubuntu-latest
+    env:
+      # prisma.config.ts가 존재 검사만 하는 값. 빌드 시점 DB 호출 0건이라
+      # 실제 연결에 쓰이지 않는다. 마이그레이션은 CI에서 실행하지 않음
+      DIRECT_URL: postgresql://user:pass@localhost:5432/db
     steps:
```

- job 레벨이라 npm ci(postinstall) 포함 모든 step에 적용된다.
- 실패 지점의 실물 (`prisma.config.ts` 27행과 `@prisma/config`의 `env()` 구현):

```ts
// prisma.config.ts
datasource: {
  url: env("DIRECT_URL"),
},
```

```js
// node_modules/@prisma/config/dist/index.js — 판독으로 확인한 원인
function env(name) {
  const value = process.env[name];
  if (!value) {
    throw new PrismaConfigEnvError(name);
  }
  return value;
}
```

값이 없으면 config 로드 즉시 throw다. DB 연결은 이 경로에 없다.

## 5. 결과 / 배운점

### 결과

- 커밋 전 로컬 재현: `.env.local` 없이 더미값만 주고 `prisma generate`
  실행 → DB 연결 없이 통과 (dotenv는 기존 process.env를 덮지 않아
  셸에서 준 더미값이 유지된다)
- push 후 CI 재실행 통과. lint → typecheck → test → build 전 단계 그린
- 다른 환경변수가 빌드에 더 필요한지는 미리 채우지 않고 한 번 돌려서
  확인했고 결과는 통과였다

### 배운점

에러 문구가 어느 단계에서 죽었는지를 알려주고 있었다. "변수를 못
찾겠다"와 "연결 실패"는 다른 말인데 처음엔 DB 접근 문제로 넘겨짚었다.

실행 시간도 단서였다. 37초는 build까지 갈 수 없는 시간이다.

CI를 붙이니 로컬이 뒤처져 있던 게 드러났다. 로컬 Node가 20이라 prisma
CLI가 ESM 에러로 안 돌았고 `.nvmrc`는 22였다. `nvm use`로 맞추고
`nvm alias default 22`로 기본값도 바꿨다. 코드 변경이 없어 커밋은 없다.

판독 프롬프트에 "확인 안 되면 확인 불가로 보고하라"고 적어뒀더니 CC가
실제로 그렇게 남겼다. 다른 환경변수의 빌드 요구 여부는 범위 밖이라고
적어준 덕에 그 부분을 미확인으로 두고 한 번 돌려보는 판단을 할 수 있었다.

## 결정 (Decisions)

- CC에 "읽고 보고만" 모드로 두 가지를 확인시켰다.
  - `prisma.config.ts`가 `DIRECT_URL`을 존재만 검사하는지 값으로
    연결하는지. `node_modules/@prisma/config`의 `env()` 구현까지 읽어
    값이 없으면 즉시 throw임을 확인했다
  - `next build`가 빌드 시점에 DB를 호출하는 경로가 있는지. 0건이었다.
    `(protected)/layout.tsx`가 쿠키를 읽어 하위 전 라우트가 요청 시점
    동적 렌더로 판정되고 그 밖의 페이지 3개(`/`·`/login`·`/signup`)는
    prisma를 쓰지 않는다. 코드 판독과 `.next/prerender-manifest.json`
    두 방향으로 교차 확인했다
- 두 확인 결과로 더미값이 확정됐다. 비밀이 아니므로 GitHub Secrets를
  쓰지 않고 워크플로에 평문으로 두었다. 프로덕션 키를 CI에 넣지 않는다는
  기준을 지켰다
- 커밋 전에 로컬에서 `.env.local` 없이 더미값만 주고 `prisma generate`를
  실행해 통과를 확인했다. 판독으로 낸 추정을 실행으로 바꾼 것이다
- 다른 환경변수가 빌드에 필요한지는 확인하지 않았다. 미리 채우지 않고
  한 번 돌려보기로 했고 결과는 통과였다

**작성일**: 2026-07-21
**관련 커밋**:

> 0308~0311은 "모바일 하단 탭바가 주소창에 가려지는 문제"를 원인별로 잡은 연속 트랙이라 묶어 회고.

---

## 1. 한 줄 요약

모바일 iOS Safari에서 하단 pill 탭바가 주소창 뒤로 밀려 가려지는 문제를, 두 가지 근본 원인(① input 포커스 자동 줌 ② 핀치 줌 후 애매한 축소 시 fixed 어긋남)으로 나눠 해결. Visual Viewport API로 탭바를 재고정하되 접근성(확대 권리)은 보존했고, 특히 "동작이 우연히 맞은 게 아닌지" 의심해 코드 검증으로 숨은 맹점(줌 종료 이벤트 누락)까지 찾아 근본 수정.

---

## 2. 왜 / 목적 / 이유

- **왜**: 실기기(iOS Safari)에서 하단 탭바가 주소창 뒤로 가려짐. 재현 (a)검색어 입력→삭제 시 (b)콘텐츠 확대 후 애매하게 축소(scale~1.1) 시 — (b)는 10회 중 4회 발생, 실사용 지장.
- **목적**: 어떤 뷰포트 상태에서도 하단 탭바가 화면에 인지 가능하게 유지(가려짐 방지).
- **이유**: 탭바는 앱 전역 네비게이션이라 가려지면 "고장인 줄" 오인. 특히 사용자가 사진/글을 확대(정상적 사용)한 뒤 축소가 애매하게 남으면 지속적으로 가려짐.

---

## 3. 판단 여정 (원인 2개로 분리)

### 원인 ① — input 포커스 자동 줌 (0309)
- iOS는 input 폰트가 16px 미만이면 포커스 시 자동 줌인, blur해도 안 줄어듦 → 확대 상태에서 fixed 탭바가 밀림. 검색창이 14px(text-sm)였음.
- **해결**: input 폰트를 모바일 16px로(`text-base md:text-sm`). web_search로 "16px가 iOS 자동 줌의 확정 해결책" 확인.
- **접근성 판단**: `user-scalable=no`/`maximum-scale`로 줌을 막는 방법은 배제 — WCAG 위반(저시력 사용자의 확대 권리 박탈). 폰트로만 해결.

### 원인 ② — 핀치 줌 후 애매한 축소 (0310·0311)
- `position:fixed`는 layout viewport 기준인데, 줌하면 visual viewport와 어긋나 탭바가 주소창 뒤로. 특히 사용자가 확대 후 손으로 축소할 때 정확히 1.0으로 안 맞고 ~1.1에 남으면 지속적으로 가림.
- **해결 (0310)**: Visual Viewport API로 `scale>1`일 때 탭바를 visual viewport 하단에 transform 재고정(MDN viewportHandler 패턴: `translate(offsetLeft, offsetTop) scale(1/vv.scale)`).
  - **scale>1 게이팅**으로 줌/키보드 구분 — visual viewport는 줌으로도 키보드로도 바뀌는데(W3C David Bokan이 "둘 구분이 어렵다"고 지적), scale>1일 때만 보정해 키보드(scale≈1) 미개입.
  - 폴백: 미지원(구형·데스크톱)은 기존 fixed 유지.
- **동작 확인**: 실기기에서 확대 후 애매한 축소 시, 탭바가 가려지지 않고 주소창 위로 걸쳐 보임 → 사용자가 탭하거나 더 축소 가능(갇히지 않음).

### 맹점 검증 (방법론 핵심)
- 실기기 동작이 됐지만 "동작이 우연히 맞은 거면 맹점이 남는다"고 의심 → CC에 코드 읽고 plan 대조 + 엣지케이스 6개 검증 지시.
- **결과**: plan과 코드 100% 일치 확인 + **맹점 발견** — B-2(이벤트 누락): iOS가 핀치 줌 중 이벤트를 매 프레임 안 쏘고, **줌이 멈춘 마지막 프레임 이벤트를 놓치면** update()가 최종 상태로 안 불려 탭바가 틀어진 채 고정(자가복구 없음).
  - **이게 "10회 중 4회 실패"의 진짜 원인** — 스샷이 성공했던 건 "그 순간 마침 이벤트가 온 덕"이라 비결정적.
- **근본 수정 (0311)**: rAF(다음 프레임 재확인) + 150ms 디바운스(이벤트 멈춘 뒤 최종 상태로 재적용) 안전망 추가 → 이벤트를 놓쳐도 최종 상태로 수렴. 상시 폴링이 아니라 이벤트 직후에만 재확인(배터리 부담 없음).
  - 실기기 10회 반복 → 실패 0에 수렴 확인.
- 맹점 ②(키보드+줌 동시)는 plan상 2단계로 유보(드묾).

## 4. 코드 작성 & 수정

### 0308 — 뷰포트 완화 (증상 완화)
- BottomTabBar에 `translateZ(0)` 레이어 승격, ThemeScope `min-h-svh`. (근본 해결은 0309·0310이고, 이건 보조 안정화)

### 0309 — input 16px
- `TagSearchBar.tsx`: `text-sm`(14px) → `text-base md:text-sm`(모바일 16px, 데스크톱 14px). 가짜 placeholder 오버레이도 크기 일치. (공유 컴포넌트라 my-story 검색창도 함께 개선)

### 0310 — Visual Viewport 줌 보정
```tsx
// BottomTabBar.tsx — ref + useEffect
const vv = window.visualViewport;
if (!vv || !el) return;                    // 미지원 폴백
const update = () => {
  if (vv.scale > 1) {                       // 줌일 때만 (키보드 미개입)
    const x = vv.offsetLeft;
    const y = vv.offsetTop + vv.height - window.innerHeight;
    el.style.transform = `translate3d(${x}px, ${y}px, 0) scale(${1 / vv.scale})`;
    el.style.transformOrigin = '0 100%';    // 바닥 기준 축소
  } else {
    el.style.transform = '';                // 원복 → className translateZ(0) 폴백
  }
};
update();
vv.addEventListener('resize', update);
vv.addEventListener('scroll', update);
return () => { /* 리스너 해제 */ };
```

### 0311 — 최종 상태 수렴 보강
```tsx
// 이벤트를 놓쳐도 최종 상태로 수렴하는 안전망
const onEvent = () => {
  update();
  cancelAnimationFrame(raf);
  raf = requestAnimationFrame(update);      // A) 다음 프레임 재확인
  clearTimeout(timer);
  timer = setTimeout(update, 150);          // B) 150ms 후 재적용(디바운스)
};
// cleanup에서 raf·timer 해제
```

## 5. 결과 / 배운점

### 결과
- 어떤 뷰포트 상태(자동 줌·핀치 줌·애매한 축소)에서도 탭바가 화면에 유지. 최악이어도 주소창 위로 걸쳐 보임(가려짐 아님).
- SpotFinder 등 전역 적용(탭바는 layout 공유).
- 10회 중 4회 실패 → 0에 수렴.

### 배운점 (방법론 자산)
- **"됐다"에서 멈추지 않고 우연을 의심 → 코드 검증 → 맹점 발견 → 근본 수정**: 실기기 동작이 성공해도 "우연히 이벤트가 온 덕"일 수 있음을 의심하고, 코드 대조 + 엣지케이스 검증으로 숨은 원인(줌 종료 이벤트 누락)을 찾았다. 동작 확인만 했으면 배포 후에도 4/10 실패가 남은 채 "고쳤다"고 착각했을 것.
- **접근성을 우선순위로**: 줌 자체를 막으면(user-scalable=no) 문제가 쉽게 사라지지만 저시력 사용자를 배제. 확대는 보존하고 자동 줌만 막는(폰트 16px) + 줌 후 탭바를 재고정하는 방향을 택함.
- **줌/키보드 구분을 scale로 우회**: visual viewport가 줌·키보드 양쪽으로 바뀌어 구분이 어렵다는 표준 논의(W3C)를, scale>1 게이팅이라는 단순한 조건으로 회피.
- **증상 완화(0308)와 근본 해결(0309·0310) 구분**: translateZ/svh는 보조였고, 진짜 원인은 폰트(자동 줌)와 fixed 기준(줌 어긋남)이었다.

---

## 결정 (Decisions)

- **input 16px로 자동 줌 방지** — user-scalable=no는 접근성 위반이라 배제. 폰트로만.
- **Visual Viewport API로 줌 시 탭바 재고정** — scale>1 게이팅으로 키보드와 구분, 폴백 유지.
- **rAF + 디바운스로 최종 상태 수렴** — iOS 줌 종료 이벤트 누락(4/10 실패의 진짜 원인) 대응. 상시 폴링 아님.
- **핀치 줌 중 fixed 미세 흔들림은 놔둠** — 웹 표준 동작이고 확대 풀면 복귀. 재정렬 완벽화는 부작용 많아 미적용(백로그).
- **맹점 ②(키보드+줌 동시)는 2단계로 유보** — 드문 조합.

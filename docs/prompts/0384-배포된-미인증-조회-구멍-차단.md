## 1. 한 줄 요약

배포 중인 `findNearbySpots` 서버 액션에 인증 가드가 없어 누구나 좌표만 넣으면 촬영지 데이터를 조회할 수 있던 구멍을 닫고, 반경 파라미터에 상한을 걸었다.

## 2. 왜 / 목적 / 이유

**왜(문제)** — S3-a에서 "근처 기존 촬영지 재사용" 기능을 만들며 추가한 `findNearbySpots`에 인증 검사가 없었다. 서버 액션은 엔드포인트로 노출되므로, 로그인하지 않은 상태에서도 좌표를 넣어 호출하면 스팟 데이터가 반환된다. **이미 배포된 상태였다.**

**목적** — 미인증 호출을 차단하고, 반경 파라미터로 DB를 훑는 것도 막는다.

**이유** — 서비스가 공개 배포 중이므로 다른 UX 작업보다 먼저 처리해야 한다고 판단했다. 반경 상한을 함께 넣은 것은, 인증만 막아도 로그인 계정 하나로 반경을 크게 넣어 전체 데이터를 긁을 수 있기 때문이다.

## 3. 작성한 프롬프트

```
[배경]

[목표]
1. 인증 가드 — 미인증이면 prisma 쿼리 전에 차단

3. 호출부는 작성 중이던 글이 날아가지 않게 처리
```

## 4. 코드 작성 & 수정

### 가드 형태 선택 (`lib/spot/nearby.ts`)

세 형태를 비교해 throw형을 택했다.

| 형태 | 판정 | 근거 |
|---|---|---|
| 리다이렉트형 | 기각 | 데이터 페치 액션이라 `NEXT_REDIRECT`를 클릭 핸들러가 기대하지 않음 |
| 값 반환형 (`{ok, data}`) | 기각 | 호출부에 union 분기를 강제 — 시그니처 변경 |
| **throw형** | **채택** | 호출부 무변경, 가드가 쿼리보다 앞이라는 것이 코드에 드러남 |

```ts
const supabase = await createClient();
const { data: { user } } = await supabase.auth.getUser();
if (!user) throw new Error('UNAUTHENTICATED');   // prisma 쿼리보다 앞
```

역할(role)은 검사하지 않는다 — 로그인한 사용자면 누구나 쓰는 기능이다.

### 반경 clamp — `Number.isFinite`가 필수였던 이유

```ts
// 산술만으로는 clamp가 샌다: Math.max(0, NaN) === NaN
const r = Number.isFinite(radiusM)
  ? Math.min(Math.max(0, radiusM), MAX_RADIUS_M)
  : DEFAULT_RADIUS_M;
```

| 입력 | 산술만 | `isFinite` 가드 후 |
|---|---|---|
| `NaN` | `NaN` (통과) | 기본 100 |
| `Infinity` | `Infinity` (통과) | 기본 100 |
| `-50` | 0 | 0 |
| `99999` | 500 | 500 |

clamp된 `r`을 boundingBox와 거리 필터 양쪽에 일관되게 썼다. 한쪽만 적용하면 상한이 무의미해진다.

### 호출부 (`components/SpotMap.tsx`)

인증 게이트 뒤 화면이라도 작성 도중 토큰이 만료되면 throw가 올라온다. 그 경우 작성 중이던 글이 날아가므로, 후보 조회 실패는 "후보 없음"으로 폴스루시켰다.

```ts
let candidates: NearbySpot[] = [];
try { candidates = await findNearbySpots(lat, lng); } catch { candidates = []; }
```

### 테스트 (`lib/spot/__tests__/nearby.test.ts`, 신규 7건)

미인증 시 throw하는 것에 더해 **`prisma.findMany`가 호출되지 않았다는 것까지** 단언했다. 가드가 존재하는 것과 가드가 쿼리보다 앞에 있는 것은 다른 문제다.

`geo.ts`는 실함수로 두고 supabase·prisma만 mock했으며, 반환 개수로 유효 반경을 판정했다.

## 5. 결과 / 배운점

### 결과

- 미인증 호출이 쿼리 이전에 차단된다.
- 반경은 최대 500m로 제한되고, `NaN`·`Infinity`·음수가 모두 흡수된다.
- 작성 중 토큰이 만료돼도 글은 보존된다.
- 테스트 7건 추가.

### 배운점

- **기능을 붙일 때 인증을 함께 붙이지 않으면 배포된 뒤에 발견된다.** 화면이 인증 게이트 뒤에 있다는 것과 그 화면이 호출하는 서버 액션이 보호된다는 것은 다른 문제다. 서버 액션은 그 자체가 엔드포인트다.
- **가드 형태는 호출부가 결정한다.** 리다이렉트·값 반환·throw 중 무엇이 옳은지는 보안 강도가 아니라 "호출부가 어떤 반환을 기대하는가"로 갈렸다. 데이터 페치 액션이라 throw형만 호출부를 건드리지 않았다.
- **`Math.max(0, NaN)`은 `NaN`이다.** 산술 clamp는 비수치 입력을 막지 못한다. 경계값 방어는 `Number.isFinite`를 먼저 통과시켜야 성립한다. 이건 리뷰에서 잡힌 실제 버그였다.
- **테스트는 "차단됐다"가 아니라 "쿼리에 도달하지 않았다"를 검증해야 한다.** 전자는 가드가 쿼리 뒤에 있어도 통과한다.
- **인증 왕복은 공짜가 아니다.** 이 작업에서 `auth.getUser()`를 액션마다 부르는 구조가 자리 잡았는데, 뒤에 0396 작업 전 지연을 실측하면서 이것이 warm 약 140ms·cold 약 754ms의 고정비라는 사실이 드러났다(수치는 그때의 세션 실측이며 코드에는 남아 있지 않다 — 상세는 0394-0396 회고 §4). 보안과 성능이 같은 자리에서 맞물린다.

### 남은 것 / 후속

- `requireUser()` 공용 가드 추출 — 지금은 `nearby.ts`에 인라인이다. 두 번째 액션이 같은 가드를 필요로 할 때 함께 추출하기로 했다(0392에서 `getSpotMeta`가 생겼으나, 테스트가 있는 `nearby`와 값반환형 `searchPlaces`까지 마이그레이션해야 해 범위가 커져 보류).
- `DEFAULT_RADIUS_M`을 100으로 둘지 200으로 올릴지 미판단.
- `supabase.auth.getUser` → `getClaims` 전환 검토(비대칭 서명 키 활성 여부 확인 선행).

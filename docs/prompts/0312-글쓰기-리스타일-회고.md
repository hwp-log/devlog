# 0312 회고: 글쓰기 화면 시안 문법 리스타일

작성일: 2026-07-22 / 소요시간: 약 2.5시간 / 관련 커밋: dfb2d79 (style: 0312)

## 1. 한 줄 요약

글쓰기 계열 6개 파일의 하드코딩 색(#1A1A1A·slate·white)을 토큰 유틸로 교체하고, 죽어있던 accent(골드) 토큰을 별점에 처음 배선했다. 본문 에디터와 지도 SDK부는 의도적으로 제외했다.

## 2. 왜 / 목적 / 이유

**왜(동기·문제)** — 시안 문법(다크 토큰·눈썹·pill)이 온전히 적용된 화면이 Story 리스트 하나뿐이었다. 글쓰기 화면은 기능이 완성돼 있는데도 색이 전부 하드코딩이라 다크 모드에서 검정 텍스트가 그대로 남아 안 보이는 상태였다.

**목적(목표 상태)** — 글쓰기 화면이 라이트/다크 어느 테마에서도 시안 톤으로 보이게 한다. 색의 출처를 lib/theme.ts 토큰 하나로 모아, 이후 화면 리스타일 때 같은 어휘를 재사용할 수 있게 한다.

**이유(결정 근거)** — 3가지 제외/유지 결정이 핵심이었다.
- **본문 에디터 제외**: 노션화(슬래시·버블·드래그)가 확정돼 있어, 지금 상단 툴바를 리스타일하면 노션화 때 그 툴바 자체가 사라져 재작업이 된다. "곧 바뀔 부분은 지금 손대지 않는다."
- **지도 SDK부 제외**: Kakao가 다크모드 미대응이라 Naver 교체가 예정됨. CustomOverlayMap·마커는 교체 때 어차피 다시 짠다.
- **별점 accent(골드)**: 시안 목업의 파란 별과 코드의 amber 하드코딩이 충돌. 관행("별=노랑")이 아니라 "브랜드 파랑과 겹치면 별점이 인터랙션 요소로 오독된다"는 기능적 구분 + theme.ts에 별점 전용으로 정의만 돼 있던 accent를 살리는 코드 정합성으로 골드 확정. 두 색을 나란히 렌더해 눈으로 비교한 뒤 결정했다.

## 3. 작성한 프롬프트

```

글쓰기 화면이 시안 문법 미적용 상태(#1A1A1A·slate-*·bg-white·glass-outer 하드코딩).
lib/theme.ts에 시안 색이 라이트/다크 토큰으로 완비돼 있고, globals.css @theme로
bg-bg·bg-card·text-fg·text-fg2·text-muted·border-border·text-primary·rounded-card
유틸이 생성됨. 이미 적용된 Story 리스트(StoryHeader/StoryCard)가 참조 어휘.

[목표]
글쓰기 화면을 시안 문법으로 리스타일. 단, 본문 에디터는 제외(별도 노션화 예정).
하드코딩된 색을 기존 토큰 유틸로 교체하는 것이 핵심 — 새 색/클래스 만들지 말 것.

[하지 말 것]

❌ 기능/로직/마크업 구조 변경 (색·스타일 클래스만 교체)
❌ SpotMap의 Kakao 지도 SDK 부분
❌ 커밋·푸시 (검수 후 현우가 직접)

[검수 모드]
파일별로 나눠서 plan 작성. 어느 하드코딩을 어느 토큰으로 바꿀지 매핑 표로 먼저 제시.
plan 요청.
```

리스타일 도중 CC가 발견한 사실에 답한 결정 프롬프트(요지): DM Mono 폰트 추가하지 않고 기존 font-mono(Geist Mono) 유지 / 플랜연결 카드 앰버 폐기(경고가 아니라 정보 카드) / SpotPopup 파급 수용(SpotFinder도 함께 정합) / 이미지 위 오버레이·파괴 액션 red는 semantic이라 유지.

## 4. 작성·수정한 코드

대상 6개: story/new/page.tsx, story/[id]/edit/page.tsx, StoryWriteForm.tsx, SpotMap.tsx, SpotList.tsx, SpotPopup.tsx

대표 패턴 — 색 클래스만 1:1 교체(구조 무변):

```tsx
// app/(protected)/story/new/page.tsx
- <h1 className="text-2xl font-bold text-[#1A1A1A] mb-2">새 스토리 작성</h1>
- <p className="text-sm text-slate-500 mb-6">…</p>
+ <h1 className="text-2xl font-bold text-fg mb-2">새 스토리 작성</h1>
+ <p className="text-sm text-muted mb-6">…</p>
```

```tsx
// components/SpotPopup.tsx — 별점: accent 토큰 첫 배선
- <Star className="fill-amber-400 text-amber-400" />   // 채운 별
- <Star className="text-slate-300" />                   // 빈 별
+ <Star className="fill-accent text-accent" />
+ <Star className="text-muted" />
```

```tsx
// components/SpotList.tsx — 위계: 컨테이너 bg-card 안 항목은 한 톤 밝게
- className="bg-white border-black/[0.08] …"
+ className="bg-surface2 border-border …"
```

Tailwind v4 확인 사항: @theme에 --color-accent만 있으면 fill-accent·text-accent가 자동 파생됨(별도 fill 유틸 등록 불필요).

## 5. 결과 / 교훈

- 다크 모드에서 글쓰기 계열 전체가 시안 톤으로 전환됨(라이트는 기존과 거의 동일 — fg≈검정, muted≈slate). SpotPopup·SpotList 공유로 SpotFinder 상세도 함께 정리됨.
- **교훈 1 — 리스타일은 색만이 아니라 위계다.** 전부 bg-card로 바꾸면 입력 필드와 컨테이너가 같은 색이 돼 경계가 사라진다. 컨테이너 안 요소는 bg-surface2로 한 톤 차이를 두는 규칙을 세웠다.
- **교훈 2 — semantic 색은 토큰화하면 안 된다.** 사진 위 오버레이(반투명 흑백)·파괴 액션 red는 "어느 테마에서도 유지돼야 하는 의미"라 테마 토큰 대상이 아니다.
- **교훈 3 — auto-accept의 위험.** SpotMap 수정이 auto-accept로 한 번에 밀려 파일 단위 검수가 건너뛰어졌다. 다행히 SDK 경계는 지켜졌지만, 이후 shift+tab으로 끄고 진행하는 것을 규칙화했다.
- **교훈 4 — 시안도 틀릴 수 있다.** 시안의 파란 별은 통일감만 보고 관행을 깬 실수였다. 시안은 기준이지만 신이 아니다 — 코드 설계(accent)와 기능적 구분이 시안을 이겼다.

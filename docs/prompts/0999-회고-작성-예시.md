## 2. 왜 / 목적 / 이유

왜: 0615로 테스트가 전부 그린(207/207)이 되어, CI가 감시할 대상이 준비됐다.
테스트가 빨간 상태에서 CI를 붙이면 매 실행이 빨강이라, 새로 생긴 문제와
원래 빨갛던 것을 구분할 수 없다. 그 선행 조건이 막 해소된 시점이었다.

목적: 검증 명령을 사람이 치는 게 아니라 push가 치게 하는 것.
지금까지는 `npm test`를 내가 기억해서 쳐야 돌았고, 안 치면 안 돌았다.
0615의 테스트 9개가 몇 달간 안 돌던 것이 그 결과다. push·PR에 걸어두면
기억하지 않아도 돈다.

이유 — 워크플로 세부 선택:
- checkout을 setup-node보다 먼저 둔 것은 npm 캐시 키가 lockfile
  해시라서다 — lockfile이 체크아웃돼 있어야 캐시 키를 계산할 수 있어
  순서에 의존한다 (ci.yml에 주석으로 명기).
- `npm install`이 아니라 `npm ci` — install은 lockfile을 갱신할 수도
  있어서 CI가 로컬과 다른 버전을 설치할 여지가 있고, ci는 lockfile에
  적힌 버전만 그대로 설치한다. 로컬에서 통과한 것과 CI에서 통과한 것이
  같은 의존성 위에서 나와야 한다.

작업은 프롬프트 4개로 나눠 진행했다: ① 워크플로 신규 → ② ban-ts-comment
설명 보강 → ③ react-hooks 조사(읽고 보고만) → ④ react-hooks 정리.
③을 ④ 앞에 따로 둔 것은, 무엇을 고치고 무엇을 남길지 정하려면 각 건의
난도를 먼저 알아야 했기 때문이다.

### 4. react-hooks 수정 3건 — 등가 치환

`app/(protected)/_components/NavLinks.tsx` 24·26 — useState 초기값에서 ref 읽기 제거:

```diff
   const startedAt = useRef(lastCenter); // 이 인스턴스 마운트 시점의 이전 위치(null=최초 로드)
-  const [center, setCenter] = useState<number | null>(startedAt.current);
+  const [center, setCenter] = useState<number | null>(lastCenter);

-  const [enabled, setEnabled] = useState(startedAt.current != null);
+  const [enabled, setEnabled] = useState(lastCenter != null);
```

등가 근거: `startedAt`은 같은 초기 render에서 모듈 변수 `lastCenter`를 캡처하고, 그 사이에 `lastCenter`를 바꾸는 코드가 없다. useState 초기값은 마운트 1회만 평가 → 항상 같은 값. ref 자체는 effect 내 최초 마운트 게이트(42·44행)에서 계속 쓰므로 유지 — effect 안 ref 접근은 규칙 위반이 아니다.

`app/(protected)/my-plan/new/MyPlanNewForm.tsx` 578~579 — ref → setter 없는 useState:

```diff
-  const savedStartRef = useRef(initialState?.startDate || null);
-  const startMin = minStartDate(savedStartRef.current);
+  const [savedStart] = useState(initialState?.startDate || null);
+  const startMin = minStartDate(savedStart);
```

등가 근거: `savedStartRef`는 이 두 줄 외 사용처가 없고 mutate도 없다(전체 grep). setter 없는 useState 초기값 = 마운트 1회 고정 — "최초 저장값 고정"이라는 0581 의도 그대로. 0581 주석의 "ref로 고정한다" 표현만 현행화.

## 5. 결과 / 배운점

### 결과

- 로컬 4개 게이트 전부 통과: `npm run lint` 에러 0(경고 12는 기존) / `npm run typecheck` 에러 0 / `npm test` 207/207 / `npm run build` 성공
- 앱 동작 변경 없음 (수정 3건 전부 등가 치환, 나머지는 주석·설정)
- **CI 첫 실행은 실패** — npm ci의 postinstall(`prisma generate`)이 `DIRECT_URL` 부재로 죽음. 이 회고는 0616 시점까지만 다루며, 해소는 0617(CI에 더미값 추가).

### 배운점

- **테스트만 안 돌던 게 아니라 lint도 안 돌고 있었다.** `npm run lint`가
  게이트로 한 번도 실행된 적이 없어 에러 9건이 쌓여 있었다. 0615와
  같은 구조가 같은 주에 두 번 나왔다 — 도구가 있는 것과 그 도구가
  도는 것은 다르다.
- **코드가 틀린 게 아니라 규칙이 새로 생긴 것이었다.** react-hooks
  5건은 전부 지금 정상 동작하는 코드고, React Compiler 대비로 규칙이
  추가되면서 걸린 것이다. 그래서 "빨간 줄 = 버그"로 보고 전부
  고치려 들면 멀쩡한 코드를 건드리게 된다.
- **에러를 안 뜨게만 막은 게 아니라, 왜 못 고치는지를 그 줄에 적어뒀다.**
  이유 없이 규칙만 끄면 나중에 볼 사람이 "여긴 왜 껐지"부터 다시
  조사해야 한다. "hydration 때문에 useState 초기화가 안 된다"까지
  적어두면 그 줄을 다시 볼 때 판단이 바로 선다.
- **내가 프롬프트에 파일명을 틀리게 적었고, 조사 단계가 그걸 잡았다.**
  ③의 배경에 "SpotPopup 내 setState"라고 썼는데 실제로는
  `SpotFinderHeader.tsx` 14행이었다. 조사 없이 바로 고치라고 시켰으면
  엉뚱한 파일을 열었을 것이다. "읽고 보고만" 단계는 CC를 못 믿어서
  두는 게 아니라, 내가 준 전제가 틀렸을 때 그게 드러나라고 두는 것이다.

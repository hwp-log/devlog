# 0509-0510 스토리 사진을 촬영지 커버로 잇기

**작성일**: 2026-08-05
**관련 커밋**:
- fix - 0509 플랜 상세 커버를 최신 스토리 사진으로 폴백 (004dea4)
- feat - 0510 대표 이미지 후보에 스토리 사진 폴백과 1장부터 선택 표시 (7a67bdd)

---

## 1. 한 줄 요약

스토리에 갇힌 촬영지 사진(StorySpot.photoUrl)을 조회 폴백으로 잇는다 — 플랜 상세의 그리드·카드(0509)와 작성·수정 화면의 대표 이미지 후보(0510)가 `Spot.coverUrl ?? 사진 있는 최신 스토리 사진`을 보고, 선택 UI는 후보 1장부터 뜬다. 저장은 무변경.

---

## 2. 왜 / 목적 / 이유

### 발단 — "사진이 없어서"가 아니라 "있는데 안 이어져서"
- 수리남 플랜의 사진 그리드가 비는 것을 확인하다, 원인이 데이터 부재가 아님을 발견.
  스토리 상세에는 허니문하우스 사진이 보이는데 플랜 상세 그리드에는 안 나온다 —
  사진은 StorySpot에 저장되고 Spot.coverUrl에는 들어가지 않아, 두 화면이 서로 다른
  필드를 보고 있었다.
- 조사 실측: **커버 없는 촬영지 21곳 중 11곳이 StorySpot 사진 보유**
  (비촬영지 확장 시 추가 혜택 0건 — 현재 데이터에선 범위 논쟁이 무의미).

### 저장 승격이 아니라 조회 폴백을 고른 이유
- 스토리 사진을 Spot.coverUrl로 복사(승격)하면 **스토리 삭제 시 죽은 URL이 남는다.**
  단일 소스를 깨고 같은 사실을 두 곳에 기록하는 구조가 됨.
- 조회 시 `coverUrl ?? 최신 StorySpot.photoUrl`로 파생하면 원본이 사라질 때 폴백도
  함께 사라진다 — PlanSpot lat/lng와 같은 계열의 결정.

### 0510이 별건에서 즉시 착수로 바뀐 경위
- 0509 조사에서 pick-cover(커버 후보)는 별건으로 분리했으나, 확인 결과 작성·수정
  화면의 후보 수집이 여전히 coverUrl만 보고 **선택 UI(0497)는 후보 2장 이상에서만**
  떴다. 담긴 Spot 커버가 0장인 플랜은 스토리 사진이 있어도 고를 수 없고, 지역
  이미지가 자동으로 붙는 걸 작성자가 확인도 못 한다 — **"폴백은 자동이 아니라
  질문으로" 원리가 이 구간에서 깨져 있어** 즉시 잇기로 함.
- 후보 1장부터 표시로 바꾼 근거: 1장이어도 "이 사진 / 지역 이미지 / 사진 없이"의
  선택이 실재한다. 특히 스토리 폴백 후보는 자동 결과와 달라 "1개=자동과 동일"이라는
  0497의 전제가 깨졌다.

### 의도된 비대칭 — 질문은 스토리를 보고, 자동은 안 본다
- 후보(getPlanCoverCandidates)는 스토리 폴백을 포함하지만, 자동 채택(resolveCover)은
  스토리를 보지 않는다. 고르지 않으면 기존 규칙(자기 커버→작품→지역) 그대로 —
  스토리 사진이 지역 이미지를 **몰래** 이기는 일이 없도록, 폴백은 후보(질문)로만 올린다.

## 4. 코드 작성 & 수정

### 1. 플랜 상세 — storySpots 조인 + 평탄화 폴백 (0509)

```ts
// app/(protected)/plan-finder/[id]/page.tsx — spot 중첩 select
// 0509: 커버 폴백용 — 사진 있는 최신 스토리 1건.
//   최신=대표(0185, lib/spot/queries.ts 썸네일 선례와 동일 규칙·동일 정렬축).
storySpots: {
  where: { photoUrl: { not: null } },
  orderBy: { story: { createdAt: 'desc' } },
  take: 1,
  select: { photoUrl: true },
},
```

```ts
// 같은 파일 — spots 평탄화 (그리드·일정 카드가 함께 소비 → 양쪽 동일 규칙)
// 0509: coverUrl 우선, 없으면 사진 있는 최신 스토리 사진(조회 폴백 — 저장 무변경).
coverUrl: s.spot?.coverUrl ?? s.spot?.storySpots[0]?.photoUrl ?? null,
```

### 2. 대표 이미지 후보 — where 완화 + 폴백 병합 (0510)

조인만 넣으면 기존 `coverUrl: { not: null }` 필터가 **폴백 대상(coverUrl 없는 Spot)을
쿼리 단계에서 걸러낸다** — where를 OR로 완화해야 폴백이 후보에 도달한다.

```ts
// app/(protected)/my-plan/new/actions.ts — getPlanCoverCandidates
const spots = await prisma.spot.findMany({
  where: {
    id: { in: ids },
    OR: [{ coverUrl: { not: null } }, { storySpots: { some: { photoUrl: { not: null } } } }],
  },
  select: {
    id: true,
    name: true,
    coverUrl: true,
    storySpots: {
      where: { photoUrl: { not: null } },
      orderBy: { story: { createdAt: 'desc' } },
      take: 1,
      select: { photoUrl: true },
    },
  },
});
...
const url = s?.coverUrl ?? s?.storySpots[0]?.photoUrl;
if (!s || !url || seen.has(url)) continue;
```

### 3. 선택 UI 게이트 — 2장 → 1장 (0510)

```ts
// app/(protected)/my-plan/new/CoverPicker.tsx
// 변경 전
if (candidates.length < 2) return null;
// 변경 후
// 0510: 후보 1개부터 표시(0장만 미표시 — 지역 폴백 흐름 무변경).
if (candidates.length === 0) return null;
```

## 5. 결과 / 배운점

### 결과
- 실데이터 대조(읽기 전용 스크립트): 수리남 플랜 상세 — 허니문하우스가 그리드 노출로
  전환(스토리 사진). 우선순위 엄밀 대조 — 둘 다 가진 유일 스팟(롯데월드몰)에서
  coverUrl 우선·스토리 무시 확인.
- 후보 수집: 수리남 후보 0→1장(스토리 출처), 미생 플랜은 변경 전후 동일 2장·동일 순서.
- CoverPicker 게이트: RTL로 1장 렌더 / 0장 미렌더 확인. `tsc --noEmit` 통과.
- 자동 채택(resolveCover)·우선순위 보장 지점·스팟파인더(우선순위 반대)·저장 경로는
  무접촉 — DB 무변경.

### 배운점
- 초안: "화면이 빈다"의 원인은 데이터 부재와 연결 부재가 다르다 —
  고치기 전에 실측(21곳 중 11곳)으로 어느 쪽인지 확정하면 해법(백필 vs 폴백)이 갈린다.
- 초안: 폴백을 넣을 때는 조인만이 아니라 **기존 where 필터가 폴백
  대상을 걸러내는지**를 봐야 한다 — select는 통과해도 where에서 죽는다.
- 초안: 게이트 조건("2장부터")은 그 전제("1장=자동과 동일")가
  유효할 때만 옳다 — 후보 소스가 바뀌면 게이트의 전제부터 다시 검사.

## 결정 (Decisions)

- 스토리 사진은 **조회 폴백**으로만 잇는다 — Spot.coverUrl로 저장 승격 금지
  (스토리 삭제 시 죽은 URL, 이중 기록. PlanSpot lat/lng와 같은 계열).
- 폴백 규칙: `coverUrl ?? 사진 있는 최신 스토리의 photoUrl`,
  정렬축 `story.createdAt desc` (0185 최신=대표, 스팟파인더 썸네일 선례와 동일).
- 폴백은 자동이 아니라 질문으로 — 후보 UI는 스토리를 보고, 자동 채택(resolveCover)은
  안 본다. 고른 값 > 자동 우선순위는 유지.
- 대표 이미지 선택 UI는 후보 1장부터 표시(0497의 "2장부터" 게이트 폐기).
- 스팟파인더(lib/spot/queries.ts)의 반대 방향 우선순위(스토리 우선)는 별건으로 유지.

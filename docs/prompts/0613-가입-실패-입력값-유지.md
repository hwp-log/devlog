## 2. 왜 / 목적 / 이유

- **왜**: 0612 문구가 세 줄로 길었고, 실패 후 비밀번호 칸은 비었는데 강도 바는 "보통"으로 남았다.
- **원인 (원문 확인)**: 세 입력이 uncontrolled + `<form action>` 조합 — **React 19(19.2.4)는 form action 완료 시 성공·실패 무관하게 폼을 자동 리셋**해 uncontrolled 필드를 비운다. 강도는 React state라 리셋 영향 밖 → 값만 사라지고 표시 잔존.
- **해법 (사용자 확정)**: controlled 3필드(mypage PasswordForm 패턴 준용) — 리셋 후 리렌더에서 state 값이 다시 그려져 유지. 강도는 별도 state를 제거하고 `getPasswordStrength(password)` 파생으로 — 단일 소스+파생(§8), 유령 원천 차단.
- **문구 "지금" 유지 이유**: 일시적 실패(rate limit·장애)도 암시 — "잠시 후 재시도" 절은 길이 문제로 축약(0612 결정의 후속 수정, 뒤집힘 정본은 코드 주석).

## 5. 결과 / 배운점

### 결과
- tsc·eslint 통과. `npm test`: 실패 2스위트/1테스트 — 기존 목록과 동일, 신규 실패 0 (SignupForm.test는 controlled 전환에도 통과 유지).
- 스코프 외 보고: **LoginForm도 같은 구조(uncontrolled + form action)라 로그인 실패 시 이메일이 리셋됨** — 이번 범위 밖, 별건.
- 0612 회고의 문구 서술은 시점 기록으로 미수정 — 뒤집힘 정본은 lib/auth/actions.ts 주석("0613에서 길이 문제로 축약").

### 배운점
- React 19 form action의 자동 리셋은 성공·실패를 구분하지 않는다 — 실패 시 값을 유지하려면 controlled가 기본기. 파생 가능한 표시 상태(강도)를 별도 state로 들면 리셋 경로마다 어긋남이 재발한다(단일 소스+파생).

## 결정 (Decisions)

- 가입 실패 문구 최종: "이 이메일로는 지금 가입할 수 없습니다. 이미 가입하셨다면 로그인해주세요." — "지금"이 일시적 실패 암시를 담당(재시도 절 대체).

- 강도 바 = password state 파생 (별도 state 금지) — §8 단일 소스+파생.

## 2. 왜 / 목적 / 이유

### 메뉴 영어 통일 (Sign In/Up/Out + Write + MyStory)
- **왜**: 네비게이션은 영어(Story/SpotFinder/CostPlan)인데 헤더 액션/드롭다운은 한글이라 일관성 없음
- **목적**: 핵심 메뉴/액션을 영어로 통일. 콘텐츠/안내는 한글 유지 (혼용)
- **이유**: Sign In/Out은 코드 함수명 `signOut`과 일관 + 현대 SaaS 트렌드 (Google/Apple/GitHub/Notion/Medium)

### Write 버튼 디자인 변경
- **왜**: 기존 "+ 스토리" 검은 버튼이 헤더에서 시각 부담
- **목적**: Medium 패턴(흰 배경 + 회색 테두리 + 펜 아이콘) 적용
- **이유**: 미니멀 + 클린. 헤더 다른 요소와 시각 조화

### 헤더 Write UX 일관성
- **왜**: Write 버튼이 /story 페이지에서만 표시, /my-dots에서 사라짐
- **목적**: 모든 protected 페이지에서 헤더 위치 고정
- **이유**: 사용자 학습 부담 ↓ (velog/Medium 패턴 = Write는 헤더 고정)

### 네이밍 변경 (MyPage → MyStory)
- **왜**: 페이지 의미 = 작성한 스토리 리스트. MyPage는 광범위
- **목적**: 페이지 의미와 이름 일치
- **이유**: 사용자 인지 부담 ↓

### my-dots 그리드 4열 추가
- **왜**: /story = 4열, /my-dots = 3열로 같은 패턴인데 다름
- **목적**: `xl:grid-cols-4` 추가 (/story 일치)
- **이유**: 같은 카드 그리드 = 같은 시각

### (protected) layout 콘텐츠 폭 통일
- **왜**: `(protected)` layout = `max-w-5xl`, `story/layout` = `max-w-7xl` → 카드 크기 다름
- **목적**: 두 layout 모두 `max-w-7xl` 통일
- **이유**: 같은 헤더 + 같은 카드 그리드 시각 보장

### 페이지 폭 통일 (헤더 + 글작성)
- **왜**: 페이지마다 콘텐츠 영역 폭 제각각
- **목적**: 헤더 `max-w-7xl` + 본문 `max-w-4xl` 패턴 정착 (0050 결정 적용)
- **이유**: 브런치/Medium 표준 (가독성 + 시각 일관성)

### /story/new 카드 구조 적용
- **왜**: /story/[id]는 흰 카드 안에 본문, /story/new는 카드 없이 폼 노출
- **목적**: /story/new도 흰 카드로 폼 감싸기
- **이유**: 작성 ↔ 상세 페이지 시각 통일

## 5. 결과 / 배운점

### 결과
- 모든 헤더 정렬 일치 (두 layout max-w-7xl)
- 모든 카드 그리드 4열 (xl 기준)
- 모든 페이지 콘텐츠 폭 통일 (외부 7xl + 본문 4xl)
- 영어/한글 혼용 체계 정착 (메뉴 영어 + 콘텐츠 한글)
- Write 버튼 모든 protected 페이지 헤더 고정
- 멘토 피드백의 "프로덕트 태" 실천

### 배운점

**1. UX 일관성은 디테일에서 결정**
사용자(본인)가 페이지 전환 시 "여기 좁아 보임", "여기 4열인데 다른 데 3열" 같은 미세한 불일치를 즉시 인지. 본문 폭 자체는 같지만 외부 카드 구조가 다르면 시각이 깨짐. 매크로 디자인(전체 구조)이 일치해도 마이크로 디자인(여백/폭/색)이 일치하지 않으면 UX가 깨짐.

**2. 영어/한글 혼용 패턴**
한국 사용자 대상 서비스에서 "전부 영어 vs 전부 한글"은 트레이드오프. Notion/토스의 표준 = 핵심 액션/메뉴는 영어, 콘텐츠/안내는 한글. Dotrip 결정 = Sign In/Out + Write + MyStory + 한글 폼 라벨/안내 = 혼용 균형.

**3. Sign In/Out vs Log In/Out**
현대 SaaS 트렌드 = Sign In/Out (Google/Apple/GitHub/Notion/Medium). 전통 IT = Log In/Out (Twitter/Facebook/Instagram). 코드 함수명 `signOut` 사용 → UI도 Sign Out으로 일관성.

**4. Medium "Write" 버튼 패턴**
검은 배경 + 흰 글씨 = 시각 부담. 흰 배경 + 회색 테두리 + 펜 아이콘 = 미니멀 + 클린. 헤더의 다른 요소(로고/네비/유저 아이콘)와 시각 조화. 브랜드 톤에 부합.

**5. 헤더 위치 학습 부담**
사용자는 한 번 학습한 위치를 기억. Write 버튼이 어떤 페이지에서는 있고 어떤 페이지에서는 없으면 인지 부담 ↑. velog/Medium처럼 모든 페이지에서 Write 버튼을 헤더에 고정 = 표준 패턴.

**6. 같은 그리드도 부모 컨테이너 폭에 따라 다른 결과**
`grid-cols-1 md:grid-cols-2 lg:grid-cols-3 xl:grid-cols-4` 같은 클래스도 부모 컨테이너 폭(`max-w-5xl` vs `max-w-7xl`)에 따라 카드 크기가 다름. CSS 클래스 자체가 같아도 부모 컨테이너가 영향. 디자인 시스템은 부모 + 자식 모두 일치 필요.

**7. 흰 카드의 시각 분리 효과**
회색 배경에 직접 폼 노출 vs 흰 카드로 감싼 폼. 시각적 분리감 + 콘텐츠 강조 효과. /story/[id]의 카드 패턴을 /story/new에 적용 = 작성 ↔ 상세 페이지 시각 일관성.

**8. 작업 흐름 = 사용자 검증 주도**
이번 7개 커밋의 공통점 = 사용자(본인)가 직접 시각 검증 후 불일치 발견. 코드 레벨 분석 X. 브라우저에서 화면을 직접 보고 발견 = 가장 빠른 불일치 탐지 방법.

## 결정 (Decisions)

- 영어/한글 혼용 = 메뉴/액션 영어 + 콘텐츠/안내 한글
- Sign In/Out 채택 (Log In/Out X) — 코드 함수명과 일관성
- Write 버튼 = Medium 패턴 (흰 배경 + 회색 테두리 + 펜 아이콘)
- Write 위치 = 모든 protected 페이지 헤더 고정
- 페이지 폭 = 외부 `max-w-7xl` + 본문 `max-w-4xl` (브런치/Medium 표준)
- URL = `/my-dots` 유지 (변경 X)

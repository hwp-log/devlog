# 0377~382 회고: 모바일 스팟 시트

작성일 2026-07-26 / 소요 약 3시간 / 커밋 0377~0382

## 핵심 판단

- **"리뷰가 가려진다"의 실체는 카드가 42px로 붕괴한 것이었다.**
- **`flex-1`이 세로 스택에서 명시 높이를 이겨 지도가 0이 되는 버그가 두 달간 잠복해
  있었다.** stash로 이전 커밋을 대조하지 않았으면 이번 변경 탓으로 잘못 고쳤을 것이다.
- **전체화면이 어색하고 시트가 자연스러운 이유를 언어로 정리했다.** 지도가 탐색
  도구면 물러나도 되지만, 작업 대상이면 계속 보여야 한다.
- **뒤로 가기가 닫기 로직을 우회하는 문제를 닫기 파이프라인 단일화로 풀었다.**
- **CDP 검증이 전부 통과했는데 실기기는 달랐다.**

## 한 줄 요약

모바일에서 스팟 리뷰가 확인되지 않던 문제를 구조 버그 수정 → 전체화면 모달 →
하단 시트 순으로 풀었다.

## 왜 / 목적 / 이유

**왜** — 모바일에서 마커를 탭해도 리뷰를 볼 수 없었다. "스크롤하면서 가려지는 느낌"이었다.

**목적** — 마커를 탭하면 그 스팟의 리뷰가 바로 읽히고, 리뷰를 쓰는 동안에도 어디를
쓰는 중인지 보이게.

**이유** — 데스크톱은 지도와 사이드 카드가 좌우로 놓이지만 모바일은 세로 스택이라
카드가 화면 밖에 있었다. 스크롤 문제로 보였지만 조사해보니 아니었다.

## 결과 / 배운 점

### 증상과 원인이 다르다

"가려진다"는 표현 때문에 스크롤 문제로 접근하기 쉬웠다. 조사 결과 원인은 두 겹이었다.

**원인 1 — 카드 높이 붕괴.** readOnly 사이드 카드는 목록과 팝업 두 레이어를 크로스페이드로
전환하는데, 팝업이 열리면 **두 자식이 모두 `absolute`**가 된다. 데스크톱은 카드가
`h-full`이라 행 높이(지도 500px)로 stretch되어 문제가 없지만, 모바일은 `flex-col`이라
카드 높이가 콘텐츠 기준이다. 콘텐츠가 전부 절대 배치면 **높이가 패딩만 남아 42px로
붕괴**하고, `overflow-hidden`에 팝업이 클립된다.

즉 리뷰는 가려진 게 아니라 **그려질 자리가 없었다.**

**원인 2 — 탭 응답이 뷰포트 밖.** 지도 400px + 카드가 세로로 쌓이면 카드는 대개 화면
아래에 있다. 마커를 탭해도 페이지 스크롤은 움직이지 않으니 시각 피드백이 지도 위의
morph·펄스뿐이었다.

### 잠복 버그를 이번 변경 탓으로 오인할 뻔

수정 후 모바일에서 **지도가 아예 사라졌다.** 나는 "0377로 카드 높이가 커지면서 지도가
눌렸다"는 가설을 세웠다.

메커니즘은 맞았다. 지도 컨테이너가 `flex-1 h-[400px]`인데 `flex-1` = `flex: 1 1 0%`이라
**`flex-basis: 0%`가 `height`를 이기고**, 자동 높이 컨테이너라 grow가 배분받을 여유
공간도 0이라 계산 높이가 0이 된다.

그런데 **인과는 틀렸다.** stash로 이전 커밋(0376) 상태를 같은 조건에서 측정했더니
동일하게 0px이었고, 이 클래스는 5월(0049)부터 있었다. **이번 변경 전부터 잠복해 있던
버그**였다. 모바일 세로 스택에서만 드러나는 조건이라 그동안 안 보였을 뿐이다.

`md:flex-1`로 한정했다. grow의 목적은 가로 행에서 남은 폭을 채우는 것뿐이고, 모바일은
명시 높이로 결정하는 게 맞다.

**stash 대조를 먼저 시킨 게 이걸 잡았다.** 안 했으면 멀쩡한 새 코드를 의심하며 헤맸을 것이다.

### 전체화면과 시트를 가르는 기준

처음엔 전체화면 모달로 갔다. SpotFinder에 검증된 셸 패턴이 있어서 그대로 이식했고,
자동 스크롤 안보다 우수했다 — 모달은 오버레이라 페이지 스크롤이 불변이고 닫으면
지도가 보던 자리 그대로다.

그런데 글쓰기에서 써보니 어색했다. 리뷰를 쓰는 동안 지도가 사라져서 "방금 찍은 게
어디였지"를 확인할 수 없었다.

**SpotFinder에서는 같은 전체화면이 어색하지 않은데 여기서는 왜 어색한가.**

답은 지도의 역할이었다.

- **SpotFinder에서 지도는 내비게이션이다.** 마커를 눌렀다 = 탐색이 끝났다. 도구가
  목적을 이뤘으니 물러나도 된다.
- **SpotMap 글쓰기에서 지도는 캔버스다.** 좌표를 찍고 리뷰를 쓰는 게 지도 위에서 하는
  작업의 일부다. 작업 대상이 눈앞에서 사라지면 이상하다.

되돌아가는 비용도 다르다. SpotFinder는 닫으면 목록으로 돌아가 다른 걸 고르면 되지만,
SpotMap은 닫으면 쓰던 폼이(생성 세션이면 스팟까지) 사라진다.

그래서 SpotMap만 하단 70% 고정 시트(`h-[max(70svh, calc(420px+env(safe-area-inset-bottom)))]`)로
바꾸고 **SpotFinder는 통일하지 않기로 했다.**
"화면끼리 다르니 통일하자"는 생각이 들 때 먼저 **"역할이 같은가"**를 물어야 한다.

앞서 기각했던 드래그·스냅 3단계 시트와도 다르다. 이건 고정 높이라 조작할 게 없고
예측 가능하다.

### 판정을 두 곳에 두지 않기

전체화면 모달에 history를 붙이면서 문제가 생겼다. 뒤로 가기가 `SpotPopup`의
`handleClose`를 우회하는데, 거기에 **생성 세션이면 스팟을 삭제하는 판정(0365)**이 있었다.
우회하면 이름 없는 유령 스팟이 남는다.

`SpotMap`이 저장 여부를 따로 추적하는 방법도 있었지만, 그러면 같은 사실이 두 곳에
기록된다. 대신 **닫기 파이프라인을 단일화**했다.

`SpotPopup`에 `closeHandleRef`를 두고 자신의 `handleClose`를 대입한다. `popstate`는
그 핸들을 호출하고, `✕`·취소는 상태를 정리한 뒤 `history.back()`으로 엔트리를 소비한다.
사용자가 보는 결과는 "✕ = 뒤로 가기"와 같고, 배선만 역방향이다. 판정의 소유권은
`SpotPopup`에 그대로 남는다.

부수로 하나 더 잡혔다. 보기 팝업의 [삭제]는 `onClose`를 안 거치고 닫히므로 거기에도
엔트리 소비를 넣어야 했다. plan에 없던 항목이었다.

### 실화면 없이는 못 잡는 것

시트로 바꾼 뒤 지도를 위 영역에 정렬하고 마커를 가시 영역 중앙에 놓는 작업에서
두 가지가 나왔다.

- **시트가 `translateY(100%)`로 진입 중이라** `getBoundingClientRect().top`이 화면 밖
  값을 줬다. `transform`에 영향받지 않는 `offsetHeight`로 최종 위치를 역산해야 했다.
- **ref를 선언만 하고 JSX에 안 붙여** 첫 측정이 0이었다. 마커가 항상 같은 위치에
  오는 게 증거였다.

그리고 effect 키를 `activeSpot` 객체가 아니라 `id`·불리언으로 둔 게 중요했다. 객체 키면
편집 입력마다 새 객체가 생겨 **글자를 칠 때마다 재정렬·재morph가 돈다.**

### 자동화 통과가 검증 완료는 아니다

CDP(Chrome 390×844) 검증은 전부 통과했다. 마커 offset 0, covered 203.6px, 정렬·복원 정상.
그런데 **실기기에서는 증상이 여전했다.**

원인은 아직 확정 못 했다. iOS Safari의 `overflow:hidden`이 `scrollY`를 리셋하는지,
실기기 `svh` 값이 다른지, 애니메이션 타이밍인지 — 다음 세션의 시작점이다.

헤드리스가 재현하지 못하는 층이 있다. 특히 모바일 브라우저의 스크롤·뷰포트 단위·
합성 동작은 실기기로만 확인된다.

## 대표 코드

```tsx
// components/SpotMap.tsx  (현재 코드 — 0383에서 풀스크린 전환으로 재작성된 상태)
  // 0383 Effect B: 지도 풀스크린 전환을 확정(autoResize)하고 가림 높이만큼 padding.bottom을 줘
  // morph가 마커를 가시 상단 스트립 중앙에 놓게 + 그 morph를 소유(핸들러 동기 morph는 모바일 미실행).
  // 풀스크린이면 지도 bottom = 뷰포트 bottom, 시트 top = 뷰포트 − 시트높이 → covered = 시트 offsetHeight
  // (측정 단순화, 지도 rect·detail-up 애니메이션 위치 의존 제거). 키를 activeSpot?.id로 — 객체 키는
  // 편집 입력(handleSpotUpdate)마다 재morph. A→B 마커 전환은 id 변화로 재실행(패딩·morph 재적용).
  // cleanup에서 패딩 0 복원(닫힘·데스크톱·전체보기 정중앙).
  useEffect(() => {
    if (!(isMobile && activeSpot && mapInstance)) return;
    const mapEl = mapDivRef.current;
    const sheetEl = sheetRef.current;
    if (mapEl) {
      // ResizeObserver(relayout effect) 선점 — 풀스크린 크기를 lastSizeRef에 미리 기록하면
      // 뒤이은 관찰자 콜백이 크기 불변 가드로 no-op → 관찰자의 setCenter가 아래 morph를 가로채지 못함.
      // (0382는 지도 400 고정이라 관찰자 미발화 → 이 선점은 풀스크린 전환의 신규 필요분)
      const r = mapEl.getBoundingClientRect();
      lastSizeRef.current = { w: r.width, h: r.height };
      mapInstance.autoResize(); // 풀스크린 캔버스 즉시 반영(관찰자 순서와 무관하게 morph 전 확정)
    }
    if (sheetEl) mapInstance.setOptions('padding', { bottom: sheetEl.offsetHeight });
    focusSpot(activeSpot);
    return () => {
      // 0386: 닫힘 애니 진행 중이면 복원을 finishClose로 미룸 — 시트 내려가는 240ms 동안 지도가
      // padding 재앵커로 슬금 움직이는 것 차단(확인 1). A→B 전환·isMobile 해제·테마 재생성은 false라 즉시 복원.
      if (!closingActiveRef.current) mapInstance.setOptions('padding', { bottom: 0 });
    };
    // eslint-disable-next-line react-hooks/exhaustive-deps -- id로만 재실행(편집 입력 재morph 방지), focusSpot/activeSpot 좌표는 id당 고정
  }, [isMobile, activeSpot?.id, mapInstance]);
```

(0382 시점 기준. 0383 풀스크린 전환으로 스크롤 정렬(Effect A)이 제거되어 현재는 Effect B만 남아 있다.)

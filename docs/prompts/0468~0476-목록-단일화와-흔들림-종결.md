## 1. 한 줄 요약

진입점마다 따로 만들던 도구 목록을 하나로 합치고, 여섯 번 고쳐도 재발하던 "목록이 흔들린다"의 진짜 원인이 **앵커 자체의 이동**임을 찾아 종결했다.

---

## 2. 왜 / 목적 / 이유

### 왜 (동기·문제)

편1까지 오면서 도구 목록이 셋으로 갈라져 있었다. 슬래시 메뉴 7항목, 버블 `BubbleMore` 8항목, 툴바 `ToolbarMore` 10항목. 셋이 셸·행·헤더 클래스를 **각자 문자열로 복제**하고 있었고, 진입점마다 "여기선 이게 맞다"고 항목을 골라 나눠뒀다.

그리고 목록이 열릴 때마다 크기와 위치가 흔들렸다. 높이를 고정하면 폭이 변했고, 폭을 고정하면 위치가 움직였다.

### 목적 (목표 상태·사용자 가치)

**"어디서 열든 같은 목록, 열어도 화면이 흔들리지 않는 상태."**

진입점별로 항목을 나눌 필요가 없다는 것이 핵심 판단이다. 편1에서 만든 `can` 맵이 이미 상황에 안 맞는 항목을 회색 처리하니, **목록은 하나로 두고 상황이 걸러주면 된다.**

### 이유 (채택 근거·결정 기준)

**툴바 높이를 목록과 같게 고정한 것**이 이 트랙의 분기점이다. 툴바 ⋯를 누르면 그 자리가 목록으로 교체되는데 60px → 131px로 변해 화면이 흔들렸다. 진입점을 줄이는 안들을 놓고 고르던 중, **"흔들림의 원인은 높이가 변하는 것이니 처음부터 안 변하게 하면 된다"**는 다른 답이 나왔다. 툴바를 처음부터 131px로 두면 교체해도 변할 게 없다.

덤이 둘 따라왔다 — 아이콘 아래 라벨을 넣을 공간이 생겨 "아이콘만으로 뜻을 모르겠다"던 문제가 툴바에서도 풀렸고, 터치 타겟이 커져 0461에서 간격 4px로 타협했던 것도 완화됐다.

**`BubbleMenu` 컴포넌트는 버리지 않았다.** 선택 감지(`shouldShow`)·선택 rect 포지셔닝·선택 해제 시 닫힘·`mousedown preventHide`가 이미 해결된 층이라, 컨테이너로 재사용하고 내용만 교체했다. "버블 제거"는 마크 버튼 바 제거를 뜻한다.

```tsx
export const TOOL_SHELL =
  'w-[250px] rounded-[12px] border border-border bg-card shadow-[0_16px_40px_-12px_rgba(0,0,0,0.5)]';

// 체인 계열 항목 공통 실행기 — 슬래시 range 삭제를 같은 트랜잭션으로 묶는다
function chainRun(fn: (c: ChainedCommands) => ChainedCommands) {
  return (editor: Editor, range?: Range) => {
    let c = editor.chain().focus();
    if (range) c = c.deleteRange(range);
    fn(c).run();
  };
}

// 비체인 항목(링크 prompt·이미지 픽커·서식 뷰) — range 삭제만 선행하고 핸들러 호출
function actionRun(action: (editor: Editor) => void) {
  return (editor: Editor, range?: Range) => {
    if (range) editor.chain().focus().deleteRange(range).run();
    action(editor);
  };
}
```

### 0474 — 실행 후 닫기 + 되살아남 방지

```tsx
// app/(protected)/story/new/TiptapEditor.tsx
// 실행 직후의 선택 범위를 기억해두고, 선택이 그대로인 동안 shouldShow가 false를
// 주게 한다. hide 메타만으로는 부족한 이유: 실행 트랜잭션(docChanged)이 건 250ms
// 디바운스 타이머를 확장 hide()가 지우지 않아 타이머 발화 시 show()로 되살아난다.
// 선택이 바뀌면 비교가 어긋나 자동 해제 — 별도 이벤트 불요
const suppressSelRef = useRef<{ from: number; to: number } | null>(null);

shouldShow={({ editor: e, state }) => {
  const sup = suppressSelRef.current;
  if (sup && state.selection.from === sup.from && state.selection.to === sup.to) return false;
  suppressSelRef.current = null;
  return !state.selection.empty && !e.isActive('image');
}}
```

```tsx
// 문제를 "이동을 보여주지 않음"으로 해소. 항목별 선별 닫기는 예측 가능성 저하로 기각

  suppressSelRef.current = { from: editor.state.selection.from, to: editor.state.selection.to };
```

## 5. 결과 / 배운 점

### 결과

- 목록 정의가 한 곳(`ToolList.tsx`)으로 모이고 **`BubbleMore` 290줄 + `ToolbarMore` 248줄이 삭제**됐다 (0468 diff: +396 / −841)
- 툴바 131px 고정으로 ⋯ 교체 시 본문 밀림이 0px이 됐다
- 흔들림이 종결됐다 — 높이·폭·위치 세 축 모두

### 배운 점

**1. 같은 증상을 여섯 번 고쳐서 안 되면 진단이 틀린 것이다.**

높이 고정(0472) → 폭 원인 규명(0473분) → 안쪽 래퍼 → 1회 스냅숏… 계속 다른 데를 짚었다. 진짜 원인은 **앵커 자체가 움직이는 것**이었다. 버블은 선택 rect에 앵커돼 있는데, 제목으로 바꾸면 글자와 마진이 커져 rect가 약 20px 내려간다. **항목을 실행하는 행위가 앵커를 옮긴다.**

그러니 "떠 있는 목록을 안 흔들리게 한다"는 목표 자체가 모순이었다. 떠 있다는 건 뭔가를 따라간다는 뜻이고, 우리가 고른 그 뭔가는 우리가 누를 때마다 변했다.

해법은 **이동을 없애는 것이 아니라 보여주지 않는 것**(실행 후 닫기)이었다.

**2. 라이브러리 한계가 아니라 설계 의도를 벗어난 사용이었다.**

tiptap `BubbleMenu`의 `width: max-content`는 합리적 기본값이다. 버블 메뉴는 원래 **버튼 몇 개짜리 작은 툴바**를 담으라고 만든 것이고, 거기에 15항목 스크롤 목록을 넣은 쪽이 예상 밖이다. 긴 목록 자체는 흔하지만 그건 **슬래시(캐럿 앵커)의 것**이지 버블의 것이 아니다. 노션·미디엄·구글독스 모두 선택 툴바는 버튼 몇 개다.

**왜 벗어났나 — 인과 사슬:**

iOS Safari에서 키보드가 뜨면 페이지가 스크롤 레이어로 감싸여 `position: fixed`가 화면 밖으로 나간다 → **웹에서는 키보드 위 고정 툴바가 불가** → 노션이 고른 답(키보드 위 툴바 + 거기서 긴 목록)이 애초에 선택지가 아님 → 문서 상단 툴바는 글 하단을 쓸 때 안 보임 → 선택 위에 긴 목록을 띄우는 쪽으로 감 → 앵커 추적·라이브러리 가정 충돌.

**"노션처럼 안 만든 이유"가 취향이 아니라 플랫폼 제약에서 연역된 것**이다.

**3. 인라인 스타일과 싸우지 말고 한 겹 안으로 내린다.**

라이브러리가 매 갱신마다 인라인 `width`를 덮어쓰니 클래스로는 못 이긴다. `!important`로 되받아쳐도 갱신마다 재경쟁이다. 셸을 안쪽 래퍼로 내리면 바깥이 무엇을 하든 결과가 상수가 된다. 0475에서 `FormatMenuContent`를 안 건드리고 바깥에서 스크롤 컨테이너로 감싼 것도 같은 결이다 — **공용 컴포넌트 대신 소비자 층에서 감싼다.**

**4. React 배칭 순서가 "실행 안 됨"으로 보일 수 있다.**

⋯ 목록의 서식이 무동작이던 원인은 래퍼가 `run()` 뒤에 `setToolsView(null)`을 불러, 서식의 `setToolsView('format')`을 같은 이벤트 배칭에서 덮은 것이었다. 서식 코드는 멀쩡했고 **호출 순서만 뒤집혀** 있었다.

**5. 라이브러리의 `hide()`가 pending 타이머까지 지우진 않는다.**

실행 후 닫기를 넣었더니 250ms 뒤에 다시 떴다. 실행 트랜잭션이 건 디바운스 타이머를 확장의 `hide()`가 지우지 않아, 타이머가 `show()`로 되살린 것이다. 선택 좌표를 기억해 `shouldShow`에서 억제하는 방식으로 풀었고, 선택이 바뀌면 자동 해제돼 정리할 리스너가 없다.

**6. 0468에서 확정한 것 중 다섯 개가 이 트랙 안에서 번복됐다.**

## 결정 (Decisions)

- 목록은 **하나** — 진입점별 항목 분리 폐기, `can` 맵이 상황을 걸러줌
- 툴바 높이 131px **상시 고정** — 교체 시 흔들림 0, 대가는 평소 71px 추가 점유
- `BubbleMenu`는 컨테이너로 **존속** — 선택 감지·포지셔닝을 다시 만들 이유 없음
- 흔들림 해법은 **실행 후 닫기**(A안) — 앵커 스냅숏 고정(B안)은 스크롤 좌표 어긋남과 라이브러리 앵커 계약과 싸우는 방향이라 기각
- 항목별 선별 닫기 기각 — 어떤 건 닫히고 어떤 건 안 닫히면 예측 가능성이 떨어짐
- 파괴적 확인은 **동작 라벨** — 예/아니오는 긍정 어휘가 파괴적 동작을 가림

## 1. 한 줄 요약

MyStory를 "내 기록 아카이브"답게 다듬었다. 헤더 인격화(0133), 카드 스크롤 페이드(0134), 검색창 태그 순환(0135)까지 세 단계로 진행했고, 마지막에 검색을 스크롤 시 헤더로 통합하려다 `backdrop-filter` 두 겹이 CSS 사양상 불가능하다는 근본 제약을 확인하고 방향만 잡은 채 멈췄다.

---

## 2. 왜 / 목적 / 이유

### 0133 헤더·빈 상태 인격화

- **왜**: MyStory는 공용 목록(Story)과 달리 "내 공간"이다. 밋밋한 "내 기록"이라는 제목은 이 공간이 개인의 아카이브라는 성격을 전달하지 못한다.
- **목적**: 사용자가 이 화면을 "내 기록이 쌓인 곳"으로 인식하게 한다. 처음 온 사용자(빈 상태)에게는 다음 행동을 안내한다.
- **이유**: 프사(w-14) + "{닉네임}님의 소중한 기록들" + "N 게시물·M 좋아요" 카운트로 소속감을 준다. 빈 상태도 "데이터 없음"이 아니라 "아직 기록이 없어요 · 첫 기록 남기기(CTA)"로 인격화해 이탈 대신 행동을 유도한다.

### 0134 카드 스크롤 페이드

- **왜**: 카드가 처음부터 전부 보이면 정적이다. MyStory는 갤러리처럼 스크롤하며 훑는 공간인데, 정적인 그리드는 "기록이 쌓여있다"는 감각을 살리지 못한다.
- **목적**: 스크롤로 카드가 뷰포트에 들어올 때 하나씩 떠오르게 해, 아카이브를 넘겨보는 느낌을 준다.
- **이유**: 이전(0119~0120)에 "시스템상 같은 카드라도 PlanFinder(리스트)와 Story(갤러리)는 사용자 눈에 다르게 보이니 진입 방식도 달라야 한다"고 정했다. MyStory도 갤러리 계열이라 그 연장선에서 스크롤 진입 페이드를 택했다. 스크롤 감지(IntersectionObserver) + 페이드 로직은 재사용될 패턴이라 인라인 대신 `CardReveal`이라는 공용 wrapper로 분리했다. (이 CardReveal이 이후 MyPlan에서 재사용되며, 필터 재등장 상황에서 예상 못 한 버그를 일으키게 된다 — 0138 회고 참고.)

### 0135 검색창 태그 순환

- **왜**: placeholder가 "검색"뿐이면 무엇을 검색해야 할지 막막하다.
- **목적**: 검색 진입 장벽을 낮추면서, MyStory(내 공간) 성격에 맞게 개인화한다.
- **이유**: placeholder에 **내가 쓴 글의 태그**(#드라마, #영화…)를 4.5초마다 순환시킨다. "내 태그로 찾을 수 있다"는 힌트인 동시에 "내가 이런 걸 썼지"를 상기시킨다. 태그 소스가 "내 글"인 점이 MyStory의 개인 아카이브 성격과 일관된다.

## 5. 결과 · 배운점

### 결과
- MyStory가 "내 기록 아카이브"로 정돈됐다. 헤더 인격화 + 스크롤 페이드 + 태그 순환으로 개인 공간 성격이 살아났다.
- CardReveal·useInViewOnce라는 재사용 가능한 스크롤 진입 페이드 패턴을 확보했다.

### 배운점 — backdrop-filter 두 겹은 CSS 사양상 불가능

0135 이후 "스크롤 시 검색창을 헤더로 통합"하려다 막혔다. blur 헤더 안에 또 blur를 넣으면 두 번째가 작동하지 않는다. 이것은 구현 실수가 아니라 **CSS 근본 제약**이다.

- `backdrop-filter`는 "가장 가까운 backdrop root까지의 뒷 픽셀"만 흐리게 처리한다. 부모가 이미 필터/불투명도를 가지면 **그 부모 자체가 backdrop root(경계)가 되어**, 자식은 부모 뒤의 실제 배경에 도달하지 못한다. 그래서 blur를 두 겹 쌓으면 서로 간섭한다.
- 인스타·유튜브가 성공한 이유는 검색을 **하나뿐인 헤더 안에 통합**해 두 번째 blur 층을 애초에 만들지 않기 때문이다.
- 우리 헤더는 공용 layout에 있고 검색 데이터(태그)는 각 page에서 fetch된다. layout이 하위 page의 데이터를 구조적으로 모르므로, 검색을 헤더로 올리는 것은 **layout↔page 데이터 경계 문제**(Context Provider 신설 또는 클라이언트 재fetch)라 중형 작업이다.

→ 그래서 0135까지 마무리하고, 검색 헤더 통합은 "blur 한 겹 원칙 + layout 데이터 경계 해결"을 전제로 다음 세션 과제로 남겼다.

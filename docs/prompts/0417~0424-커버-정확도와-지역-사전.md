## 1. 한 줄 요약

카드에 뜨는 사진이 그 플랜과 무관하다는 문제를 소스 교체·지역 제한으로 좁혀가고, 그 과정에서 네 곳에 흩어져 있던 시·도 판정 로직을 사전 하나로 합쳤다.

---

## 2. 왜 / 목적 / 이유

### 왜 (동기·문제)

커버 자동 부여(0405·0410)까지 끝내고 실화면을 보니 사진이 코스와 맞지 않았다. **쌍문동 카드에 실내 푸드코트, 이태원 카드에 주얼리 매장이 떠 있었다.**

원인은 명확했다. 지역 풀을 `searchKeyword2("서울")`로 만들었는데, 그 API는 **서울 전체에서 아무 관광 POI나 준다.** 제주 쪽이 괜찮아 보였던 건 후보가 10개뿐이라 유명한 것만 남은 우연이었다.

그리고 문제가 하나가 아니었다.

- 지역 풀이 서울·제주도 2종뿐이라 그 외 지역 플랜은 **회색 카드**가 된다
- 사진 품질 자체가 낮다 — POI 첫 등록 사진이라 매장 내부·화장실이 섞인다
- 시·도를 판정하는 로직이 **네 곳에 흩어져** 각자 다른 표기 목록을 들고 있다

### 목적 (도달하려는 상태)

- 어떤 지역의 플랜이든 커버가 붙는다
- 그 사진이 관광 홍보에 쓸 만한 품질이다
- 카드의 지역 칩과 사진의 지역이 어긋나지 않는다
- 시·도 표기가 바뀌면 고칠 자리가 한 곳이다

### 이유 (채택 근거)

**촬영지 사진을 우선하기로 한 이유** — 우리에게 이미 `Spot.coverUrl` 45장이 있고, 그건 관광공사 무작위 POI가 아니라 **실제 촬영지 사진**이다. K-콘텐츠 촬영지 서비스라는 정체성과도 맞고 API 호출도 없다.

**촬영지가 있는 지역은 관광공사 보충을 막은 이유(0417)** — 서울이 촬영지 9장 + 관광공사 1장이 되면, 그 1장이 다시 무관한 POI일 수 있다. 10장 중 1장이라 **10% 확률로 원래 문제가 재발한다.** 9장으로 두면 전부 촬영지라 일관된다. 10장은 겹침을 줄이려는 목표치지 채워야 할 정원이 아니다.

**갤러리로 소스를 바꾼 이유(0419)** — 두 API를 실호출로 비교했다.

| API | 성격 | 결과 |
|---|---|---|
| `searchKeyword2` | POI 첫 등록 사진 | 매장 내부·화장실 혼입, 장소 다양성은 있음 |
| `gallerySearchList1` | 홍보 큐레이션 | 품질이 훨씬 낫고 위치 필드도 옴. 단 `arrange=A`는 같은 POI 사진이 무더기 |

갤러리가 품질에서 명백히 나았고, 쏠림은 정렬을 바꾸고 장소 단위로 중복을 제거하면 풀렸다. **그래서 "어느 API가 좋은가"가 아니라 "쏠림을 어떻게 없애는가"로 문제가 바뀌었다.**

**보충 판정선을 `>0`에서 `>=3`으로 완화한 이유(0419)** — `>0` 규칙은 관광공사 사진이 무관한 POI라서 만든 것이었는데, **갤러리로 바꾸면서 그 전제가 사라졌다.** 대구·충남·경남은 촬영지가 1장뿐이라 그 지역 플랜이 둘만 생겨도 같은 사진이 반복된다. 큐레이션된 대표 랜드마크라면 섞여도 어색하지 않다.

**지역 사전을 만든 이유(0424)** — 시·도 판정이 네 곳에 흩어져 있었고, 각자 다른 목록을 들고 있었다. 행정 개편이 나면 네 곳을 다 고쳐야 하고 **하나를 빠뜨리면 조용히 틀린다.** 실제로 이 구간에서 그 상황을 겪었다(아래 참조).

## 4. 작성·수정한 코드

### 0417 — 전 시·도 확장

`REGIONS`를 2개에서 17개로 늘리고, `Spot.address`에서 시·도를 판정할 접두 표를 만들었다.

```ts
// 경상북/남·전라북/남은 '경상'·'전라'로 뭉뚱그리면 남↔북이 섞이므로 접두를 길게 잡는다.
const SPOT_ADDR_PREFIX: Record<string, string[]> = {
  서울: ['서울'], 부산: ['부산'], /* … */ 경기: ['경기'], 강원: ['강원'],
  충북: ['충청북'], 충남: ['충청남'],
  전북: ['전라북', '전북'], 전남: ['전라남', '전남'],
  경북: ['경상북', '경북'], 경남: ['경상남', '경남'],
  제주도: ['제주'],
};
```

주석 한 줄이 이 표의 전부를 설명한다. `경상`으로 자르면 경북과 경남이 같은 키로 들어간다.

이 시점 보충 규칙은 **촬영지가 하나라도 있으면 보충 금지**였다.

```ts
const spotUrls = await spotCoversFor(region);
if (spotUrls.length > 0) {
  // Spot 커버가 있으면 그대로 사용(보충 없음) — 무관 POI 혼입 방지
  regions[region] = spotUrls;
  continue;
}
// Spot 0장 → 관광공사 searchKeyword2로 보충(게이트 적용)
```

`REGION_ALIAS`도 6줄에서 17 시·도 전체로 늘렸다. 축약·정식·신명칭을 전부 같은 키로 수렴시킨다(`강원`·`강원도`·`강원특별자치도` → `강원`). **주석에 제약을 명시했다** — 시(市) 단위는 17 시·도가 아니라 미매핑이고, `경주` 같은 입력은 `null`이 되어 작품 후보로만 폴백한다.

### 0418 — 더미 시드

실제 데이터를 절대 건드릴 수 없게 만드는 게 이 스크립트의 요건이었다. 접두사 하나로 생성·조회·삭제를 전부 묶었다.

```ts
const PREFIX = '[DUMMY] ';
// 제목이 `${PREFIX}${region} ${movie} 코스`라 실제 플랜은 접두사 불일치로 미접촉
```

삭제는 **조건을 이중으로** 걸었다.

```ts
await prisma.$transaction([
  planCost.deleteMany, planSpot.deleteMany, planFlight.deleteMany, planLike.deleteMany,
  myPlan.deleteMany({ where: { id: { in: ids }, title: { startsWith: PREFIX } } }), // 접두사 재확인
]);
```

`id in ids`만으로 충분한데 `title startsWith PREFIX`를 한 번 더 건다. id 수집 단계에서 실수가 있어도 접두사가 막는다.

커버는 하드코딩하지 않고 **실제 로직을 그대로 통과시켰다.**

```ts
// 직전까지 커밋된 플랜 기준 최소사용 커버 선택(순차 생성이라 회피 동작이 실제로 작동)
const coverUrl = await pickPlanCover(movie, region);
```

플랜 하나가 트랜잭션 하나이고 30번을 **순차로** 돈다. 병렬로 만들면 각 플랜이 같은 시점 스냅샷을 보게 되어 최소 사용 회피가 작동하지 않는다. 이 스크립트의 목적이 그 알고리즘 검증이므로 순차가 요건이다.

### 0419 — 갤러리로 교체

호출 API와 응답 필드가 통째로 바뀌었다(`firstimage` → `galTitle`/`galWebImageUrl`/`galPhotographyLocation`). 핵심은 쏠림을 없앤 방식이다.

```ts
for (let page = 1; page <= MAX_PAGES && accepted.length < need; page++) {
  const items = [...await gallery(keyword, page, 'B'), ...await gallery(keyword, page, 'C')];
  // …
  if (usedTitles.has(title)) { dup++; continue; }   // 같은 장소 1장만
}
```

**B(조회순)와 C(수정일순)를 합집합으로 쓰고, `galTitle` 기준으로 장소당 1장만 채택한다.** 정렬 하나만 쓰면 그 정렬의 상위가 같은 장소로 몰리는데, 두 정렬은 상위가 다르므로 합치면 장소 수가 늘어난다.

지역 판정은 `startsWith`를 버렸다.

```ts
function locProvKeys(loc?: string): Set<string> {
  for (const [n, k] of PROV_FULL)  if (t.includes(n)) s.add(k);
  if (s.size) return s;                                    // 정식명이 있으면 그것만
  for (const [n, k] of PROV_SHORT) if (t.includes(n)) s.add(k);  // 없으면 약칭 집합
}
```

두 경우를 동시에 처리한다.

- **`경기도 광주시`** — 정식명 `경기도`가 있으므로 `{경기}`만. `startsWith`였다면 광주로 오분류됐다
- **`전남광주통합특별시`** — 정식명이 없는 합성명이라 약칭 집합 `{전남, 광주}`를 반환하고, **최종 소속은 검색 키워드가 결정한다**

두 번째가 이 커밋에서 가장 시간을 쓴 지점이다(아래 별도 서술).

보충 판정선도 완화했다.

```diff
- if (spotUrls.length > 0) { /* 보충 없음 */ }
+ if (spotUrls.length >= SPOT_MIN) { /* 보충 없음 */ }
+ // 미만이면 Spot을 앞에 두고 need = 10 - spotUrls.length 만큼 갤러리로 채움
```

### 0420 — 커밋 없는 수정

풀에 화장실 사진이 남아 있어 갤러리 전환이 덜 먹은 줄 알았는데, **그 사진은 지역 풀이 아니라 `Spot.coverUrl`이었다.** 수원 화성의 커버가 몇 주 전 백필 때 저장된 화장실 사진이었고, 경기는 촬영지가 10장이라 갤러리 보충이 0장이어서 이번 교체가 닿지 않은 지역이었다.

갤러리에서 "가을의 화성"으로 교체했다. DB 값 변경이라 코드 커밋이 없고, 결과는 `region-covers.json` 재생성으로 0419에 반영됐다. **`Spot.coverUrl`은 SpotFinder와 스토리 상세에도 쓰이므로 그 화면들도 함께 고쳐졌다.**

### 0421 — 인과를 뒤집다

기존 더미 시드는 지역과 작품을 **각각 독립적으로** 뽑았다. 그래서 `제주도 이태원 클라쓰 코스` 같은 실재하지 않는 조합이 생겼고, 커버 선택이 작품을 우선하니 제주 플랜에 경기 사진이 붙었다.

순서를 뒤집어 **작품이 지역을 결정하게** 했다.

```ts
const provsOf = new Map<string, string[]>();   // 작품 → 촬영지 시·도(dedup)
for (const m of movies) {
  const set = new Set<string>();
  for (const sm of m.spotMovies) {
    const first = sm.spot.address?.trim().split(/\s+/)[0];
    const prov = first ? ADDR_PROV[first] : undefined;
    if (prov) set.add(prov);
  }
  if (set.size) provsOf.set(m.title, [...set]);
}
```

```ts
// 무촬영지 작품은 소수 슬롯만: 지역 랜덤(경주 포함 → 커버 null 일부 유지)
const noSpotSlot = i % NO_SPOT_EVERY === 0 && withoutProv.length > 0;
```

**`경주`를 남긴 건 의도다.** 17 시·도가 아니라 풀이 없고 커버가 `null`이 되므로, 무채 폴백 화면을 확인할 표본이 된다.

### 0422 — 2커밋을 산 파일

`SPOT_ADDR_PREFIX`를 공용 모듈로 뽑고 판정 함수를 붙였다.

```ts
// Spot.address가 풀 키의 시·도 접두로 시작하는지 판정.
export function addressMatchesRegionKey(
  address: string | null | undefined,
  regionKey: string,
): boolean {
  const a = address?.trim();
  if (!a) return false;
  return (SPOT_ADDR_PREFIX[regionKey] ?? []).some((p) => a.startsWith(p));
}
```

시그니처가 **"주소 + 키 → boolean"**이다. 키를 이미 알고 있고 맞는지 확인만 한다. 이 방향이 0424에서 뒤집힌다.

### 0423 — 지역을 벗어나는 사진 금지

작품 후보 수집에 지역 필터를 넣었다.

```ts
// 0423: 작품 후보를 플랜 region의 시·도 촬영지로 제한 — 지역 칩과 커버 사진의 지역 어긋남 방지.
// region이 풀 키로 해석되지 않으면(예: "경주") 작품 후보도 0.
const regionKey = normalizeRegionKey(region);
if (movie && movie.trim() && regionKey) {          // ① regionKey 없으면 작품 후보 스킵
  const links = await prisma.spotMovie.findMany({
    where: { movieId: { in: ids } },
    select: { spot: { select: { coverUrl: true, address: true } } },  // ② address 추가
  });
  for (const l of links) {
    const u = l.spot.coverUrl;
    if (!u || seen.has(u)) continue;
    if (!addressMatchesRegionKey(l.spot.address, regionKey)) continue;  // ③ 지역 불일치 제외
    seen.add(u); movieCovers.push(u);
  }
}
```

이 변경으로 **"작품 촬영지 전체" 단계가 사라졌다.** 이전에는 충남 플랜이 오징어 게임 촬영지 전부(서울 포함)를 후보로 삼았는데, 이제는 충남 소재만 본다. 지역 일치가 작품 우선보다 앞선다.

### 0424 — 사전 하나로

네 곳에 흩어진 매핑을 한 파일로 모았다. 사전의 한 항목이 그 지역의 **모든 표기**를 들고 있다.

```ts
export type Province = {
  key: string;            // 풀 키
  formal: string;         // 현행 정식명(신명칭)
  oldFormals: string[];   // 구 정식명 — 데이터·입력에 신·구가 공존하므로 유지
  short: string;          // 약칭
  extraAliases: string[]; // 자유 입력 전용 기타 별칭
  addrPrefixes: string[]; // 주소 startsWith 접두. 키 간 상호 배타
};

{ key: '제주도', formal: '제주특별자치도', oldFormals: ['제주도'], short: '제주',
  extraAliases: ['제주시'], addrPrefixes: ['제주'] },
```

그 위에 **용도별 조회 함수 3종**을 올렸다. 입력 형태가 다르므로 판정 방식도 다르다.

| 함수 | 입력 | 반환 | 판정 |
|---|---|---|---|
| `regionKeyFromFreeText` | 자유 입력 `강원도 강릉` | `string \| null` | 첫 토큰 exact 매치 |
| `regionKeyFromAddress` | 주소 `전라남도 순천시…` | `string \| null` | `addrPrefixes` startsWith |
| `regionKeysFromLabel` | 라벨 `전남광주통합특별시` | `string[]` | 정식명 includes → 없으면 약칭 집합 |

**세 함수 모두 "값 → 키" 방향이다.** 0422의 `addressMatchesRegionKey`가 "키를 주고 확인"이었던 것과 반대다. 그래서 소비처가 이렇게 바뀌었다.

```diff
- if (!addressMatchesRegionKey(l.spot.address, regionKey)) continue;
+ if (regionKeyFromAddress(l.spot.address) !== regionKey) continue;
```

**`lib/plan/spot-addr-prefix.ts`는 0422에 생겨 0424에 삭제됐다. 2커밋 수명이다.** 소비처 두 곳이 모두 사전으로 옮겨가면서 남는 참조가 없어졌다.

네 곳이 각각 이렇게 줄었다.

```diff
# region-cover.ts — REGION_ALIAS 22줄 삭제
- const firstToken = region.trim().split(/\s+/)[0];
- const key = REGION_ALIAS[firstToken];
+ const key = regionKeyFromFreeText(region);

# seed-dummy-plans.ts — ADDR_PROV 20종 삭제
- const first = sm.spot.address?.trim().split(/\s+/)[0];
- const prov = first ? ADDR_PROV[first] : undefined;
+ const prov = regionKeyFromAddress(sm.spot.address);

# seed-region-covers.ts — PROV_FULL·PROV_SHORT·locProvKeys 26줄 삭제
+ const keys = regionKeysFromLabel(it.galPhotographyLocation);
```

`seed-dummy-plans` 쪽은 **판정이 조금 넓어졌다.** 첫 토큰 exact 매치에서 접두 startsWith로 바뀌면서 `강원 원주시` 같은 약칭 주소도 잡힌다. 순수 이동이라고 했는데 여기만 결과가 달라질 수 있어 완료 보고에 명시하게 했다. 원래 잡았어야 할 걸 놓치고 있던 것이라 개선이지 회귀는 아니다.

테스트는 **"이 사전이 왜 필요했는가" 순으로** 짰다.

| 함수 | 케이스 |
|---|---|
| `FromFreeText` | 표기 수렴(`강원`/`강원도 강릉`/`강원특별자치도 춘천시` → `강원`) · 남북 미혼동 · 시 단위(`경주`)는 `null` |
| `FromAddress` | 신·구 주소 수렴 · 남북 미혼동 6건 · 해외(`일본 도쿄`)는 `null` |
| `FromLabel` | 통합 명칭이 두 키(`전남광주통합특별시` → `['광주','전남']`) · 정식명 우선(`경기도 광주시` → `['경기']`) |

세 함수 모두 빈 문자열·공백·`null`·`undefined`를 같은 세트로 반복 검증한다.

검수에서 **옛 방식과 새 방식을 같은 데이터에 돌려 대조**했다. `Spot` 63행 주소, `MyPlan` 전체 `region`, 구 별칭 토큰 59건 — 불일치 0.

## 5. 결과 / 배운 것

### 결과

- 지역 풀이 2종 → 17 시·도, 합계 165장(촬영지 34 · 갤러리 87 + 재생성분)
- 매장 내부·화장실 사진이 사라지고 큐레이션된 대표 랜드마크로 바뀜
- 카드의 지역 칩과 사진의 지역이 일치 — 더미 30개 재생성에서 **불일치 0/30**
- 시·도 판정이 사전 한 곳으로 모이고 테스트 41개가 붙음
- 더미 시드로 커버 알고리즘이 실제로 분산되는 걸 확인 — 29개 플랜이 26개 URL에 흩어지고 **최대 중복 2회, 3회 이상 0**

### 배운 것

**외부 API가 우리보다 최신일 수 있다.** 갤러리 응답의 위치 라벨에 `전남광주통합특별시`가 찍혀 나왔고, 처음엔 데이터 오류로 봤다. 검색해보니 **2026년 7월 1일 광주광역시와 전라남도가 실제로 통합**됐고, TourAPI가 그걸 정확히 반영한 것이었다. 우리 코드가 옛 체제였다. 강원·전북 특별자치도 개편은 이미 반영해뒀는데 이번 것만 빠져 있었다.

그 결과 **위치 필드를 검증에 쓸 수 없게 됐다.** 두 지역 사진의 라벨이 같아져 구분이 안 되기 때문이다. 단일 시·도를 채택하는 규칙이면 한쪽이 반드시 0장이 되고, 실제로 중간 실행에서 전남 0을 실측했다. 그래서 **집합을 반환하고 검색 키워드로 확정하는** 방식으로 우회했다. 검증을 포기하고 키워드를 믿는 선택이고, 그 대가(광주 풀에 전남 사진이 섞일 이론적 여지)까지 함께 기록했다. 두 풀의 URL 교집합이 0인 것으로 실질 위험은 없음을 확인했다.

**"API 중 뭐가 좋은가"가 아니라 "결함을 어떻게 없애는가"였다.** 갤러리는 품질이 좋지만 정렬 때문에 한 장소로 쏠렸고, `searchKeyword2`는 다양하지만 품질이 낮았다. 어느 쪽도 그대로는 쓸 수 없었는데, 쏠림은 정렬 합집합과 장소 단위 dedup으로 풀 수 있고 품질은 코드로 못 고친다. **고칠 수 있는 결함을 가진 쪽을 고르는 게 판단이었다.**

**규칙의 전제가 사라지면 규칙도 바뀌어야 한다.** `Spot이 1장이라도 있으면 보충 금지`는 관광공사 사진이 무관한 POI라서 만든 규칙이었다. 갤러리로 바꾸는 순간 그 전제가 없어졌는데, 규칙만 남아 있으면 촬영지 1장짜리 지역이 같은 사진을 반복하게 된다. **규칙을 만들 때의 이유를 기록해두면 언제 폐기해야 하는지도 알 수 있다.**

**중간 산물이 2커밋만 살 수도 있다.** `spot-addr-prefix.ts`는 0422에 만들어져 0424에 삭제됐다. 낭비처럼 보이지만 그 사이에 0423(지역 필터)이 그 함수를 쓰면서 목적을 달성했고, 통합 시점에는 소비처가 명확해져 있어 옮기기 쉬웠다. **한 번에 최종 형태로 가지 않아도 된다** — 다만 그 중간 산물이 오래 남으면 그때는 부채가 된다.

**순수 이동일수록 대조가 필요하다.** 0424는 값을 옮기기만 했는데, 표를 합치다 접두 하나가 빠지거나 순서가 달라지면 조용히 틀린다. 옛 방식 사본과 새 함수를 같은 데이터에 돌려 불일치 0을 확인하고 나서야 안전하다고 말할 수 있었다.

### 남긴 것

- 매핑을 사전으로 합쳤지만 `backfill-*.ts` 5개의 자체 `PROV` 튜플과 `seed-region-covers.ts`의 `FORMAL_NAME`은 손대지 않았다. 전자는 일회성 스크립트라 다시 돌 일이 없고 후자는 판정이 아니라 검색 키워드 생성용이다

# 0065 회고: 카테고리 색상 + 상세 비용 모듈화

- 날짜: 2026.06.03
- 소요: 약 1시간
- 관련 커밋: `feat: 0065 카테고리 색상 + 상세 비용 요약`

## 1. 한 줄 요약
카테고리의 색·라벨·통화 기호·금액 포맷을 `_lib/cost.ts` 한 곳으로 모으고, 편집기 막대에 색을 입히고, 상세 화면에도 읽기 전용 비용 요약을 붙였다.

## 2. 왜 / 목적 / 이유 — `cost.ts` 공유 모듈로 분리
- **왜(동기/문제):** 색·라벨·포맷이 편집기와 상세에 각자 흩어지면, 고칠 때 두 군데를 손봐야 하고, 한쪽만 고치면 같은 카테고리가 화면마다 다르게 보이는 어긋남(drift)이 생긴다. 같은 데이터를 화면마다 다르게 보여주는 버그다.
- **목적(도달 상태/사용자 가치):** 어느 화면에서든 카테고리가 늘 같은 색·라벨·포맷으로 보이는 일관된 경험.
- **이유(의사결정):**
  - 카테고리의 표시 규칙은 "화면의 속성"이 아니라 "카테고리 개념 자체의 성질"이다. 그래서 `_lib/cost.ts` 한 곳(단일 진실 공급원, single source of truth)에 모아 편집기·상세가 가져다 쓰게 했다. 일관된 UI는 그 결과다.
  - 추가로, 편집기가 클라이언트 컴포넌트라 `cost.ts`에 Prisma 타입(`@prisma/client`)을 들이지 않고 문자열 union으로 뒀다. 서버/DB 전용 코드가 클라이언트로 딸려 들어가지 않게 하는 모듈 경계 결정.

## 3. 작성한 프롬프트
(실제 보낸 프롬프트로 교체·보강)
```
[배경] 색·라벨·포맷이 편집기/상세에 흩어져 어긋날 위험.
[목표] 카테고리 표시 규칙을 _lib/cost.ts 한 곳에 모으고, 상세에도 읽기 전용 비용 요약 추가.
[하지 말 것] ❌ cost.ts에서 @prisma/client import ❌ 화면별 색/라벨 중복 정의
[참조 패턴] 편집기·상세 모두 cost.ts를 단일 출처로 참조
[검수 모드] 막대 합 = 총비용 / 편집기·상세 색·라벨 동일
plan 요청.
```

export type CostCategory = 'TRANSPORT' | 'STAY' | 'FOOD' | 'TICKET' | 'ETC';

export const CATEGORY_COLOR: Record<CostCategory, string> = { TRANSPORT: '파랑', STAY: '주황', FOOD: '빨강', TICKET: '초록', ETC: '회색' };
export const CURRENCY_SYMBOL: Record<Currency, string> = { KRW: '₩', USD: '$', JPY: '¥' };
export function formatAmount(n: number, c: Currency) { return CURRENCY_SYMBOL[c] + n.toLocaleString(); }

## 5. 결과 / 배운점
- **결과:** 교통/숙박/식비/입장료/기타 색상이 편집기·상세 양쪽에서 동일하게 표시. 상세 화면에 읽기 전용 비용 요약 추가.
- **배운점:**
  - 같은 개념의 표시 규칙은 화면이 아니라 **개념 쪽에 단일 출처**로 둔다 — 어긋남 방지.
  - 공유 표시 상수는 **DB 타입과 분리**해 클라이언트 안전성을 확보한다(모듈 경계).
  - 일관된 UI는 목표가 아니라 단일 진실 공급원의 **결과**다.

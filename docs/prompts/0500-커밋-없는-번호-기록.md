# 0500 — git log에 커밋이 없는 번호

**기록일**: 2026-08-12
**성격**: 결번 아님. **작업은 있었으나 코드 변경이 없어 커밋이 생기지 않은 번호.**

---

## 무엇을 한 번호인가

0493(플랜을 Spot에 연결) 검증 과정에서 만든 **잔여 테스트 데이터 정리**.

- 제목이 "테스트"인 플랜 삭제 (0493 3·4단계 종단 검증용으로 만든 것)
- 그 플랜이 참조하던 user 생성 Spot 중 참조가 0이 된 고아 2건 삭제
  (`김포공항역 공항철도`, `김포공항역 9호선`)

## 왜 커밋이 없는가

작업 대상이 **원격 DB의 행뿐이었고 코드·스키마·마이그레이션 변경이 하나도 없었다.**
일회성 삭제 스크립트를 썼으나 실행 후 폐기했고 스테이징하지 않았다.

따라서 `git log`에는 0499(`f9e97a3`) 다음이 0501(`fc6ef99`)로 이어지고 0500이 비어 있다.

## 왜 번호를 소비했는가

한 작업 = 한 번호 원칙을 따랐다. 커밋이 없다고 번호를 건너뛰면
"0500이 왜 없지"를 나중에 다시 조사하게 되고, 회고 번호와 커밋 번호의 대조도 어긋난다.
번호는 부여하되 **커밋 부재 사실을 이 문서로 남긴다.**

## 삭제 대상이 무엇이었는지 (실측)

| 대상 | 판정 근거 |
|---|---|
| 플랜 "테스트" | 0493 검증용으로 생성, 항목 1건(김포공항역), 실사용 데이터 아님 |
| Spot `김포공항역 공항철도` | 위 플랜 삭제 시 `planSpots` 참조 0이 되는 고아 |
| Spot `김포공항역 9호선` | 앞선 검증 플랜이 이미 삭제돼 참조 0인 상태로 잔존하던 고아 |

- 시드 Spot은 삭제 대상에서 제외(`source=user`만 대상)
- 시연용 플랜 "미생 촬영지 서울 코스"와 그 연결 Spot은 무영향

## 남긴 관찰

플랜을 지워도 Spot은 `onDelete: SetNull`이라 남는다(0493 2단계 결정).
그래서 **검증용 플랜을 지울 때마다 고아 Spot이 쌓인다.** 이번엔 손으로 치웠지만,
검증 데이터를 자주 만들면 정리 절차가 필요해질 수 있다.

## 회고 편성상 위치

트랙 2(0493·0494·0496·0500 — 플랜을 Spot에 연결)에 흡수돼 있다.
별도 회고 편은 만들지 않는다.

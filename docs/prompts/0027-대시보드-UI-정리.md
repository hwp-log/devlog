# 0027 회고: 대시보드 UI 정리

**작성일**: 2026-05-16
**소요 시간**: 약 2시간
**관련 커밋**: feat - 0027 대시보드 UI 정리 (위젯 + 본문 + 헤더 사용자 정보 + 로그아웃 버튼 + 호버효과)

---

## 한 줄 요약

기존 대시보드는 위젯만 배치되어 있고, 헤더에는 사용자 정보나 로그아웃 버튼이 없었음.
또한 작성한 기록들이 모두 같은 카드 모양이라 글의 카테고리(TIL/DeepDive/TechStudy)를 구분하기 어려웠으며, 클릭 가능한 요소들이 시각적으로 구분되지 않았음.

이를 해결하기 위해 (protected) layout에 공용 헤더를 적용하고, 카드에 유형 배지를 추가하고, 클릭 가능한 요소에 호버 효과를 적용.

---

## 이번 작업의 3가지 핵심 요소

### 1. 헤더/네비게이션 패턴 정착

**목적**

대시보드 외 페이지에서는 헤더가 없거나 임시로 작성되어 있었음.
따라서 이 점을 보충하기 위해,
로그인한 사용자가 어느 페이지에 있어도 자기 정보와 로그아웃 버튼이 보이게 레이아웃을 적용함.

**고민 — 어떻게 풀까?**

[케이스 A] 각 페이지마다 헤더 컴포넌트 넣기
1. 페이지별로 헤더 JSX를 그대로 적용.
2. 페이지 7개 = 헤더 코드 7번 작성됨.
3. 헤더를 수정할 때마다 7곳 모두 수정 필요.
4. 변경 비용이 큼.

[케이스 B] (protected) layout에 헤더 적용
1. app/(protected)/layout.tsx에 헤더 컴포넌트를 넣음.
2. 하위 페이지는 자동으로 헤더가 적용됨.
3. 헤더 수정 시 한 곳만 수정.
4. Next.js App Router의 layout 패턴 그대로.

[결론]
[케이스 B] 채택. 라우트 그룹 layout이 이미 적용된 상태라 추가 작업도 적음.
헤더 = (protected) 안에서만 보이게. 비로그인 페이지(메인/로그인/회원가입)는 헤더 X.

**방법**

- (protected)/layout.tsx에 헤더 컴포넌트 적용
- 헤더 안: 사용자 이메일 표시 + 로그아웃 버튼
- 사용자 이메일: Server Component에서 `supabase.auth.getUser()`로 직접 조회
- 로그아웃 버튼: Client Component로 분리 (onClick 필요)
- 비로그인 페이지: 헤더 X / 자체 레이아웃

**기술 적용**

- `app/(protected)/layout.tsx` — Server Component, getUser() 호출
- `app/(protected)/LogoutButton.tsx` — Client Component, 'use client' + signOut() 호출
- 헤더 UI: 상단 고정, slate-50 배경, 하단 테두리 slate-200
- 메인/로그인/회원가입 페이지: (protected) 밖이라 헤더 자동 제외

> **라우트 그룹**
> Next.js App Router의 (괄호) 폴더.
> URL 경로에는 반영 X, 레이아웃만 그룹화.
> (protected)/dashboard → /dashboard

> **Server Component / Client Component 분리**
> 서버에서 사용자 조회는 Server Component.
> onClick 같은 인터랙션은 Client Component.
> 한 레이아웃에서 두 가지를 조합.

**배운점**: 
"수정 비용이 비싸지는 시점"이 공용 컴포넌트를 사용할 시점이라는 것을 배움.
지금 적용하면 = 수정비용 1번, 나중에 적용하면 = 늘어난 페이지 수만큼 수정해야 함.

### 2. 카드 유형 배지로 시각 구분

**목적**

대시보드에 작성한 기록들이 모두 같은 모양의 카드로 표시되어 있어,
TIL/DeepDive/TechStudy 유형을 한눈에 구분하기 어려웠음.
카드를 클릭하지 않고도 어떤 유형의 기록인지 바로 알 수 있게 좌측상단에 배지로 표시.

**고민 — 어떻게 풀까?**

[케이스 A] 글자색만 다르게 적용
1. 유형별로 제목 글자색을 다르게 적용.
2. 카드 자체는 그대로 유지.
3. 시각 신호가 약함. 색약 사용자는 구분 어려움.
4. "이게 유형 구분이라는 의도"가 명확하지 않음.

[케이스 B] 카드 배경색 자체를 유형별로 변경
1. TIL = 파란 배경, DeepDive = 초록 배경, TechStudy = 빨간 배경 적용.
2. 한눈에 구분 가능.
3. 그러나 시각 노이즈가 큼. 카드가 너무 화려해짐.
4. 카드의 본질(기록 내용 표시)이 색에 묻힘.

[케이스 C] 배지(작은 라벨)로 표시
1. 카드 안에 작은 배지 추가. 유형 텍스트 + 유형별 색.
2. 한눈에 구분 가능 + 카드 본질 유지.
3. 색 + 텍스트 = 색약 사용자도 구분 가능.
4. 일반적인 패턴 (GitHub Issues, Linear, Notion 등이 사용).

[결론]
[케이스 C] 채택. 배지 = 명확한 시각 신호 + 카드 본질 유지.
유형별 색은 의미와 매칭: TIL(blue, 기본 학습) / DeepDive(emerald, 깊이) / TechStudy(rose, 기술).

**방법**

- 카드 왼쪽 상단에 작은 배지 적용 (self-start)
- 유형 텍스트 + 유형별 배경색 + 유형별 글자색
- 색 매칭: TIL=blue / DeepDive=emerald / TechStudy=rose
- 알 수 없는 유형이 들어오면 = TIL 색으로 fallback
- 배지 스타일: rounded-md + text-xs + font-medium + px-2 py-0.5

**기술 적용**

- `badgeStyle` 객체로 유형 → CSS 클래스 매핑
- `?? 연산자`로 fallback 처리 (badgeStyle[entry.type] ?? badgeStyle['TIL'])
- TypeScript 타입: `type: 'TIL' | 'DeepDive' | 'TechStudy'`
- 배지 위치: 카드 안 `self-start`로 왼쪽 정렬

> **?? 연산자 (Nullish Coalescing)**
> 왼쪽 값이 null 또는 undefined일 때만 오른쪽 값 사용.
> `||` 연산자와 달리 falsy 값(0, '', false)은 통과.
> badgeStyle에 없는 유형이면 TIL로 fallback.

> **Record<string, string>**
> TypeScript의 객체 타입.
> 키와 값이 모두 string인 객체.
> badgeStyle 객체의 타입으로 사용.

**배운점**: 시각으로 구분할 때 "신호의 강도"와 "본질 유지" 사이의 균형이 중요함.
배경색 전체 변경 = 너무 강한 신호 → 카드 본질이 묻힘.
글자색만 변경 = 너무 약한 신호 → 의도 전달 X.
배지 = 적절한 강도의 신호 + 본질 유지 가능.
"신호의 본질은 그 신호가 무엇을 전달하는가"이지 "신호의 크기"가 아님.

### 3. 호버 효과 적용(카드/버튼)

**목적**

페이지에 있는 카드나 버튼이 클릭 가능한지 사용자가 알기 어려웠음.
"클릭 가능한 요소"라는 신호를 시각으로 전달하고자 함.

**고민 — 어떻게 풀까?**

[케이스 A] 호버 효과 일괄 추가
1. 모든 요소에 hover:bg-slate-100 같은 효과 적용.
2. 사용자가 어디든 호버하면 반응.
3. 그러나 호버 효과가 적용된 곳이 너무 많으면 = "이게 클릭 가능한 건가?" 혼란.
4. 시각 노이즈가 커짐.

[케이스 B] 클릭 가능한 요소에만 선택적으로 호버 효과
1. 실제로 클릭 가능한 요소만 호버 효과 적용.
2. 카드(Link로 감싼 것), 버튼, 토글 등에 한정.
3. 단순 정보 표시 요소는 호버 효과 X.
4. 사용자가 "호버하면 = 클릭 가능"으로 자연스럽게 학습.

[결론]
[케이스 B] 채택. 호버 효과는 "신호"이지 "장식"이 아님.
신호를 너무 많이 넣으면, 신호로서 기능 X -> 사용자 혼동 유발.

**방법**

- TIL 카드: hover:shadow-md + hover:-translate-y-1 + transition-all
- 버튼: hover:bg-slate-700 (주요), hover:bg-slate-300 (보조)
- 로그아웃 버튼: hover:bg-slate-200 + hover:text-slate-900
- 정보 표시 요소(이메일, 날짜, 본문): 호버 효과 X
- transition duration-500 ease-out으로 부드러운 전환

**기술 적용**

- Tailwind hover: 변형 사용
- transition-all로 모든 속성 부드러운 전환
- duration-500 (500ms) + ease-out 적용
- 카드: shadow + translate-y 조합 (살짝 떠오르는 느낌)

> **transition-all + duration-500**
> 모든 속성에 transition 적용 + 500ms 지속.
> 카드처럼 여러 속성이 동시에 변할 때 사용.
> 부드럽고 자연스러운 전환.

> **-translate-y-1**
> Y축으로 -4px 이동 (위로 4px).
> 호버 시 카드가 살짝 떠오르는 효과.
> shadow와 함께 사용하면 입체감이 적용됨.

**배운점**: 호버 효과는 사용자에게 보내는 신호.
신호의 본질은 "다른 것과 구분되는 것"임. 모든 요소에 적용하면, 혼란유발.
"이 요소는 클릭 가능한가"의 답이 호버 효과를 적용할 기준.

## 코드 변화 (실제 결과물)

### 1. (protected) layout에 헤더 추가 (변경)

```typescript
// app/(protected)/layout.tsx
import Link from 'next/link';
import { createClient } from '@/lib/supabase/server';
import { LogoutButton } from '@/app/(protected)/dashboard/LogoutButton';
import { signOutAction } from '@/app/(protected)/dashboard/actions';

export default async function ProtectedLayout({ children }: { children: React.ReactNode }) {
  const supabase = await createClient();
  const { data: { user } } = await supabase.auth.getUser();
  const initial = user?.email?.charAt(0).toUpperCase() ?? '?';

  return (
    <div className="min-h-screen bg-slate-50">
      <header className="sticky top-0 z-10 bg-white border-b border-slate-200">
        <div className="max-w-5xl mx-auto px-6 h-14 flex items-center justify-between">
          <Link href="/dashboard" className="text-lg font-bold text-slate-800">DevLog</Link>
          <nav className="flex items-center gap-4">
            <Link href="/dashboard" className="text-sm text-slate-600 hover:text-slate-900 transition-colors">대시보드</Link>
            <Link href="/til" className="text-sm text-slate-600 hover:text-slate-900 transition-colors">TIL</Link>
            <div className="flex items-center gap-2">
              <div className="w-7 h-7 rounded-full bg-slate-200 text-slate-700 flex items-center justify-center text-xs font-medium">
                {initial}
              </div>
              <span className="text-sm text-slate-600">{user?.email}</span>
            </div>
            <LogoutButton action={signOutAction} />
          </nav>
        </div>
      </header>
      <main>{children}</main>
    </div>
  );
}
```

### 3. 대시보드 본문 통합 + 카드 유형 배지 (대규모 변경)

```typescript
// app/(protected)/dashboard/page.tsx
import { getTilEntries } from '@/lib/til/actions';
import StreakWidget from './StreakWidget';
import Link from 'next/link';

type TilEntry = {
  id: string;
  title: string;
  content: string;
  created_at: string;
  type: 'TIL' | 'DeepDive' | 'TechStudy';
};

// 유형별 배지 스타일 매핑
const badgeStyle: Record<string, string> = {
  TIL:       'bg-blue-100 text-blue-700',
  DeepDive:  'bg-emerald-100 text-emerald-700',
  TechStudy: 'bg-rose-100 text-rose-700',
};

export default async function DashboardPage() {
  const entriesResult = await getTilEntries();
  const entries: TilEntry[] = 'error' in entriesResult
    ? []
    : (entriesResult.data.entries as TilEntry[]).slice(0, 6);

  return (
    <div className="flex flex-col gap-8">
      <div className="max-w-xs">
        <StreakWidget />
      </div>

      <section>
        <div className="flex justify-between items-center mb-4">
          <h2 className="text-xl font-semibold text-slate-700">기록</h2>
          <Link
            href="/til/new"
            className="text-sm bg-slate-800 text-white rounded-lg px-4 py-2 hover:bg-slate-700 transition-colors"
          >
            TIL 작성
          </Link>
        </div>

        {entries.length === 0 ? (
          <p className="text-slate-500 text-sm py-8 text-center">아직 작성한 기록이 없습니다</p>
        ) : (
          <ul className="grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-4">
            {entries.map((entry) => (
              <li key={entry.id}>
                <Link
                  href={`/til/${entry.id}`}
                  className="bg-white rounded-xl shadow-sm p-5 flex flex-col gap-2 hover:shadow-md hover:-translate-y-1 transition-all duration-500 ease-out block h-full"
                >
                  {/* 유형 배지 */}
                  <span className={`self-start text-xs font-medium rounded-md px-2 py-0.5 ${badgeStyle[entry.type] ?? badgeStyle['TIL']}`}>
                    {entry.type}
                  </span>
                  <h3 className="font-semibold text-slate-800 line-clamp-1">{entry.title}</h3>
                  <p className="text-sm text-slate-600 line-clamp-3 flex-1">{entry.content}</p>
                  <time className="text-xs text-slate-400">
                    {new Date(entry.created_at).toLocaleDateString('ko-KR')}
                  </time>
                </Link>
              </li>
            ))}
          </ul>
        )}
      </section>
    </div>
  );
}
```

## 1. 한 줄 요약

Tiptap을 유지한 채 다크 대응 → 버블 메뉴 → 슬래시 메뉴 → 드래그 핸들 순으로 노션식 편집 경험을 넣었다. 네 커밋 모두에서 **의존성을 어떻게 다룰 것인가**가 핵심 판단이었고, 세 번 다 다른 결론(설치 0건 / 정확 버전 핀 설치 / 공식 기각 후 커뮤니티 대체)이 나왔다.

---

## 2. 왜 / 목적 / 이유

- **왜**: 본문 에디터가 툴바 버튼만 있는 기본 형태였다. 다크모드에서는 색이 하드코딩돼 있어 대응도 안 됐다. 여행 기록은 사진·제목·인용이 섞이는 글인데, 매번 상단 툴바로 마우스를 올리는 조작은 흐름을 끊는다.
- **목적**: 글을 쓰는 동안 손이 본문을 떠나지 않는 편집 경험. 선택하면 서식이 따라오고, `/`로 블록을 부르고, 블록을 잡아 옮길 수 있는 것.
- **이유**: 앞서 Plate 이관을 검토했다가 기각했다. shadcn 신규 도입 + Slate 데이터 마이그레이션 비용이 크고, 저장 형식이 HTML 문자열인데 썸네일 추출이 **첫 `<img>` 파싱에 의존**하고 있어 JSON 전환이 불가능했다. **Tiptap을 유지한 채 노션화하면 이관 없이 같은 목표에 도달한다**는 게 이 트랙의 전제다.
- 사양은 **하이브리드**로 확정했다 — 상단 툴바를 없애고 `/`만 남기는 순수 노션 방식 대신, 툴바를 유지하고 버블·슬래시를 더했다. 근거는 **사용자 연령대가 넓어 발견성이 중요**하다는 것. 슬래시 블록도 4개(제목/목록/인용/이미지)로 절제했다 — 여행 기록에 코드블록·표는 과하다.

## 3. 판단 여정

### 0323 — 다크 분기를 어떻게 할 것인가

`.tiptap-content`에 색 3개가 하드코딩돼 있었다(본문 #1A1A1A, 링크 #2563eb, placeholder #94a3b8). 프로젝트에는 다크 분기 선례가 두 가지 있었다.

- `[data-theme="dark"]` 원시 선택자 — `color-mix` 합성값처럼 토큰 하나로 안 끝나는 경우에 사용
- Tailwind `dark:` 변형 — 유틸 클래스 층 전용

그런데 **제3안이 가능했다.** 토큰 CSS 변수는 `buildThemeCss()`가 `:root`와 `[data-theme="dark"]` 두 스코프로 발행하므로, `color: var(--fg)` 하나만 쓰면 다크에서 값이 자동으로 반전된다. **분기 코드 0줄.**

이 판단이 뒤에 배당을 줬다. 이후 버블·슬래시·드래그 핸들 UI가 전부 "색은 토큰 `var()` 또는 토큰 유틸만, 분기 없음"이라는 같은 패턴을 따랐고, 다크 대응을 매번 다시 설계하지 않았다.

같은 커밋에서 상세 페이지 본문의 `text-slate-800`을 제거했다. 이 클래스가 캐스케이드에서 `.tiptap-content`의 색을 덮고 있어서, 토큰화해도 무력화되는 구조였기 때문. 제거하니 **편집과 상세의 색 소스가 하나로 합쳐지면서** 0319에서 남겨뒀던 마지막 불일치 항목도 닫혔다.

### 0324 — "신규 설치 필요"가 틀렸다

버블 메뉴는 Tiptap v3에서 API가 크게 바뀐 지점이다. 사전에 확인해 CC에 전달한 내용:

- import 경로가 `@tiptap/react` → `@tiptap/react/menus`
- `tippyOptions` → `options={{ offset, placement }}`
- `@floating-ui/dom`이 새 필수 의존성, tippy.js는 불필요

**그런데 뒤의 두 줄 중 "신규 설치 필요"가 틀렸다.** CC가 로컬 `node_modules`의 `package.json`·d.ts를 직접 읽어 정정했다:

- `@floating-ui/dom`은 이미 `extension-bubble-menu`의 의존성으로 설치돼 있음
- `@tiptap/react`도 이미 직접 의존성
- **우리 코드가 직접 import하지 않으므로**(옵션 값만 전달) package.json 명시 불요

→ **설치 0건.** 문서의 설치 안내는 "이 기능을 쓰려면 이 패키지가 트리에 있어야 한다"는 뜻이지 "당신이 직접 선언해야 한다"는 뜻이 아니었다.

구현 자체는 작았다. 기존 `ToolbarButton`을 그대로 재사용했는데, 그 컴포넌트에 이미 `onMouseDown` preventDefault가 있어서 **버튼을 눌러도 에디터 선택이 풀리지 않는** 문제가 자동으로 해결됐다. 0323에서 토큰화해둔 덕에 스타일도 새로 만들 게 없었다.

### 0325 — 마운트 지점이 테마 스코프를 벗어난다

슬래시 메뉴는 이번 트랙에서 가장 큰 작업이었다. 두 가지 함정이 있었다.

**함정 1 — ERESOLVE.** `@tiptap/suggestion@^3.23.6`으로 설치하니 캐럿이 최신 3.28.0으로 풀리는데, **Tiptap v3는 peer를 정확 버전으로 고정**한다(suggestion@3.28.0이 core@3.28.0을 요구, 설치본 core는 3.23.6). `--legacy-peer-deps`로 우회하지 않고 정확 버전 핀으로 재설치해 해결. 다만 **락파일 없이 재해석하면 같은 에러가 재발하는 구조**이고, 업그레이드하려면 @tiptap 패키지 7종을 동시에 올려야 한다는 점을 기록으로 남겼다.

**함정 2 — 팝업을 `document.body`에 붙이면 안 된다.** 이건 착수 전에 짚어 확인을 요청했고, 결과가 반쪽만 맞았다.

| | 우려 | 실제 |
|---|---|---|
| 토큰(다크) | body 직속은 스코프 밖이라 반전 안 될 것 | **틀림** — `data-theme`가 `<html>`에 걸리므로 body 어디든 상속됨 |
| 폰트 | body의 Arial로 렌더될 것 | **맞음** — Pretendard는 ThemeScope의 inline style로만 적용되고 `body`는 `font-family: Arial` |

폰트가 끊기므로 마운트 지점을 `editor.view.dom.parentElement`(EditorContent 래퍼)로 정했다. ThemeScope 내부라 폰트·토큰 둘 다 상속되고, 에디터 컨테이너에 `overflow: hidden`이 없어 클리핑도 없다. 좌표계는 `strategy: 'fixed'`로 통일했는데, fixed의 유일한 함정인 "transform 조상이 containing block이 되는 경우"를 조상 체인에서 없음을 확인하고 채택했다.

**수명주기 검수 — `destroy()`만으로는 부족하다.** `ReactRenderer.destroy()`는 React 트리만 언마운트하고, 우리가 `append()`로 붙인 DOM 노드는 부모에 그대로 남는다. `/`를 칠 때마다 빈 div가 쌓이는 누수가 된다. 그리고 Esc로 닫으면 `onKeyDown`에서 destroy한 뒤 `onExit`도 불리므로 이중 실행 가드가 필요하다.

구현을 확인해보니 두 가지가 다 처리돼 있었고, 이중 가드는 별도 플래그 없이 `component = null` + 옵셔널 체이닝으로 해결돼 있었다. 플래그를 추가하는 것보다 깔끔한 처리다.

### 0326 — 협업 CRDT를 짊어질 것인가

드래그 핸들은 v2에서 Pro(유료) 확장이었다가 v3에서 MIT로 풀렸다. 그런데 조사 결과 **공식 패키지가 `isChangeOrigin`을 무조건 import**해서, 설치하면 협업 체인 4종(`collaboration`·`y-tiptap`·`yjs`·`y-protocols`)이 딸려온다.

- yjs는 실시간 공동편집용 CRDT다. 우리는 협업 기능이 **없다.**
- 번들에 수십 KB가 붙는 것보다 더 걸리는 건 **업그레이드 지뢰**다. 0325에서 확인했듯 v3는 peer를 정확 고정하므로, 동시에 올려야 할 패키지가 7종에서 11종으로 늘어난다.
- 게다가 드래그 핸들은 노션 네 기능 중 **가치가 가장 낮다.** 버블·슬래시가 "노션스러움"의 대부분을 만들었고, 여행 기록은 몇 문단이라 블록 순서를 드래그로 바꿀 일이 드물다.

대안으로 커뮤니티 패키지(`tiptap-extension-global-drag-handle@0.1.18`, MIT)를 조사했다. import가 core·pm뿐이라 협업 의존 0, peer 선언 없어 ERESOLVE 0, 배선 1줄. 다만 **0.x 버전에 배포 공백 17개월**이라 v3 호환이 불확실했다.

여기서 **"peer 충돌 0"이 동작 보증이 아니라는 점**을 짚었다. 0.x는 peerDependencies를 느슨하게 선언하거나 아예 선언하지 않는 경우가 많아, 충돌이 없는 게 당연할 수 있다. 그래서 **중단 조건을 명시**하고 진행했다.

> 설치+배선 후 dev에서 핸들 미표시·드래그 미동작·콘솔 에러 중 하나라도 발생하면 **디버깅하지 말고 즉시 되돌리고 보류로 전환.** v3 호환은 peer 선언이 아니라 실동작으로만 판정.

그리고 placeholder 문구 교체를 **드래그 핸들 성패와 무관하게** 같은 사이클에 포함시켰다. 드래그 핸들이 엎어져도 커밋이 빈손으로 끝나지 않게 하려는 안전장치였다.

결과적으로 동작했다.

### 0325 — 슬래시 메뉴 수명주기

```tsx
render: () => {
  let component: ReactRenderer<SlashMenuHandle, SlashMenuProps> | null = null;

  const destroy = () => {
    (component?.element as HTMLElement | undefined)?.remove(); // DOM 먼저 제거
    component?.destroy();                                      // 그다음 React 언마운트
    component = null;                                          // 이후 호출은 옵셔널 체이닝으로 no-op
  };

  return {
    onStart: (props) => {
      component = new ReactRenderer(SlashMenu, { props: {...}, editor: props.editor });
      const el = component.element as HTMLElement;
      el.style.position = 'fixed';
      // body 직속은 Pretendard 상속이 끊김 — EditorContent 래퍼에 마운트
      props.editor.view.dom.parentElement?.append(el);
      updatePosition(props.clientRect);
    },
    onUpdate: (props) => { component?.updateProps({...}); updatePosition(props.clientRect); },
    onKeyDown: (props) => {
      if (props.event.key === 'Escape') { destroy(); return true; }
      return component?.ref?.onKeyDown(props) ?? false;
    },
    onExit: destroy,
  };
},
```

오발동 방지는 이중 가드로 넣었다 — `startOfLine: true`(줄 첫 글자만)와 `allow`의 문단 가드. `2026/07/23` 같은 문장 중간 `/`에는 뜨지 않는다.

### 0326 — 드래그 핸들

```css
/* 패키지가 뷰포트 좌표를 style.left/top에 직접 대입하므로 fixed 필수 (absolute 금지) */
.drag-handle {
  position: fixed;
  width: 20px;   /* dragHandleWidth 기본값 20과 동기 — TiptapEditor sm:pl-[38px]의 파생원 */
  height: 24px;  /* 패키지 수직 센터링 상수와 파생 관계 */
  color: var(--muted);
  cursor: grab;
}
.drag-handle::before { content: '⠿'; }
.drag-handle:hover   { color: var(--fg2); background: var(--popover); }
.drag-handle.hide    { opacity: 0; pointer-events: none; }
```

`.hide`에 `pointer-events: none`을 같이 넣은 이유는, opacity만 주면 보이지 않는데 클릭은 먹는 유령 요소가 남기 때문이다.

placeholder도 교체했다: `'다녀온 그 장소의 이야기를 남겨주세요...'` → `'그곳에서 어떤 장면을 만났나요?...'`

## 5. 결과 / 배운점

### 결과

- 에디터 전체가 다크 대응. 분기 코드 0줄.
- 텍스트 선택 시 서식 바(B/I/H1/H2/링크), `/` 입력 시 블록 팝업(제목/목록/인용/이미지), 블록 hover 시 드래그 핸들.
- 편집과 게시 결과의 색·타이포가 완전히 일치.
- 의존성 순증: `@tiptap/suggestion`, `@floating-ui/dom`(직접 명시), `tiptap-extension-global-drag-handle` 3개. **협업 체인 0개.**
- 인수인계서 백로그 "본문 노션화" 종료.

### 배운점

- **의존성 판단에는 단일 규칙이 없다.** 세 커밋에서 세 결론이 나왔는데, 각각 다른 축을 봤기 때문이다 — 0324는 "우리가 직접 import하는가", 0325는 "peer를 어떻게 고정하는가", 0326은 "번들에 무엇이 딸려오는가". "설치하라니까 설치"가 아니라 매번 실제 트리를 읽어야 한다.
- **문서보다 로컬 `node_modules`가 사실에 가깝다.** 내가 문서를 근거로 전달한 "신규 설치 필요"가 두 항목 다 틀렸고, d.ts와 package.json 실측이 정정했다. 특히 메이저 버전이 바뀐 라이브러리는 문서와 설치본이 어긋나기 쉽다.
- **"peer 충돌 없음"은 호환 보증이 아니다.** 선언하지 않으면 충돌도 없다. 0.x·장기 미배포 패키지는 실동작으로만 판정해야 하고, 그래서 중단 조건을 미리 정하는 게 의미가 있다.
- **되돌리기 비용이 싸면 시도하는 게 낫다.** 커뮤니티 패키지는 단일 설치에 배선 1줄이라 실패해도 손실이 거의 없었다. 대신 성공하면 협업 체인을 통째로 피한다. 이럴 때는 "확실해질 때까지 조사"보다 "중단 조건 걸고 시도"가 빠르다.
- **한 커밋에 회수 가능한 조각을 섞어둔다.** placeholder 교체를 드래그 핸들과 같은 사이클에 두되 성패를 분리해서, 실패해도 커밋이 빈손이 되지 않게 했다.
- **첫 커밋에서 세운 패턴이 이후 세 커밋의 설계 비용을 줄였다.** 0323의 "색은 토큰 `var()`, 분기 없음"이 기준이 되어 버블·슬래시·드래그 핸들 모두 다크 대응을 따로 설계하지 않았다.
- **라이브러리가 만들어준 것과 우리가 붙인 것은 정리 책임이 다르다.** `ReactRenderer.destroy()`는 React만 정리한다. 우리가 `append()`한 DOM은 우리가 `remove()`해야 한다.

## 결정 (Decisions)

- **Tiptap 유지 + 노션화** — Plate 이관은 shadcn 신규 도입 + Slate 마이그레이션 비용으로 기각. 저장 형식 HTML도 유지(썸네일 추출이 첫 `<img>` 파싱 의존).
- **하이브리드 방식** — 상단 툴바 유지 + 버블·슬래시 추가. 사용자 연령대가 넓어 발견성 우선.
- **슬래시 블록 4개로 절제** — 제목/목록/인용/이미지. 코드블록·표는 여행 기록에 과함.
- **다크 분기는 토큰 `var()` 직결(제3안)** — 기존 선례 2종은 각각 합성값·유틸 클래스 용도라 이 케이스에 과함.
- **버블 메뉴 의존성 명시 안 함** — 직접 import하지 않으므로 과잉.
- **`@tiptap/suggestion`은 캐럿 아닌 정확 버전 핀** — v3 peer 고정 구조. `--legacy-peer-deps` 우회는 미채택.
- **슬래시 팝업 마운트는 에디터 래퍼** — `document.body`는 Pretendard 상속이 끊김.
- **공식 드래그 핸들 기각** — 협업 CRDT 체인 강제 설치. 커뮤니티 단일 패키지로 대체하되 중단 조건 명시.
- **드래그 핸들 gutter는 `sm:` 한정** — 모바일은 hover가 없어 핸들이 뜨지 않으므로 여백 불요.
- **상세 페이지의 나머지 하드코딩(제목 색 등)은 범위 밖** — 상세 전체 리스타일로 별도 처리.

## 1. 한 줄 요약

데스크탑 목록 행과 지도 마커를 잇는 다리로 호버 강조를 넣되(0270), 강조+pan·강조+pan+선택 동기까지 **실제로 만들어 실사용 비교한 뒤 전부 폐기**하고 "강조만"을 확정했으며, 강조 수단은 앰버 색 차용을 실화면 비교로 기각하고 같은 회색의 **명도 상승**으로 정리했다(0272).

---

## 2. 왜 / 목적 / 이유

> 근거: `docs/0228-0273-회고-재료-인수인계.md` 묶음 6.

- **왜**: 데스크탑 목록 행과 지도 마커 사이에 다리가 없었다 — "이 행이 지도의 어디인가"를 클릭하지 않고는 알 수 없었다.
- **출발점**: 사용자가 바이크 중고 사이트(REITWAGEN)를 레퍼런스로 제시했다.

### 결정 여정 (이 묶음에서 가장 긴 왕복)

1. **레퍼런스 판독을 두 번 틀렸다.** Claude가 레퍼런스를 "강조만"으로 두 번 오독했고, 사용자가 연속 스크린샷으로 "호버 시 강조 + 스무스 pan + 선택까지"임을 실측으로 확인시켰다. **실측이 판독을 이긴 사례.**
2. **0270 — 강조만 구현.** `data-spot-id`/`data-pill` 훅 + `setMarkerHover`(DOM 직접 `classList` 토글 + `setZIndex` 5↔1, **React 렌더 0회**). 0261의 `scrollTop` 직접 설정과 같은 계열 판단.
3. **B′(강조 + 200ms 디바운스 pan) 구현 → 선택 동기까지 확장.** 선택 동기 버전에서는 `hoverSelectRef` 1회성 플래그로 0261 정렬을 제외했다 — 경계에 걸친 행의 게이트 구멍까지 발견해 막았다.
4. **실사용 "의외로 괜찮은데?"** — 그러나 "어지러울 사람이 있다", "클릭도 나쁘지 않다"로 결론. **전부 checkout 폐기, 강조만 확정.**
5. **0272 — 강조 수단 확정.** 앰버 색 차용안을 실화면 비교 후 기각했다(선택 파랑과 인지 경쟁). 같은 회색의 **명도 반응**을 채택.

### 근거 체계 (면접 답변 완성형)

- **Material Design States 공식**: selection과 hover가 동시에 발생할 때 **둘 다 표시하되 우선순위를 차등**한다 — 공존은 표준이다.
- **에어비앤비 실동작**: 호버 = 가격 pill 강조만, 지도 무이동(사용자가 직접 스크린샷으로 확인).
- **Figma 가이드**: 호버는 subtle, 극적인 색 교체는 jarring.
- **자기 실험**: pan·선택 동기 버전을 실제로 만들어 비교한 뒤 기각했다 — "표준을 그냥 따른 게 아니라 대안을 만들어 비교했다".
- **화면 밖 스팟은 클릭의 영역**으로 정리했다 — 호버 = 위치 힌트, 클릭 = 결정.
- **위계 원칙**: 호버 = 경량(강조), 클릭 = 커밋(선택 + 줌 morph). 일시 상태는 무채 명도, 지속 상태에만 색.

### 2. 폐기된 B′ / 선택 동기 (커밋 없음)

`git log`에 해당 커밋이 없다 — checkout으로 폐기됐으므로 **인용할 diff가 존재하지 않는다.** 기록으로 남은 사실만:

| 안 | 내용 | 결과 |
|---|---|---|
| A | 강조만 | **채택** (0270) |
| B′ | 강조 + 200ms 디바운스 pan | 구현 후 폐기 |
| B″ | B′ + 선택 동기 (`hoverSelectRef` 1회성 플래그로 0261 정렬 제외) | 구현 후 폐기 |

폐기 사유: 의도 없는 화면 변화(pan)는 어지러움을 유발하고, 화면 밖 스팟 접근은 호버가 아니라 클릭의 영역이라는 정리(백로그 B절).

### 3. 0271 — 목록 선택 표시를 회색 틴트로

```tsx
// components/SpotFinderMapNaver.tsx (0271) — 데탑·모바일 행 양쪽 동일 변경
- ? 'border-primary bg-primary/[0.08]'
+ ? 'border-transparent bg-white/[0.16]'
```

`border-transparent`로 남긴 이유는 레이아웃 시프트 방지(테두리 자리 유지). 백로그 C절에 따르면 **스토리 카드 틴트 통일안은 선택 상태와 혼동돼 기각**됐다.

> 번호 관련 사실 하나: 0271 커밋(`8123eea`)이 추가한 주석 안에 이미 `0272:` 라벨이 붙은 설명
> (`틴트 파랑 0.11 → 흰색 저투명 0.08 … 0.06·0.08 비교 후 강도 2배(0.16)로 상향`)이 들어 있다 —
> 커밋 번호(0271)와 주석 번호(0272)가 어긋난다.

### 4. 0272 — 앰버 기각, 명도 반응 채택

```css
/* app/globals.css (0272) */
/* 0270: 데탑 목록 hover 마커 강조 — pill 확대 + 명도 상승(색상 무변). 앰버 색 차용은 실화면 비교 후 기각 —
   선택(파랑)과 인지 경쟁. 무채 명도 반응 채택(Material 상태 차등).
   배경·테두리·글자는 markerContent inline(0269)에 있어 클래스 선택자로 못 이김 — !important가 유일한 덮어쓰기 수단(구조 근거).
   배경 스톱은 평상(#33383d→surface2)의 각 스톱 한 톤 상향(#454b52→#33383d — 밝은 스톱이 평상 어두운 스톱과 연속).
   caveat: linear-gradient는 transition 비보간 — background는 즉시 전환, 체감 부드러움은 border-color·color·transform이 담당. */
[data-pill] { transition: transform 120ms ease-out, background 120ms ease-out, border-color 120ms ease-out, color 120ms ease-out; transform-origin: 50% 100%; }
.marker-hover [data-pill] {
  transform: scale(1.12);
  background: linear-gradient(to bottom, #454b52, #33383d) !important;
  border-color: rgba(255, 255, 255, 0.8) !important;
  color: #e5e7eb !important;
}
```

**"평상 pill의 각 스톱을 한 톤씩 올린다"**는 산출 방식이라, 호버 상태가 평상 상태의 파생으로 정의된다 — 새 색을 도입하지 않았다.

## 5. 결과 / 배운점

### 결과
- 호버는 **강조만**으로 확정. 지도는 호버로 움직이지 않는다.
- `setMarkerHover`·`data-spot-id`·`data-pill`·`.marker-hover` 전부 오늘까지 유지.
- 이 묶음의 결론이 0273에서 **CLAUDE.md §9 상태 표시의 위계**로 승격됐다 — "일시 상태(호버)는 무채·명도로 낮추고, 지속 상태(선택)에만 색을 배정한다".
- 근거 체계(Material·에어비앤비·Figma + 자기 실험)가 백로그 B절에 결정 기록으로 정리됐다.

### 배운점

- **순수 시각 상호작용은 React 상태를 경유하지 않는다** (DOM 직접 토글 — 0261 `scrollTop`과 같은 성능 판단 계열).
- **의도 없는 화면 변화(호버발 pan)는 접근성 리스크다** — 모션 민감·읽기 중 오발.
- **레퍼런스 판독은 스크린샷 비교 실측으로.** 두 번 틀린 뒤에 확립됐다.
- **표준을 따르되 대안을 만들어 비교한다.** pan·선택 동기를 실제로 만들어 써 보고 기각했다 — 그 과정이 결론의 근거가 된다.
- **상태가 겹치면 색이 아니라 강도를 나눈다.** 호버와 선택이 공존할 때 둘 다 표시하되, 일시 상태는 무채 명도로 낮춘다.

## 1. 한 줄 요약

"내가 찍은 장소가 어디인지 클릭하지 않고 알 수 있는가"를 기준으로, 블록 순서를 바꾸고 마커 탭 시 줌 방향을 뒤집고 마커에 장소명 라벨을 붙였다.

## 2. 왜 / 목적 / 이유

**왜(문제)** — 세 가지가 같은 뿌리에서 나왔다.

1. 좌표를 등록하면 지도에 파란 도트만 보여서, 그 장소를 정말 등록했는지 클릭해봐야 알 수 있었다.
2. `SPOTMAP` 블록이 페이지 하단 전체 수정 버튼 바로 위에 있어, 좌표 리뷰를 고치려 할 때 팝업 안의 수정이 아니라 페이지 전체 수정 버튼을 누르는 혼동이 실제로 발생했다.
3. 0383에서 지도가 풀스크린이 되면서, 마커를 탭할 때 `ZOOM_FOCUS`(16)로 확대하는 기존 동작이 너무 가깝게 느껴졌다.

**목적** — 지도만 봐도 무엇을 등록했는지 읽히고, 조작이 의도한 대상에 닿는 상태.

**이유** — 0387의 블록 순서는 "두 수정 버튼이 가까이 있어서 생긴 혼동"이므로 거리를 벌리는 것으로 해결된다. 0388의 줌 방향은 사용자가 보던 배율을 기준으로 한 단계 낮추는 쪽을 택했다 — `ZOOM_FOCUS` 상수를 낮추는 대안도 있었으나, 그건 항상 같은 배율로 안착시켜 "보던 화면"과의 연속성이 끊긴다. 0390의 라벨은 SpotFinder에 이미 있는 `markerContent`를 이식하는 것이 새로 설계하는 것보다 옳다고 봤다 — 같은 처방이 두 화면에 따로 존재하면 갈라진다.

## 4. 코드 작성 & 수정

### 0387 — 블록 순서 (`StoryWriteForm.tsx`, `story/[id]/page.tsx`)

순서를 `태그 → SPOTMAP → PLAN → 등록/수정 버튼`으로 바꿨다. 글쓰기와 글수정이 같은 컴포넌트(`edit` 페이지가 `story/new/`에서 import)라 대상은 2파일이다.

확인 과정에서 드러난 사실 셋:

| 항목 | 확인 결과 | 영향 |
|---|---|---|
| 블록 마진 | 이미 전부 자기-top (`pt-[46px]`/`mt-[46px]`) | 리듬 이전 불필요 |
| PLAN `<select>` | `name` 없음, 제출은 form 내부 hidden `plan_id` | form 밖으로 옮겨도 payload 불변 |
| 등록·수정 버튼 | form 밖에서 `form=` 속성 연결(0340) | 위치 유지 |

PLAN 블록을 form 밖으로 옮겨야 했는데, 제출값이 상태 파생 hidden input이라 payload는 그대로였다.

### 0388 — 줌 방향과 버튼 (`components/SpotMap.tsx`)

```ts
// 모바일: 사용자가 보던 배율에서 한 단계 축소, 하한 클램프
morph(coord, Math.max(currentZoom - 1, getMinZoom()));
// 데스크톱: 지도가 422px이라 조건이 달라 기존 확대 유지
morph(coord, Math.max(currentZoom, ZOOM_FOCUS));
```

전체보기 버튼은 제거가 아니라 **시트가 열려 있는 동안만 숨김**이다. 조건을 `!sheetOpen`으로 둔 것이 중요하다 — `sheetOpen`은 `closingSpot`을 포함하므로 닫힘 애니 240ms 동안에도 숨은 상태가 유지되어, 시트가 다 내려간 뒤에 버튼이 나타난다. `activeSpot`만으로 걸면 닫기 시작하는 순간 버튼이 커버 뒤에서 튀어나온다.

데스크톱은 `sheetOpen`이 never true라 자동으로 무변이다.

### 0390 — 라벨 마커 (`components/SpotMap.tsx`)

SpotFinder `markerContent`를 항목별로 갈라 판단했다.

| 항목 | 이식 | 근거 |
|---|---|---|
| 라벨 pill 상시 표시 | O | 목적 자체 |
| selected 강조 (`setIcon` effect) | O | rebuild 없이 전이 |
| 도트 좌표 앵커 | O | 클릭·펄스 위치 불변 |
| 클러스터링 | X | 스팟 최대 20개 |
| 선택 카드(썸네일 히어로)·ping | X | 시트가 상세를 담당 |
| 이름 끊기 | 보강 | SpotFinder는 `nowrap` 무보정 |

구조를 `[라벨 pill][도트]` 스택으로 바꾸면서 앵커를 다시 잡았다.

```
translate(-50%, calc(-100% + 9px)) + anchor(0,0)
→ 도트 중심이 좌표에 고정 (기존 중앙앵커와 동일 위치)
```

**빈 이름 경로** — 지도를 찍으면 `addSpot('')`로 이름 없이 먼저 `localSpots`에 편입되므로, 이름 입력 전까지 `name=''`이다. 이 경우 pill을 생략하고 도트만 표시한다.

**긴 이름** — 스팟명 상한이 50자인데 SpotFinder pill은 `white-space:nowrap` 무보정이라 그대로 이식하면 약 600px로 지도를 가린다. `max-width:140px` + ellipsis를 보강했다.

### 0390 — 겹침, 그리고 병합이 만든 새 문제

겹침 대책으로 "선택된 마커만 라벨"을 검토했으나 기각했다. 미선택 라벨을 숨기면 "클릭 없이 어느 장소인지 읽힌다"는 목적 자체가 소멸한다. 대신 50m 병합(`groupByProximity`) + max-width 끊기 + 선택 마커 zIndex 상향 + 탭 시 줌 변화로 이웃 분산을 택했다.

그런데 **병합 자체가 새 문제를 만들었다.** 병합 그룹은 대표 스팟 이름만 라벨에 나오고 개수 표시가 없어 단일 스팟과 시각적으로 구별되지 않는다. 50m 안에 서로 다른 장소가 둘 존재하는 것은 실제로 일어나므로(S3-a 실측: 14m 같은 장소 / 4m 다른 장소), 그 케이스에서 "등록 여부 확인"이라는 목적이 붕괴한다.

처방은 pill에 `+N` 접미(N = `orders.length - 1`)다. SpotFinder 클러스터 마커의 숫자 배지 어휘를 따르되, pill에 이미 이름이 있으므로 총개수가 아니라 **추가분** 의미로 조정했다("롯데월드몰 +1").

긴 이름에서 `+N`이 잘리지 않도록 레이아웃을 분리했다.

```
이름 span: min-width:0 + ellipsis   ← 줄어드는 쪽
+N span:   flex:none                 ← 항상 노출
```

### 테스트 mock 처리

목록 클릭 morph 테스트가 `setIcon is not a function`으로 깨졌다. 원인은 mock 불완전이었다 — 실제 `naver.maps.Marker`에는 `setIcon`/`setZIndex`가 있는데 테스트 mock에 없었다. expect를 완화하거나 skip하지 않고 mock에 no-op 두 개만 추가해 9/9 통과시켰다.

## 5. 결과 / 배운점

### 결과

- 마커 옆에 장소명이 표시되어 클릭 없이 등록 내용이 읽힌다. 실기기 확인 완료(롯데월드몰·아레나광장 정상 표시).
- 병합 그룹은 `+N`으로 구별된다.
- 마커 탭 시 한 단계 축소되며, 최소 줌 아래로는 내려가지 않는다.
- 블록 순서가 세 화면(글쓰기·글수정·상세)에서 통일됐다.

### 배운점

- **해결책이 만든 새 문제를 확인해야 한다.** 50m 병합은 겹침 대책으로 옳았지만, 병합 결과가 "대표 이름만 표시"라는 것을 확인하지 않았다면 이번 작업의 목적이 그 케이스에서 조용히 실패했을 것이다. 대책의 이면을 코드로 확인하는 단계가 필요하다.
- **선택-only 라벨처럼 "겹침을 줄이는" 안이 목적과 충돌할 수 있다.** 목적이 "클릭 없이 읽힌다"인데 미선택을 숨기면 그 목적이 사라진다. 대책을 고를 때 목적을 다시 읽어야 한다.
- **이미 있는 처방을 이식할 때는 항목별로 갈라 판단한다.** SpotFinder `markerContent`를 통째로 가져오면 클러스터링·썸네일 카드까지 따라온다. 두 화면의 조건 차이(스팟 수, 지도 크기, 상세를 무엇이 담당하는가)로 항목마다 이식 여부를 갈랐다.
- **테스트가 깨졌을 때 expect를 고치기 전에 왜 깨졌는지 본다.** `setIcon is not a function`은 코드 결함이 아니라 mock이 실제 API 표면을 반영하지 않은 것이었다. 여기서 expect를 완화했다면 검증하던 동작(morph 호출)까지 잃었다.
- **닫힘 애니가 있는 UI에서 조건은 "닫히는 중"까지 포함해야 한다.** `!activeSpot`이 아니라 `!sheetOpen`이어야 버튼이 애니 도중에 튀어나오지 않는다. 상태 파생값이 스냅샷을 포함하는지 확인하는 습관이 필요하다.

### 남은 것 / 후속

- `escapeHtml`이 SpotFinder·SpotMap 두 사본으로 존재한다 — 공용 추출 대상.

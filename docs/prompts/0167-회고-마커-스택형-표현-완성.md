# 0167 회고: 마커 스택형 표현 완성 — 점 발광·라벨·썸네일 + 클러스터러 재그리기 가드

- **작성일**: 2026-08-10 (소급 작성 — 작업일 2026-07-12 오후)
- **소요 시간**: 약 1.5시간 (시행착오 왕복 포함)
- **관련 커밋**: `f5ff397` 마커 스택형 표현 완성 - 점 발광·라벨·썸네일, 클러스터러 재그리기 가드

## 1. 한 줄 요약

마커를 2단계 표현(미선택 = 점+지명 라벨, 선택 = 점 발광 위로 라벨·썸네일 카드가 쌓이는 **스택형**)으로 완성하고, 더블 핑의 근본 원인이던 클러스터러의 idle 전체 재그리기에 구성 불변 가드를 넣어 애니메이션 재시작과 렌더 낭비를 함께 잡았다.

## 2. 왜 / 목적 / 이유

- **왜(문제)**: 다크 타일까지 완성돼도 마커가 14px 점이라 지도가 정보를 못 담았다 — 멘토 서비스(마커에 썸네일·가격 내장)와의 최대 격차. 시안의 마커는 "점 + 지명 / 선택 시 썸네일"의 2단계 언어.
- **목적**: 지도만 봐도 "어디에 뭐가 있는지" 읽히는 마커 — 시안의 발광 문법 그대로.
- **이유(구조 확정 — 이 작업의 핵심 판단)**: 처음엔 선택 시 점을 카드로 **교체**하는 구조로 갔고, 글로우가 카드에 가려지는 문제를 z-index·간격·radial로 세 차례 우회하다 전부 실패했다. 사용자가 시안의 실제 구조를 정정 — **스택형**: 점은 좌표에 항상 남아 발광하고, 그 위 공간에 라벨, 그 위에 썸네일 카드가 쌓인다. 점이 안 사라지니 글로우가 가려질 일 자체가 없고, anchor도 점 기준으로 단순해진다. 우회책 3종이 필요 없던 이유 = 애초에 시안이 그 구조여서.

## 5. 결과 / 배운 점

- **결과**: 토글 드리프트 0.0px(4단계 좌표 실측), animationstart 1회, 지도가 "파란 점 5개"에서 "발광하는 촬영지들"로 바뀜 — 사용자 평 "비단 지도만의 문제가 아니었네, 저거 넣으니 퀄이 확 산다."
- **최대 교훈 — 시안은 눈이 아니라 구조로 읽는다**: 정적 그림에서 "선택 마커 = 썸네일"로 보이는 것을 교체형으로 오독해 3차례 우회(z-index 샌드위치·간격 18px·광역 radial)를 전부 낭비했다. 사용자가 좌표 비유("점이 (1,1)이면 제목은 (1,2), 사진은 (1,3)")로 정정해준 뒤에야 스택임을 이해 — 우회책이 자꾸 필요하다는 것 자체가 구조를 잘못 읽었다는 신호였다.
- **증상 처치 vs 원인 제거**: animation-delay 0.55s는 panTo 케이스만 가렸고, 근본은 벤더의 idle 재부착이었다. 가드를 넣자 임시 처치를 걷어낼 수 있었고 성능까지 따라왔다 — "delay로 덮은 버그는 다른 경로로 다시 나온다."
- **터치 타겟 관례 유지**: 점 시각 14px과 히트 44px 분리(CLAUDE.md §5), 클러스터 원은 히트 분리가 불가해 44px 상향 — 판단값 표기.

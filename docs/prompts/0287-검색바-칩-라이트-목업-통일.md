---

## 1. 한 줄 요약

SpotFinder 좌측 검색 입력창·칩 바를 확정 목업대로 통일 — 라이트에서 3요소(입력창·비활성 칩·화살표)를 동일 연회색(card 토큰)·테두리 없음·평면으로, 칩 바 컨테이너는 무박스로, 입력창 포커스는 파란 선 대신 primary 글로우(0.18, 220ms)로. 다크·모바일 시트는 현행 보존.

---

## 2. 왜 / 목적 / 이유

- **왜**: 검색바·칩이 평평한 회색이라 완성도가 떨어졌다. 유백색 유리 질감을 시도했으나, 흰 배경 위 흰 유리는 대비가 없어 흐려지는 걸 실기기로 확인.
- **목적**: 검색바·칩·화살표를 같은 연회색으로 통일 + 테두리 제거, 입력창 포커스는 파란 선 대신 부드러운 글로우.
- **이유**: 흰 배경 위 요소는 유리가 아니라 회색이 정답(대비 확보). 포커스는 색 변화에 transition을 걸어 툭 튀지 않게. 포커스 표시를 완전히 없애면 키보드 접근성이 깨지므로 글로우는 남김.

---

## 3. 작성한 프롬프트

```
[목표 — 확정 목업]
흰 배경 / 입력창·칩·화살표 전부 같은 연한 회색 / 테두리 전부 없음 /
입력창 클릭 시 파란 선 대신 부드러운 파랑 글로우. 라이트 전용, 다크 현행 유지.

[작업]
1. 배경 통일 — 입력창·비활성 칩·화살표 같은 연회색 (theme.ts 정합 토큰 우선)
2. 테두리 전부 제거
3. 활성 칩(전체 50) = primary 채움 + 흰 텍스트 유지
4. 포커스: 파란 선 제거, box-shadow 0 0 0 3px rgba(77,158,255,0.18),
   transition box-shadow 0.22s ease, prefers-reduced-motion에서 해제
5. 흰 배경 위 대비 확인

[하지 말 것]
다크 값 변경 ❌ / 포커스 표시 완전 제거 ❌ (접근성 — 키보드 포커스 가시) /
검색바·칩·화살표 외 ❌ / blur·유리 그라데이션 ❌ / 커밋 ❌
```

## 4. 코드 작성 & 수정

### `components/SpotFinderMapNaver.tsx` — 5개 지점

연회색 = `bg-card` 토큰(#f2f2f5 라이트/#1d1f21 다크) 그대로 — 양 테마 공용이라 배경은 클래스 1개.
테두리·그림자·포커스·transition만 라이트/다크 분리.

```tsx
// ① 데탑 검색 입력창 — 라이트: 무테두리·무그림자·글로우 포커스 / 다크: dark: 복원 전량
className="... border-0 dark:border dark:border-border bg-card dark:shadow-sm
  transition-[box-shadow] duration-[220ms] ease-[cubic-bezier(0.25,0.1,0.25,1)] motion-reduce:transition-none
  dark:transition-[color,border-color,box-shadow] dark:duration-200 dark:ease-out
  hover:border-muted focus:outline-none focus:border-primary
  focus:shadow-[0_0_0_3px_rgba(77,158,255,0.18)] dark:focus:shadow-[0_0_0_3px_rgba(77,158,255,0.15)]"
// 라이트 border-0이라 focus:border-primary·hover:border-muted는 폭 0으로 자연 무효 — 다크 전용 동작

// ② 칩 바 컨테이너 — 라이트 무박스(흰 배경 동화), blur도 다크 전용 이동
className="... border-0 dark:border dark:border-border dark:bg-card/80 dark:backdrop-blur-sm dark:shadow-sm ..."

// ③ 화살표 ×2 — bg-card 유지, 라이트 그림자 제거(dark:shadow-sm)

// ④ 칩 — 베이스 border 제거, 폭을 분기로: 데탑 라이트만 무테두리
? 'border border-primary lg:border-0 lg:dark:border bg-primary text-white'      // 활성 — primary 무변
: 'border border-border lg:border-0 lg:dark:border bg-card text-fg2'            // 비활성
```

- **모바일 시트 무변**: 목업은 좌측(데탑) 한정 + 시트 배경이 card라 무테두리 시 pill 소멸 —
  칩은 공유 렌더러라 `lg:` 스코프로 분리(모바일 라이트 = 기존 테두리 유지). 모바일 검색바도 원상 무변.

## 5. 결과 / 배운점

### 결과
- 빌드 성공, `npm test` 기존 실패(6스위트/8테스트) 외 증가 없음.
- **캐스케이드 순서 실측 확증**(변형 겹침이 이번 패턴의 유일 리스크): 컴파일 CSS에서
  `.border`(360행) < `.border-0`(361) < `.lg:border-0`(775) < `.dark:border`(792) < `.lg:dark:border`(826, min-width 미디어 내)
  — 다크·데탑 복원이 라이트 제거를 정확히 덮는 순서. transition 4종(220ms·베지어·dark 복원 3종)도 전부 생성 확인.
- `ease-[ease]`는 **Tailwind가 생성하지 않음**(키워드 arbitrary 미지원 실측) → CSS `ease` 등가 베지어
  `ease-[cubic-bezier(0.25,0.1,0.25,1)]`로 대체.
- **Tailwind v4가 docs/*.md도 콘텐츠 스캔**함을 실측 — 기각안(유리)의 클래스 문자열을 회고 초안에 그대로
  적으면 죽은 CSS가 번들에 생성됨. 이 회고는 기각안을 값 서술로만 기록(클래스 원문 회피).
- 접근성: 포커스는 글로우로 상시 가시(제거 아님). `motion-reduce:transition-none`은 무스코프라
  다크의 reduced-motion 사용자에게도 transition 해제 — 시각 상태 무변·모션 접근성 개선이라 수용(보고).
- 브라우저 수동 확인 잔여(사용자): 라이트 데탑 — 흰 배경 위 회색 pill 대비(연하면 popover #ececf1로 한 톤
  조정 여지), 포커스 글로우 질감, 다크·모바일 무변.

### 배운점
- 유리 실험에서 얻은 룰: 흰 배경 위 흰(유백색) 유리는 대비가 없어 흐려진다. 유리는 배경이 받쳐주는 자리에서 살고, 흰 배경 위 요소는 회색이 정답. 목업이 예뻐 보인 건 회색 배경이 받쳐줘서였다.
- 구현 함정 두 개: Tailwind에서 ease-[ease]가 안 만들어져 베지어로 대체, 회고 .md의 죽은 CSS 문자열이 번들에 섞이던 것 정리.

## 결정 (Decisions)

- **검색바·칩 라이트 확정 = 연회색(card) 무테두리 평면 + 포커스 글로우** — 유리(대비 부족)·테두리 회색(목업 대체) 2안 기각.
- **라이트 무테두리에서 다크 복원은 `border-0` + `dark:border` 폭 페어** — 색(border-*)은 폭 0이면 자연 무효라 무스코프 유지 가능. 변형 겹침(lg:·dark:·lg:dark:)은 컴파일 순서 실측으로 확증하고 쓴다.
- **공유 렌더러의 문맥 차이는 브레이크포인트 스코프로** — 같은 칩이 데탑(흰 배경)과 시트(card 배경)에서 다른 대비 요구를 가지면 `lg:`로 분리, 렌더러는 쪼개지 않는다.
- **회고에 기각안의 유틸 클래스 원문을 적지 않는다** — Tailwind v4 자동 콘텐츠 스캔이 md를 포함, 죽은 CSS가 번들에 실림.

---

## 1. 한 줄 요약

프로필 드롭다운의 이동 구역을 `MyPage → MyPlan → MyStory`에서
**`MyPage → MyStory → MyPlan`**으로 바꿔, 상단 내비(`Story → SpotFinder → PlanFinder`)와
같은 순서로 읽히게 했다.

---

## 2. 왜 / 목적 / 이유

> 사후 작성편이라, 아래는 **커밋과 함께 들어간 주석이 직접 밝힌 근거**를 옮긴 것이다
> (`0546: … 상단 내비와 내 화면 축을 같은 순서로 동조(두 메뉴가 한 벌로 읽히게)`).
> 주석에 없는 부분은 "기록 없음"으로 명시한다.

### 두 메뉴가 한 벌로 읽히지 않았다
헤더에는 두 개의 이동 수단이 동시에 있다 — 상단 내비(공개 화면)와 프로필 드롭다운
(내 화면). 같은 도메인 축(스토리·플랜)을 다루는데 **순서가 서로 뒤집혀 있었다**:

```
상단 내비   : Story    → SpotFinder → PlanFinder
드롭다운(전): MyPage   → MyPlan     → MyStory     ← 스토리·플랜이 역순
드롭다운(후): MyPage   → MyStory    → MyPlan      ← 동조
```

사용자가 한 화면에서 두 메뉴를 번갈아 보는데 축 순서가 다르면, 위치로 기억한 항목을
다시 찾게 된다. 순서를 맞추면 **"위쪽 메뉴의 내 버전"**이라는 관계가 위치만으로 전달된다.

### SpotFinder에는 짝이 없다 — 판단 기록 없음
내비 3항 중 SpotFinder만 `My-` 대응 화면이 없어서, 동조라 해도 2항 대 3항의
부분 대응이다. **이 비대칭을 어떻게 봤는지(문제 아님으로 넘긴 것인지, 향후 확장 여지로
둔 것인지)는 코드·커밋에 남아 있지 않다.** 다만 순서 동조는 두 항목만으로도 성립하므로
이 작업의 성패에 영향을 주진 않는다.

`app/(protected)/_components/UserDropdown.tsx` 한 파일. 두 `<Link>` 블록의
`href`·라벨을 교환하고 근거 주석을 얹었다.

```tsx
 </Link>{/* MyPage */}
+{/* 0546: MyStory → MyPlan 순 — 상단 내비(NavLinks: Story → SpotFinder → PlanFinder)와
+    내 화면 축을 같은 순서로 동조(두 메뉴가 한 벌로 읽히게) */}
 <Link

+  href="/my-story"
   role="menuitem"
   className="block px-4 py-2 text-sm text-slate-700 dark:text-fg2 hover:bg-slate-50 dark:hover:bg-surface2 transition-colors duration-150"
   onClick={() => setOpen(false)}
 >
-  MyPlan
+  MyStory
 </Link>
 <Link
-  href="/my-story"
+  href="/my-plan"
   ...
 >
-  MyStory
+  MyPlan
 </Link>
```

`role="menuitem"`·닫힘 핸들러·클래스는 두 항목이 동일해서, 교환으로 인한 동작 차이는
없다.

## 5. 결과 / 배운점

### 결과
- 드롭다운 이동 구역이 상단 내비와 같은 도메인 순서. 구역 구성(0482의 3구역:
  이동 / Admin / 설정)은 불변.

### 이 커밋이 만든 주석 부패 (사후 정정)
같은 파일 아래쪽 0482 주석이 **순서를 전제로 쓰여 있어서 이 커밋으로 어긋났다**:

```tsx
// 0546 직후 — 부패 상태
{/* Admin은 이동 그룹에 편입(0482 3구역 재구성) — 선행 구분선 제거해 MyStory와 한 그룹. */}
```

Admin 위에 오는 항목은 0546 이후 MyStory가 아니라 **MyPlan**이다. 이 회고를 쓰면서
함께 정정했다:

```tsx
{/* Admin은 이동 그룹에 편입(0482 3구역 재구성) — 선행 구분선 제거해 이동 그룹과 한 덩어리.
    0482 당시 직전 항목은 MyStory였으나 0546 순서 동조로 MyPlan이 됐다(그룹 소속은 불변) */}
```

> **회고-코드 동기 확인**: `0477~482-버튼-체계-3x2-격자-통일.md`에서 0482는 "범위 내
> 별건"으로 표에만 있고 본문 서술이 없다. 즉 **정정할 회고 문장은 없고, 코드 주석
> 1곳만 부패**했다. (CLAUDE.md §7 "회고-코드 동기" 점검 결과)

### 배운점
- **순서를 근거로 쓴 주석은 순서가 바뀌면 거짓이 된다.** "MyStory와 한 그룹"처럼
  이웃 항목 이름을 박아둔 주석은, 그 이웃이 움직이는 순간 부패한다. 이웃을 지목할 땐
  **역할("이동 그룹")로 쓰는 편이 수명이 길다.**
- 3주 가까이 부패가 안 잡힌 이유는 **회고가 없어서**로 보인다 — 소작업이라도 회고를
  쓰면 그 시점에 같은 파일의 앞뒤 주석을 다시 읽게 된다.

# 0464 버블 ⋯를 슬래시 모양 선택 도구 목록으로 교체

**작성일**: 2026-08-02

## 1. 한 줄 요약

버블 ⋯가 열던 툴바용 2열 그리드를 버블 전용 세로 목록(신규 BubbleMore)으로 교체 — 슬래시 메뉴와 동일한 생김새(셸·행·sticky 그룹 헤더·max-h 208 내부 스크롤)로 마크 4종(작게·취소선·인라인 코드·링크) + 블록 변환 4종(H2·H3·목록·인용)을 선택 유지 상태에서 적용. 툴바 ⋯(그리드 10항목)는 존속.

---

## 2. 왜 / 목적 / 이유

(초안 — 확정 지시에서 추린 초안 수준)

- **왜**: 0463의 버블 ⋯는 툴바 그리드를 그대로 열어 의도와 다름. 접힌 블록 삽입에 닿으려던 이전 방향(Suggestion 발동)은 **캐럿이 "/" 뒤에 있어야 해 선택이 풀리는 구조적 제약**으로 기각 — 같은 생김새의 목록을 직접 렌더.
- **역할 구분(사용자 확정)**: 버블 = 이미 있는 글을 다루는 자리 → 변환 가능한 것만. 삽입(이미지)은 슬래시·툴바, 전체 교체(서식)는 툴바, 콜아웃은 선택을 감싸는 동작이 불확실해 제외.
- **그룹 헤더 근거**: 텍스트 마크는 고른 구간에만, 블록 변환은 문단 전체가 바뀜 — 적용 결과가 달라 구분 표기.

## 4. 코드 작성 & 수정

### 조사 확정 (구현 전 검수 ①~⑤)
- 슬래시 실측: 셸 `w-[250px] rounded-[12px] … bg-card` + **모바일 max-h 208px**(MOBILE_MAX_H) + 내부 스크롤, 행 ≈52px, sticky 헤더 ≈31px → 208px에 ≈3.4행 노출.
- 0463 억제 배선은 그대로 유효 — BubbleMore가 `onOpenChange`만 받으면 배선 변경 0 (목록 열림 중 "/" 억제·슬래시 열림 중 목록 열기 시 슬래시 닫기 유지).
- 선택 유지: mousedown preventDefault + PM 상태 선택 + `chain().focus()` 재적용 — 0463 패널 마크로 검증된 경로 (iOS 실기기만 실측 항목).
- 8종 적용: 마크=구간 / H2·H3=걸친 문단 각각 / 목록=문단별 li 한 리스트 / 인용=하나의 blockquote.
- 툴바 ⋯ 유지 성립: 콜아웃=툴바⋯+슬래시, 이미지=한 줄+슬래시, 서식=툴바⋯ 유일.

### 후속 0464-b — 목록 열림 중 버블 숨김 (실기기 확인 반영, 미커밋)
실기기에서 버블+목록 두 오버레이가 위아래로 겹치던 문제 — 목록 열림 중 BubbleMenu에 `invisible`(visibility:hidden, 레이아웃 보존이라 트리거 rect·목록 앵커 무이동), 목록 팝오버는 `visibility: visible`로 상속 역전해 단독 표시. 뒤로·ESC·바깥탭 닫힘 시 클린업 경유 통지로 버블 복귀(선택 붕괴 언마운트에도 invisible 잔류 없음). 포커스 복귀는 rAF 지연(hidden 요소는 포커스 불가).

**[0464-c 정정] 위 `invisible` 숨김은 어느 환경에서도 작동하지 않았다.** className은 floating 엘리먼트에 정확히 붙지만(@tiptap/react `syncClassName`), 플러그인(BubbleMenuView)이 `show()`·`updatePosition()`마다 같은 엘리먼트에 inline style `visibility: visible`을 재설정 — inline이 클래스를 항상 이겨 무효(패키지도 visibility를 PLUGIN_MANAGED_STYLE_PROPERTIES로 관리). `invisible!`(Tailwind v4 postfix important)로 역전해 해결. 자식 목록의 자체 `visibility: visible`은 유효 유지(!important는 같은 엘리먼트 캐스케이드에만 작용, 상속 비전파).

**[0464-d 후속] 0464-c의 blur 1단계는 실기기 확인 후 기각.** iOS 자체 선택 메뉴는 웹에서 차단 불가 확정(-webkit-touch-callout iOS15+ 미동작, iOS 26.1 동일)이고 blur는 선택을 깨뜨려 제거 — 겹침 수용. 함께: ① 목록 앵커를 `top-end`로 변경(invisible 버블의 잔존 레이아웃 아래 = 선택 텍스트를 가리던 문제 — 위쪽=이미 읽은 이전 줄 방향, 부족 시 flip 아래 폴백) ② 적용 불가 항목 비활성 — 인라인 코드 마크가 `excludes: "_"`(전체 배제)라 코드 위 마크 적용이 조용히 무시되던 것(ProseMirror addToSet 표준)과 콜아웃 안 블록 변환(content: paragraph+)을 `editor.can()` 기반 can 맵(useEditorState 확장)으로 툴바·버블·두 더보기 전부 회색 처리(disabled/aria-disabled + opacity-40) ③ 작게×제목 충돌(13px 고정이 제목을 이겨 깨짐 — 우리가 만든 문제)은 제목 안 작게 비활성 + globals.css 제목 안 `[data-size]` font-size:inherit 가드(기존 저장 글 표시 정상화).

**[0465 후속] 비활성 처리(위 0464-d ②③)의 실기기 재확인 반영.** 판정(can)·배선·CSS 생성은 전 층 정상 실증(헤드리스 tiptap + 실스캐너 빌드) — 문제는 표시와 앵커: ① opacity-40 단독 감쇠는 이미 회색(fg2)인 아이콘의 다크 배경 대비 차가 작아 실기기 식별 불가 → 버튼·목록 행 모두 muted 색 강등 병행, 상태 축 분리(선택/hover=배경 채움, 비활성=콘텐츠 강등·배경 금지) ② BubbleMore 비활성 행이 selectedIndex 하이라이트를 받아 "안 풀리는 hover"처럼 잔존(iOS 탭=mouseenter 발화·mouseleave 없음, v4 CSS hover는 media 게이팅으로 무관) → 비활성 행을 선택 대상에서 제외(mouseenter 무시·화살표 스킵·초기 선택은 첫 활성 행) ③ 목록 앵커가 invisible 버블 안 ⋯ 트리거라 선택 위 ~68px 죽은 공간 위로 떠 본문을 더 가림 → 선택 rect 가상 앵커(posToDOMRect, 버블 플러그인과 동일 기준)로 교체.

**[0466 후속] "목록 열면 선택 풀림"의 실제 원인은 invisible이 아니라 열림 시 첫 항목 auto-focus.** 항목 focus → 에디터 blur → iOS가 blur된 contenteditable의 선택 표시를 제거(시각). PM 상태 선택은 안 무너짐을 실증(prosemirror-view가 blur 중 selectionchange를 `hasFocusAndSelection`으로 게이팅 + 헤드리스 실측 + 목록이 계속 떠 있음 = shouldShow !empty 통과). "뒤로" 미복귀는 close()가 에디터 아닌 ⋯ 트리거를 포커스한 탓. 조치: ① 터치 열림엔 auto-focus 생략(키보드 열림 — 트리거 포커스 상태 Enter — 만 항목 포커스, 0464 "풀리면 auto-focus 생략" 예고의 이행) ② close() 포커스 복귀는 포커스가 메뉴 안일 때만 ③ **위 0464-b~c의 invisible/`invisible!` 숨김은 철회** — 목록이 선택 rect 기준이라 버블 구간[선택 위 8~60px]을 수직으로 완전히 덮어(z-50) 오버레이 단일화가 기하로 달성되고, 선택 유지(에디터 포커스 보존)가 우선. 자식 visibility 역전·close rAF 지연도 함께 제거.

## 결정 (Decisions)
- 버블 ⋯의 내용 = 버블 전용 선택 도구 목록(BubbleMore) — 버블은 "이미 있는 글의 변환" 자리: 마크 4종+블록 변환 4종만, 삽입·전체 교체·콜아웃 제외
- Suggestion(슬래시)은 선택 유지 맥락에서 발동 불가(캐럿 제약) — 같은 생김새 직접 렌더가 정답, "/" 프로그래매틱 삽입안은 기각
- 툴바 ⋯ 그리드는 캐럿·문서 도구로 존속 — 서식의 모바일 유일 진입점
- 슬래시 셸 리터럴(max-h 208 등)은 BubbleMore와 주석 상호 참조로 동기 (한쪽만 바꾸면 어긋남)

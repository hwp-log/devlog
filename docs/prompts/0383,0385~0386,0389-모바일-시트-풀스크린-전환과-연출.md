## 1. 한 줄 요약

0382까지의 "페이지를 스크롤해 지도와 시트를 맞추는" 접근이 방향부터 틀렸다고 판단해 지도를 풀스크린으로 올리고 시트를 그 위에 겹치는 구조로 바꾸고, 이어서 저장 경로·열고 닫는 연출·스크롤 바운스를 실기기 기준으로 다듬었다.

## 2. 왜 / 목적 / 이유

**왜(문제)** — 0381에서 전체화면 모달을 하단 70svh 고정 시트로 바꾸고, 0382에서 시트를 열 때 페이지를 스크롤해 지도를 정렬하고 마커를 가시 영역 중앙으로 보내는 처리를 넣었다. CDP 검증에서는 마커 중앙 안착·covered 203px·정렬이 모두 통과했는데 실기기에서는 증상이 그대로였다. 위쪽에 지도 카드의 일부만 얇게 보이는 화면이 나왔다.

**목적(원하는 상태)** — 마커를 탭하면 위쪽을 지도가 꽉 채우고 아래가 시트인 화면. 즉 "지도 카드의 일부가 위에 걸치는" 것이 아니라 지도가 화면 전체를 쓰는 형태.

**이유(방향 결정의 근거)** — 실기기 결과를 받고 나서 이것이 버그가 아니라 방향 자체의 오류라고 재정의했다. 지도가 문서 흐름 안 카드(h-400)로 남아 있는 한, 페이지 스크롤로 위치를 맞추는 접근은 전제부터 어긋난다. 대신 구글 지도·Turo가 쓰는 형태 — 지도 풀스크린 + 시트 오버레이 + 지도 `padding.bottom`으로 카메라 보정 — 를 따르기로 했다. 0382의 Effect B(covered 측정 → padding → focusSpot morph)가 이미 그 패턴이었으므로 유지하고, Effect A(scrollTo 정렬·scroll lock·복원)만 걷어냈다.

이어진 세 커밋의 이유:
- **0385** — 리뷰를 저장해도 시트가 남아 있어 흐름이 끊겼다. 조사 과정에서 실제 증상이 하나 더 드러났는데, 0378의 pushState 엔트리가 남아 저장 후 뒤로가기 한 번이 페이지 이탈이 아니라 시트 닫기에 소비되고 있었다.
- **0386** — 시트가 갑자기 사라져 화면이 끊기는 느낌이라는 판단에서 퇴장 트랜지션을 넣기로 했고, 작업 중 진입까지 범위를 넓혔다.
- **0389** — 시트 안에서 아래로 당기면 상단에 빈 회색 띠(실기기 약 170px)가 드러났다.

## 4. 코드 작성 & 수정

### 0383 — 지도 래퍼 토글 (`components/SpotMap.tsx`)

같은 DOM 노드의 클래스만 갈아끼워 지도 재init·이동을 피했다.

```tsx
// sheetOpen이면 풀스크린, 아니면 기존 카드
className={sheetOpen
  ? 'fixed inset-0 z-[55]'
  : 'relative md:flex-1 h-[400px] md:h-[500px] rounded-xl'}
```

Effect A 전량 삭제, `restoreScrollRef` 제거. Effect B의 covered 계산은 지도 rect 의존을 걷고 `sheetEl.offsetHeight` 하나로 단순화했다(풀스크린이라 시트 높이 = 가림 높이).

시트 스크롤러 하단 여백도 함께 줄였다. 시트(z-60)가 탭바(z-40)를 덮으므로 탭바 겹침 보정이 불필요해졌고, 저장 버튼이 화면 끝·홈 인디케이터에 붙지 않을 만큼만 남겼다.

```diff
- pb-[calc(88px+env(safe-area-inset-bottom))]
+ pb-[calc(16px+env(safe-area-inset-bottom))]
```

**신규로 생긴 리스크와 처방** — 풀스크린 전환으로 mapDiv 크기가 바뀌면서, 기존에는 발화하지 않던 `ResizeObserver` 콜백의 `setCenter`가 열기 morph 도중에 끼어들어 morph를 얼렸다(줌이 `ZOOM_FOCUS`에 미도달). morph 직전에 `lastSizeRef`를 풀스크린 크기로 선점해 관찰자를 size 불변 가드로 no-op화하고 `autoResize()`를 명시 호출해, 발화 순서와 무관하게 morph가 항상 최후가 되도록 했다.

| 조건 | 관찰자 발화 | 처방 |
|---|---|---|
| 카드 → 풀스크린(시트 열기) | 발화 | `lastSizeRef` 선점 + 명시 `autoResize` |
| 마커 A → B 전환 | 미발화 | `sheetOpen` 불변이라 지도 크기도 불변 |

### 0385 — 저장 시 닫기 (`components/SpotPopup.tsx`)

`onValid`의 두 종료 경로 끝에 `onClose?.()` 추가.

```ts
// handleClose가 아니라 onClose를 직접 부른다.
// handleClose는 같은 렌더의 stale isCreationSession(=true)을 읽어
// 방금 저장한 스팟을 onDelete로 지운다.
onClose?.();
```

`onClose`(= `handlePopupClose`)는 `setActiveSpot(null)` + `setMode('menu')` + `consumeHistoryEntry`라 히스토리 엔트리 소비는 타면서 삭제 분기만 우회한다. 이 이유를 코드 주석으로 남겼다 — "닫기 통일" 리팩터링 시 재발할 수 있는 자리다.

사진은 유실 위험이 없음을 코드로 확인했다. `onValid`에서 File을 인자로 `onFileSelect` → `onPhotoSelect` → `setPendingPhotos`까지 동기 커밋되며 `onClose`보다 앞이고, `handedOffUrlRef`로 blob revoke도 건너뛴다.

저장 후 팝업이 유지되는 것을 검증하던 기존 테스트 2건(`SpotPopup.test.tsx`)은 바뀐 동작에 맞춰 갱신했다.

### 0386 — 열기·닫기 연출 (`components/SpotMap.tsx`)

설계 축은 **source-of-truth는 즉시 정리하고 프레젠테이션만 지연**이다. 닫기 5경로 핸들러를 일절 건드리지 않고, "모바일에서 `activeSpot`이 non-null → null로 떨어지는 전이"만 `useLayoutEffect`로 관측했다. 확인 과정에서 `handleDelete`가 `handlePopupClose`를 경유하지 않는다는 사실이 드러났는데, 전이 관측 방식이라 자동으로 커버됐다.

CSS 애니메이션으로 시작했다가 실기기에서 닫힘이 재생되지 않아 WAAPI로 전환했다.

| 안 | 판정 | 근거 |
|---|---|---|
| `key` 교체 | 기각 | SpotPopup까지 리마운트되어 편집 중 닫으면 보기 모드로 튐 |
| 강제 리플로우(`void offsetHeight`) | 기각 | 의도가 코드에 드러나지 않음 |
| **WAAPI** | **채택** | 명령형이라 재시작 문제라는 범주 자체가 없고, `finished`가 animationend + failsafe 타이머를 대체 |

커버 오버레이는 `themeFade` 재사용이 아니라 전용으로 뒀다. 재사용하면 fade-in도 250ms라 차오르는 동안 늘어난 GL 프레임이 새어 나온다. 커버 상태는 `boolean`으로는 표현이 안 돼 `{opacity, ms}`로 일반화했다 — 켤 때와 끌 때 지속이 다른 프로파일이 넷이기 때문이다.

| 프로파일 | 지속 |
|---|---|
| 열기-인 | 0ms (transition 없이 즉시 opaque) |
| 열기-아웃 | 750ms (`SHEET_OPEN_COVER_OUT_MS`) |
| 닫기-인 | 240ms (`SHEET_CLOSE_MS` 공유 — 하강 종료 = 완전 불투명) |
| 닫기-아웃 | 450ms (`SHEET_COVER_OUT_MS`) |

`closingActiveRef`로 Effect B cleanup의 `setOptions('padding', {bottom:0})`을 닫힘 애니 중 건너뛰고 `finishClose`에서만 복원했다. 네이버 GL에서 padding은 중심 latlng의 화면 앵커라, bottom 복원이 카메라 명령 없이도 재투영을 일으켜 시트가 내려가는 동안 지도가 슬금 움직인다.

### 0389 — 고무줄 바운스 (`components/SpotMap.tsx`)

```diff
- <div className="h-full overflow-y-auto overscroll-contain pb-[...]">
+ <div className="h-full overflow-y-auto overscroll-none pb-[...]">
```

높이 계산 문제는 배제됐다. 스크롤러가 `h-full`이라 시트 컨테이너와 동일 높이이고 컨테이너는 `overflow-hidden`이라 자기 바운스가 없으므로, 바운스 주체는 `overflow-y-auto` 스크롤러다. `overscroll-contain`은 뒤 페이지로의 체이닝만 막고 자기 요소의 고무줄 바운스는 허용한다. `none`은 `contain`의 상위라 체이닝 방지도 함께 충족한다.

## 5. 결과 / 배운점

### 결과

- 마커를 탭하면 지도가 화면을 꽉 채우고 시트가 그 위에 올라오는 형태로 전환됐다. 실기기 확인 완료.
- 닫기 5경로(✕·취소·저장·삭제·뒤로가기) 모두 아래로 내려가는 연출로 닫히고, 닫히는 동안 지도 중심이 정지한다.
- 시트 안에서 당겨도 빈 띠가 드러나지 않는다.
- 커버 걷힘 속도는 실기기에서 두 차례 조정했다(열기 250 → 500 → 750, 닫기 150 → 300 → 450).

### 배운점

- **CDP 통과가 실기기 통과를 보장하지 않는다.** 0382는 헤드리스 검증을 전부 통과했는데 실기기에서는 증상이 그대로였다. svh 실제값, 애니메이션 타이밍, 스크롤 동작이 갈리는 지점이라 시트·지도·키보드가 얽힌 작업은 실기기 확인을 검증 절차에 넣어야 한다.
- **증상이 반복되면 수정이 아니라 방향을 의심한다.** 0382를 버그로 보고 계속 고쳤다면 스크롤 정렬 위에 보정을 더 쌓았을 것이다. "원하는 화면이 무엇인가"로 되돌아가자 표준 패턴(풀스크린 + 오버레이)이 답으로 나왔고, 기존 작업 중 살릴 것(Effect B)과 버릴 것(Effect A)도 그 기준으로 갈렸다.
- **닫기 5경로를 각각 고치는 대신 상태 전이 하나를 관측하는 편이 안전했다.** 핸들러를 건드리지 않아 0365 생성 세션 삭제 로직에 손대지 않았고, 경유하지 않는 경로(`handleDelete`)가 있다는 사실이 나중에 드러났을 때도 자동으로 커버됐다.
- **같은 이름의 닫기가 두 개면 하나는 부작용을 갖는다.** `handleClose`는 stale한 `isCreationSession`을 읽어 방금 저장한 스팟을 지운다. 이런 자리는 주석 없이는 리팩터링에서 되돌아온다.
- **`fill: forwards`로 완주한 CSS 애니메이션은 이름 교체로 재시작되지 않는다.** 노드가 재사용되는 구조(`key` 없음)와 겹치면 "열기만 되고 닫기는 안 되는" 형태로 나타난다. WAAPI는 이 범주 자체를 없앤다.
- **`overscroll-behavior: contain`은 자기 요소의 바운스를 막지 않는다.** 체이닝 방지와 바운스 억제는 다른 문제이고, 후자까지 필요하면 `none`이다.
- **지도 SDK의 padding은 카메라 앵커다.** 값 복원만으로 재투영이 일어나므로, 애니메이션 중에는 복원 시점을 제어해야 한다.

### 남은 것 / 후속

- 시트 ✕가 스크롤러 안에 있어 콘텐츠와 함께 스크롤된다. 상단 고정이 자연스럽다.
- 커버가 지도 래퍼 안이라 교체 프레임에 카드 바깥 페이지가 즉시 드러난다. 라이트에서는 무해하나 다크는 명도 차가 커 팝이 보일 수 있다. 거슬리면 커버를 페이지 레벨로 빼는 별건이 필요하다.
- 인-코드 주석 번호 정정 대상: `d68778a`(0386) 주석 5곳이 0387·0388로, `a2843dc`(0389) 주석 1곳이 0388로 적혀 있다. 작업 중 커밋 번호가 밀리면서 생긴 어긋남이다.
- `SpotMap.tsx`의 "키보드 열림 시 저장 버튼 도달성은 별건(0384 visualViewport)" 주석도 번호가 잘못됐다 — 0384는 보안 작업이고, 키보드 대응은 번호가 배정되지 않은 채 대기열에 남았다.

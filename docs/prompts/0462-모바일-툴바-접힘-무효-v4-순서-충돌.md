# 0462 모바일 툴바 접힘 무효 — Tailwind v4 display 순서 충돌

**작성일**: 2026-08-02
**소요 시간**: 기록 없음
**관련 커밋**: fix: 0462 모바일 툴바 접힘 무효 — hidden을 max-sm:hidden으로 교체(v4 순서 충돌) (14b91b6)

---

## 1. 한 줄 요약

0461의 접힘 클래스 `hidden sm:inline-flex`가 ToolbarButton 베이스 `inline-flex`에 덮여(Tailwind v4 알파벳 출력 순서 h<i, 동특이도) 모바일에서 무효 — 접힘 9버튼·구분선·서식 래퍼를 `max-sm:hidden`(미디어 스코프라 순서 무관)으로 교체해 해소.

---

## 2. 왜 / 목적 / 이유

(초안 — 원인 규명 과정에서 추린 초안 수준)

- **왜**: 0461 적용 후에도 모바일 툴바가 3줄. 접혀야 할 9버튼이 그대로 보이고 order만 적용돼 남길 6개가 뒤로 밀림(.next 삭제 후에도 동일).
- **원인**: v3에선 `hidden`이 display 유틸 마지막에 출력돼 "베이스 display 유틸 + hidden" 관용구가 동작했지만, **v4는 유틸리티를 사실상 알파벳순으로 출력**해 `.inline-flex`가 `.hidden` 뒤로 감 — 같은 특이도에선 뒤의 규칙이 이겨 hidden 무효.
- **처방 근거**: `max-sm:hidden`은 `@media (width<40rem)` 스코프 규칙이라 베이스 유틸 뒤 미디어 블록에 출력 — 순서 무관하게 이김. sm 복원 클래스도 불필요해져 더 단순.

## 4. 코드 작성 & 수정

### 원인 특정 — 빌드 CSS 바이트 오프셋 실측

```
.flex{display:flex           @ 18232
.hidden{display:none         @ 18270
.inline-flex{display:inline-flex @ 18349  ← hidden보다 뒤 = 승자
sm:* 미디어 블록              @ 60079~
```

사용자 가설 4번(기본 클래스 충돌) 적중. 구분선·FormatMenu 래퍼는 베이스에 display 유틸이 없어 무관(정상 숨김이었음), order·sm: 복원 규칙은 전부 존재·정상 — "order만 적용된" 증상과 정합.

### 수정

```tsx
// TiptapEditor.tsx — 접힘 9버튼 (9곳 동일)
className="hidden sm:inline-flex"  // 변경 전 — inline-flex(베이스)에 덮여 무효
className="max-sm:hidden"          // 변경 후 — 미디어 스코프, sm 복원 클래스도 불필요

// ToolbarDivider·FormatMenu 래퍼 — 동작엔 문제 없었으나 한 파일 두 관용구 혼재 방지로 통일
"hidden sm:block ..." → "max-sm:hidden ..."
```

ToolbarButton className prop 주석에 함정 명기: "숨김은 반드시 max-sm:hidden — 베이스 inline-flex가 무접두 hidden을 v4 순서상 덮음".

### 수정 후 재검증 (같은 방법)

```
.inline-flex     @ 18349 (베이스)
max-sm\:hidden   @ 59437 (미디어 블록 — 베이스 뒤) ← 모바일에서 항상 이김
```

## 결정 (Decisions)
- **베이스에 display 유틸이 있는 요소의 반응형 숨김은 무접두 `hidden` 금지, `max-sm:hidden`(미디어 스코프) 사용** — v4 알파벳 출력 순서상 동특이도 충돌(빌드 CSS 오프셋 실측 확정)
- 스타일 미적용 판정은 빌드 CSS의 규칙 존재·출력 순서(바이트 오프셋)로 — 소스·JIT 추측 금지

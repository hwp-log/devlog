# 0115~118 회고: PlanFinder 진입 모션 통일 + 카드 레이아웃 개선

- 작성일: 2026-06-28
- 소요: 약 6시간 (0115~0118 누적)
- 관련 커밋: 676b6b5(0115), 1b66967(0116), 2df2f89(0117), 2206e8c(0118)

## 1. 한 줄 요약

PlanFinder 상단에 타이핑 헤드라인을 넣었다가, 타이핑이 "진입점에 시선을 모으는" 효과라 콘텐츠 탐색 페이지와는 안 맞는다는 걸 깨닫고 전체 fade로 통일했다. 함께 카드의 카테고리 예산을 색 막대에서 아이콘+비율%로 바꿔 정확한 값이 한눈에 읽히게 했고, 정렬·필터 변경 시 카드가 어색하게 일부만 다시 뜨던 문제와 카드 transform이 드롭다운을 가리던 z-index 문제를 정리했다.

## 2. 왜 / 목적 / 이유

### 타이핑 헤드라인 → 전체 fade 통일 (0115에서 넣고 0117에서 버림)

- 왜: 0115에서 상단 헤드라인에 타이핑 애니메이션(한 글자씩 + 깜빡 커서)을 넣었다. 그런데 진입 시 본문 카드는 fade로 떠오르는데 제목만 타이핑이라, 둘이 따로 놀았다. 처음엔 "커서 깜빡임을 부드럽게" 같은 디테일을 만지다가, 더 근본적으로 "타이핑이 왜 어색한가"를 따졌다.
- 목적: 헤드라인부터 카드까지 위에서 아래로 한 호흡으로 떠오르는, 통일된 진입 경험.
- 이유:
  1. 타이핑은 본질적으로 **진입점에 시선을 모으는** 효과다. hero·랜딩 헤더에서 순차 노출로 narrative pacing을 만들고, 깜빡 커서로 시선을 핵심 한 곳에 끌어당긴다. 검증 차원에서 찾아보니 "사이트가 이미 시선을 끄는 콘텐츠로 차 있으면 상단에 추가 연출은 불필요하다"는 가이드도 같은 맥락이었다.
  2. PlanFinder는 랜딩이 아니라 **여러 코스를 둘러보는 콘텐츠 탐색 페이지**다. 여기선 시선이 한 곳에 멈추는 게 아니라 카드들을 훑으며 흘러야 한다. 타이핑(집중)과 카드 fade(흐름)는 목적이 충돌한다.
  3. 부수적으로 타이핑은 SEO·접근성 비용도 있다. 크롤러·스크린리더가 처음엔 빈 요소로 인식할 수 있고, prefers-reduced-motion 대응도 따로 해야 한다. 콘텐츠 페이지가 굳이 질 비용이 아니다.
  - 매몰비용(0115에서 만든 타이핑)이 있어도 UX를 해치면 의미가 없다. 만든 걸 버리고 fade로 무게중심을 옮긴 게 0117의 핵심 결정이다.

### 카테고리 예산: 색 막대 → 아이콘 + 비율% (0116)

- 왜: 처음엔 카테고리별 예산을 색 막대 그래프로 표현했다. 막대면 사용자가 비율을 한눈에 볼 거라 생각했는데, 막상 보니 막대 길이만으론 정확히 몇 %인지 안 읽혔다.
- 목적: "이 코스가 무엇에(✈️🍴🚌) 얼마나(%)" 돈을 쓰는지가 정확한 값으로 바로 읽히는 카드.
- 이유: 색 막대는 비율감(어느 쪽이 큰지)은 주지만 정확한 값은 못 준다. 게다가 카테고리가 여러 개면 막대들이 한눈에 안 들어온다. 그래서 lucide 카테고리 아이콘(무엇에) + 숫자%(얼마나)로 바꿔 정확한 값을 직접 보여줬다. 이건 "내가 만든 막대를 사용자 눈으로 다시 본" 결정이다 — 만들고 "되네" 하고 넘어가는 대신 "근데 이거 한눈에 안 들어오는데?"를 스스로 잡았다.

### 정렬/필터 변경 시 카드 재등장 통일 (0118)

- 왜: 정렬(인기순↔최신순)이나 필터를 바꾸면, 순서만 바뀐 카드는 그대로 떠 있고 일부만 fade로 떠서 어정쩡했다.
- 목적: 첫 진입은 헤드라인 흐름과 통일, 정렬·필터 조작 시엔 카드 목록 전체가 깔끔하게 다시 정렬되는 일관된 동작.
- 이유: 카드 진입 애니는 React `key` 기준으로 동작한다. 순서만 바뀐 카드는 key가 같아 애니가 재실행되지 않고, 그래서 일부만 fade되는 어정쩡한 상태가 됐다. 카드 컨테이너에 `${sort}-${filter}` 동적 key를 줘서, 정렬·필터가 바뀌면 컨테이너째 새 마운트 → 안의 카드 전체가 다시 등장하게 통일했다. 단 상단(헤드라인·통계·필터)은 컨테이너 밖이라 영향 없게 분리했다 — 정렬할 때마다 헤드라인까지 다시 뜨면 부산스러우니까. 진입 모션(첫 로드)과 인터랙션 피드백(조작)의 역할을 나눈 것이다.

const isFirstRenderRef = useRef(true);
useEffect(() => { isFirstRenderRef.current = false; }, []);

  {/* ↑ relative z-10: 카드 transform이 만든 stacking context로 드롭다운이 가리던 문제 수정 */}

## 5. 결과 / 배운점

### 결과
- "기계적이다"로 시작한 PlanFinder가 헤드라인·카드 전면 재설계·드롭다운·통일된 진입 모션까지 완전히 다른 화면이 됐다. 진입은 eyebrow→헤드라인→통계→필터→카드가 한 호흡으로 떠오르고, 정렬·필터는 카드 목록만 깔끔하게 다시 정렬된다. (4개 커밋 모두 배포 완료, tsc 통과.)

### 배운점
- **타이핑은 진입점 효과지 콘텐츠 페이지 효과가 아니다.** 같은 애니라도 "왜 쓰는가"가 페이지 성격과 맞아야 한다. 랜딩은 시선을 한 곳에 모으고, 탐색 페이지는 시선이 흘러야 한다. 타이핑(집중)과 fade(흐름)는 목적이 충돌했다.
- **만든 걸 사용자 눈으로 다시 본다.** 색 막대도, 타이핑도 "되네" 하고 넘어갈 수 있었지만 "한눈에 안 들어오는데?" "따로 노는데?"를 스스로 잡았다. 매몰비용이 있어도 UX를 해치면 버리는 게 맞다 — 단, 이건 멘토 피드백(디테일보다 볼륨)과 균형을 잡아야 할 지점이기도 하다.
- **진입 모션과 인터랙션 피드백은 역할이 다르다.** 첫 로드의 진입 애니는 "첫인상"용이라 한 번이면 되고, 정렬·필터 조작 시엔 "결과가 바뀌었다"는 피드백이 필요하다. 같은 fade라도 첫 로드(0.48s, 헤드라인과 통일)와 재등장(0, 즉시)을 분리해 둘을 구분했다.
- **transform은 stacking context를 만든다.** 카드 진입 애니(transform)가 새 stacking context를 생성해 드롭다운이 카드에 가려졌다. 필터 영역에 `relative z-10`으로 위 레이어를 확보해 해결했다. transform↔z-index의 충돌은 CSS에서 자주 나오는 함정이라, 증상(가려짐)이 아니라 원인(stacking context)을 추적해 고친 게 핵심이었다.

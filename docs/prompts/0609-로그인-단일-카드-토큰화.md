## 2. 왜 / 목적 / 이유

- **왜**: 0608에서 랜딩을 걷어내며 /login 좌측 소개 패널이 짝을 잃었다. 좌측 패널·사진 배경·전용 폰트는 랜딩과 한 벌이던 디자인이라 서비스 안쪽과 따로 놀았다.
- **목적**: 로그인은 이미 서비스를 아는 사람이 오는 화면 — 브랜드 소개가 필요 없다. 서비스 내부 토큰 디자인으로 정합.
- auth-bg.png 삭제 사유: 출처 불명 외부 사진, 저작권 정리 대상 (사용자 지시).

## 5. 결과 / 배운점

### 결과
- tsc·eslint 통과. `npm test`: 실패 4스위트/6테스트 — 기존 실패 목록(6스위트/8테스트, auth 5+SpotPopup)의 **부분집합**. 신규 실패 0. login 3스위트(9테스트)는 재작성 후 전부 통과(기존 실패 2스위트 해소로 추정 — 목록 대조 기준).

### 배운점
- 공유 레이아웃((auth))의 디자인 전환은 "파일 미수정 = 영향 없음"이 아니다 — /signup 파일을 안 건드려도 배경·폰트가 함께 바뀐다. 영향 범위는 파일이 아니라 렌더 트리로 판단.
- 스펙(44/48 반응형 버튼)과 격자 정본이 충돌하면 축을 임의 생성하지 않고 보고 → 격자 우선으로 수렴.

## 결정 (Decisions)

- auth 배경은 body 토큰 위임 — 랜딩 페어(사진+글래스) 폐기. glass-outer/glass-form의 auth 소비처 소멸(유틸 자체는 존치 — 정리 여부 별건).
- `data-allow-landscape` 유지 — 근거가 "2단 레이아웃"에서 "단일 폼은 가로에서 안 깨짐"으로 교체 (주석 현행화).
- auth 카드 폭 max-w-[400px]은 로컬 리터럴 — 토큰화는 auth 네 화면 완성 후 공통값이 보이면 판정.
- 비밀번호 재설정 경로 레포에 없음 — "비밀번호 찾기" 링크 미배치 (신규 구현은 별건).

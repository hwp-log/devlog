## 1. 한 줄 요약

플랜 항목의 장소를 자유 타이핑에서 검색-선택으로 바꾸고(0493-1), 그 좌표로 실제 `Spot`과

자동 재사용 판정을 "거리만"에서 "거리 + 이름 정규화 일치"로 교정했다(0496).

## 2. 왜 / 목적 / 이유

- 왜 `PlanSpot.lat/lng`가 `0,0` 하드코딩이었는지, 왜 이 시점에 되살렸는지

### 0493-1 — 검색-선택 필드 (`PlaceSearchInput.tsx` 신규 134줄)

`searchPlaces` 재사용. 디바운스·seq 가드는 SpotMap의 관용구 이식(상수값 동일).

```tsx
const SEARCH_DEBOUNCE_MS = 300;
const MIN_SEARCH_LEN = 2;

// seq 가드: 늦게 보낸 요청이 먼저 도착해 최신 결과를 덮는 것 방지(SpotMap 0396 ①).
const seq = ++searchSeqRef.current;
const result = await searchPlaces(kw);
if (seq !== searchSeqRef.current) return; // 스테일 응답 폐기
```

`PlanItem`에 화면 전용 메타 추가:
```ts
// 검색-선택한 장소 메타 — 화면 상태에만 보관(저장 payload 미포함, 다음 단계).
place?: { id: string; lat: number; lng: number; address: string };
```

타이핑하면 `place: undefined`로 무효화(선택 메타와 이름의 어긋남 차단).
결과 목록 폭은 입력칸에서 분리(`w-[min(20rem,calc(100vw-2rem))]`), wrapper 도입으로
사라진 최소 폭 바닥은 `min-w-[8rem]`으로 복원.

### 0493-3 — 좌표 nullable화 + `0,0` 폐기 (마이그레이션 `20260804123000_planspot_coords_nullable`)

```sql
ALTER TABLE "plan_spots" ALTER COLUMN "lat" DROP NOT NULL;
ALTER TABLE "plan_spots" ALTER COLUMN "lng" DROP NOT NULL;
-- 기존 156행은 전부 place 없이 생성된 0,0(spot_id 전무·가짜값) → NULL 정리(백필 아님, 가짜 제거).
UPDATE "plan_spots" SET "lat" = NULL, "lng" = NULL WHERE "spot_id" IS NULL AND "lat" = 0 AND "lng" = 0;
```

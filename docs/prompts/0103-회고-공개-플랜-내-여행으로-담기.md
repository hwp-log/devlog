# 0103 회고: 공개 플랜을 내 여행으로 담는 기능 추가

- 작성일: 2026-06-14
- 소요: 약 2시간
- 관련 커밋: 57720b6 `feat: 0103 공개 플랜을 내 여행으로 담는 기능 추가`

---

## 1. 한 줄 요약

공개 플랜을 본인 마이플랜으로 복사하는 "내 여행으로 담기"를 추가했다. 일정·동선·소개·지역·작품은 복사하되 비용은 제외해, 0097부터 막아온 남의 정밀 지출이 복사를 통해 내 손에 들어오는 우회로를 차단했다. 출처는 원본 id(`sourcePlanId`)와 담던 시점의 작성자 닉네임 스냅샷(`sourceNickname`) 둘 다 기록하고, 본인 플랜에는 담기 버튼을 띄우지 않는다.

---

## 2. 왜 / 목적 / 이유

### 일정·동선은 복사, 비용은 제외

- 왜: 비용은 작성자의 사생활 정보(PII)다. 공개 상세에서도 정밀 금액은 미전송하고 가공 구간만 보여줬는데(0097), "담기"는 공개 플랜을 마이플랜으로 복사하는 것이고 마이플랜은 정밀 비용을 그대로 보여주는 화면이다. 비용까지 복사하면 가공·미전송으로 막아둔 남의 정밀 지출이 내 마이플랜에 정밀값으로 들어오는 우회로가 생긴다.
- 목적: 여행 코스(일정·동선·소개·지역·작품)는 따라 담되, 남의 정밀 비용은 어떤 경로로도 내 손에 들어오지 않는 상태.
- 이유: 복사 트랜잭션에서 spots(일정·동선)와 메타(제목·소개·지역·작품·통화)만 복사하고 cost 관련은 select·복사 대상에서 모두 제외했다. 코스는 따라 가되 지갑은 베끼지 않는다 — 0097 정밀 미전송 원칙의 연장.

### 출처를 id + 닉네임 스냅샷 둘 다 기록

- 왜: `sourcePlanId`로 원본을 조회하면 작성자 닉네임도 따라온다. 하지만 그건 지금 원본이 살아 있고 작성자가 닉네임을 안 바꿨을 때만이다. 원본 작성자가 닉네임을 바꾸면 조회 결과가 "담을 때의 그 사람"과 달라지고, 원본이 삭제되면 조회 자체가 안 돼 출처가 통째로 사라진다.
- 목적: 원본이 바뀌거나 사라져도 "담을 때 누구 걸 담았는지"가 내 플랜에 그대로 남는 상태.
- 이유: 담는 시점의 작성자 닉네임을 `sourceNickname`에 스냅샷으로 박아뒀다. id는 "지금 살아 있으면 찾아가는 링크", 닉네임 스냅샷은 "담던 순간을 박제한 기록"이라 역할이 다르다. 0097에서 마이플랜 복사가 `sourceStoryId`를 FK 관계 없는 plain String으로 둔 것과 같은 결 — 살아 있는 연결(FK)이 아니라 끊어져도 남는 스냅샷이다.

### 본인 플랜에는 담기 버튼 미표시

- 왜: 내 플랜을 내가 담는 건 의미가 없다. 같은 코스를 중복 생성할 뿐이다.
- 목적: 담기 버튼이 남의 공개 플랜에만 뜨고, 본인 플랜에는 안 뜨는 상태.
- 이유: 서버에서 `isOwner`(현재 유저 == 플랜 owner)를 계산해 CostPlanDetail로 넘기고, `!isOwner`일 때만 담기 버튼을 렌더한다.

## 4. 코드 작성 & 수정

### 신규: `app/(protected)/cost-plan/[id]/actions.ts` — copyPublicPlanAction

공개 플랜만 조회 → 트랜잭션으로 spots만 복사(비용 제외) → 출처·작성 중 상태 기록.

```ts
export async function copyPublicPlanAction(planId: string): Promise<{ error: string } | undefined> {
  const supabase = await createClient();
  const { data: { user } } = await supabase.auth.getUser();
  if (!user) redirect('/login');

  const original = await prisma.myPlan.findFirst({
    where: { id: planId, isPublic: true },   // 공개 플랜만
    select: {
      title: true, description: true, region: true, movie: true, currency: true,
      owner: { select: { nickname: true } },           // 스냅샷용 닉네임
      spots: {                                          // 코스만 — cost select 없음
        select: { day: true, order: true, name: true, lat: true, lng: true },
        orderBy: { order: 'asc' },
      },
    },
  });
  if (!original) return { error: '원본 플랜을 찾을 수 없습니다' };

  try {
    await prisma.$transaction(async (tx) => {
      const plan = await tx.myPlan.create({
        data: {
          ownerId: user.id,
          isPublic: false,
          isDraft: true,                       // 작성 중 상태
          sourcePlanId: planId,                // 원본 링크
          sourceNickname: original.owner.nickname,   // 담던 시점 닉네임 스냅샷
          title: original.title, currency: original.currency,
          description: original.description, region: original.region, movie: original.movie,
        },
      });
      for (const spot of original.spots) {     // 일정·동선만 복사, 비용 제외
        await tx.planSpot.create({
          data: { planId: plan.id, day: spot.day, order: spot.order, name: spot.name, lat: spot.lat, lng: spot.lng },
        });
      }
    });
  } catch {
    return { error: '복사 중 오류가 발생했습니다' };
  }
  redirect('/my-plan');
}
```

### 신규: `app/(protected)/cost-plan/[id]/CopyCostPlanButton.tsx`

```tsx
'use client';
export function CopyCostPlanButton({ planId }: { planId: string }) {
  const [isPending, startTransition] = useTransition();
  const handleCopy = () => {
    startTransition(async () => {
      const result = await copyPublicPlanAction(planId);
      if (result?.error) alert(result.error);
    });
  };
  return (
    <button type="button" onClick={handleCopy} disabled={isPending} className="...">
      {isPending ? '담는 중...' : '내 여행으로 담기'}
    </button>
  );
}
```

## 5. 결과 / 배운점

- 검증 통과: 담기 → 내 마이플랜에 코스(일정·동선) 복사·비용 없음·작성 중 상태, 원본 닉네임이 sourceNickname에 스냅샷으로 기록, 본인 플랜엔 담기 버튼 없음, 담은 플랜 상세에 "원본 플랜 보기" 링크, migrate·tsc 통과.
- 배운점 1: 복사 기능은 보안 경계를 우회하는 새 통로가 될 수 있다. 공개 상세에서 정밀 비용을 미전송으로 막아도, 담기에서 비용까지 복사하면 그 비용이 마이플랜 화면에 정밀값으로 부활한다. "무엇을 복사하느냐"를 정할 때 PII가 경계를 넘지 않는지 함께 봐야 한다 — 코스는 담되 지갑은 베끼지 않는다.
- 배운점 2: 링크와 스냅샷은 역할이 다르다. id는 원본이 살아 있을 때 찾아가는 연결이고, 닉네임 스냅샷은 원본이 바뀌거나 사라져도 "담던 순간"을 박제하는 기록이다. 출처처럼 시점이 중요한 정보는 살아 있는 조회(FK)에만 의존하지 말고 스냅샷으로 박아둔다 — 0097 sourceStoryId와 같은 결.
- 배운점 3: 멱등 마이그레이션. is_draft는 `DEFAULT false`로 기존 행이 자동으로 채워지고, source_nickname은 nullable이라 백필이 필요 없다. `IF NOT EXISTS`로 재실행해도 안전하다.

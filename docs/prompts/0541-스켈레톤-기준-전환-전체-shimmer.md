## 1. 한 줄 요약

0539 "틀 실물 + 데이터만 shimmer"가 실화면 검수에서 기각되어, §11 판단 기준을 "틀이 데이터에 의존하는가" → **"실물로 남길 게 한두 줄인가"**(기본 = 골격 전체 shimmer)로 전환하고 mypage/loading.tsx를 전체 shimmer로 재작성.

---

## 2. 왜 / 목적 / 이유

- **왜**: 실화면 검수 판정 — "전체가 로딩 화면으로 보여야 하는데 뼈대가 먼저 선행 표시된 게 이상하다." 실물 텍스트가 화면 절반이면 로딩 화면이 읽을거리가 되어 사용자가 "온 것/아직"을 판단하게 된다.
- **근거 보강**: 웹 권고 동일 — 스켈레톤은 주요 구조 요소에만 자리표시자, 라벨·버튼·폼 필드 같은 작은 요소는 표현에서 제외(실물로 그리는 게 아니라 안 그림). Netflix도 포스터·제목·설명 전부 회색 블록.
- **0413과의 관계**: "정적 텍스트는 실물 렌더"는 목록 헤더 한두 줄에서 나온 판단 — 적용 범위를 "화면 크롬 수준 한두 줄" 예외로 한정.

## 4. 코드 작성 & 수정

### §11 재작성 (CLAUDE.md)

기본·기준 전환·기각 이력·0413 범위 한정·구조선 실색 공통을 명기. 공통 원칙(1벌 공유·조건부 대표형·리터럴 준용·줄높이 산식)·금지·포인터·체크리스트는 유지하되 체크리스트 1번을 "실물로 남길 게 한두 줄인가"로 수정.

### mypage/loading.tsx 재작성

조판·폭 토큰·짝 주석·줄높이 산식은 0539 그대로, 실물 텍스트를 전부 회색 블록으로:

```tsx
// 인사말 — h1 arbitrary text-[26px]/[28px] → lh 상속 1.5 = 39/42px 박스 안 바
<div className="h-[39px] sm:h-[42px] flex items-center">
  <div className="h-7 sm:h-8 w-56 rounded skeleton-shimmer" />
</div>
// 버튼·input — 통 블록, 높이는 실물 산식 주석 (h-[52px]=py26+lh24+border2 등)
// WarningBox — h-[192px] 근사 블록 (문안 줄바꿈 폭 의존, 산식 주석)
// 구조선(2px 실선·hairline·카드 테두리)만 실색 유지
```

### StoryWriteSkeleton(0491) 판단 — 재작성 대상 아님

실물 텍스트 0개(전부 shimmer 바), 실물은 구조선뿐 — 새 기준에 이미 부합. §11에서 소속을 "전체 shimmer 계열"로 정정만.

## 5. 결과 / 배운점

### 결과
- `npx tsc --noEmit` 통과. 커밋 문서·코드 분리(43229a9 / 70f23d9).
- 미커밋 0539 회고 초안의 기각된 결정 2건에 [0541 정정] 취소선 주기.
- 잔여 근사 1건: WarningBox 블록 높이(h-[192px])는 문안 줄바꿈이 폭 의존이라 데스크톱 1줄 기준 근사 — 모바일에서 수 px 시프트 가능(뷰포트 하단이라 체감 미미).

### 배운점
초안 — 스켈레톤에 실물 텍스트가 섞이면 "부분 로드"로 읽힌다 — 로딩 상태는 단일 신호여야 하고, 0413의 "실물 렌더" 판단은 규모(한두 줄)가 전제였다

## 결정 (Decisions)

- 스켈레톤 기본 = 골격 전체 shimmer, 예외 = 화면 크롬 한두 줄 (0539 2형 구분 폐기, CLAUDE.md §11 정본)
- 0413 "정적 텍스트 실물 렌더"의 적용 범위를 크롬 예외로 한정
- 구조선(실선·hairline·카드 테두리)은 전 방식 공통 실색 — shimmer 대상은 텍스트·콘텐츠 면만

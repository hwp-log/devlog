### 0502 — 출발지 = 직전 장소 (앱 스킴·인텐트만)

```ts
// 0502: origin(선택) — 출발지. 앱 스킴/인텐트에만 slat/slng/sname으로 실음(공식 지원, WGS84 그대로).
//       미지정이면 현행대로 목적지만(출발지는 네이버 앱이 현재 위치로 잡음).
const startQuery = origin
  ? `slat=${origin.lat}&slng=${origin.lng}&sname=${encodeURIComponent(origin.name)}&`
  : '';
```

호출부 — 같은 날 order상 직전 항목:
```tsx
// 0502: 출발지 = 같은 날 order상 직전 항목(items는 order asc). 그날 첫 항목이거나
//       직전 항목에 좌표가 없으면 undefined → 현행처럼 목적지만.
const prev = i > 0 ? items[i - 1].spot : null;
const origin = prev && prev.lat != null && prev.lng != null
  ? { name: prev.name, lat: prev.lat, lng: prev.lng } : undefined;
```

### 0503 — 웹 URL 출발지 슬롯

```ts
// 0503: 웹 URL 출발지 슬롯. 실브라우저로 {lng},{lat},{name} 형식 동작 확인 → origin 있으면 채우고
//       없으면 현행대로 '-'(빈 슬롯 = 출발지 미지정). 좌표계 WGS84 그대로.
```

## 5. 결과 / 실측

- 플랫폼 분기(기존 구조 유지): Android → `intent://`(미설치 시 마켓 폴백) /
  iOS → 스킴 시도 후 2초 내 전환 실패 시 App Store / 그 외 → 웹 길찾기 새 탭.
- 웹 길찾기 URL 형식(`map.naver.com/p/directions/{출발}/{도착}/-/transit`)은 **공식 문서 부재 —
  실측 확증분**(파일 상단 주석). 0503의 출발지 슬롯도 실브라우저 시험으로 확인.
- 앱 스킴 파라미터(`slat`/`slng`/`sname`)는 NCP 공식 문서 지원 범위.
- 모바일 터치 타겟 44px 확보 (CLAUDE.md §5) — 이 구현이 카드 높이를 밀어 **트랙 7(0508)의 문제**가 됨.

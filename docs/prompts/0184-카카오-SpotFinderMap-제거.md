# 0184 회고: 카카오 SpotFinderMap 제거 — 네이버 전환 완료분 정리

작성일: 2026-07-13 / 소요: 약 30분 / 커밋: 6145582

## 1. 한 줄 요약
롤백용으로 남겨둔 카카오 지도 컴포넌트(419줄)를 삭제했다 — 죽은 코드가 처음으로 비용을 청구한 순간에.

## 2. 왜 / 목적 / 이유
- **왜**: S2 읽기 전환에서 공유 타입을 바꾸자, 라이브 임포트가 없는 카카오 변형도 tsc 컴파일 대상이라 함께 깨졌다. CC가 "리네임만 이식해 롤백 유지"를 제안했다.
- **목적**: 죽은 파일에 새 필드를 이식하는 대신 삭제. S3·S4마다 죽은 파일을 따라 고치는 세금을 끊는다.
- **이유**: 롤백은 git 히스토리로 충분하다. 코드베이스를 백업 저장소로 쓰지 않는다. 타입 몇 줄 맞춰둔다고 실제 롤백(SDK·키·클러스터링 전체)이 가능해지는 것도 아니다 — 롤백 가능성의 착시였다.

## 3. 작성한 프롬프트
```
중단. SpotFinderMap.tsx(카카오) 처리 방침을 바꾼다.
리네임 이식 금지. 이 파일은 삭제한다.
1. components/SpotFinderMap.tsx 삭제
2. 삭제 후 tsc --noEmit으로 잔여 참조 전수 확인
3. 카카오 지도 SDK·키·기타 잔재가 함께 죽는지 보고만 (제거는 별도 커밋)
4. 삭제는 C1과 분리해 선행 커밋으로
```

## 4. 작성·수정한 코드
```
D components/SpotFinderMap.tsx        (419줄 삭제)
M components/SpotFinderMapWrapper.tsx (댕글링 주석 "카카오 롤백 = 1줄 리버트" → "네이버 지도 사용")
```

## 5. 결과 / 교훈
- 2파일 1+/420-. 순삭제 커밋.
- 카카오 SDK 자체는 SpotMap.tsx(스토리 작성)가 아직 사용 중이라 유지 — "카카오 SDK 제거" 로드맵은 SpotMap 네이버 전환이 선행 조건임이 확정됐다.
- 교훈: **죽은 코드는 놔두는 동안은 공짜지만, 구조가 바뀌는 순간부터 사이클마다 세금을 걷는다.** 삭제 판단의 근거는 "안 쓰니까"가 아니라 "이제부터 세금을 내야 하니까".

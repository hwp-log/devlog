# 0204 회고: 공유 스팟 작품 기록 서버 차단

작성일: 2026-07-14 / 소요: 약 20분 / 커밋: e9c0440

## 1. 한 줄 요약
UI의 disabled는 우회 가능하다 — 서버에서 reusedSpotId면 SpotMovie 기록을 차단해 공유 자산 오염을 막았다.

## 2. 왜 / 목적 / 이유
- **왜**: 0203의 잠금은 UI뿐 — DevTools로 payload를 조작하면 movieId를 보낼 수 있고, 그러면 공유 스팟(SpotMovie)에 작품이 추가돼 전원에 영향.
- **목적**: 작성 경로는 `if (spot.movieId && !spot.reusedSpotId)` 조건, 수정 경로는 재사용 루프의 spotMovie.upsert 블록 제거.
- **이유**: **UI 검증은 UX, 서버 검증은 보안** — clampRating(0199)과 같은 층. 두 경로(작성·수정) 모두 막아야 구멍이 없다.

## 3. 작성한 프롬프트
0203 승인문에 서버 방어 함의 포함 → CC가 양 경로에 적용, diff로 확인 후 커밋.

## 4. 작성·수정한 코드
```ts
// new/actions.ts
if (spot.movieId && !spot.reusedSpotId) { await tx.spotMovie.upsert(...) }
// [id]/actions.ts — 재사용 스팟 루프에서 spotMovie.upsert 제거 (StorySpot만 upsert)
```

# 0313 회고: 글쓰기 레이아웃 개편 1차 — 헤더 눈썹·폼 카드 제거·SpotMap 좌우 반전

작성일: 2026-07-22 / 소요시간: 약 1.5시간 / 관련 커밋: ef29cbb (feat: 0313)

## 1. 한 줄 요약

new·edit 헤더에 눈썹+타이틀을 신설하고, 폼을 감싸던 카드 박스를 제거해 폼과 SpotMap을 같은 정렬선에 놓았으며, SpotMap을 지도 좌·목록 우로 반전했다. 폭 최종값(폼 760 + SpotMap 확폭)은 표준 2중 검증까지 마치고 다음 커밋으로 넘겼다.

## 2. 왜 / 목적 / 이유

**왜(동기·문제)** — 리스타일(0312) 후에도 화면이 시안과 다르게 느껴졌다. 원인을 추적하니 색이 아니라 구조였다: ① 시안에 있던 눈썹+타이틀이 실제 코드엔 처음부터 없었고(시안 이미지를 실물로 착각하고 있었음 — CC grep으로 확인) ② 폼은 카드 박스 안(p-8 안쪽), SpotMap은 박스 밖이라 좌우 라인이 어긋났고 ③ SpotMap이 시안(지도 좌)과 반대(목록 좌)였다.

**목적(목표 상태)** — 글쓰기 화면의 뼈대가 시안 구조와 일치하게 한다: 눈썹+타이틀 헤더, 폼·SpotMap이 하나의 세로 흐름으로 정렬, 지도가 왼쪽.

**이유(결정 근거)**
- **눈썹 신설·보조문구 제거**: 기존 화면(STORY·SpotFinder)이 전부 "눈썹+타이틀만"이라 일관성. 보조문구는 추상적이면 인지 부하만 늘린다는 현우 판단 → new 타이틀도 감성 카피("화면 속 한 장면을…") 대신 실용 카피("다녀온 촬영지를 이야기로 남겨보세요")를 승격.
- **폼 카드 제거**: 박스가 있으면 폼만 패딩만큼 안으로 들어가 SpotMap과 어긋난다. 두 안(박스 유지+정렬 vs 박스 제거)을 시안으로 비교해 제거 확정.
- **좌우 반전은 DOM 순서 교체**: flex-row-reverse는 시각만 뒤집고 읽기 순서(a11y)는 그대로라, 자식 순서 자체를 [지도, 카드]로 교체. 모바일 세로 스택(지도 위)도 자동으로 시안과 일치.
- **폭은 이번 커밋에서 제외**: "폼·SpotMap 760 동일"로 갔다가 실화면에서 지도 444px가 너무 작음을 발견 → 재검색으로 "텍스트 680~780 / 지도·미디어는 더 넓게"가 표준임을 확인(웹검색+퍼플렉시티 2중 검증) → "폼 760 + SpotMap만 확폭"으로 방향 수정. 값 미세조정이 남아 별도 커밋으로 분리.

## 5. 결과 / 교훈

- 헤더·정렬·지도 위치가 시안 구조와 일치. 타입체크·JSX 균형 통과, 지도 SDK 내부 무변.
- **교훈 1 — 시안 이미지와 실물 스크린샷을 혼동했다.** "new에는 눈썹이 이미 있다"고 반복 전제했는데 CC grep 결과 코드에 없었다. 추측 금지 원칙이 사람(과 AI)의 착각까지 잡아낸 사례 — 구조 작업 전 "읽고 보고만" 확인이 이번에도 방향을 바꿨다.
- **교훈 2 — 시안값은 도구 제약의 산물일 수 있다.** 아침에 정한 760px 통일은 Visualizer(680px 고정폭) 안에서 그럴듯해 보였지만, 실화면에선 지도가 444px로 쪼그라들었다. 표준 재검색으로 "텍스트 폭과 지도 폭은 기준이 다르다"를 확인하고 방향을 수정했다. 시안 → 실화면 → 표준 재검증의 루프를 돌아야 한다.
- **교훈 3 — 화면마다 폭이 다른 건 비일관성이 아니다.** SpotFinder는 풀블리드, 글쓰기는 좁게 — 콘텐츠 유형별 폭 최적화(텍스트=가독 폭, 지도=전폭)가 표준이며, 일관성은 폭이 아니라 눈썹 문법·토큰·컴포넌트에서 지킨다.
- **교훈 4 — 큰 작업은 완결 단위로 커밋을 쪼갠다.** 반전·헤더는 확정이라 커밋하고, 폭은 미세조정이 남아 다음 커밋(0314 예정)으로 분리했다. 새벽에 피곤한 상태로 폭 값까지 밀어붙였으면 또 번복됐을 것.

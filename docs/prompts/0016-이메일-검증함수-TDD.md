## 판단근거 (왜)

### 왜 첫 TDD 대상으로 이메일 검증 함수를 골랐나

- **순수 함수**: 외부 의존성 0 (Supabase, DB 등 mock 불필요)
- **명확한 입출력**: string → boolean
- **재사용 가능**: 로그인, 회원가입 양쪽에서 사용
- **케이스 발굴 쉬움**: 명백한 유효/무효 입력 구분 가능
- **학습 진입 장벽 낮음**: TDD 흐름 자체에 집중 가능

### 왜 lib/auth/ 위치인가

- 인증 비즈니스 로직 모음 (Supabase 인프라와 분리)
- `app/(auth)/`는 라우팅/UI, `lib/auth/`는 로직
- "한 파일 한 책임" 원칙 적용

### 왜 학습 사이클로 진행했나

- TDD 첫 경험 → 흐름 체득이 우선

- 한 단계씩 시키며 매 단계 검증 → AI 통제 메커니즘 손에 익힘

## 함수의 진화 흔적

코드 자체는 4번의 개선을 거쳤다:

### 사이클 1 (Green)

```typescript
export function isValidEmail(email: string): boolean {
  return false;
}
```

### 사이클 2 (Green - Fake It)

```typescript
export function isValidEmail(email: string): boolean {
  if (email === '') return false;
  if (email === 'user@example.com') return true;
  return false;
}
```

### 사이클 3 (Green - 일반화 시작)

```typescript
/**
 * 이메일 형식 검증 함수
 * @ 문자 포함 여부로 1차 형식 검증
 */
export function isValidEmail(email: string): boolean {
  return email.includes('@');
}
```

### 사이클 4 (Green - 최종)

```typescript
/**
 * 이메일 형식 검증 함수
 * @ 앞뒤로 문자가 있는지 검증
 */
export function isValidEmail(email: string): boolean {
  const [local, domain] = email.split('@');
  return Boolean(local && domain);
}
```

개선 흔적이 코드에는 남지 않지만, 각 단계에서 케이스가 추가되면서 자연스럽게 일반화로 수렴했다.

- Fake It Till You Make It (사이클 1, 2)
- Triangulation (사이클 3 — 같은 카테고리 다른 입력으로 가짜 깨뜨림)
- 점진적 일반화 (사이클 3, 4 — 케이스 누적이 일반 패턴 유도)

**적용하지 않은 것:**
- Refactor 단계 (Green 결과가 이미 깔끔해서 불필요)
- 정규식 도입 (split + Boolean으로 충분)
- Edge case 모두 커버 (실용적 범위에서 멈춤)

## 발견한 통찰

본 사이클에서 발견한 학습 통찰들 (블로그 글감):

1. **TDD가 AI 출력 분포를 좁힘** — 테스트가 명세 역할을 하여 AI의 답이 수렴
2. **AI 의인화의 함정** — AI는 stress 받지 않음. 토큰 확률 분포가 본질
3. **TDD = 함수 공간에서의 소거법** — 조건 추가로 답 공간 점진적 축소
4. **AI 할루시네이션은 자유의 산물** — 범위 제한이 할루시네이션 차단
5. **TDD는 통념의 명문화** — 모호한 "이래야 한다"를 명확한 명세로 변환
6. **AI를 후임처럼 다루기** — 위치 명시 + 범위 명시가 좋은 지시의 본질
7. **기계어 로직은 AI, 본질은 인간** — 사용자가 두 테스트로 '@' 핵심성 발견. AI는 그것을 코드로 구현
8. **다층 하네스** — CLAUDE.md(규칙) + TDD(검증) + 정보 흐름 분리(구조) + Plan Mode(승인) + 단위 커밋(롤백)
9. **AI 시스템 경계 인식** — 웹 Claude / 클로드 코드 / npm test는 별개 시스템. 사용자가 정보 다리
10. **CLAUDE.md 진화 전략** — 한 번에 완벽 불가. 사이클마다 약점 발견 시 보강
11. **약속 기반 통제 vs 구조 기반 통제** — 구조가 약속을 이김
12. **AI 코드 검증의 4 Layer** — 문법(자동), 테스트(자동), 의도 일치(사람), 설계 적절(사람)

이 통찰들은 추후 블로그 시리즈로 정리 예정.

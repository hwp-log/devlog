## 2. 왜 / 목적 / 이유

### 드래그 정렬 인터랙션

- **왜**: 0047 폴리라인 + 색상 분기 완료 후 마커 순서가 클릭 순서로 고정됨. 사용자가 순서를 변경하려면 마커 삭제 후 다시 추가해야 하는 불편 발생.
- **목적**: 마커 목록 UI에서 드래그로 순서 변경. 출발/도착 색상도 새 순서에 따라 자동 갱신.
- **이유**: 영화/드라마 촬영지 컨셉상 "여러 지역 이동"이 핵심이라 순서 변경이 잦은 사용 시나리오. dnd-kit 채택 = 현대적 + 접근성 + React 18+ 호환 + 약 10kb.

### Prisma $transaction + 권한 검증

- **왜**: 마커 순서 변경 시 모든 spot의 `order` 필드를 동시에 갱신해야 함. 한 spot만 갱신하면 `order` 충돌 발생. 다른 사용자의 spot을 갱신하는 보안 경로 차단 필요.
- **목적**: 모든 spot의 `order` 갱신을 단일 트랜잭션으로 보장. 부분 실패 시 전체 롤백.
- **이유**: `$transaction` 배열 형식 = Prisma 표준 패턴. `where: { id: spotId, storyId }` 이중 권한 검증 = 다른 `storyId`의 spot 갱신 시도 차단. `count` 검증 추가 = `spotIds` 모두 해당 `storyId` 소유 보장.

### 낙관적 UI + 비동기 cleanup 함정

- **왜**: 드래그 끝에 서버 응답을 기다리면 UX가 답답함. 낙관적 UI로 즉시 반영 + 실패 시 롤백 필요. 추가로 드래그 직후 비동기 fetch 진행 중에 `revalidatePath`로 SpotMap 리마운트 발생 → 옛 map 인스턴스에 `getSource` 호출 → TypeError 발생.
- **목적**: 낙관적 UI로 즉시 반영 + 비동기 cleanup 패턴으로 stale closure 함정 차단.
- **이유**: `useState localSpots` + `setLocalSpots`로 낙관적 갱신 + `prev` 참조로 롤백. `useEffect` cleanup에서 `cancelled` 플래그 토글 + 비동기 경계마다 `cancelled` 체크 = 리마운트 후 옛 작업 무효화.

### 4-2. components/SpotList.tsx (신규)

dnd-kit의 `SortableContext` + `useSortable`을 활용한 드래그 가능한 마커 목록.

```typescript
'use client';

import {
  DndContext, closestCenter, KeyboardSensor, PointerSensor,
  useSensor, useSensors, type DragEndEvent,
} from '@dnd-kit/core';
import {
  SortableContext, sortableKeyboardCoordinates, useSortable,
  arrayMove, verticalListSortingStrategy,
} from '@dnd-kit/sortable';
import { CSS } from '@dnd-kit/utilities';
import { GripVertical } from 'lucide-react';
import type { Spot } from '@prisma/client';
import { getSpotColor } from '@/lib/spot-color';

function SortableItem({ spot, index, total, isReordering }: SortableItemProps) {
  const { attributes, listeners, setNodeRef, transform, transition, isDragging } =
    useSortable({ id: spot.id });

  const color = getSpotColor(index, total);
  const canDrag = total > 1 && !isReordering;

  return (
    <li
      ref={setNodeRef}
      style={{ transform: CSS.Transform.toString(transform), transition }}
      className={`flex items-center gap-2 px-3 py-2 bg-white rounded-lg border border-black/[0.08] ${isDragging ? 'opacity-50 shadow-lg' : ''}`}
    >
      <span
        className="w-5 h-5 rounded-full flex-shrink-0 text-white text-[10px] font-bold flex items-center justify-center"
        style={{ backgroundColor: color }}
      >
        {index + 1}
      </span>
      <span className="flex-1 text-sm text-[#1A1A1A] truncate">{spot.name}</span>
      <button
        type="button"
        aria-label="드래그 핸들"
        className={`text-slate-400 flex-shrink-0 transition-colors ${
          canDrag ? 'cursor-grab active:cursor-grabbing hover:text-slate-600' : 'cursor-default opacity-30'
        }`}
        {...(canDrag ? { ...attributes, ...listeners } : {})}
      >
        <GripVertical size={16} />
      </button>
    </li>
  );
}

export function SpotList({ spots, onReorder, isReordering }: SpotListProps) {
  const sensors = useSensors(
    useSensor(PointerSensor),
    useSensor(KeyboardSensor, { coordinateGetter: sortableKeyboardCoordinates })
  );

  function handleDragEnd(event: DragEndEvent) {
    const { active, over } = event;
    if (!over || active.id === over.id) return;
    const oldIndex = spots.findIndex((s) => s.id === active.id);
    const newIndex = spots.findIndex((s) => s.id === over.id);
    onReorder(arrayMove(spots, oldIndex, newIndex));
  }

  return (
    <DndContext sensors={sensors} collisionDetection={closestCenter} onDragEnd={handleDragEnd}>
      <SortableContext items={spots.map((s) => s.id)} strategy={verticalListSortingStrategy}>
        <ul className="flex flex-col gap-1">
          {spots.map((spot, i) => (
            <SortableItem key={spot.id} spot={spot} index={i} total={spots.length} isReordering={isReordering} />
          ))}
        </ul>
      </SortableContext>
    </DndContext>
  );
}
```

### 4-3. app/story/[id]/spots/actions.ts (reorderSpots 추가)

기존 `createSpot` 유지. 권한 검증 3단계 + `$transaction` 추가.

```typescript
export async function reorderSpots(
  storyId: string,
  spotIds: string[]
): Promise<{ error: string } | { ok: true }> {
  const supabase = await createClient();
  const { data: { user } } = await supabase.auth.getUser();
  if (!user) return { error: '로그인이 필요합니다' };

  const story = await prisma.story.findUnique({ where: { id: storyId } });
  if (!story || story.userId !== user.id) return { error: '권한이 없습니다' };

  const count = await prisma.spot.count({ where: { id: { in: spotIds }, storyId } });
  if (count !== spotIds.length) return { error: '잘못된 요청입니다' };

  await prisma.$transaction(
    spotIds.map((spotId, i) =>
      prisma.spot.update({
        where: { id: spotId, storyId },
        data: { order: i + 1 },
      })
    )
  );

  revalidatePath(`/story/${storyId}`);
  revalidatePath(`/story/${storyId}/edit`);
  return { ok: true };
}
```

## 5. 결과 / 배운점

### 결과

- SpotList 표시 (마커 N개에 따라 색상 점 + 번호 + 이름 + 드래그 핸들)
- 드래그로 마커 순서 변경 작동 (낙관적 UI 즉시 반영)
- 색상 분기 동적 갱신 (예: 4번 마커가 1번으로 이동 시 초록으로 갱신)
- 새로고침 후 새 순서 유지 (`revalidatePath` 작동)
- 폴리라인 stale closure 함정 해결 (cleanup 패턴)

### 배운점

**1. dnd-kit 통합 패턴**
`DndContext` (sensors + collisionDetection + onDragEnd) 래핑 → `SortableContext` (items + strategy) 안에 `SortableItem`. `useSortable` hook으로 ref + transform + transition + isDragging 주입. `arrayMove`로 불변 배열 반환. `PointerSensor` + `KeyboardSensor` = 마우스 + 키보드 접근성 보장.

**2. Prisma $transaction = 무결성 보장**
배열 형식: `prisma.$transaction(spotIds.map((id, i) => prisma.spot.update(...)))`. 한 `update` 실패 시 전체 롤백 보장. `order` 충돌 없이 모든 spot 동시 갱신.

**3. 권한 검증 다층화**
1단계: `story.userId === user.id` (소유권). 2단계: `count({ where: { id: { in: spotIds }, storyId } }) === spotIds.length` (spotIds 전체 소유 확인). 3단계: `where: { id, storyId }` 조건으로 update 자체에도 권한 조건 포함.

**4. 낙관적 UI + 롤백 패턴**
낙관적 UI(Optimistic UI) = 좋아요 클릭처럼 거의 성공할 단순 기능에서 서버 응답 기다리지 않고 UI를 먼저 갱신하는 패턴. 서버 응답 시간(200ms~2초) 동안 사용자 체감 속도 개선이 목적. 실패 시 롤백.
`const prev = localSpots` (참조 보관) → `setLocalSpots(newSpots)` (즉시 반영) → 서버 응답 후 분기: 성공 = 유지, 실패 = `setLocalSpots(prev)`. `isReordering` 토글로 저장 중 race condition 방지.

**5. 비동기 cleanup 패턴 = stale closure 해결**
문제: 낙관적 UI 갱신 → useEffect 트리거 → fetch 시작 → 동시에 `revalidatePath` → 리마운트 → 옛 fetch 응답이 옛 map 호출 → TypeError. 해결: `let cancelled = false` + 비동기 경계마다 `if (cancelled) return` + cleanup에서 `cancelled = true`. 핵심: useEffect = 동기 cleanup뿐 아니라 진행 중인 비동기 작업도 무효화 필요.

**6. key 패턴 = 리마운트 트리거 설계**
`key={spots.length}` → 개수 변화 시만 리마운트 (드래그 정렬 = 개수 동일 → 리마운트 없음). `key={spots.map(s => s.id).join(',')}` → 순서 변경도 감지. `revalidatePath` 후 부모 재렌더 → 새 `spots` prop → key 갈음 → SpotMap 리마운트 → `useState` 초기값 재실행 → `localSpots` 동기화.

**7. 유틸 함수 분리 시점**
마커 색상 분기 로직이 SpotMap에서만 존재 → SpotList 추가 시 동일 로직 필요 발생 → `lib/spot-color.ts`로 분리. 한 곳 수정으로 양쪽 동기화 보장. 중복이 발생하는 시점이 분리 시점.

**8. dnd-kit 접근성**
`KeyboardSensor` + `sortableKeyboardCoordinates`로 키보드 드래그 가능. Tab으로 핸들 포커스 → Space로 grab → 화살표로 이동 → Space로 drop. `attributes` spread = role, tabIndex, aria-roledescription 자동 주입. 주의: `attributes` 조건부 spread 시 접근성 일부 제한 가능. MVP 단계 수용.

## 2. 왜 / 목적 / 이유

### 폴리라인 + 마커 색상 분기

- **왜**: 0046b 마커 추가 인터랙션 완료 후 경로 시각화 없음. 마커 색상이 모두 동일해 출발/도착 방향 불명확.
- **목적**: Mapbox Directions API 호출로 도로 따라 곡선 폴리라인 표시 + 색상으로 여행 순서 시각화.
- **이유**: 영화/드라마 촬영지 컨셉상 "여러 지역 이동"이 핵심 가치. 폴리라인 + 마커 색상 분기가 이 컨셉을 직관적으로 전달함.

### 폴리라인 타이밍 가드 (style.load → idle → loaded() 순서로 갈음)

- **왜**: 첫 시도에서 `style.load` 이벤트가 이미 발생한 후 등록되어 콜백이 영원히 호출되지 않음. `drawRoute` 미호출로 폴리라인 미표시.
- **목적**: 지도 객체 생성 시점과 사용 준비 시점 분리. `mapRef.current` truthy ≠ 라이브러리 사용 준비 완료.
- **이유**: `idle` 이벤트로 갈음 후에도 `isStyleLoaded()` 호출 시 콘솔 경고 부작용 발생. 최종적으로 `map.loaded()` + `once('load')` 패턴이 가장 안정적.

### 메쉬 에러 차단 시도 4개 후 받아들이는 결정

- **왜**: Mapbox Standard 스타일 v3의 GLB 모델 메쉬 렌더링 버그(GitHub issue #13341, 1년 5개월 미해결)로 콘솔에 `json.meshes is not iterable` 에러 지속 출력.
- **목적**: 콘솔 노이즈 차단으로 dev 작업 흐름 유지.
- **이유**: 4가지 시도(lightPreset 갈음 / `console.error` 가로채기 / `instrumentation-client.ts` / 환경변수) 모두 실패. Next.js 16의 에러 오버레이는 별도 경로라 차단 불가능. 비대칭 차단(콘솔 차단 / 오버레이 표시)보다 일관성(둘 다 표시) 선택. Production 영향 없음.

### 4-2. 폴리라인 useEffect 신규 (components/SpotMap.tsx)

타이밍 가드 3회 갈음 끝에 최종 확정된 `map.loaded()` + `once('load')` 패턴.

```typescript
// 폴리라인: spots 변경 시 Directions API 호출
useEffect(() => {
  if (!mapRef.current || spots.length < 2 || !token) return;
  const map = mapRef.current;

  const drawRoute = (geometry: GeoJSON.Geometry) => {
    const data = { type: 'Feature' as const, geometry, properties: {} };
    const existing = map.getSource('route') as mapboxgl.GeoJSONSource | undefined;
    if (existing) {
      existing.setData(data);
    } else {
      map.addSource('route', { type: 'geojson', data });
      map.addLayer({
        id: 'route-line',
        type: 'line',
        source: 'route',
        layout: { 'line-join': 'round', 'line-cap': 'round' },
        paint: {
          'line-color': '#fb923c',
          'line-width': 4,
          'line-opacity': 0.85,
          'line-emissive-strength': 1.0,
        },
      });
    }
  };

  const fetchAndDrawRoute = async () => {
    const coords = spots.map(s => `${s.lng},${s.lat}`).join(';');
    const url = `https://api.mapbox.com/directions/v5/mapbox/driving/${coords}?geometries=geojson&overview=full&access_token=${token}`;
    try {
      const res = await fetch(url);
      if (!res.ok) throw new Error('Directions API 실패');
      const data = await res.json();
      if (!data.routes || data.routes.length === 0) {
        console.warn('폴리라인: 경로를 찾지 못함');
        return;
      }
      drawRoute(data.routes[0].geometry);
    } catch (err) {
      console.error('폴리라인 오류:', err);
    }
  };

  if (map.loaded()) {
    fetchAndDrawRoute();
  } else {
    map.once('load', () => fetchAndDrawRoute());
  }
}, [spots, token]);
```

### 4-3. instrumentation-client.ts (작성 후 제거)

메쉬 에러 차단 시도를 위해 프로젝트 루트에 작성. Next.js `intercept-console-error`보다 먼저 실행되는 클라이언트 진입점.

```typescript
// instrumentation-client.ts
// Mapbox Standard 스타일 v3 메쉬 버그 콘솔 노이즈 차단 시도.
// Next.js intercept-console-error보다 먼저 실행되어 필터링 우선순위 확보 의도.

const originalError = console.error;
console.error = function (...args: unknown[]) {
  const firstArg = args[0];
  const message =
    firstArg instanceof Error
      ? firstArg.message
      : typeof firstArg === 'string'
      ? firstArg
      : '';

  if (message.includes('meshes is not iterable')) {
    return;
  }

  originalError.apply(console, args);
};

export {};
```

결과: `console.error`로 출력되는 콘솔 메시지는 차단 성공. 단, Next.js dev 모드 에러 오버레이는 별도 경로(window error 이벤트 또는 React Error Boundary)로 발생해 차단 불가능. 최종적으로 파일 삭제.

## 5. 결과 / 배운점

### 결과

- 폴리라인 정상 표시 (dusk 톤에서 orange-400 / `line-emissive-strength: 1.0` 적용으로 선명)
- 마커 색상 분기 작동 (출발=초록, 경유=파랑, 도착=빨강)
- 메쉬 에러는 콘솔에 출력된 채로 유지 (의도적 결정)

### 배운점

**1. vanilla JS 라이브러리 + React 통합**
`mapRef.current` truthy ≠ 라이브러리 사용 준비 완료. 객체 생성(동기)과 객체 준비(비동기)는 별개. Mapbox처럼 내부적으로 비동기 초기화가 있는 라이브러리는 준비 완료 시점을 별도로 확인해야 함.

**2. API 메서드의 부작용**
`isStyleLoaded()`는 boolean 반환이지만 스타일 미로드 상태에서 호출 시 콘솔 경고를 출력하는 부작용이 있음. getter처럼 보이는 메서드가 부작용을 가질 수 있다는 것을 Mapbox 소스에서 직접 확인.

**3. 이벤트 타이밍 함정**
`style.load`는 이미 발생한 후 등록하면 영원히 호출되지 않음. `map.loaded()` 체크 후 `false`일 때만 `once('load')` 등록하는 패턴이 안전.

**4. Next.js 16 instrumentation-client.ts 패턴**
클라이언트 진입점으로 다른 모듈보다 먼저 실행됨. 단, Next.js dev 에러 오버레이는 별도 시스템 경로라 `console.error` 가로채기로 차단 불가능. 전역 초기화, 퍼포먼스 모니터링 등에 적합. 에러 오버레이 차단 용도에는 부적합.

**5. Mapbox 3D 라이팅**
dusk 환경광이 라인 색을 어둡게 만듦. `line-emissive-strength: 1.0`으로 환경광 영향 차단해 라인 자체 색상 유지.

**6. 라이브러리 버그 받아들이는 결정**
우회 시도 4개 후 트레이드오프 분석으로 받아들이는 결정. 비대칭 차단(콘솔 차단 / 오버레이 표시)보다 일관성(둘 다 표시)이 더 명확한 상태. Production 영향 없음.

**7. 큰 서비스의 콘솔 에러 표준 패턴**
Facebook, YouTube, Naver, Coupang 등 대형 서비스에도 콘솔 에러가 존재함. 외부 의존성 통제 불가능 + 비즈니스 우선순위 + 에러 추적 도구로 fatal만 구분. 노이즈 vs 신호 구분이 시니어 개발자의 핵심 역량.

## 결정 (Decisions)

- **폴리라인 타이밍 가드**: `map.loaded()` + `map.once('load', ...)` 패턴 확정. `isStyleLoaded()` + `once('style.load')` 패턴 제거.
- **메쉬 에러**: Mapbox Standard v3 GLB 메쉬 버그는 라이브러리 자체 미해결 이슈. 차단 시도 없이 콘솔 표시로 결정.
- **폴리라인 색상**: `#fb923c` (orange-400). dusk 환경에서 amber-400보다 선명.
- **마커 색상**: 출발 `#16a34a` (green-600) / 경유 `#0ea5e9` (sky-500) / 도착 `#dc2626` (red-600).

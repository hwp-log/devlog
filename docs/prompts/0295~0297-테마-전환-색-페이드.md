## 1. 한 줄 요약

테마 전환의 "툭 바뀜"을 세 겹으로 완화 — ① globals.css `@layer base` 유니버설 색 3속성 transition(0.2s)으로 토큰 소비 요소 페이드 ② 지도는 재생성이라 CSS transition이 안 닿아, 재생성 구간을 bg-card 페이드 오버레이(tilesloaded 후 300ms 홀드)로 가림 ③ 재생성 없는 setOptions('customStyleId') 런타임 교체를 실험했으나 실기기 미반영으로 폐기, 재생성 확정.

---

## 2. 왜 / 목적 / 이유

- **왜**: 테마 라이트↔다크 전환 시 화면 전체 색이 툭 바뀌고, 특히 지도는 재생성이라 "빈 배경 번쩍 + 타일 촤락" 2단계로 튐. [사용자 확인 필요]
- **목적**: 색 속성만 부드럽게(업계 표준 150~300ms, reflow·물결 방지) + 지도 재생성 구간 은폐 + 재생성 자체를 없앨 수 있는지 타진.
- **이유**: transition은 비상속이라 유니버설 셀렉터가 표준 지점. 지도는 CSS 밖(재생성)이라 오버레이가 유일 수단. setOptions는 0284 "런타임 불가"가 추정 판정이었고 padding 선례가 있어 재검증할 가치가 있었음.

## 3. 작성한 프롬프트 (3작업)

- **0295 (색 페이드)**: globals.css 유니버설 색 transition(3속성, all 금지) + prefers-reduced-motion 해제.
- **0296 (지도 오버레이)**: 재생성 구간을 지도 래퍼 형제 bg-card 오버레이로 가림 — 발동은 이전 테마 ref 비교(첫 진입 제외), 해제는 tilesloaded once + 2s 안전망.

## 4. 코드 작성 & 수정 (최종 상태)

### 1. `app/globals.css` — @layer base 유니버설 색 룰

```css
@layer base {
  *, ::before, ::after {
    transition: background-color 0.2s ease, color 0.2s ease, border-color 0.2s ease;
  }
  @media (prefers-reduced-motion: reduce) {
    *, ::before, ::after { transition: none; }
  }
}
```
- **@layer base가 핵심**(조사 보고 정정): 비레이어 규칙은 캐스케이드 레이어상 특이도 무관하게 `@layer utilities`를 덮음 — base(<utilities)라 기존 transition-colors·시트 max-height·knob·[data-pill] 120ms가 항상 이겨 인터랙션 보존.

### 2. `components/SpotFinderMapNaver.tsx` — 지도 재생성 페이드 오버레이

```ts
// 상태·ref
const [themeFade, setThemeFade] = useState(false);
const prevThemeRef = useRef<string | null>(null);
// init effect 내 — 발동(전환만)·해제(tilesloaded once + 300ms 홀드)·안전망(2000ms)
const themeChanged = prevThemeRef.current !== null && prevThemeRef.current !== resolvedTheme;
prevThemeRef.current = resolvedTheme;
const fadeInTimer = themeChanged ? window.setTimeout(() => setThemeFade(true), 0) : undefined;
let holdTimer;
const tilesListener = themeChanged
  ? naver.maps.Event.once(map, 'tilesloaded', () => { holdTimer = window.setTimeout(() => setThemeFade(false), 300); })
  : undefined;
const failsafeTimer = themeChanged ? window.setTimeout(() => setThemeFade(false), 2000) : undefined;
// cleanup: tilesListener 제거 + 타이머 3종 clear (기존 뷰 캡처·destroy 무변)
// 오버레이 JSX — 지도 래퍼 안 mapSlot 형제
<div aria-hidden className={`pointer-events-none absolute inset-0 z-20 bg-card
  transition-opacity duration-[250ms] ease-[cubic-bezier(0.25,0.1,0.25,1)]
  ${themeFade ? 'opacity-100' : 'opacity-0'}`} />
```

### 3. setOptions 실험 — 최종 코드에 없음(폐기)

`setOptions('customStyleId')` 런타임 교체는 실기기에서 호출만 통과하고 스타일 미반영 → `RECREATE_ON_THEME_CHANGE` 스위치·전환 effect·마커 setIcon 갱신을 전량 제거, init effect는 0284 재생성 원상 복귀. 판정 근거만 주석으로 보존(죽은 코드 없음).

## 5. 결과 / 배운점

### 결과
- 빌드 성공, `npm test` 기존 실패(6스위트/8테스트) 외 증가 없음. transition-opacity·유니버설 룰 컴파일 확인.
- 색 페이드: 컴파일 CSS에서 base 레이어 내부(프리플라이트 뒤) + reduced-motion 해제 + 뒤에 @layer utilities — 레이어 순서로 기존 유틸 우선 확증.
- 오버레이 무영향: 첫 진입(themeChanged=false → 미발동)·일반 이동(once 소비 후 리스너 부재)·재생성 로직·mapSlot·시트 z 위계 무변. 연타 전환은 cleanup이 이전 리스너·타이머 정리.
- **setOptions 실측 판정**: 호출 통과·스타일 미반영 확정 — 0284 추정 판정이 실측으로 확정. MapOptions 키라도 런타임 반영이 키별로 다름(padding 반영·customStyleId 미반영).
- `tilesloaded`는 공식 레퍼런스 확증 이벤트(타입 문서는 eventName: string 비열거). 지도·마커는 재생성 경로라 CSS transition 미발동 — 화면 내 지도 타일만 즉시 교체되는 이원 질감은 구조적.
- 브라우저 수동 확인 잔여(사용자): 토글 시 서피스·텍스트 페이드 + 지도 영역이 card로 덮였다 타일 완료 후 걷힘, reduced-motion 시 즉시 전환, 기존 인터랙션 타이밍 무변.

## 결정 (Decisions)

- **전역 색 페이드 = @layer base 유니버설 룰** — 비레이어는 utilities를 덮으므로 금지(캐스케이드 레이어가 특이도보다 우선). 색 3속성 한정·all 금지.
- **오버레이 해제 = tilesloaded once + 2000ms 안전망**, 홀드 300ms(3초는 답답함으로 기각). init은 타일 미완이라 부적합. 상시 마운트 + opacity 토글(조건부 마운트는 fade-out 불가 — 0263 역방향 교훈). 색 = bg-card(도착 테마 자동 해석).
- **테마 전환 = 지도 재생성 확정(실측)** — setOptions는 키별로 런타임 반영이 다름. "동일 API 선례"는 개연성일 뿐 키 단위 실측이 판정. 추정 판정은 저비용 실험(스위치 폴백)으로 승격 → 실측 → 확정, 실험 코드는 제거하고 근거만 주석 보존.
- transition-all 19곳(조사 전수)은 4단계 토큰화 트랙에서 정리 — 이번 범위 제외.

## 2. 왜 / 목적 / 이유

### 네비게이션 MyPage 항목 제거
- **왜**: 멘토 피드백 = "My Dots 제거하고 아이콘 눌렀을 때 마이페이지로"
- **목적**: 네비게이션을 핵심 기능(Story / SpotFinder / CostPlan)으로 좁힘
- **이유**: MyPage는 개인 영역이라 네비게이션 메뉴가 아닌 유저 아이콘 안에 두는 게 표준 (GitHub, Gmail, Notion)

### 헤더 이메일 raw text 제거
- **왜**: 멘토 피드백 = "이메일 raw text 노출 없애기"
- **목적**: 헤더 정보를 줄여 시각 부담 감소
- **이유**: 이메일은 사용자 정보로 드롭다운 안에서만 표시. 헤더는 네비게이션 + 액션에 집중

### 로그아웃 버튼을 드롭다운으로 이동
- **왜**: 멘토 피드백 = "로그아웃 버튼 유저 아이콘 안으로 숨김"
- **목적**: 헤더에 별도 액션 버튼 제거
- **이유**: 로그아웃은 자주 쓰는 액션이 아님. 드롭다운 안에서 접근하는 게 표준 패턴

### 마이페이지 쓴글 리스트
- **왜**: 멘토 피드백 = "마이페이지로 쓴글 리스트업"
- **목적**: 사용자가 본인 작성한 스토리를 한곳에서 확인
- **이유**: velog/Tistory 표준 패턴. Prisma where userId 필터로 본인 글만 조회

## 4. 코드 작성 & 수정

### 1. UserDropdown.tsx (신규)

```tsx
// app/(protected)/_components/UserDropdown.tsx
'use client';
import { useRef, useEffect, useState } from 'react';
import { User } from 'lucide-react';
import Link from 'next/link';
import { signOut } from '@/lib/auth/actions';

export function UserDropdown({ email }: { email: string }) {
  const [open, setOpen] = useState(false);
  const ref = useRef<HTMLDivElement>(null);

  // 외부 클릭 닫기 표준 패턴
  useEffect(() => {
    function handleClickOutside(e: MouseEvent) {
      if (ref.current && !ref.current.contains(e.target as Node)) {
        setOpen(false);
      }
    }
    document.addEventListener('mousedown', handleClickOutside);
    return () => document.removeEventListener('mousedown', handleClickOutside);
  }, []);

  return (
    <div className="relative" ref={ref}>
      <button
        onClick={() => setOpen(v => !v)}
        aria-label="사용자 메뉴"
        aria-expanded={open}
        aria-haspopup="menu"
        className="w-8 h-8 rounded-full bg-slate-200 flex items-center justify-center hover:bg-slate-300 transition-colors"
      >
        <User className="w-4 h-4 text-slate-600" />
      </button>
      {open && (
        <div
          role="menu"
          aria-label="사용자 메뉴"
          className="absolute right-0 top-10 w-52 bg-white rounded-lg shadow-lg border border-slate-200 py-1 z-50"
        >
          <p className="px-4 py-2 text-xs text-slate-500 truncate">{email}</p>
          <hr className="border-slate-100 my-1" />
          <Link href="/my-dots" role="menuitem" className="block px-4 py-2 text-sm text-slate-700 hover:bg-slate-50" onClick={() => setOpen(false)}>
            마이페이지
          </Link>
          <form action={signOut}>
            <button type="submit" role="menuitem" className="w-full text-left px-4 py-2 text-sm text-slate-700 hover:bg-slate-50">
              로그아웃
            </button>
          </form>
        </div>
      )}
    </div>
  );
}
```

## 5. 결과 / 배운점

### 결과
- 헤더 = 네비게이션 3개 + 유저 아이콘 1개로 정리
- 드롭다운 = 이메일 + 마이페이지 + 로그아웃 통합
- 마이페이지 = 본인 글 카드 그리드 + 빈 상태 CTA
- 멘토 피드백 항목 완료

### 배운점

**1. Server Action을 Client Component에서 직접 import**
Next.js App Router에서 `'use server'` 파일의 함수를 `'use client'` 컴포넌트가 직접 import 가능. `signOut`을 form의 `action` 속성에 전달하면 submit 시 자동으로 Server Action이 실행됨. 별도 prop 전달 없이 컴포넌트를 자기 완결적으로 작성할 수 있다.

**2. 외부 클릭 닫기 표준 패턴**
`useRef + useEffect + mousedown` 이벤트가 React 드롭다운의 표준. `ref.current.contains(e.target)`으로 내부 클릭 판별. cleanup으로 이벤트 리스너 제거 필수.

**3. 접근성 (a11y)**
`role="menu"` + `aria-label` + `aria-expanded` + `aria-haspopup="menu"`가 드롭다운의 기본 접근성. `menuitem` role을 자식에게 추가. 키보드 사용자 + 스크린 리더 사용자 대응.

**4. RLS vs Prisma where 분리**
SELECT는 public, UPDATE/DELETE는 본인만 = Supabase RLS의 표준 구조. 마이페이지는 읽기 전용이므로 Prisma `where: { userId }` 필터로 충분. RLS는 데이터 무결성, Prisma where는 비즈니스 로직으로 역할이 분리됨.

**5. 빈 상태 (Empty State) 디자인**
velog/Tistory 표준 = 안내 메시지 + CTA 버튼. 사용자 이탈 방지 + 다음 액션 유도. 멘토 피드백의 "프로덕트 태"를 구성하는 요소 중 하나.

**6. 컴포넌트 재사용 (DRY)**
`extractFirstImage` + `extractTextPreview` = 기존 `story/page.tsx`에서 사용한 유틸 재사용. 카드 그리드 패턴도 동일 적용. 일관된 디자인 시스템 유지.

**7. 두 곳의 레이아웃 중복**
`app/(protected)/layout.tsx` + `app/story/layout.tsx`에 같은 헤더 구조가 분리되어 있음. 추후 Header 컴포넌트로 추출 가능 (0055 헤더 브런치 패턴에서 통합 예정).

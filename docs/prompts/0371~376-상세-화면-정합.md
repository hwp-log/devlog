# 0371~376 회고: 상세 화면 정합

작성일 2026-07-26 / 소요 약 2시간 / 커밋 0371~0376

## 핵심 판단

- **편집과 상세의 이원화를 하나씩 걷어냈다.** 카드 → 폭 → 블록 순서 → 헤더 →
  지도 크기 → 마무리 버튼. 전부 "쓸 때와 읽을 때가 달라 보인다"의 잔재였다.
- **블록 순서를 시안 기준으로 판단했다가 뒤집었다.** 진짜 기준은 시안이 아니라
  편집 화면과의 일치였다.
- **"상세는 비율"이라는 분기의 근거가 이미 무효였다.** 잔여 기본값으로만 남아 있었다.
- **제목 위에 카테고리를 넣으려다 조사에서 접었다.** 실데이터의 57%가 빈 상태였다.

## 한 줄 요약

시안의 READ 블록을 기준으로 상세 화면을 정리하면서, 편집 화면과 어긋나 있던 것들을
차례로 맞췄다.

## 왜 / 목적 / 이유

**왜** — 상세는 본문이 흰 카드 안에 있는데 그 아래 방문장소·PLAN은 카드 밖이었다.
한 페이지에서 두 규칙이 섞여 있었고, 편집 화면과도 인상이 달랐다.

**목적** — 읽는 표면은 페이지 배경 위에, 조작 표면(지도·목록)만 카드에. 편집 화면과
같은 문법으로.

**이유** — 편집에서 상자를 다 걷어냈으므로(0341·0360) 상세만 카드로 남으면 두 화면이
따로 논다. 사용자는 같은 글을 쓰고 읽는데 매번 다른 화면을 본다.

## 결과 / 배운 점

### 기준을 잘못 잡았다가 정정하기

블록 순서를 두고 "시안은 예산 → 여행동선인데 지금은 방문장소 → PLAN"으로 프레임을 잡고,
"시안 이후 PLAN 블록이 무거워졌으니 현행 유지"로 판단했다.

그런데 실제 문제는 시안과의 차이가 아니라 **편집(PLAN → SPOTMAP)과 상세(방문장소 → PLAN)가
서로 반대**라는 것이었다. 같은 글인데 쓸 때와 읽을 때 순서가 뒤집혀 있었다.

이건 0316~0322 폭 트랙, 0349~0350 PLAN 블록에서 이어온 WYSIWYG 정합의 남은 항목이었고,
시안 얘기가 아니었다.

**문서를 기준으로 삼으면 실제 문제를 놓친다.** 1편에서 "요약 대신 원본"을 배웠는데,
여기서는 "원본(시안)마저도 기준이 아닐 수 있다"는 형태로 같은 실수가 나왔다.
기준은 사용자가 겪는 상태였다.

### 무효가 된 분기가 잔재로 남아 있기

상세 지도 카드가 글수정보다 작았다. 조사해보니 코드 주석에 근거가 있었다.

> 글쓰기: 섹션 760 폭이라 비율(304)이 과협소 → 고정 폭 적용. 상세(readOnly)는 미전달=비율 2/5.

즉 **"상세를 비율로 둔다"는 적극적 결정이 아니었다.** 글쓰기 컨테이너가 좁던 시절
글쓰기 쪽 사정으로 고정 폭을 도입했고, 상세는 그냥 기본값으로 남은 것이었다.

그리고 그 전제는 이미 사라져 있었다. 글쓰기가 860으로 넓어졌고(0322), 상세도 860으로
맞췄으므로(0373) 두 화면 폭이 같아졌다. 분기가 존재할 이유가 없었다.

`WRITE_SIDE_CARD_WIDTH`를 `SIDE_CARD_WIDTH`로 개명했다. 상세도 쓰게 되면 "글쓰기 전용"이라는
이름이 거짓이 된다.

### 폭 일원화에서 빠져 있던 곳

상세가 `max-w-4xl`(896px)이고 글쓰기가 860px이었다. 조사해보니 `max-w-4xl` 사용처는
상세가 유일했고, 상위 레이아웃이 이미 같은 폭을 제공하므로 페이지의 래퍼는 순수 중복이었다.

0321에서 "폭 소스 일원화"로 중복 `max-w`를 4곳 제거했는데 **상세만 그 정리에서 빠져
있었다.** 정리 작업은 대상을 다 훑었는지 확인해야 한다.

### 데이터를 보고 접기

제목 위에 눈썹과 상위 분류를 넣으려 했다. 참고한 화면들이 그 자리에 카테고리를 놓았고,
우리 서비스는 K-콘텐츠 촬영지 기록이니 "작품"이 자연스러운 분류로 보였다.

조사 결과 **실데이터 14건 중 8건(57%)이 표시할 작품이 없었다.** Story에 Movie 직접 관계가
없고 `StorySpot → Spot → SpotMovie` 4단 경유인데, 스팟에 작품을 연결하는 흐름이 잘
쓰이지 않고 있었다.

절반 넘는 글에서 빈 상태가 되면 "카테고리 자리"가 아니라 "가끔 뭔가 뜨는 자리"가 된다.
접었다.

**그리고 57%라는 숫자 자체가 별개 신호다.** 작품 연결이 K-콘텐츠 서비스의 핵심 연결인데
안 쓰이고 있다는 뜻이라 따로 볼 항목으로 남겼다.

### 하드코딩 색이 0이 되기까지

상세에는 `#1A1A1A`와 `slate` 하드코딩이 남아 다크 미대응이었다. 특히 제목이 다크에서
안 뒤집히는 게 눈에 띄었는데, 원인이 그 하드코딩이었다.

이번에 만지는 요소마다 클래스를 전면 재작성하는 자리라 교체 비용이 0이었고, 하나씩
토큰으로 바꿨다. 마지막으로 `← 목록으로` 링크를 "다른 이야기 보기" 버튼으로 바꾸면서
**상세 페이지의 하드코딩 색 잔재가 0이 됐다.** 전 요소가 토큰 기반이라 다크 완전 대응.

백로그 하나가 별도 작업 없이 닫혔다. 만지는 김에 되는 것만 챙기는 방식이 효율적이었다.

### 주요 행동이 무엇인가

하단 링크를 전체 폭 파란 버튼으로 바꿀지 논의했다. 나는 파란 채움이 "그 화면의 주요
행동"을 뜻하므로 읽기 화면에서는 위계가 뒤집힌다고 봤다.

그런데 반박이 맞았다. **다 읽은 독자의 다음 행동은 "다른 글 읽기"**이고, 그게 콘텐츠
서비스가 원하는 방향이기도 하다. 주요 행동이 맞다.

그래서 문구도 바꿨다. `← 목록으로`는 되돌아가는 말이라 주요 행동에 어울리지 않는다.
"다른 이야기 보기"로 하니 나아가는 행동이 됐다.

이로써 글쓰기·수정·읽기 세 화면이 모두 하단 전체 폭 버튼으로 끝나는 리듬을 갖게 됐다.

## 대표 코드

```tsx
// components/SpotMap.tsx  (발췌 — 상수 선언과 소비처 두 곳)
// 사이드 카드 고정 폭 — 실화면 비교용 단일 스위치. 0376: 글쓰기·상세 공용이 되어
// WRITE_ 접두 개명(비율 분기는 fallback으로 존치 — 미래 화면의 비율 사용 여지).
// 현재 426 고정: 카드 426 / 지도 422(=860−426−12). ↔ 'w-full md:w-2/5': 카드 344 / 지도 504.
const SIDE_CARD_WIDTH = 'w-full md:w-[426px]';

/* 사이드 카드 — 항상 DOM에 존재, transition으로 show/hide.
    열림 폭: 글쓰기·상세=SIDE_CARD_WIDTH(426 고정, 0376 통일) / 비율 2/5는 fallback. … */
<div className={`overflow-hidden rounded-xl flex-shrink-0 md:max-h-[500px] transition-all duration-200 ${(canAddSpot || activeSpot || readOnly) ? `${fixedSideWidth ? SIDE_CARD_WIDTH : 'w-full md:w-2/5'} opacity-100` : 'w-0 opacity-0 pointer-events-none'
  }`}>
```

## 2. 왜 / 목적 / 이유

(초안 — 초안)

- **왜**: 같은 플랜인데 두 상세가 딴판 — 수정 버튼을 눌렀을 때 읽던 내용과 안 이어짐. 0527이 "위계 정돈 별도 사이클"로 보류했던 건.
- **버튼 이동(제안 승인)**: 상단 pill 3개(작성 화면 인상) 해체 → 메타 행 우측 = 공개 전환 pill(상태 표시 겸이라 pill 유지) + 수정·삭제 아이콘 칩(0481 스토리 상세 선례·동일 재질).
- **비용 실값 유지(제안 승인)**: 소유자는 입력값 검증 화면 — 공개의 "약 N만원"은 프라이버시 가공(0492), 같은 소스의 두 뷰. 안내문이 차이를 설명.

## 4. 코드 작성 & 수정

### 조사 확정
- 파급 없는 범위 = PlanDetail.tsx(소비처 단독) + page.tsx. CostSection은 0527에서 이미 토큰화돼 있어 무접촉 가능(구식은 호출부 12px 라벨뿐). SectionHeader(0531)는 추출만 되고 미적용 상태 — 이번이 첫 적용. PlanSpot엔 coverUrl·address·movie가 없어 행의 썸네일·주소는 데이터 부재로 자연 생략(0517 규칙 정합).

### 주요 변경
- page.tsx: 프로필(nickname·avatarUrl) 조회 + createdAtLabel 전달
- PlanDetail.tsx: `max-w-[var(--reading-w)]` 래퍼 / 히어로(HERO_SIZES 리터럴 복제+짝) / 메타 행(AuthorAvatar·닉네임·작성일 + 우측 버튼군 + 안내문 유지) / 지표 밴드 3열(총 비용 formatAmount 실값) / 섹션 순서 일정→비용(고정비 포함)→항공 / SectionHeader 3곳("여행 일정"·"예상 비용"(sub 실제 입력값)·"항공편"(sub 예상)) / 일정 행(번호+이름+연결 비용 실값 인라인·"무료" 규칙 승계, hairline) / 고정비 3열 토큰 행(카테고리 11→12px §5 시정) / 소개문 본문화 / 하단 링크 토큰화

## 결정 (Decisions)

- 소유자/공개 상세는 같은 골격(860·히어로·밴드·SectionHeader·행), 값 표기만 다름(실값 vs 근사 — 0492 가공 정책의 두 뷰)
- 소유자 버튼군 = 메타 행 우측, 상태 겸 토글(공개 전환)만 pill·나머지는 아이콘 칩 (0481 문법 확장)
- 파급 경계 컴포넌트(CostSection·FlightLeg)는 호출부에서만 정돈 — 내부 무접촉

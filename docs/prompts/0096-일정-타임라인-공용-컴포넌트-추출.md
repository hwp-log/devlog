## 1. 한 줄 요약

마이플랜 상세에 인라인으로 작성돼 있던 일정 타임라인 JSX와 `buildTimeline` 함수를 `PlanTimeline` 공용 컴포넌트로 추출하고, 금액 표시 여부를 `showAmount` prop으로 호출하는 페이지가 결정하게 분리했다.

---

## 2. 왜 / 목적 / 이유

### 공용 컴포넌트 추출

- 왜: 마이플랜 상세에 타임라인 JSX가 인라인으로 작성돼 있었고, 곧 만들 PlanFinder 공개 상세에서 같은 타임라인이 필요했다. 복사하면 같은 화면을 두 곳에서 따로 고쳐야 한다.
- 목적: 타임라인 렌더를 한 컴포넌트로 모아서, 마이플랜과 PlanFinder가 같은 화면 요소를 공유하는 상태.
- 이유: 데이터 가공(`buildTimeline`)과 렌더(`PlanTimeline`)를 한 파일로 모아 두 페이지가 같은 부품을 재사용. 0070에서 쓴 빌더 분리 패턴을 그대로 따랐다.

### showAmount prop

- 왜: 같은 타임라인인데 마이플랜은 금액('무료' 포함)을 보여주고, PlanFinder는 금액 칸 자체를 숨겨야 한다. 같은 "금액 없음" 상태(cost 매칭이 없거나 amount가 0)가 마이플랜에선 '무료', PlanFinder에선 '숨김' — 두 의미라 데이터값만으로는 어느 쪽인지 결정할 수 없다.
- 목적: 금액 표시 여부를 호출하는 페이지가 결정하고, 컴포넌트는 그 결정을 받아 렌더만 하는 상태.
- 이유: 분기 기준이 데이터 안에 없고 페이지 맥락에 있으니, 그 맥락을 prop으로 주입한다. `showAmount=true`(기본값)면 금액 렌더, `false`면 금액 칸 자체 생략. 마이플랜은 prop 생략으로 기본 true 유지(화면 불변), PlanFinder만 `false` 전달.

> 일반화: 컴포넌트는 "어떻게 보일지"만 알고, "무엇을 의도하는지"는 호출 측이 prop으로 준다. 데이터에 의미가 담기면 컴포넌트가 자동 처리하고, 의미가 맥락에 달리면 호출 측이 prop으로 주입한다.

## 4. 코드 작성 & 수정

### 신규: `app/(protected)/my-plan/_components/PlanTimeline.tsx`

원래 `PlanDetail` 안에 있던 `buildTimeline` 함수와 타임라인 JSX를 이 파일로 옮겼다. `'use client'` 없이 작성(부모 `PlanDetail`이 클라이언트 컴포넌트라 그 번들에 포함되지만 문제없음).

```tsx
// app/(protected)/my-plan/_components/PlanTimeline.tsx (신규)
import type { PlanSpot, PlanCost } from '@prisma/client';
import { CATEGORY_COLOR, formatAmount, type CostCategory } from '../_lib/cost';
import { CATEGORY_ICON } from './CostSection';

export type TimelineItem = {
  spot: PlanSpot;
  cost: PlanCost | null;
};

export function buildTimeline(
  spots: PlanSpot[],
  costs: PlanCost[],
  day: number,
): TimelineItem[] {
  const daySpots = spots.filter((s) => s.day === day);
  const costMap = new Map(
    costs.filter((c) => c.planSpotId != null).map((c) => [c.planSpotId!, c]),
  );
  return daySpots.map((spot) => ({ spot, cost: costMap.get(spot.id) ?? null }));
}

interface Props {
  items: TimelineItem[];
  currency: 'KRW' | 'USD' | 'JPY';
  showAmount?: boolean;       // 기본 true → 마이플랜 호출은 prop 생략으로 화면 불변
}

export function PlanTimeline({ items, currency, showAmount = true }: Props) {
  return (
    <div className="glass-outer p-5 mb-4">
      {items.length === 0 ? (
        <p className="...">항목이 없습니다.</p>
      ) : (
        // ...마커·연결선·카드 레이아웃 (추출 전 PlanDetail 인라인과 동일)...
        // 우측 금액 영역: showAmount=true일 때만 렌더
        showAmount && (
          <p className="...">
            {cost && cost.amount > 0
              ? formatAmount(cost.amount, currency)
              : '무료'}
          </p>
        )
        // showAmount=false면 위 <p> 자체를 그리지 않음 (칸 제거)
      )}
    </div>
  );
}
```

> 금액 판정: `cost && cost.amount > 0`일 때만 금액, 아니면(매칭 없거나 amount 0) '무료'. `showAmount=false`면 이 `<p>` 자체를 그리지 않아 칸이 사라진다.

## 5. 결과 / 배운점

- `showAmount` 기본값 true로 마이플랜 화면·동작 불변, PlanFinder만 `false`로 금액 칸 제거 준비 완료. tsc 통과, 화면 추출 전과 동일.
- 처음엔 "데이터 주도(cost 유무로 자동 분기)"라고 단정했는데, 마이플랜의 '무료' 표시 때문에 같은 "금액 없음" 상태가 두 의미(무료 / 숨김)가 돼서 데이터만으로는 구분이 안 됐다. 가정을 검증하고 prop 방식으로 교정했다.
- 배운점: 재사용 컴포넌트의 분기를 설계할 때, 데이터로 결정되는 분기와 호출 측 의도에 의존하는 분기를 구분한다. 후자는 prop으로 의도를 주입한다.

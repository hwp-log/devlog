## 1. 한 줄 요약

작품 칩 클릭이 z14로 7.7단을 한 번에 점프하던 것을 "시스템은 조망(②)까지만, 깊이는 사용자가 정한다" 원칙으로 재설계 — 칩 = fitBounds+maxZoom 상한, 클러스터 클릭 = 분해 스냅, 휠 자유, 선택 = panTo만의 3단계형으로 통일했다.

## 2. 왜 / 목적 / 이유

- **왜(문제)**: 체감은 "칩 누르면 5~6번 확대돼서 답답하다"였는데, 실측하니 확대 횟수가 아니라 **z14 직행 + 긴 morph 하나**가 여러 번처럼 느껴진 것 — 공간 감각을 잃게 하는 순간이동이 원인이었다.
- **목적(목표 상태)**: 전체(큰 클러스터) → 중간(분해 조망) → 개별 마커의 탐색 리듬이 지켜지는 지도. 프로그램 이동의 종착은 항상 ②까지.
- **이유(정책 4개가 원칙 하나에서 파생)**:
  1. **칩 = ② 조망 상한**: 칩은 "이 작품의 무대가 어디들인지"까지만. 1스팟 작품도 동일 규칙 — 스팟 수 분기안은 같은 행동이 데이터에 따라 다르게 반응해 예측 불가 UI가 되므로 기각
  2. **클러스터 클릭 = 분해 스냅**: "다음 단계가 보일 때까지" 한 번에. 단 멤버가 사실상 1지점(퇴화)이면 중간 계단 없이 상한 줌 직행
  3. **휠·핀치 = 자유**: 스냅안 기각 — 일관성은 시스템의 행동에 요구하는 것이지 사용자의 손에 요구하는 게 아니다. 전 세계 지도가 연속 줌인 이유
  4. **리스트/마커 선택 = panTo만**: 정보는 우측 패널 몫, 지도는 데려다주기까지. 확대 동반안은 줌 맥락 점프의 뒷문 재발이라 기각 — CC recap이 이걸 기각안(morph 확대)으로 오기해 정정한 이력 있음
- **추가 결정**: ③(개별 스케일)로의 자동 확대 경로 자체를 제거 — 개별 확대는 오직 사용자 입력만.

## 5. 결과 / 배운 점

- **결과**: 실측 검증 전 항목 통과(칩 = 조망 정지, 클러스터 = 계단 분해, 리스트 = 줌 유지). 인터뷰 4답이 "시스템은 조망까지만"이라는 한 문장에서 전부 파생돼 정책의 예측 가능성이 확보됐다.
- **체감의 언어를 실측의 언어로**: "5~6번 확대"라는 체감 보고를 그대로 믿지 않고 계측하니 실체는 "한 번의 7.7단 점프"였다 — 사용자 관찰은 정확한 신호였고, 원인 규정만 실측이 담당하는 분업.
- **plan 인터뷰의 가치**: 목적지(어디까지 확대할지)는 취향이 아니라 제품 결정이라, CC가 선택지 질문으로 정리하고 사용자가 하나씩 답하는 방식이 유효했다. 단 CC recap이 기각안을 채택안으로 오기한 사례가 있어 — **인터뷰 답과 최종 명세의 대조는 사람 몫**.
- **판단값 표기**: maxZoom 캡(10 vs 11)은 현 5개 스팟 기준 판정 — 시딩 후 분해 임계가 달라지면 재조정 항목으로 명시해뒀고, 실제로 시딩(45곳) 후 거리 기반 공식으로 재작업됐다.

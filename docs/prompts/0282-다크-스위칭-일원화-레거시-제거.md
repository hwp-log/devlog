## 1. 한 줄 요약

create-next-app 잔재였던 `--background`/`--foreground` 변수와 `@media (prefers-color-scheme: dark)` 자동 다크 블록을 `globals.css`에서 제거하고, body·landscape-blocker의 색을 theme.ts 토큰(`--bg-deep`/`--bg`/`--fg`)으로 치환 — `data-theme` 속성이 유일한 다크 스위칭이 됨.

---

## 2. 왜 / 목적 / 이유

- **왜**: 라이트 테마를 새로 설계하려 했으나, 확증 결과 색 쌍·스위칭 엔진이 theme.ts에 이미 있었다. 스위칭 기준이 둘(data-theme, prefers-color-scheme)로 공존해, 라이트 스위치를 추가하면 OS 다크모드 설정과 앱 테마가 충돌하는 구조였다.
- **목적**: data-theme를 유일한 스위칭 기준으로 남기고, create-next-app 잔재 레거시를 제거해 단일 진실(single source)을 확보.
- **이유**: 정본이 둘인 채로 토글 UI를 얹으면 절반만 어두워지는 비결정 상태가 된다. 눈에 보이는 기능(토글)보다 그 아래 스위칭 기준부터 하나로 잡는 게 순서.

## 5. 결과 / 배운점

### 결과
- 컴파일된 프로덕션 CSS에서 `prefers-color-scheme` 0건 — 자동 다크 경로 완전 소멸. data-theme 없으면 무조건 라이트로 귀결.
- `var(--background)`/`var(--foreground)` 참조 0건 (grep 확증). `bg-background`/`text-foreground` 유틸 소비 컴포넌트도 원래 0건이라 매핑 제거 무해.
- SpotFinder 강제 다크 무영향 — DARK_ROUTES(`ThemeScope.tsx:5`)·`spot-finder/page.tsx:8` 모두 data-theme 스코프 방식이라 독립. 프로덕션 서버 응답에서 `<style id="dotrip-theme">` :root 라이트 + `[data-theme="dark"]` 오버라이드 발행 확인.
- `npm run build` 성공. `npm test` 6 스위트/8 테스트 실패 = 변경 전 stash 기준과 동일(기존 실패, 회귀 0).
- 시각 변화: body 배경 #f8f9fa→#f6f6f8, 글자 #171717→#191a1c (미세). OS 다크 사용자는 body·blocker가 더 이상 어두워지지 않음 — 의도된 변화.
- 잔여 사항: landscape-blocker는 body 직속(ThemeScope 밖)이라 다크 화면 위에서도 라이트 오버레이 — 2단계에서 data-theme를 html/body 레벨로 올리면 자연 해소. *(정정: 0283에서 next-themes가 html 레벨에 data-theme를 부여하면서 해소됨 — 블로커가 루트 토글을 상속 추종.)*

### 배운점
- 라이트 테마 작업의 첫 삽은 코드 작성이 아니라 현재 색 시스템의 실태 확증이었다. 시안(목표)과 실제 코드(현재)의 간극이 레이아웃이 아니라 토큰 채택률이라는 걸 정찰로 확인하지 않았으면 없는 엔진을 새로 만드는 헛수고를 했을 것.
- 실기기(iOS Safari) OS 다크모드 상태에서 앱이 라이트로 유지됨을 확인 — prefers 제거가 목적대로 작동.

---

## 결정 (Decisions)

- 다크 스위칭 유일 경로 = `data-theme` 속성 (theme.ts `buildThemeCss()` 발행). `prefers-color-scheme`는 코드베이스에서 사용하지 않는다 — OS 설정 반영은 2단계 토글 로직이 data-theme 부여로 담당할 사항.
- `bg-background`/`text-foreground` Tailwind 유틸은 폐기 (소비처 0건 확인 후 매핑 제거). 전역 서피스·전경의 정본은 `bg-deep`/`fg` 토큰.

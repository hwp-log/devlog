## 1. 한 줄 요약

화면마다 로컬로 다시 만들던 UI 조각 5종(섹션 헤더·버튼 3급·빈 상태·지표 밴드·목록 행)의
중복 실태를 조사하고, 공통분모가 실제로 있는 **섹션 헤더 1종만** 공용 컴포넌트로 추출했다.
사용처는 이번 사이클에서 바꾸지 않았다(시각 무변).

## 2. 왜 / 목적 / 이유

### 왜 지금 추출인가
- **왜**: 남은 화면(MyStory·Admin·스팟파인더 사이드)을 다듬기 전에 뽑아야 같은 조각을
  세 번째로 다시 만드는 일이 없다.
- **이유**: 0099의 "공용 컴포넌트 적용 시점 = 수정 비용이 비싸지는 시점"과 같은 판단.
  섹션 헤더는 이미 4벌이고, 남은 3화면에 손대면 7벌이 된다.
- "적용은 이번에 안 한다"고 분리한 이유 — 추출과 적용을 한 커밋에
  섞으면 시각 변화가 추출 실수인지 적용 판단인지 구분이 안 되기 때문으로 이해했는데,
  의도한 바가 맞는지 확인 필요.

### 왜 섹션 헤더 1종만인가
- **버튼 3급**: 공용 단일 소스(`lib/button-styles.ts`, 0477)가 **이미 있었다**. 새로 뽑을
  것이 없고, 문제는 격자를 안 쓰는 방언 13곳(적용 작업)과 격자에 없는 축 2개(판정 작업).
- **빈 상태**: 지시문 15px/600 + 설명 14px 2단은 실제로 **1벌뿐**이었다. 나머지 9곳은
  13/14/15/16px로 갈리고 아이콘·점·CTA 유무도 제각각 — 공통분모가 없었다.
- **지표 밴드**: 라벨 11 vs 12px, 값 bold vs normal이 각각 0512·0529의 살아있는 판정.
  게다가 11px은 §5(12px 미만 금지) 위반이라 통일 자체가 시각 변화를 부른다.
  → 접근성 결함 정리 사이클(작품 칩 11px·태그 칩 12.5px과 같은 묶음)로 합류시켰다.
- **목록 행**: 공통이 `py-[13px] sm:py-[14px]` + `border-b border-hairline` 2유틸·2곳뿐.
  상수 1개를 위해 파일을 늘리는 건 순이득이 아니라 판단, 3곳을 넘으면 재검토하기로.

### 신규 파일 (전문)

```tsx
// app/(protected)/_components/SectionHeader.tsx
import type { ReactNode } from 'react';

export function SectionHeader({
  title,
  sub,
  badge,
}: {
  title: string;
  sub?: ReactNode;
  badge?: string;
}) {
  return (
    <div className="flex items-baseline justify-between gap-3 border-b-2 border-section-rule pb-2 sm:pb-2.5">
      <h2 className="text-[20px] sm:text-[22px] font-bold tracking-[-0.02em] text-fg break-keep">
        {title}
        {badge && <span className="ml-1.5 text-xs sm:text-sm font-medium text-muted">{badge}</span>}
      </h2>
      {sub && <span className="text-xs sm:text-sm text-muted shrink-0 text-right">{sub}</span>}
    </div>
  );
}
```

(파일에는 산출 근거 주석 40여 줄이 함께 들어간다 — 4벌 출처, 상수가 아닌 컴포넌트인 이유,
위치 근거, 갈린 3축의 통일 판정, 담당하지 않는 것 4항.)

### 통일 판정 3건

| 축 | 갈린 값 | 판정 | 근거 |
|---|---|---|---|
| 모바일 제목 | 19px(1벌) vs 20px(3벌) | **20px** | 다수 3:1, §5와 무관한 값이라 실측 판정이 아닌 시점 차. 적용 시 PlanFinderDetail만 1px 커짐 — 알고 받는 값 |
| 보조 정렬 | `text-right`(1벌) vs 없음(3벌) | **text-right 채택** | 한 줄일 땐 시각 동일, 2줄로 접힐 때 우측 정렬이 실선 끝과 맞음 |
| 위여백 | 내장(1벌) vs 호출부(3벌) | **prop 미수용** | 여백은 섹션 간 조판 = 호출부 책임. prop이면 화면마다 다른 mt가 이 파일에 쌓임(0518 재발 경로) |

`badge`는 1곳 전용이지만 유지 — **조판을 두 벌로 가르는 variant가 아니라 선택적 자식**이라
0518 전례(variant로 조판 두 벌 → 죽은 코드)에 해당하지 않는다.

## 5. 결과 / 배운점

### 결과
- `npx tsc --noEmit` 무오류.
- `git diff --stat` 비어 있음 — 신규 1파일 외 **기존 파일 수정 0건**. 시각 무변 확인.
- 사용처 import 0곳. 적용은 다음 사이클.
- 조사 5종 중 추출 1종 / 제외 4종, 제외 사유 전건 기록.

### 배운점
- **"공통분모가 있는 것만"이라는 제약이 4/5를 걸러냈다.** 다섯 조각이
  전부 중복처럼 보였지만, 실제로 값까지 같은 건 하나뿐이었다. 지시문 없이 진행했으면
  빈 상태 5벌을 prop 4개짜리 컴포넌트로 합쳤을 가능성이 크다.
- **이미 있는 단일 소스를 못 쓰는 것과 단일 소스가 없는 것은 다른 문제다.**
  버튼은 0477이 이미 격자를 세웠는데 소비처가 4파일뿐이었다. 추출로 풀 문제가 아니라
  적용·격자 확장으로 풀 문제 — 조사를 먼저 하지 않았으면 7번째 버튼 상수를 만들었을 것.
- **§5 위반이 통일을 막는다.** 지표 밴드의 11px은 "합치면 고쳐야 하는데
  고치면 시각이 변하는" 상태였다. 시각 무변 제약이 있는 사이클에서는 접근성 결함을
  품은 값끼리 합칠 수 없다 — 결함 정리가 통일보다 먼저다.

## 결정 (Decisions)

- 섹션 헤더 공용 위치는 `app/(protected)/_components/` — 사용처 5화면이 전부 (protected)
  그룹 안이고, 이 디렉토리가 AppHeader·Footer·Pagination 등 그룹 공용 UI를 담는 관례.
  `components/` 루트는 스팟 도메인 몫. (`components/SpotFinderMapNaver.tsx`가 이미 이
  디렉토리의 `ThemeToggle`을 import하는 선례가 있어 방향 문제 없음)
- 클래스 상수(`lib/button-styles.ts`) vs 컴포넌트 판별 기준: **호출부 시그니처가 제각각이면
  상수, DOM이 동일하면 컴포넌트.** 버튼은 button·label·submit·ref·onMouseDown으로 갈려
  상수가 맞았고, 섹션 헤더는 4벌 전부 같은 DOM이라 컴포넌트.
- 섹션 헤더 모바일 제목은 **20px 단일값** (19px 폐기).
- 위여백은 컴포넌트가 담지 않는다 — 호출부 래퍼 책임.
- 목록 행 셸 상수는 **뽑지 않는다.** 공통이 2유틸·2곳. 3곳을 넘으면 재검토.
- 지표 밴드 통일(라벨 11→12px 시정 + bold/normal 판정)은 **접근성 결함 정리 사이클**로
  이관 — 작품 칩 11px·태그 칩 12.5px과 같은 §5 위반 묶음에서 함께 처리.

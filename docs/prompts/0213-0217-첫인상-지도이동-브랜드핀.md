## 1. 한 줄 요약

SpotFinder를 "쓸 수 있는 화면"에서 "보여줄 수 있는 화면"으로 다듬으면서, 첫 진입·클릭·칩 복귀라는 세 이동 경로의 규칙을 정하고 클러스터 마커를 브랜드 마크로 바꿨다.

---

## 2. 왜 / 목적 / 근거

### 왜 (동기·문제)

기능은 다 됐는데 화면이 어색했다. 다섯 가지가 걸렸다.

**첫 화면이 빈약했다.** 초기 선택이 `spots[0]`(최신 등록 스팟)이라, 사진도 리뷰도 작품도 비어 있는 스팟이 뜰 수 있었다. 포트폴리오 시연에서 앱을 켜자마자 보이는 화면인데 기능이 하나도 안 보인다.

**선택된 게 목록에서 안 보였다.** 지도와 우측 패널은 특정 스팟을 가리키는데 좌측 목록은 맨 위를 보여준다. 사용자는 "뭐가 선택된 거지?" 하게 된다.

**클릭해도 그 장소가 안 보였다.** 줌 아웃 상태에서 목록이나 마커를 클릭하면 패널만 바뀌고 지도는 그대로다. 클러스터 뭉텅이만 보여서 클릭한 장소가 어디인지 알 수 없다.

**"전체" 칩이 화면을 흔들었다.** 모든 스팟을 담으려고 `fitBounds`가 도는데, 제주 스팟 하나 때문에 남북으로 크게 늘어나 화면이 과하게 축소되고 흔들렸다.

**클러스터가 밋밋했다.** 그냥 파란 원에 숫자였다. 브랜드와 아무 관계가 없었다.

### 목적 (도달 상태)

- 첫 화면에서 기능이 한눈에 보인다. 빈 필드가 없는 스팟이 뜬다
- 선택된 스팟이 지도·패널·목록 세 곳에서 일치한다
- 클릭하면 그 장소가 보이는 배율까지 지도가 이동한다
- 전체 칩이 한반도를 안정적으로 담는다
- 클러스터 마커가 브랜드 마크와 이어진다

### 근거 (결정 기준)

**첫 화면은 id가 아니라 이름으로 찾았다.** 시연용으로 특정 스팟을 고정하는 건 하드코딩이다. 다만 `id`로 박으면 dev와 prod의 값이 달라 배포본에서 안 먹힌다. 이건 0207에서 이미 확인한 사실이다(백필 매칭 키를 `id` 대신 `name`+좌표로 잡은 이유가 같다). 그래서 이름으로 찾고, 못 찾으면 `spots[0]`으로 떨어지게 했다.

고른 스팟은 롯데월드몰이다. **작품 2편·평점·스토리 1편·사진이 전부 채워져 있어서 화면에 빈 칸이 없다.** 그리고 시딩 스팟(`source='seed'`)이라 0208 자동 청소에서 보호된다. 스토리를 지워도 사라지지 않으니 하드코딩해도 깨질 일이 없다.

**클릭 이동은 새 규칙을 만들지 않고 기존 규칙을 적용했다.** 0166~0168에서 정한 3단계 내비게이션이 이미 있었다.

```
// 3단계형 내비게이션: 프로그램 이동(칩·클러스터 클릭·리사이즈 재적합)의 종착은 항상
// ② 분해 조망 — ③ 개별 확대는 사용자 휠·핀치 전용 (프로그램 경로 없음)
const STAGE2_MAX_ZOOM = 11;
```

그리고 단일 지점 이동에 대한 선례도 있었다. `moveToStage2`가 "퇴화 스팬(사실상 1개 지점)이면 ② 상한으로 morph"를 이미 하고 있었다. **스팟 클릭은 정확히 그 케이스다.** `max(현재줌, 11)` 같은 규칙을 발명하지 않고 선례를 따랐다.

**제주는 bounds 계산에서만 뺐다.** 실제 좌표를 조회해 경계를 정했다.

```
제주 최북   33.51 (제주공항)
육지 최남   35.35 (동부마을)
```

**둘 사이가 완전히 비어 있어서 34.0은 어떤 값을 골라도 안전하다.** 감으로 정한 게 아니라 데이터에 공백이 있어서 그 안에 선을 그었다. 그리고 마커와 목록에는 제주가 그대로 남는다. 화면 맞추기 계산에서만 제외한다.

**클러스터 핀은 로고 형태를 참조하되 색은 토큰을 썼다.** `Logo.tsx`는 수정하지 않았다. 기하만 가져왔다.

| 요소 | Logo.tsx (viewBox 20×27) | 클러스터 핀 (viewBox 18×25) |
|---|---|---|
| 머리 원 | `cx10 cy9 r8` | `cx9 cy9 r8` |
| 흰 구멍 | `cx10 cy9 r3 fill=white` | 없음 (제거) |
| 꼬리 | `points 3,13 17,13 10,21` | `points 2,13 16,13 9,21` |
| 바닥 그림자 | `cx10 cy25 rx3.4 ry1.4 opacity0.55` | `cx9 cy23.6 rx3.2 ry1.1 opacity0.55` |
| 색 | 하드코딩 `#0EA5E9` | `${PRIMARY}` (테마 토큰) |

**흰 구멍은 포기했다.** 로고의 특징이지만 클러스터는 숫자가 주인공이다. 구멍을 살리려 확대했더니 링만 남아 도넛처럼 보였고, 핀을 키우니 지도에서 과했다. **가독성과 브랜드 요소가 충돌할 때 가독성을 골랐다.** 핀 실루엣과 바닥 그림자만으로도 로고와 이어진다.

### 0216은 한 번 잘못 만들었다가 되돌렸다

처음엔 "제주를 포기하고 첫 진입 뷰로 돌아가라"로 프롬을 짰다. 구현까지 갔는데, 전체 칩을 누르면 롯데월드몰로 가버렸다. **"전체" 칩이 전체를 안 보여주면 그 칩의 의미가 없다.** 내가 요청을 잘못 옮긴 것이었다. 되돌리고 "제주를 bounds 계산에서만 뺀다"로 다시 갔다.

```tsx
+ // 그림자 cy23.6(tip 아래 3px 띄움 — 입체감) rx3.2 ry1.1 PRIMARY. 바닥 여백은 그림자 안착용 투명 공간뿐(핀 크기·tip 위치 불변).
+ // 세 자리 대비: 100+는 머리에 안 들어감 — 그때 "99+" 축약 필요. 지금은 미구현.
+ function clusterIconContent(): string {
+   return `<div style="position:relative;width:36px;height:50px;cursor:pointer;filter:drop-shadow(0 2px 4px rgba(0,0,0,0.4))">
+     <svg viewBox="0 0 18 25" width="36" height="50" style="display:block">
+       <ellipse cx="9" cy="23.6" rx="3.2" ry="1.1" fill="${PRIMARY}" opacity="0.55"/>
+       <circle cx="9" cy="9" r="8" fill="${PRIMARY}"/>
+       <polygon points="2,13 16,13 9,21" fill="${PRIMARY}"/>
+     </svg>
+     <span data-count style="position:absolute;left:0;top:0;width:36px;height:${(9 / 25) * 50 * 2}px;display:flex;align-items:center;justify-content:center;font-size:12px;font-weight:700;color:#fff;line-height:1;transform:translateY(1px)">1</span>
+   </div>`;
+ }
```

**앵커를 핀 tip으로 옮겼다.** 원 마커는 중심이 좌표였지만 핀은 뾰족한 끝이 좌표를 가리켜야 한다.

```tsx
// components/SpotFinderMapNaver.tsx  (클러스터러 설정)
- icons: [{ content: clusterIconContent(), size: new naver.maps.Size(44, 44), anchor: new naver.maps.Point(22, 22) }],
+ icons: [{ content: clusterIconContent(), size: new naver.maps.Size(36, 50), anchor: new naver.maps.Point(18, 42) }], // 핀 tip(18,42)이 좌표 (캔버스 50, 바닥 2px는 그림자용)
```

숫자 갱신 대상도 바꿔야 했다. 기존엔 `div`를 잡았는데, 이제 안에 SVG가 있어서 전용 요소를 지정했다.

```tsx
// components/SpotFinderMapNaver.tsx  (stylingFunction)
- const el = root?.querySelector('div');
+ const el = root?.querySelector('[data-count]'); // SVG 아닌 count 전용 요소만 갱신
```

## 5. 결과 / 배운 것

### 결과

첫 진입에서 롯데월드몰이 선택되고, 지도가 그 위치에서 시작하고, 목록도 그 카드가 화면 중앙에 보인다. 우측 패널에 아쿠아리움 사진·작품 2편·촬영 장면 설명·평점·다녀온 이야기가 전부 채워져 있어 **빈 칸이 없다.**

전체 칩을 누르면 한반도가 안정적으로 담기고 흔들리지 않는다. 클러스터는 브랜드 핀 형태로 지면에 서 있는 것처럼 보인다.

### 배운 것 1 — 새 규칙을 만들기 전에 기존 규칙을 찾는다

0215에서 "클릭하면 어느 줌까지 갈 것인가"를 정해야 했다. 감으로 정할 수도 있었고, `max(현재줌, 11)` 같은 규칙을 발명할 수도 있었다.

그런데 코드에 이미 답이 있었다.

```
// 프로그램 이동의 종착은 항상 ② 분해 조망
// 퇴화 스팬(사실상 1개 지점) → ② 상한으로 morph
```

**스팟 클릭은 "단일 지점 이동"이고, 그건 이미 정의된 케이스였다.** 새 규칙을 만든 게 아니라 있던 규칙을 적용한 것이다.

프롬프트에 "임의로 정하지 말고 기존 설계값을 쓸 것"을 명시한 게 이걸 강제했다. 그리고 이 방식은 나중에 설명하기도 쉽다. "왜 11인가"에 "3단계 내비게이션의 ② 상한이고 클러스터 분해 임계와 같은 값"이라고 답할 수 있다.

### 배운 것 2 — 하드코딩에도 안전한 방식이 있다

첫 화면 스팟 고정은 명백한 하드코딩이다. 다만 두 가지를 지켰다.

**이름으로 찾았다.** `id`는 환경마다 다르다. 0207에서 마이그레이션 백필 키를 `id` 대신 `name`+좌표로 잡았던 것과 같은 이유다. 로컬에서 되고 배포본에서 안 되는 종류의 버그를 미리 피했다.

**폴백을 뒀다.** 못 찾으면 `spots[0]`으로 떨어진다. 기존 동작과 완전히 같다. 시딩이 바뀌거나 다른 환경에 배포해도 앱이 깨지지 않는다.

**그리고 그 스팟이 안 사라진다는 근거가 있었다.** 롯데월드몰은 `source='seed'`라 0208 자동 청소에서 보호된다. 이건 이틀 전 작업(0207~0208)이 없었으면 확신할 수 없는 부분이다.

### 배운 것 3 — 요청을 옮길 때 의도가 바뀐다

0216을 한 번 잘못 만들었다.

```
사용자 요청   "제주까지 담는 건 포기하고, 한반도만 보이게"
내가 옮긴 것  "제주를 포기하고 첫 진입 뷰로 돌아가라"
결과          전체 칩을 누르면 롯데월드몰로 감
```

**"제주를 포기한다"가 "롯데월드몰로 간다"가 될 이유는 없었다.** 요청은 "한반도만 담는다"였고, 나는 "제주를 포기한다"만 듣고 그다음을 임의로 채웠다.

구현이 끝나고 화면을 보고서야 어긋난 걸 알았다. **"전체" 칩이 전체를 안 보여주면 그 칩의 의미가 없다**는 게 명백한데도, 프롬을 짤 때는 그 점검을 안 했다.

되돌리고 다시 갔다. 손해는 30분쯤이었지만, 커밋했으면 더 컸다.

### 배운 것 4 — 브랜드와 가독성이 충돌하면 가독성

클러스터 핀에서 로고의 흰 구멍을 살리려고 세 번 시도했다.

```
구멍 그대로(r3)     숫자가 안 들어감
구멍 확대(r5.5)     링만 남아 도넛처럼 보임 — 핀 인상이 사라짐
핀 전체 확대        구멍은 살지만 지도에서 과함. 그림자도 벌어짐
```

결국 구멍을 포기하고 숫자를 흰 글씨로 넣었다. **클러스터는 숫자가 주인공이고, 구멍은 그걸 방해한다.**

포기하고 나서 보니 핀 실루엣과 바닥 그림자만으로도 로고와 충분히 이어졌다. 브랜드 요소를 전부 옮기지 않아도 알아본다.

바닥 그림자를 tip에서 3px 띄운 것도 같은 결이다. 붙이면 납작해 보이고, 많이 띄우면 물방울처럼 따로 논다. 그 사이를 찾는 데 두 번 더 조정했다.

### 배운 것 5 — 번호를 안 찍으면 번호가 사라진다

이 구간에서 0218·0219·0220 세 개가 결번이 됐다.

핀 디자인을 조정하며 각 단계에 번호를 붙이기로 했는데, **중간 커밋을 안 찍고 수정만 반복하다가 마지막에 한 번에 커밋**했다. 그 커밋이 0217이고, 네 단계 작업이 전부 그 안에 들어갔다.

흔적이 이렇게 남았다.

| 번호 | 코드 주석 | 커밋 |
|---|---|---|
| 0218 | 3곳에 남음 (이후 0223에서 사라짐) | 없음 |
| 0219 | **아예 없음** (되돌린 단계라 코드에 안 남음) | 없음 |
| 0220 | 2곳에 남음 (현재 HEAD에도 있음) | 없음 |

**0219가 특히 흥미롭다.** 구멍을 확대했다가 도넛처럼 보여 되돌린 단계인데, 되돌렸기 때문에 코드에 아무 흔적이 없다. 번호만 소비되고 사라졌다.

교훈은 단순하다. **커밋하지 않은 번호는 쓰지 않는다.** 작업 중 예정 번호를 정하더라도, 커밋 시점에 실제 번호로 주석을 정리해야 한다.

### 배운 것 6 — 커밋 메시지가 사실이 아니었다

회고를 쓰려고 diff를 다시 읽다 발견했다. **0217은 "클릭 목표 줌을 16으로 심화"라고 커밋했는데, 실제 값이 11이었다.**

```
커밋 메시지    "도심에서 마커 라벨이 겹쳐 안 읽혔다. 클릭 목표 줌을 16으로 심화"
주석 (3곳)     "골목 단위(z16)까지 확대", "16=클릭 착지", "SPOT_CLICK_ZOOM=16 착지"
실제 선언       const SPOT_CLICK_ZOOM = 11;
```

즉 **0217 시점에 클릭 줌은 아무것도 안 바뀌었다.** 동작은 이전(`STAGE2_MAX_ZOOM = 11`)과 동일했다. 그리고 이걸 아무도 못 잡았다. 다음날 0222~0223에서 클릭 줌을 통째로 재작성하면서 그 상수 자체가 사라졌기 때문이다.

같은 커밋에서 0216의 주석 4곳도 `0217:`로 적혀 있었다. 커밋 번호와 주석 번호가 어긋난 채 지금도 HEAD에 남아 있다.

**이 세션에서 같은 형태가 네 번 나왔다.**

| 건 | 문서상 | 실제 코드 |
|---|---|---|
| 0212 | 커밋 0212 | 주석 `0214:` |
| 0216 | 커밋 0216 | 주석 `0217:` |
| 0217 | z16 심화 | `SPOT_CLICK_ZOOM = 11` |
| 0222 | z15 | `CLICK_ZOOM_DENSE = 13` |

전부 **"보고서와 커밋 메시지는 읽었지만 diff의 그 줄을 직접 안 봤다"**이다. 상수 하나짜리 변경일수록 diff에서 그 줄을 보는 게 빠른데, 요약을 믿고 넘어갔다.

회고를 쓰는 이유가 여기 있다. 네 건 다 커밋 당시에는 몰랐고, diff를 다시 읽으며 나왔다.

## 각주 — 0210 (다녀온 이야기 카드 → 스토리 이동)

이 구간 직전에 한 줄짜리 작업이 하나 있었다. 단독 회고를 쓰기엔 얇아 여기 붙인다.

### 무엇을

SpotFinder 우측 패널의 "다녀온 이야기" 카드에 `›` 화살표가 그려져 있는데 클릭 이동이 없었다. 0200에서 카드를 만들며 화살표까지 그리고, 이동은 다음으로 미뤄뒀던 자리다.

```tsx
// components/SpotFinderMapNaver.tsx  (SpotDetailContent)
+ import Link from 'next/link';

- {/* ... 클릭 이동은 0201. */}
- <div className="flex items-center gap-3 rounded-[13px] bg-surface2/80 px-3 py-2.5 transition-colors hover:bg-surface2">
+ {/* 0210: Link로 스토리 상세 이동(같은 탭). story.id는 이미 내려옴 — 추가 쿼리 없음. */}
+ <Link href={`/story/${story.id}`} className="flex items-center gap-3 rounded-[13px] bg-surface2/80 px-3 py-2.5 transition-colors hover:bg-surface2">
    ...
    <ChevronRight size={16} className="text-muted shrink-0" />
- </div>
+ </Link>
```

바깥 `div`를 `Link`로 교체한 게 전부다. `story.id`는 `SpotFinderSpot.stories`에 이미 내려와 있어 추가 쿼리가 없다.

### 판단은 두 가지였다

**하나, `<a>`가 아니라 `<Link>`.** 클라이언트 라우팅이라 지도가 통째로 다시 그려지지 않는다.

**둘, 뒤로가기 상태를 코드로 추정하지 않고 눌러봤다.** 스토리를 보고 돌아왔을 때 지도 중심·선택 스팟·작품 칩이 리셋되면, 사용자는 매번 처음부터 다시 찾아야 한다. 그러면 이동 기능이 오히려 방해가 된다.

이건 코드만 봐서는 알 수 없어서 실제로 눌러봤고, 세 가지가 다 유지됐다. 리셋됐다면 URL 쿼리로 상태를 올리는 별도 작업이 붙었을 것이다.

`SpotDetailContent` 한 벌이 데스크탑 aside와 모바일 풀스크린 모달 양쪽에 쓰이므로, 한 곳만 고치면 양쪽에 적용된다.

### 현재

**바이트 단위로 그대로다.** `Link` 래핑, 클래스 문자열, 0210 주석까지 원문 유지. 이후 이 블록에 들어온 커밋 2건(0240·0329)은 카드가 아니라 바로 아래 출처 표기 블록 변경이었다.

### 여기서도 번호가 어긋났다

0210이 지운 주석은 `클릭 이동은 0201.`이었다. 즉 **0200에서 카드를 만들며 "이동은 0201에서 하겠다"고 예고했는데, 실제로는 0210에서 했다.** 열 번호 차이다.

다만 커밋 메시지는 `0200에서 화살표만 그리고 클릭 이동은 만들지 않았다`로 정확하다. 카드화를 한 커밋은 `7098769 = 0200`이 맞고, 주석의 0201이 예고 번호였던 것으로 보인다.

**이 세션에서 확인된 여섯 번째 번호·값 불일치다.** 다른 다섯 건과 형태가 조금 다르다 — 앞의 것들은 "정한 것과 박힌 것이 다르다"였고, 이건 **"예고한 번호와 실제 번호가 다른데 주석이 갱신되지 않았다"**이다.

예고 주석(`~는 NNNN에서`)은 그 작업이 실제로 그 번호에 안 들어가면 화석이 된다. 0217의 `0218:` 주석, 0216의 `0217:` 주석도 같은 계열이다. **작업을 미룰 때 번호를 미리 적지 않는 편이 안전하다.** "다음 작업에서"로 적으면 어긋날 일이 없다.

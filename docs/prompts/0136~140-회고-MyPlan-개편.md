## 1. 한 줄 요약

MyPlan(내 여행 계획 목록)을 PlanFinder의 쌍으로 통일했다. 헤더 인격화(0136), 필터·정렬 도입(0137), 카드 가로형 통일(0138), 요약 평균 정확화(0140). 이 과정에서 "필터를 누르면 맨 위 카드만 페이드 없이 뜨는" 버그를 만났고, 여러 헛다리 끝에 과거 회고(0118)를 근거로 "컨테이너 key 재마운트"라는 정석 해법을 찾아 opt-in prop으로 해결했다.

---

## 2. 왜 / 목적 / 이유

### 0136 헤더·빈 상태 인격화

- **왜**: MyPlan 디자인이 기계적이었다. h1 + "새 계획" 버튼뿐이라 "내 계획들"이라는 개인 공간 성격이 없었다.
- **목적**: MyStory(0133)에서 확립한 "내 공간" 패턴을 MyPlan에도 이식해 일관성을 만든다.
- **이유**: 프사 + "{닉네임}님의 여행 계획들" + 카운트로 인격화. 빈 상태도 "{닉네임}님, 첫 여행을 계획해볼까요?" + CTA로 안내. MyStory:Story = MyPlan:PlanFinder라는 대칭 구조를 완성한다.
- **판단 교정**: 카운트를 처음 "N개 계획 · 총 스팟 M개"로 했으나, 스팟이 촬영지뿐 아니라 음식점·공항 등 잡다한 것을 포함해 의미가 흐려진다고 보고 "N개 계획"만 남겼다. (지표는 "정확히 셀 수 있고 의미가 분명한 것"만 노출한다.)

### 0137 필터·정렬 도입

- **왜**: 계획이 늘면 원하는 것을 찾기 어렵다. PlanFinder에는 필터·정렬이 있는데 MyPlan에는 없어 비대칭이었다.
- **목적**: 헤비 유저(계획 다수)가 가격대·시작일 기준으로 계획을 추릴 수 있게 한다.
- **이유**: PlanFinder의 `FilterDropdown`(제네릭)을 재사용. 가격대 필터는 `summarizePlanCost`의 band 기준(PlanFinder와 동일 구간). 정렬 4종(최신순/시작일순/가격 낮은순/높은순). **인기순은 제외** — 내 계획 목록에 남의 좋아요로 정렬하는 것은 부자연스럽다(목적성 불일치).

### 0138 카드 가로형 통일

- **왜**: MyPlan 카드가 PlanFinder와 형태가 달라 "쌍"으로 안 보였다.
- **목적**: PlanFinder와 카드를 통일하되, 내 계획이므로 정확한 총액은 유지한다(공개 피드의 band와 달리 본인은 정확값을 봐도 된다).
- **이유**: 가로형 4블록(제목+지역/기간 pill / 카테고리 단일색 아이콘+% / 정확 총액 / chevron). 원본 PlanCard를 손대지 않기 위해 MyPlanCard를 신설. 정렬을 위해 flex→grid로 전환, 카테고리 중앙 배치는 minmax fr로. 카테고리 아이콘 색은 통일(getCategoryColor 제거→sky).

### 0140 요약 평균 정확화

- **왜**: 요약 "평균 약 M만원"이 band(가격대 중간값) 기준이라 뭉툭했다.
- **목적**: 실제 값에 가까운 평균을 보여준다.
- **이유**: band 중간값 평균 → total(calcPlanTotal) 평균으로 변경, 만원 이하 절사. 예산 미입력(total 0)은 평균에서 제외(0원이 평균을 낮추는 것 방지). 통화가 KRW뿐이라 total 평균에 문제없다.

### 0138 페이드 버그 해결 (핵심)

```tsx
// app/story/_components/CardReveal.tsx
// staggerOnRemount opt-in prop 추가
if (initialPhaseRef.current) {
  setDelay(0.36 + Math.min(index, 8) * 0.12);   // 초기 진입 스태거 (유지)
} else if (staggerOnRemount) {
  setDelay(Math.min(index, 8) * 0.12);           // 재등장 스태거 (0부터, PlanFinder 리듬)
} else {
  setDelay(0);                                   // MyStory 스크롤 진입 (유지)
}
```

## 5. 결과 · 배운점

### 결과
- MyPlan이 PlanFinder의 쌍으로 통일됐다(헤더·필터·카드·요약). "MyStory:Story = MyPlan:PlanFinder" 대칭 완성.
- 필터 재등장 페이드 버그를 정석으로 해결하고, CardReveal에 opt-in 스태거를 더해 MyStory에 무영향으로 유지했다.

### 배운점 ① — 필터 첫 카드 페이드 버그: 두 원인의 구분

**증상**: 필터/정렬 드롭다운을 누르면 맨 위 카드만 페이드 없이 이미 완성 상태로 떠 있고, 나머지는 정상 페이드.

- **헛다리**: 처음 "delay 0의 페인트 타이밍 버그"로 오판해 CardReveal의 delay를 0.05로 땜질하려 했다. 그러나 실제 증상과 맞지 않았다.
- **정석(과거 회고에서 발견)**: PlanFinder는 0118에서 같은 증상을 **카드 컨테이너에 `key={`${sort}-${filter}`}`를 줘 컨테이너째 재마운트 → 전체 재페이드**로 해결했었다. 근본 원인은 "순서만 바뀐 카드는 React key가 같아 진입 애니가 재실행되지 않는다"는 것이다. delay 0의 페인트 문제와 **key 재실행 문제는 별개**이며, 이 버그의 진짜 원인은 후자였다.
- **적용**: MyPlan은 CardReveal(스크롤 페이드) 구조라 PlanFinder(단순 appear-up)와 달랐다. 그래서 컨테이너 key 재마운트 + CardReveal에 `staggerOnRemount` opt-in prop을 더해, 재등장 시 0부터 순차 스태거(PlanFinder 리듬)가 돌게 했다. opt-in이라 prop을 넘기지 않는 MyStory는 무영향.

### 배운점 ② — "확증이 실제 증상과 어긋날 수 있다"

CC 확증이 처음 "MyPlan은 이 문제 없음"이라고 했으나, 실제로는 버그가 있었다. 확증이 "이미 본 카드는 재페이드 안 한다"는 것만 보고 "안 보이던 카드가 위로 올라오는 경우"를 놓친 것이다. **코드를 읽은 추론보다 실제 동작이 우선**이다. 실제 증상이 확증과 어긋날 때는 확증을 다시 의심해야 한다. 과거 회고를 근거로 삼아 정석을 찾은 것이 결정적이었다.

### 한 줄 교훈
같은 페이드 버그라도 원인이 여럿(delay 0 페인트 vs key 미변경)이다. 증상만 보고 아무 knob이나 돌리지 말고, 원인을 분리해 확인해야 한다. 그리고 과거의 나(회고)가 남긴 해법이 현재의 나를 구했다.

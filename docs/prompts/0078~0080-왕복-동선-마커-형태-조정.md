# 0078~0080 회고: 왕복 동선 마커 형태 조정

- 작성일: 2026-06-08
- 소요: 약 2시간
- 관련 커밋: `4e774e3` (0078 중복 좌표 마커 병합 + 색 혼용 그라데이션) / `c2ffdea` (0079 순서 변경 시 번호·색 즉시 반영) / `a5d153f` (0080 클릭 파동 그라데이션 채움)
- 변경 파일: components/SpotMap.tsx

---

## 1. 한 줄 요약

왕복 동선처럼 같은 장소를 여러 번 방문하면 마커가 같은 좌표에 겹쳐 덮이던 문제를, 좌표 병합("1·7") + 첫→끝 색 그라데이션 + 클릭 파동 그라데이션으로 해결했다. 작업 중 순서 변경이 저장 전까지 반영 안 되던 회귀도 함께 잡았다.

---

## 2. 왜 / 목적 / 이유

### 같은 좌표 마커 병합 (0078)
- 왜: 같은 장소를 두 번 들르면(왕복) 마커가 같은 좌표에 겹쳐, 나중에 그린 마커가 앞 번호를 덮는다.
- 목적: 한 장소의 여러 방문이 한 마커에 "1·7"처럼 보이는 상태.
- 이유: 좌표 50m 이내(haversine, 엡실론)면 같은 장소로 묶고 방문 순번을 정렬해 표기했다. 오프셋·펼치기보다 "이 장소를 두 번 들렀다"는 정보를 그대로 전달하면서 구현이 작다.

### 병합 마커를 첫→끝 색 그라데이션으로 (0078)
- 왜: 단색은 사용자를 헷갈리게 한다. 초록 단색이면 "출발"로 읽히는데, 그 장소는 도착이기도 해서 여러 위치인 점이 하나의 위치처럼 보인다.
- 목적: 한 장소가 출발이자 도착(여정의 범위)임이 한눈에 읽히는 상태.
- 이유: 병합 마커는 단일 점이 아니라 여정의 범위(span)다. 범위는 그라데이션이 자연스러운 표현이라, 첫 방문 색 → 마지막 방문 색으로 이었다. 같은 색 방문(예: 2·6)은 자동으로 단색처럼 보인다. 두 색을 한 색으로 섞으면(평균) 머디한 색이 나와 의미가 안 읽혀, 두 색을 다 보여주는 그라데이션을 택했다.

### 순서 변경 즉시 반영 (0079, 회귀 수정)
- 왜: 0078 이후 순서를 드래그해도 마커 번호·색·병합 라벨이 저장 전까지 안 바뀌었다.
- 목적: 드래그 즉시 번호·색·병합 라벨이 갱신되는 상태.
- 이유: 0078에서 라벨의 의존 대상을 배열 인덱스에서 spot.order로 바꿨는데, reorder(arrayMove)는 배열 위치만 바꾸고 order 필드는 재배정하지 않아 stale했다. handleReorder에서 order를 배열 위치로 재배정(i + 1)해 해결했다. 렌더가 의존하는 값을 바꾸면 그 값의 갱신 의무도 함께 따라온다.

### 클릭 파동을 그라데이션 채움으로 (0080)
- 왜: 파동이 단색 border 링이라 병합 마커의 혼용색이 파동에는 드러나지 않았다.
- 목적: 클릭 파동도 마커와 같은 의미(범위)를 가지는 상태.
- 이유: 파동은 마커와 같은 그라데이션이어야 일관된다. border에 그라데이션은 border-radius를 깨므로(border-image 한계), 채움형 원이 커지며 페이드하는 방식으로 교체했다. 라벨이 가려지지 않게 라벨 zIndex를 파동보다 위로 두었다.

## 4. 코드 작성 & 수정

```tsx
// components/SpotMap.tsx — 좌표 근접 그룹핑 (병합)
const MERGE_EPSILON_KM = 0.05; // 50m 이내 = 같은 장소
function groupByProximity(spots: LocalSpot[]) {
  const groups = [];
  for (const spot of spots) {
    const hit = groups.find((g) => haversineKm(g.representative, spot) < MERGE_EPSILON_KM);
    if (hit) hit.orders.push(spot.order);
    else groups.push({ representative: spot, orders: [spot.order] });
  }
  groups.forEach((g) => g.orders.sort((a, b) => a - b));
  return groups;
}
```

## 5. 결과 / 배운점

- 색은 의미다. 병합 마커는 단일 점이 아니라 여정의 범위(span)이고, 범위는 그라데이션으로 표현하는 게 자연스럽다. 사용자 영향은 "헷갈린다"로, 그 메커니즘은 "여러 위치를 하나로 뭉갠다"로 — 층위를 나눠 본다.
- 렌더가 의존하는 값을 바꾸면 그 값의 갱신 의무도 따라온다. 0078에서 라벨을 인덱스에서 order로 바꾸면서 reorder의 order 갱신이 빠졌고(우리가 만든 회귀), 0079에서 직접 잡았다.
- border에 그라데이션은 border-radius를 깬다(border-image 한계). 둥근 요소의 그라데이션은 채움 또는 마스크로 푼다.
- 한계: 엡실론은 같은 장소 판정의 불안정한 프록시다. 검색 추가는 좌표가 동일해 깔끔히 병합되나, 지도 핀은 좌표가 흔들려 같은 장소도 병합되지 않을 수 있다. 안전한 단일 엡실론 값이 없다. 더 견고한 방향은 신원(placeId·이름) 기반 판정 + 입력 시점 "같은 장소로 추가?" 사용자 확인이다(모호한 판정은 알고리즘 추측이 아니라 맥락을 아는 사용자에게 입력 시점에 넘긴다). 미실현 개선.
- 남은 왕복 문제: 가는 길·오는 길이 한 직선에 포개진다. 베지어 아치로 좌우 분리 — 다음 작업.

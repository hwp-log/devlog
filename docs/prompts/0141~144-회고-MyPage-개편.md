# 0141 회고: MyPage 대개조 (eyebrow 통일 · 인격화 · 좌우 통합 카드 대시보드)

- 날짜: 2026-07-01
- 소요: 약 반나절
- 관련 커밋: 0141(2019962) / 0142(cd9a59d) / 0143(1b7b7c7) / 0144(c6b67dd)

---

## 1. 한 줄 요약

밋밋한 세로 폼 나열이던 MyPage를 "내 활동 / 회원정보 관리" 두 영역의 좌우 통합 카드로 재구성했다. eyebrow 라벨 통일(0141), 헤드라인 인격화(0142), 좌우 통합 카드 + 활동 대시보드 + 최근 활동(0143), 진입 페이드(0144). 여러 방향(중앙 정렬 → 대시보드 → 통합)을 실제 화면으로 확인하며 좁혔고, "카드 안 카드"를 피하고 구분선으로 섹션을 나누는 통합 방식을 web_search 근거로 채택했다.

---

## 2. 왜 / 목적 / 이유

### 0141 eyebrow 라벨 통일

- **왜**: PlanFinder·SpotFinder·Story에는 헤드라인 위 작은 라벨(eyebrow)이 있는데 마이 페이지들(MyStory·MyPlan·MyPage)에는 없어 페이지 간 이질감이 있었다.
- **목적**: 여섯 페이지 헤더를 "eyebrow → 헤드라인" 한 구조로 통일한다.
- **이유**: 기존 eyebrow 스타일(`text-xs font-semibold text-sky-500 mb-1 appear-up`)을 그대로 재사용해 MyStory/MyPlan/MyPage에 이식. 새로 만들지 않고 검증된 패턴을 옮겨 일관성을 확보한다.

### 0142 헤드라인 인격화

- **왜**: MyPage 헤드라인이 "마이페이지"라 밋밋했다. 다른 페이지는 인격 있는 문구인데 MyPage만 기능명이었다.
- **목적**: "내 계정"이라는 개인 공간 성격을 살린다.
- **이유**: "안녕하세요, {닉네임}님"으로 인사. 처음 "{닉네임}님, 안녕하세요"였으나 한국어 인사로는 "안녕하세요, {닉네임}님"이 더 자연스러워 순서를 뒤집었다. 닉네임 없으면 "안녕하세요" 폴백.

### 0143 좌우 통합 카드 + 활동 대시보드 (핵심)

- **왜**: MyPage가 왼쪽 `max-w-md`에 폼(프사·이메일·닉네임·비번)이 세로로 몰려 오른쪽이 텅 비었다.
- **목적**: 여백을 채우되, 페이지에 의미 있는 구조를 준다.
- **이유 (방향 탐색)**: 여러 방향을 실제 화면으로 확인하며 좁혔다.
  1. **A안(중앙 정렬)**: `mx-auto`로 폼을 중앙에 — 세로 기둥 하나가 떠 있어 오히려 휑함. 기각. (단 이 세로 스택은 모바일에는 적합 → 반응형으로 활용.)
  2. **B안(활동 허브)**: 왼쪽 폼 유지 + 오른쪽에 활동 대시보드. 채택.
  3. 최종: 성격별 좌우 재배치 — **왼쪽 = 내 활동**(프사·활동 통계·최근 활동), **오른쪽 = 회원정보 관리**(이메일/닉네임·비번·위험구역). "보는 것 / 관리하는 것"으로 나뉘고, 오른쪽은 위험도 순(닉네임→비번→탈퇴)으로 아래로 내려간다.
- **활동 대시보드**: 스토리·계획·받은 좋아요·평균 예산. 각 페이지가 흩어져 조회하던 통계를 MyPage에서 집계(story=userId, myPlan=ownerId — 필드명 주의). "3초 안에 내 활동 파악".
- **최근 활동**: 최근 스토리·계획을 한 카드 두 섹션으로. 썸네일 없이 제목+날짜 한 줄로 통일(truncate)해 "부서진 계단"(콘텐츠 길이 불균형)을 방지.

### 0144 진입 페이드

- **왜**: MyPage 카드만 페이드 없이 즉시 표시돼 다른 페이지와 달랐다.
- **목적**: 헤더 다음 카드가 떠오르게 통일.
- **이유**: 좌우 큰 카드에 `appear-up` + `animationDelay: 0.24s`. 초기 진입만이라 delay 0.24(>0)여서 "delay 0 툭 뜸" 이슈 회피(0138에서 배운 것).

### 0143 통합 카드 (핵심)

```tsx
// mypage/page.tsx — 좌우 각각 하나의 큰 카드, 내부는 divide-y로 섹션 구분
<div className="md:grid md:grid-cols-2 md:gap-6">
  <div className="glass-outer divide-y divide-black/5">   {/* 왼쪽: 내 활동 */}
    <AvatarForm ... /> <ActivityDashboardCard ... /> <RecentActivityCard ... />
  </div>
  <div className="glass-outer divide-y divide-black/5">   {/* 오른쪽: 회원정보 관리 */}
    <NicknameForm ... /> <PasswordForm /> <DangerZoneCard />
  </div>
</div>
```

- 각 섹션 컴포넌트에서 `glass-outer`(카드 스타일) 제거 → "카드 안 카드" 회피, `p-6`는 유지
- 큰 카드에서 `space-y-*` 제거 → 섹션 간 여백은 각 `p-6`이 담당(divide 라인이 뜨는 것 방지)

### 통계 조회

```ts
// mypage/page.tsx — Promise.all로 4쿼리 동시
prisma.story.count({ where: { userId } })
prisma.myPlan.count({ where: { ownerId } })   // 필드명 주의: story=userId, myPlan=ownerId
prisma.like.count({ where: { story: { userId } } })
// 평균 예산: myPlan findMany(include costs·flight) → calcPlanTotal → total>0 평균
```

## 5. 결과 · 배운점

### 결과
- MyPage가 "내 활동 / 회원정보 관리" 두 영역의 좌우 통합 카드로 재구성됐다. 데스크탑은 2열, 모바일은 세로 스택.
- 활동 대시보드·최근 활동으로 "설정 페이지"에서 "내 활동 허브"로 확장됐다.

### 배운점 ① — "카드 안 카드"는 왜 나쁜가, 그리고 언제 괜찮은가

통합을 두고 "큰 카드 하나에 폼 카드들을 넣으면 카드 안 카드 아니냐"는 고민이 있었다. web_search로 확인한 결론:

- **나쁜 경우**: 같은 강한 스타일(테두리+그림자+배경)을 **중첩**할 때. 테두리 안 테두리, 그림자 위 그림자가 되어 경계가 흐려지고 답답해진다. 우리 `glass-outer`(반투명+blur+테두리)를 두 겹 쌓으면 이 경우다.
- **괜찮은 경우**: 안쪽이 **다른 스타일**(배경만 있는 섹션, 테두리 없음)일 때. 이건 "카드 안 카드"가 아니라 "카드 안 섹션"이다.
- **정석(ServiceNow 등 디자인 시스템)**: 큰 카드 안은 또 카드로 만들지 말고 **구분선(divider)으로 섹션을 나눈다.**

→ 그래서 각 폼의 `glass-outer`를 벗기고(섹션화), 큰 카드 하나 + `divide-y`로 구분. 폼 3개가 MyPage 전용(다른 사용처 0건)이라 스타일을 벗겨도 안전함을 확증으로 확인한 뒤 진행했다.

### 배운점 ② — 여백은 "결함"이 아니라 판단 대상

처음엔 오른쪽 여백을 "채워야 할 결함"으로 봤다. web_search 결과, 설정 페이지의 폼 컬럼 + 여백은 오히려 표준이었다. 즉 여백을 없애는 방법(중앙 정렬)과 채우는 방법(대시보드)은 둘 다 선택지이며, "무엇이 더 나은가"를 실제 화면으로 비교해 정하는 것이 맞다. A안(중앙 정렬)을 실제로 렌더해 보고서야 "휑하다"를 확인하고 B안으로 갔다 — 목업/화면 확인이 말보다 빠른 판단 근거였다.

### 배운점 ③ — 콘텐츠 길이 불균형은 통일로 잡는다

최근 스토리(썸네일 큼)와 계획(썸네일 없음)을 그대로 넣으면 카드 높이가 들쭉날쭉("부서진 계단")해진다. 썸네일을 빼고 제목+날짜 한 줄로 형태를 통일(truncate)해 해결했다. 카드는 "콘텐츠 길이를 고정"할 때 정돈돼 보인다.

### 한 줄 교훈
"채운다/비운다"를 말로 다투지 말고 실제로 렌더해 눈으로 정한다. 그리고 카드 중첩은 스타일 중첩일 때만 문제이므로, 구분선으로 섹션을 나누면 하나의 카드에 여러 성격을 담을 수 있다.

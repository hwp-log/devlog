> **Edge Runtime**
> Vercel/Cloudflare 같은 글로벌 분산 서버에서 돌아가는 가벼운 실행 환경.
> Node.js와 다름 (V8 isolate 기반, Node API 일부 X).
> - 장점: 사용자 가까운 곳에서 빠르게 응답
> - 단점: 기존 Jest(Node 환경)에서 테스트 어려움

> **proxy.ts (Next.js 16)**
> 모든 요청을 가로채는 파일.
> Next.js 15까지는 `middleware.ts`라는 이름이었는데, 16부터 `proxy.ts`로 변경됨.

## 이번 작업의 3가지 핵심 요소

### 1. Server Action 파일 분리

0019(로그인) 작업에서 `Server Action`을 UI 컴포넌트에 작성했다가 테스트 환경에서 에러 발생. `actions.ts` 로 분리.

**배운점**: UI 컴포넌트에 Server Action을 같이 작성하면 컴포넌트 테스트 시 실제 서버 호출이 시도되어 에러 발생. 별도 파일로 분리해야 jest.mock으로 테스트 가능.

> **Server Component vs Server Action**
> 이름이 비슷하지만 역할이 다름.
>
> | 종류 | 본질 | 예시 |
> |------|------|------|
> | Server Component | 서버에서 렌더링되는 페이지 (async 함수, JSX 반환) | `DashboardPage` |
> | Server Action | 서버에서 실행되는 함수 (form 제출 받음, 데이터 처리) | `signOutAction` |

### 2. proxy.ts TDD 연기

Edge Runtime 환경 = Jest 테스트 어려움. 브라우저 검증으로 대체.

**배운점**: Edge Runtime은 V8 isolate 기반이라 Node 환경인 Jest와 호환 X. 환경 한계 인지하고 브라우저 검증으로 대체 결정. 향후 후속작업(0024 proxy.ts 테스트 보강) 단계에서 처리조치 예정. 

### 3. Red 단계 강화

대시보드 페이지에 임시로 만든 빈 "로그아웃" 버튼이 이미 있어서, 진짜 로그아웃 기능을 추가하기 전에도 "로그아웃" 텍스트 검증 테스트가 통과됨. "form 존재 여부"로 검증 방식 변경.

**배운점**: 임시 버튼과 진짜 컴포넌트 양쪽에 같은 텍스트가 있으면 TDD Red 단계가 의도와 다르게 통과됨. 임시 버튼에는 없고 진짜 컴포넌트에만 있는 "form 존재 여부"로 검증해야 TDD 테스트의 의미가 있음.

## 코드 변화 (실제 결과물)

### 1. 대시보드 페이지 (Server Component)

```typescript
// app/(protected)/dashboard/page.tsx
export default async function DashboardPage() {
  const supabase = await createClient();
  const { data: { user } } = await supabase.auth.getUser();

  return (
    <div>
      <h1>환영합니다, {user?.email}</h1>
      <LogoutButton />
    </div>
  );
}
```

### 2. 로그아웃 Server Action

```typescript
// app/(protected)/dashboard/actions.ts
'use server';

export async function signOutAction(_formData?: FormData) {
  const supabase = await createClient();
  await supabase.auth.signOut();
  redirect('/login');
}
```

### 3. proxy.ts (인증 가드)

```typescript
// proxy.ts (Next.js 16)
export async function middleware(request) {
  const supabase = createServerClient(/* ... */);
  const { data: { user } } = await supabase.auth.getUser();
  const { pathname } = request.nextUrl;

  if (!user && pathname === '/dashboard') {
    return NextResponse.redirect(new URL('/login', request.url));
  }

  if (user && pathname === '/login') {
    return NextResponse.redirect(new URL('/dashboard', request.url));
  }

  return NextResponse.next();
}

export const config = {
  matcher: ['/dashboard', '/login', '/signup'],
};
```

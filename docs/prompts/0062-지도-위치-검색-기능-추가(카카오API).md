## 1. 한 줄 요약

0061에서 이관한 카카오 `keywordSearch`로 촬영지 직접검색을 살리고, 동선 폴리라인을 애플 지도 스타일(연한 파랑 코어 + 진한 파랑 외곽)로 다듬어 지하철 노선색과의 혼동을 해소했다.

---

## 2. 왜 / 목적 / 이유

**왜 (동기 · 문제)**
- 0061에서 검색 버튼을 비활성으로 남겨둔 상태 — 이관한 진짜 이유(한국 POI 정확도)를 아직 못 써먹고 있었다.
- 동선 폴리라인이 주황(`#f97316`)이라 서울 지하철 3호선(주황)과 색이 겹쳐, 지도 위에서 "또 하나의 노선"으로 묻혀 보였다.
- 구간 중점 방향 화살표가 선 위에 여러 개 떠서 오히려 난잡했다.

**목적 (도달할 상태 · 사용자 가치)**
- 사용자가 "광화문광장"을 검색하면 진짜 그 장소가 나와 클릭 한 번으로 spot으로 추가·저장되는 흐름.
- 동선이 베이스맵(특히 지하철 노선) 위에서 "딱 우리 선"으로 한눈에 읽히는 지도.

**이유 (채택 근거 · 의사결정)**
- `services` 라이브러리가 `useKakaoLoader(libraries:['services'])`로 이미 로드돼 있어 추가 키·REST 없이 `kakao.maps.services.Places().keywordSearch()`만 붙이면 됐다.
- 실시간(매 글자) 검색이 아니라 Enter/버튼 제출 방식 — 무료 쿼터를 글자마다 소진하지 않기 위한 의식적 선택.
- 검색 입력창을 사이드카드 안 → 지도 위 오버레이로 배치: 검색할 때 사용자 시선이 지도(결과가 찍히는 곳)에 머물게 하기 위함. 사이드카드는 미니멀 힌트로.
- 폴리라인 색: 카카오 Polyline은 외곽선 옵션이 없어 흰 케이싱 + 색 코어 2겹이 표준(카카오 자체 대중교통 경로도 동일 방식). 주황이 3호선과 겹치는 게 혼동의 뿌리라, 애플 지도 경로처럼 연한 파랑 코어 + 진한 파랑 외곽으로 교체. 외곽을 두껍게 두르면 색이 1·4호선과 가까워도 "위에 얹힌 선"으로 구별된다(애플이 같은 상황을 해결한 방식).
- 화살표는 제거: 방향은 마커 번호(1→2→3…)가 이미 알려주므로, 화살표를 줄줄이 두는 것보다 없애는 쪽이 깔끔했다.

> 면접용 한 문장(0061과 안 겹치는 0062 고유 포인트):
> "검색은 실시간이 아니라 제출 방식으로 막았다 — 카카오 무료 쿼터를 글자마다 소진하지 않으려는 선택이었고, 비용/할당량을 UI 결정에 반영한 사례다. 폴리라인 색도 '예뻐서'가 아니라 지하철 3호선 주황과 겹쳐 혼동을 일으키는 문제를 풀려고 바꿨다 — 베이스맵이 이미 점유한 색 팔레트를 피하고, 카카오가 외곽선 옵션을 주지 않으니 2겹(코어+케이싱)으로 직접 입체감을 만들었다."

## 4. 코드 작성 & 수정

**(가) keywordSearch + 좌표 변환 (★★★)**
카카오 검색 결과는 `x=경도(lng)`, `y=위도(lat)`, **문자열**. `parseFloat` 후 `addSpot(name, lng, lat)` 순서로 전달.

```ts
// components/SpotMap.tsx — 검색 결과 선택
function handlePlaceSelect(place: KakaoPlace) {
  const lng = parseFloat(place.x); // x = 경도
  const lat = parseFloat(place.y); // y = 위도
  addSpot(place.place_name, lng, lat); // 0061 시그니처: (name, lng, lat)
  setActiveSpot(/* 추가된 spot */);
  setMode('edit');
}

// keywordSearch 콜백 status 분기
const ps = new kakao.maps.services.Places();
ps.keywordSearch(searchKeyword, (data, status) => {
  if (status === kakao.maps.services.Status.OK)        setSearchStatus('ok'),    setSearchResults(data);
  else if (status === kakao.maps.services.Status.ZERO_RESULT) setSearchStatus('zero');
  else                                                  setSearchStatus('error');
});
```

## 5. 결과 / 배운점

**결과**
- "서울시청" 검색 → "서울특별시청"(서울 중구 태평로1가 31) 정확히 표시 — Mapbox "원주시"와 대비되는 이관의 보상 확인.
- 검색 → 선택 → 마커 추가 → 저장까지 흐름 정상, spot DB에 남음.
- 동선이 애플 스타일 파랑 2겹으로 지하철 노선색과 분리돼 한눈에 읽힘.
- 화살표 제거로 난잡함 해소, 마커 번호가 방향을 대신함.

**배운점**
- **비용/할당량도 UI 결정에 반영된다.** 실시간 검색을 일부러 막고 제출 방식으로 간 건 기능이 아니라 무료 쿼터를 지키려는 판단이었다.
- **색은 취향이 아니라 가독성 문제다.** 베이스맵이 이미 점유한 색(지하철 3호선 주황)을 피하는 게 핵심이었다 — "예쁜 색"이 아니라 "안 겹치는 색".
- **API가 안 주는 건 직접 만든다.** 카카오 Polyline에 외곽선 옵션이 없으니 2겹(코어+케이싱)으로 입체감을 직접 구성했고, 이건 카카오 대중교통 경로도 쓰는 표준 방식이었다.
- **덜어내는 것도 마감이다.** 화살표는 추가가 아니라 제거가 정답이었다 — 정보(방향)는 마커 번호가 이미 주고 있었으니까.

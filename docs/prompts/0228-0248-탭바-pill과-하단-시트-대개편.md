## 1. 한 줄 요약

모바일 하단 탭바를 밀착 바에서 인셋 floating pill로 바꾸고, 스팟 카드를 바닥밀착 시트로 전환한 뒤 검색·작품 칩·스팟 목록을 전부 그 시트로 이관 — 선택 카드/미선택 시트의 배타 전환을 폐지하고 "목록 상시 노출 + 선택 행 하이라이트"로 정리, 시트 단계는 3단을 만들었다가 2단(peek/half)으로 축소, 모바일 전용 pan-only 확대 디스패처를 폐지해 데스크탑과 확대 룰을 통일.

## 2. 왜 / 목적 / 이유

> 근거: `docs/0228-0273-회고-재료-인수인계.md` 묶음 1.

### 시안 오독을 발견하고 전면 재설계로 확대
- **왜**: 출발점은 "탭바가 이상하다" 수준의 지적이었다. 그런데 시안 원문을 다시 확인해 보니 이전 세션이 내린 "시안 분리 구조" 결론이 **오독**이었다 — 실제 시안은 카드가 바닥에 밀착한 시트이고 탭바 pill이 그 위에 뜨는 구조였다.
- **목적**: 오독을 전제로 물려받은 구조를 걷어내고 시안 원문대로 다시 세운다.
- **이유**: 형태 논의는 시안 원문 확인에서 시작해야 한다. 이전 세션의 결론을 전제로 물려받지 않는다.

### 상단 검색·칩 제거 (0232)
- **왜**: 모바일 지도 화면에서 상단 검색창과 작품 칩이 지도를 가려 시야가 좁았다.
- **목적**: 지도 화면의 시야를 확보한다.
- 네이버 로고·저작권은 약관상 표기 의무라 숨기지 않고 비워진 상단으로 **위치만** 옮겼다(코드 주석 근거).

### 드래그·스냅 바텀시트 미채택 → 비드래그 탭 토글
- **왜**: 하단 시트의 높이 조절 방식을 정해야 했다.
- **이유**: 드래그·스냅 바텀시트는 업계 안티패턴이다(오터치·제스처 충돌, 핀터레스트·트위터도 페이지 내비게이션으로 회귀). 그래서 **드래그 없이 그래버 탭으로만** 단계를 바꾸는 방식을 택했다.

### 3단 → 2단 축소 (0246 → 0247)
- **왜**: peek/half/full 3단을 실제로 만들었다(코드 주석 근거: 애플·구글 지도 표준 detent).
- **목적**: full 단계가 실사용에서 쓸모가 있는지 확인.
- **이유**: 만들어서 실사용해 본 뒤 "쓸 일이 없다" 판정으로 제거했다 — **만들어보고 뺀 것**이라는 점이 근거다. 커밋에 남은 사유는 "full에서는 시트가 지도를 덮어 행을 탭해도 이동 결과가 안 보임".

### 확대 룰을 데스크탑과 통일 (0248)
- **왜**: 모바일만 pan-only(줌 유지) 디스패처 `selectSpot`을 따로 쓰고 있었다.
- **목적**: 마커 탭·행 탭·데스크탑 클릭이 하나의 확대 경로를 공유하게 만든다.
- **이유**: pan-only의 근거였던 ‹› 페이저가 0244에서 사라졌다 — **"같은 의도는 같은 경로"**.

### 4. 그래버 탭 토글 — 드래그 없는 높이 전환 (0245 → 0246 → 0247)

0245에서 2단 토글(58svh ↔ 88svh)을 넣고, 0246에서 애플·구글 detent를 따라 3단(peek/half/full)으로 확장했다가, 0247에서 full을 제거했다.

```tsx
// components/SpotFinderMapNaver.tsx (0245) — 도입 시점
<div className={`lg:hidden fixed inset-x-0 z-30 bottom-0 flex flex-col rounded-t-[22px] … transition-[max-height] duration-[320ms] ease-[cubic-bezier(0.32,0.72,0,1)] ${sheetExpanded ? 'max-h-[88svh]' : 'max-h-[58svh]'} pt-1 px-4 pb-[calc(78px+env(safe-area-inset-bottom))]`}>
  {/* 0245: 높이 토글 그래버 — 히트 44×64(§5), 시각 chevron 18(0236 전례). 반높이=∧(펼치기)/전체=∨(접기) */}
  <button
    type="button"
    aria-label={sheetExpanded ? '시트 접기' : '시트 펼치기'}
    onClick={() => setSheetExpanded((v) => !v)}
    className="self-center flex h-11 w-16 shrink-0 items-center justify-center text-muted hover:text-fg2 transition-colors"
  >
    {sheetExpanded ? <ChevronDown size={18} /> : <ChevronUp size={18} />}
```


## 5. 결과 / 배운점

### 결과
- 모바일 SpotFinder가 "지도 + 바닥밀착 시트 + 그 위에 뜨는 탭바 pill" 한 구조로 정리됐다. 상단 조작부 0개.
- 선택/미선택 두 벌 UI가 한 벌로 합쳐졌다(0244) — 이 단순화가 0248의 디스패처 폐지까지 연쇄로 끌어냈다.
- 시트 단계는 2단(peek/half)으로 확정. 이 구조와 주석은 오늘 코드까지 유지된다.

### 배운점

- **형태 논의는 시안 원문 확인부터.** 이전 세션의 결론을 전제로 물려받지 않는다. 이번엔 "탭바가 이상하다"에서 시작해 오독을 발견하고 전면 재설계로 확대됐다.
- **실사용이 설계를 이긴다.** full 단계(0246→0247)도, 선택 카드·‹› 페이저(0244)도, 모바일 전용 pan-only(0248)도 전부 "만들어서 써 본 뒤" 제거했다 — 구현 후 기각이 다수였다.
- **근거가 사라진 분기는 남기지 않는다.** pan-only는 ‹› 페이저를 전제로 만든 것이었고, 페이저가 사라지자 분기의 존재 이유도 함께 사라졌다 — "같은 의도는 같은 경로".
- **업계 안티패턴도 표준이다.** 드래그·스냅 바텀시트를 "만들지 않은 것"이 이 묶음의 결정 중 하나다.

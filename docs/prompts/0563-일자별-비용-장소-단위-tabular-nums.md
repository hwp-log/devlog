# 0563 — 일자별 비용을 장소 단위로 + 금액 전 화면 tabular-nums

## 한 줄 요약

읽기 "여행 일자별 비용"의 평면 나열을 날짜 → 장소 → 카테고리 층위로 재구조화하고
(3px 색 막대 폐기 → 점+카테고리명), 금액 숫자를 전 화면 tabular-nums로 통일했다.
별건으로 항공 카드 비행기 아이콘의 하드코딩 흰 배경(라이트 어긋남)을 마스크 폐기로 수정.

## 왜 / 목적 / 이유

초안 — 이 섹션은 "이 코스에 얼마가 어디에 쓰였나"에 답하는 자리(플랜파인더의 핵심)인데,
PlanCost 행을 금액순으로 평평하게 나열해(0499 "롤업 X") 같은 장소 지출이 흩어지고
(숯불에닭 두 줄 이산), 카테고리가 색 막대뿐이라 무엇인지 알 수 없었다.
tabular-nums 근거: 숫자 열은 자릿수가 같은 폭이어야 세로 비교가 된다(업계 표준) —
한 곳만 적용하면 화면마다 숫자 모양이 달라지므로 전 화면.

## 작성한 프롬프트

```
[목표] 일자별 비용을 장소 단위로 묶고 층위를 세운다
① 날짜 = 칩(999px, 12px/500) + 오른쪽에 그날 소계 — 일정 날짜 탭과 같은 형태
② 장소 = 15px/500 + 그 장소 합계 — 카테고리 1건이면 [점+카테고리명] 병기 한 줄
③ 카테고리 줄 = 13px muted, [7px 점+이름]+금액, 들여쓰기 13px — 3px 막대 폐기
④ 금액 전 화면 font-variant-numeric: tabular-nums
⑤ (별건) 항공권 비행기 아이콘 배경색 라이트 어긋남 — 하드코딩 확인해 토큰으로

[먼저 확인해 보고할 것]
1. 장소 단위로 안 묶인 이유 — summarize 출력 단위, 묶기를 lib/소비처 어디서
2. 기타 지출은 장소명 자리에 label이 오면 되는지
3. 같은 장소 여러 날 — 날짜별 각각 묶이는 게 맞다
4. tabular-nums 적용 대상 전수
```

## 코드 작성 & 수정

### 조사 답 (plan 단계 보고)

1. summarize가 day 그룹 안을 **PlanCost 행 그대로 금액순** 나열 + 행에 planSpotId 미탑재 →
   금액순 정렬이 장소를 끊음. **묶기는 lib** — 그룹핑 파생의 기존 자리(0499~0505 계보),
   day 그룹 소비처는 PublicCostSection 하나뿐, 기존 테스트는 ratios·total만 단언
2. 기타 지출은 label이 장소명 자리 — 그룹 키 `planSpotId ?? 'misc:'+label`로 같은 라벨 묶임
3. day 버킷이 바깥이라 **구조적으로 날짜별 각각** — 확정 동작
4. 읽기 5곳 + 폼·소유자 4곳(전수 grep). "❌ 폼 변경"과 ④ "전 화면" 충돌은 클래스만
   적용(구조 무변)으로 해석 — 폼 밴드는 읽기 밴드의 거울(C)이라 갈리면 안 됨

### lib — dayGroups 신설 (`0545e35`)

```ts
dayGroups: Array<{ day; total; places: Array<{ label; total; items: [{category, amount}] }> }>
// itemGroups는 day=null 전용으로 — 소비처의 filter(day===null)는 무변 동작
```

정렬: 날짜 오름차순 / 장소 합계 내림차순(0498 계보를 장소 축으로 승계) / 카테고리 금액 내림차순.

### 렌더 — 층위 3단 + 점 통일

- 날짜 칩(bg-surface2 필 12px — 일정 Day 탭과 같은 형태) + 그날 소계, 아래 1px fg/15,
  날짜 간 26px. 스펙의 `surface-3`·`border-strong`은 레포에 없는 이름이라
  surface2·fg/15로 매핑(plan 승인으로 확정)
- 장소 15px + 합계. 1건이면 [7px 점 + 카테고리명 12px] 병기 한 줄(금액 중복 제거),
  2건 이상은 13px 들여쓰기 나열(장소 합계 cost-amount보다 한 단 아래 cost-label)
- 3px 막대 → CategoryDot(7px 원형 + 이름 병기) — **고정 비용 행도 같은 언어로 전환**
  (같은 섹션 두 언어 방지). 카테고리 요약의 막대는 누적 막대 색 대응 장치라 유지

### tabular-nums (`6b86a4d`)

### 아이콘 fix (`73fffe6`)

원인: `FlightLeg.tsx` 노선 선 위 `bg-white` 패치(마스크) + `text-[#5C7BC9]` — 카드가
반투명(glass-outer)이라 배경 일치 단색이 없어 라이트에서 흰 사각형. 마스크 폐기 —
선을 아이콘 앞에서 끝내 배경색 의존 제거, 색은 검색 폼과 같은 primary.
카드의 나머지 라이트 하드코딩(#1A1A1A·#888)은 별건 보고만.

## 결과 / 배운점

### 실측 (CDP, 공개 플랜)

- **수리남**: 조사 원문의 문제가 그대로 해소 — "숯불에닭 두 줄 이산"이
  장소 한 묶음(식비 30,000 + 교통 10,000, 합계 40,000) 나열로. 장소당 1건
  (서귀포호텔·허니문하우스)은 병기 한 줄 — 자연스러움 확인(스크린샷)
- **시드 도깨비**: 같은 라벨 기타 지출("더미 비용")이 misc 키로 한 묶음 +
  날짜별 분리(8.23/8.24 각각) — 질문 2·3 확정 동작 실증
- 라이트·다크 / 360·390·768 전부 가로 스크롤 0, 신규 색 0(surface2·fg/15·cat-* 토큰)
- 숫자 정합 검산: 밴드·총액 ₩513,844 = DB(비용 400,000 + 항공 113,844).
  B 시절 503,844과의 차 10,000은 사용자가 E 육안 테스트 중 추가한 실비용 — 화면·DB 일치
- tsc·eslint 통과, `npx jest lib/plan` 7/7, npm test 기존 실패 목록 외 회귀 없음
- 사용자 육안 잔여: 비공개 D 검증 플랜(청계천 2건 나열 + 기타 1건 한 줄) — 소유자만 열람 가능

### 배운점

초안 —

- **정렬 기준이 정보 구조를 부순다.** 금액 내림차순은 "큰 지출 먼저"라는 그럴듯한
  기준이었지만 장소라는 상위 단위를 관통해 정렬하는 순간 같은 장소가 흩어졌다.
  정렬은 층위 안에서만.
- **표시 언어는 개수보다 통일이 먼저.** 1건일 때 막대, 여러 건일 때 점이면 사용자는
  두 문법을 배워야 한다 — 점+이름 하나로 통일하고 막대는 "누적 막대 색 대응"이라는
  다른 역할이 있는 자리에만 남겼다.

## 결정 (Decisions)

- 일자별 비용의 정보 구조 = **날짜 → 장소 → 카테고리** — 정렬(금액순)은 각 층위 안에서만
- 그룹핑 파생은 lib(summarize) — 소비처는 조판만 (0499~0505 계보 유지)
- 기타 지출 그룹 키 = `misc:label` — 같은 라벨은 한 묶음
- 카테고리 표시 = 7px 점 + 이름 병기 (3px 막대는 카테고리 요약의 누적 막대 대응에만 잔존)
- 금액 숫자는 전 화면 tabular-nums — 폼 포함(클래스만, "폼 변경 금지"는 구조 기준으로 해석)
- 스펙에 없는 토큰 이름은 기존 토큰으로 매핑(surface-3→surface2, border-strong→fg/15) —
  한 자리를 위한 토큰 신설은 증식
- 반투명 면 위 마스크 패치 금지 — 배경과 일치하는 단색이 없다. 가리지 말고 조판으로 비울 것

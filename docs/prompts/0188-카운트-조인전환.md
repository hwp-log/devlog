# 0188 회고: 작품 스팟 수 카운트를 조인 기준으로 전환

작성일: 2026-07-14 / 소요: 약 30분 / 커밋: 1365d49

## 1. 한 줄 요약
admin·movie 쿼리의 스팟 수 집계를 구컬럼 FK에서 spot_movies 조인으로 옮겼다 — 그리고 이 대조가 dual-write 무결성 검증을 공짜로 해줬다.

## 2. 왜 / 목적 / 이유
- **왜**: 지금은 dual-write라 두 축이 같은 답을 내지만, S3에서 레거시 기록이 멈추면 카운트가 얼어붙은 옛 숫자를 조용히 보여준다.
- **목적**: `_count.spots` → `_count.spotMovies`, raw SQL의 `LEFT JOIN spots` → `LEFT JOIN spot_movies` + `COUNT(DISTINCT sm.spot_id)`.
- **이유**: S3의 선행 조건. DISTINCT는 @@unique가 있어도 조인 결과 중복 방어.

## 3. 작성한 프롬프트
[검수 모드] ★★★★ — 전환 전후 카운트 실쿼리 대조 요구. "다르면 dual-write에 구멍이 있다는 뜻"을 명시.

## 4. 작성·수정한 코드

2파일 8+/8-. **한 줄도 늘지 않은 치환**이고, 각 파일에서 같은 수정이 두 번씩 나온다
(admin은 PENDING·APPROVED 두 쿼리, queries.ts는 검색·목록 두 쿼리).

```ts
// app/(protected)/admin/page.tsx — Prisma _count 대상 교체 (×2)
- include: { _count: { select: { spots: true } } },
+ include: { _count: { select: { spotMovies: true } } },

- spotCount={m._count.spots}
+ spotCount={m._count.spotMovies}
```

```sql
-- lib/movie/queries.ts — 원시 SQL 조인 교체 (×2)
- SELECT m.id, m.title, COUNT(s.id) AS spot_count
- LEFT JOIN spots s ON s.movie_id = m.id
+ SELECT m.id, m.title, COUNT(DISTINCT sm.spot_id) AS spot_count
+ LEFT JOIN spot_movies sm ON sm.movie_id = m.id
```

`COUNT(s.id)` → `COUNT(DISTINCT sm.spot_id)`가 핵심이다. 조인 테이블은 (spot, movie) 쌍이라
한 스팟이 같은 작품에 두 번 연결될 일은 UNIQUE 제약이 막지만, **집계 대상이 행이 아니라
장소**임을 SQL에 명시해 둔다.

## 5. 결과 / 교훈
- 2파일 8+/8- 순수 치환. 12개 작품 전량 카운트 일치, 양방향 고아 0.
- 교훈: **전환 커밋의 대조는 회귀 검증이자 기존 구조의 무결성 확증이다.** 15분짜리 작업에서 어제 dual-write의 건강 검진을 공짜로 얻었다.

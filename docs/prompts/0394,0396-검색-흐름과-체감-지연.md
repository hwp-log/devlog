## 1. 한 줄 요약

모바일 검색이 "결과가 안 뜬다/느리다"로 체감되던 원인을 실측으로 세 층(구조·피드백·왕복 비용)으로 갈라, 그중 구조와 피드백을 처리했다.

## 2. 왜 / 목적 / 이유

**왜(문제)** — 실기기에서 세 가지가 걸렸다.

1. 검색 결과에서 항목을 선택해도 결과 목록이 남아 있었다.
2. 선택 후 "근처에 이런 촬영지가 있어요"(chooser)가 뜨는 경우 화면에서 보이지 않았다 — chooser가 지도 아래 사이드 카드 자리에 렌더되는데 모바일에서는 그 위치가 화면 밖이다.
3. 검색창을 탭하면 화면이 확대되고 되돌아오지 않았다.

이후 0395까지 마친 뒤 다시 실기기에서 반응 속도가 문제로 제기됐다 — 검색 결과가 안 보이거나 늦게 뜨고, 선택·찍기 후 편집 화면 전환이 늦었다.

**목적** — 검색해서 장소를 고르면 곧장 글 쓰는 화면으로 이어지고, 기다리는 동안 무엇이 일어나는지 보이는 상태.

**이유** — 속도 문제는 추측으로 고치면 헛짚는다고 보고 실측부터 했다. 실제로 이 판단이 맞았다 — 처음 세운 가설("0394가 `setActiveSpot`을 await 뒤로 옮겨서 느려졌다")은 git 실측으로 뒤집혔다(§4).

## 4. 코드 작성 & 수정

### 0394 — chooser를 시트에 (`components/SpotMap.tsx`)

프롬프트는 "`sheetOpen` 조건에 `nearbyChooser`를 포함"하라고 지시했으나, 실제 구현은 다른 길을 택했고 그쪽이 옳았다.

| 안 | 판정 | 근거 |
|---|---|---|
| `sheetOpen` 파생에 `nearbyChooser` 추가 | 기각 | 소비처(시트 마운트·WAAPI open키·Effect B focus 대상·history push·popstate)를 전부 손봐야 함 |
| **chooser 등장 시 `activeSpot` 세팅** | **채택** | 코드베이스 불변식("모든 진입 경로가 `activeSpot` 세팅")을 따르면 시트·풀스크린·전체보기 숨김·Effect B·history·WAAPI가 개조 없이 재사용 |

`renderChooser()`를 추출해 데스크톱 사이드 카드와 모바일 시트가 같은 마크업을 공유하게 했다. chooser 활성 시 `closeHandleRef`를 SpotMap이 소유하도록 해, 뒤로가기에서 0365 미저장 스팟 제거가 계속 돌게 했다(chooser 상태에서는 SpotPopup이 마운트되지 않아 핸들 소유자가 없다).

입력 자동확대는 `text-sm` → `text-base sm:text-sm`(모바일 16px)로 차단했다.

### 지연 실측 — 원인 세 층

| 서버 함수 | 핵심 작업 | cold | warm |
|---|---|---|---|
| `searchPlaces` | 카카오 keyword 1콜 | 118ms | 40~48ms |
| `findNearbySpots` | prisma bbox 쿼리 | 346ms | 43~44ms |
| `getSpotMeta` | 역지오코딩 + 교통 병렬 | — | 77~120ms |
| **매 액션 auth** | `createClient` + `getUser` | **754ms** | **123~158ms** |

**서버 작업 자체는 빠르다.** 지배적 고정비는 모든 서버 액션이 매번 지불하는 `supabase.auth.getUser()`였다 — `getUser`는 JWT를 로컬에서 신뢰하지 않고 매 요청 Auth 서버에 왕복한다. 검색→선택 흐름에 액션이 셋이므로 순수 인증만 warm 420ms다.

원인을 세 층으로 갈랐다:

1. **구조** — 편집 시트가 `await findNearbySpots` 뒤에야 올라온다. 후보는 chooser를 띄울지 정하는 데만 쓰이고 편집 폼 자체는 필요로 하지 않는데, 시트 상승 전체가 그 왕복을 기다린다.
2. **피드백 부재** — 디바운스 자동검색이 없어 Enter를 눌러야만 검색되고, `searchStatus`에 `'loading'`이 아예 없어 왕복 동안 무피드백이다. "결과가 안 뜬다"의 실체가 이것이다.
3. **왕복 비용** — 위 auth 고정비 + Vercel 콜드 스타트.

**가설 정정** — 지연의 원인으로 "0394가 `setActiveSpot`을 await 뒤로 옮겼다"를 의심했으나 git 실측으로 뒤집혔다. 0394 이전에도 no-candidate 브랜치는 이미 await 뒤였고, chooser 브랜치는 `setActiveSpot`을 아예 호출하지 않아 모바일 시트가 안 뜨던 것이 0394가 고친 버그였다. 지연은 S3-a 원설계(후보 조회가 chooser/편집 분기를 결정)에서 유래한다.

### 0396 — 피드백과 즉시 상승

```ts
// 디바운스 300ms, 최소 2자. 2자 미만은 0ms 타이머로 idle 정리
// (effect 본문 동기 setState를 피해 캐스케이드 렌더 lint 통과)
const delay = kw.length < MIN_SEARCH_LEN ? 0 : SEARCH_DEBOUNCE_MS;
searchDebounceRef.current = setTimeout(() => void runSearch(kw), delay);
```

응답 역전은 시퀀스 가드로 막았다. 서버 액션은 `AbortController` 정합이 어려워, 최신 요청 번호가 아니면 도착한 응답을 버리는 방식을 택했다.

시트 즉시 상승은 모바일 한정이다 — 데스크톱은 사이드 카드가 상시 노출이라 지연이 없어 기존 배치를 유지했다.

```
[변경 전] tap → await findNearbySpots → setActiveSpot → 시트 상승
[변경 후] tap → setActiveSpot → 시트 상승(320ms) ┐
                await findNearbySpots ──────────┘ 대개 애니 안에 도착
```

시트 상승 애니(`SHEET_OPEN_MS` 320ms)가 warm 조회를 대체로 덮으므로, 빠를 때는 대기 표시가 보이지 않는다. 편집 폼을 먼저 보였다가 chooser로 바꾸면 0394가 없앤 flash가 되살아나므로, 조회 중에는 `nearbyPendingId`로 대기 콘텐츠를 띄웠다.

조회 중 취소·삭제되면 유령 chooser가 뜨지 않도록 alive 가드를 넣고, `closeHandleRef` 소유 조건에 `nearbyPendingId`를 포함해 대기 중 뒤로가기에서도 0365 제거가 돌게 했다.

## 5. 결과 / 배운점

### 결과

- 타이핑만으로 검색되고, 왕복 동안 "검색 중…"이 표시된다.
- 항목을 고르면 결과 목록이 비워지고 시트가 곧장 올라온다.
- 후보가 있으면 같은 시트가 chooser로, 없으면 편집 폼으로 이어진다.
- 검색창 탭 시 화면이 확대되지 않는다.

### 배운점

- **체감 지연의 원인은 층이 다르고 처방도 다르다.** 실측 전에는 "구조 문제"로 뭉뚱그렸는데, 실제로는 구조(후보 조회 게이팅)·피드백 부재(로딩 표시 없음)·왕복 비용(인증)이 각각 기여했다. 이 중 피드백 부재는 코드를 아무리 최적화해도 해결되지 않고, 왕복 비용은 구조를 고쳐도 남는다.
- **"안 뜬다"와 "늦게 뜬다"는 같은 뿌리일 수 있다.** 자동검색이 없어 아무 일도 안 일어나는 것과 로딩 표시가 없어 진행 중임이 안 보이는 것이 합쳐져 두 증상으로 보였다.
- **애니메이션이 지연을 덮는다.** 시트 상승 320ms 안에 조회가 끝나면 사용자는 대기 상태를 아예 보지 않는다. 지연을 없애는 것과 지연을 안 보이게 하는 것은 둘 다 유효한 처방이고, 후자가 훨씬 쌀 때가 있다.
- **디바운스 자동검색은 응답 역전 처리가 세트다.** 없이 넣으면 옛 키워드 결과가 새 결과를 덮어 지금보다 나빠진다.
- **불변식이 있으면 그것을 따르는 쪽이 표면이 작다.** "모든 진입 경로가 `activeSpot`을 세팅한다"는 규칙 위에 얹으니 시트·연출·history가 개조 없이 따라왔다. 지시대로 `sheetOpen` 파생을 고쳤다면 소비처를 전부 검토해야 했다.
- **인증 왕복이 성능의 지배 항목일 수 있다.** 실제 작업이 40~120ms인데 인증이 140~754ms였다. `getUser`가 매 요청 Auth 서버에 왕복하기 때문이다. 보안 처리가 성능 비용을 만드는 자리를 실측 전에는 보지 못했다.

### 남은 것 / 후속

- **인증 왕복 절감**: `supabase.auth.getUser` → `getClaims`. 비대칭 서명 키가 켜져 있으면 로컬 검증이라 왕복이 사라진다(대칭이면 이득 없으므로 확인 선행). 다만 JWT 만료 전까지 정지·삭제된 사용자를 감지하지 못하므로 `requireAdmin` 등 역할 검사는 `getUser` 유지.
- chooser에서 뒤로가기로 취소하면 닫힘 연출이 chooser가 아니라 편집 폼 스냅샷을 보인다 — `closingChooser` 스냅샷이 필요.
- 검색창 외 16px 미만 입력창 전수 정리(0399에서 처리).

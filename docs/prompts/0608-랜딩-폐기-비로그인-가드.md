## 1. 한 줄 요약

app/page.tsx를 `redirect('/story')` 한 줄로 교체해 랜딩을 폐기(인증 여부 무관 공개 목록 직행) + /my-plan·/my-story의 `user!` non-null assertion 6곳을 미인증 시 `redirect('/login')` 가드로 교체. 중간 시도였던 랜딩 "둘러보기" 텍스트 링크는 실화면 검수에서 기각(회색 작은 글씨라 눈에 안 들어옴)되어 랜딩 폐기로 전환.

## 2. 왜 / 목적 / 이유

### 랜딩 폐기 — 비로그인도 바로 /story
- **왜**: 랜딩의 나가는 문이 회원가입·로그인 둘뿐 — /story·/spot-finder·/plan-finder는 이미 비로그인 공개인데 처음 온 사람은 가입 전엔 서비스 내용을 하나도 못 봄.
- **경위**: 1차 시도는 랜딩 유지 + "둘러보기" 텍스트 링크(약한 위계) 추가였으나, 실화면에서 회색 작은 글씨라 처음 온 사람이 그 문을 못 찾고 나갈 판이라 기각. 랜딩 자체를 걷어내는 안으로 전환.
- **목적**: 첫 진입에서 곧바로 서비스 실물(공개 스토리 목록)을 보게 함. 가입·로그인 진입은 헤더의 기존 "로그인" 링크(AppHeader, 비로그인 시 노출)가 담당.
- **이유**: 진입로를 "추가"하는 안은 위계를 약하게 하면 안 보이고, 강하게 하면 기존 두 버튼과 경쟁. 문을 늘리는 대신 벽을 없애는 쪽이 처음 온 사람의 목적(서비스 구경)에 직행.

### my-plan/my-story 가드 (유지)
- **왜**: 두 페이지가 가드 없이 `user!`를 사용 — 비로그인 진입 시 TypeError로 죽음. 랜딩 폐기로 비로그인 유입이 더 늘어나므로 오히려 필요성 증가.
- **이유**: 기존 관례(my-plan/actions.ts:9, story/new/actions.ts:22)와 동일한 `if (!user) redirect('/login')` 방식 준용.

## 5. 결과 / 배운점

### 결과
- `npx tsc --noEmit` 통과 — 미사용 import 잔여 없음.
- `npm test`: 6 스위트/8 테스트 실패 — 기존 실패 목록(auth 5스위트 + SpotPopup)과 일치, 회귀 없음.
- 비로그인 `/` 진입 → 즉시 /story. /my-plan·/my-story 비로그인 직접 진입 → /login (TypeError 해소).

### 배운점
① 조사 전제("루트가 /login 리다이렉트")가 코드와 달랐음(실제는 랜딩 렌더) — 수정 전 원문·git log 대조가 스코프를 바꿈. ② 약한 위계 진입로는 실화면에서 확인해야 함 — 산식(44px 타겟)은 통과해도 시인성은 별개.

## 결정 (Decisions)
- 랜딩 폐기 — `/`는 인증 여부 무관 /story로 직행. "둘러보기" 링크 추가안은 실화면 시인성 문제로 기각 (옛 랜딩은 git 93454dd~에 보존, 컴포넌트 추출 보존 안 함).
- 미인증 페이지 가드는 `if (!user) redirect('/login')` 기존 패턴 준용 (서버 액션 4종 패턴 통일은 별건).

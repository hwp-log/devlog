# 0349~351 회고: 예산 블록을 PLAN 블록으로

작성일 2026-07-26 / 소요 약 2시간 / 커밋 0349~0351

## 핵심 판단

- **`server-only` 제약을 우회하지 않고 데이터 경로를 설계했다.** 서버 페이지에서
  비중을 미리 계산해 결과만 내리니 드롭다운 전환에 서버 왕복이 없다.
- **부수 효과가 본 효과보다 컸다.** 원 금액이 클라이언트 payload에서 아예 빠져,
  "금액 미표시" 정책이 표현이 아니라 데이터 층에서 지켜지게 됐다.
- **블록 이름이 애매하게 느껴진 원인은 이름이 아니라 내용이었다.**

## 한 줄 요약

금액을 보여주던 예산 블록을 비중 트리맵으로 바꾸고, 플랜 제목·링크·소개를 합쳐
"PLAN 블록"으로 재편했다. 글쓰기와 상세 양쪽에 같은 구성으로.

## 왜 / 목적 / 이유

**왜** — 상세 화면은 이미 비중만 보여주는데 글쓰기는 정확 금액을 보여줬다. 쓸 때와
게시된 것이 달랐고, "연결 시 이 비용 정보가 스토리에 공개됩니다"라는 안내가 사실과
어긋난 상태였다.

**목적** — 편집과 상세가 같은 블록을 보게 해서 WYSIWYG을 성립시킨다.

**이유** — 비중 계산 함수 `summarizePlanCost`가 `server-only`라 클라이언트 폼에서
직접 부를 수 없었다. 이 제약을 푸는 방식이 이번 작업의 본체였다.

## 결과 / 배운 점

### 제약을 우회하지 않고 경로를 설계하기

두 안을 비교했다.

- **A안** — 서버 페이지에서 플랜별 요약을 미리 계산해 `{id, title, summary}`만 클라이언트로
- **B안** — 선택할 때마다 Server Action으로 요약 조회

B안은 드롭다운을 바꿀 때마다 서버 왕복이 생기고 로딩 상태 관리가 붙는다. A안을 택했다.

**의도하지 않은 이득이 더 컸다.** A안으로 가면 원 금액(`costs`·`flight`·`currency`)이
클라이언트로 아예 내려가지 않는다. 지금까지는 화면에 안 보일 뿐 브라우저 payload에는
금액이 실려 있었는데, 요약만 보내니 **정책이 표현 층이 아니라 데이터 층에서 지켜진다.**

(0349 시점 기준. 이후 트리맵과 비중 공개는 폐기되어 현재는 summaryLine 문자열을 내린다.)

`server-only` 모듈에서 타입만 `import type`으로 가져오는 건 런타임 import가 없어
안전하다. 기존에 같은 선례가 있어 그대로 따랐다.

### 이름이 아니라 내용을 고치기

블록 이름을 "여행계획"으로 정하고 나니 애매하게 느껴졌다. 플랜을 연결해도 비용만
표시되니 "여행비용"이 맞나 싶었다.

그런데 상세에서는 그 타이틀이 **플랜 제목 겸 링크**다. "여행비용"으로 바꾸면 누르면
비용 페이지로 가는 것처럼 읽힌다. 애매함의 원인은 이름이 아니라 **블록이 플랜을
가리키는데 내용이 비용뿐**이라는 것이었다.

그래서 이름을 내용에 맞추는 대신 **내용을 이름에 맞췄다.** 플랜 간단소개를 2줄 클램프로
넣으니 "이 스토리에 붙은 여행계획은 이런 코스고, 비용은 이런 비중이었다"가 한 블록에서
읽힌다.

### 눈썹 이름을 BUDGET에서 PLAN으로

블록에 플랜 링크가 들어오면 예산은 그 안의 내용이 된다. 상위 개념인 `PLAN`이 맞고,
내비게이션의 `PlanFinder`와 같은 말이라 새 용어를 만들지 않아도 됐다.

부수 효과로 0343에서 남겨둔 문제가 함께 풀렸다. 총액 0인 플랜에서 `BUDGET / 예산 요약`
헤더만 뜨는 게 이상했는데, 그 헤더는 예산을 약속하고 안 지킨 것이었다. 플랜 제목은
약속이 아니라 그 자체가 정보이자 링크라 단독으로 성립한다.

### 등록 버튼 위치가 만든 오해

0340에서 등록 버튼을 여행동선 아래로 옮겼더니, 플랜·여행동선까지 다 채워야 발행되는
것처럼 읽혔다. 안내 한 줄을 넣었다가 다시 지웠다.

**문제 자체는 아직 남아 있다.** 안내를 지우면서 그 신호가 사라졌고, 대체 수단은 없다.
실사용자가 생기면 재판단할 항목으로 남겼다.

## 대표 코드

```tsx
// app/(protected)/story/new/page.tsx  (발췌 — 조회~가공 부분만)
  const plans = await prisma.myPlan.findMany({
    where: { ownerId: user.id, story: null },
    select: {
      id: true, title: true, description: true, currency: true, coverUrl: true,
      // 요약 한 줄(일수·스팟·인원·금액) 소스 — 상세 PLAN 카드와 동일 필드(0459 정합)
      startDate: true, endDate: true, headcount: true, isPublic: true,
      _count: { select: { spots: true } },
      costs: { select: { category: true, amount: true } },
      flight: { select: { totalAmount: true } },
    },
    orderBy: { createdAt: 'desc' },
  });
  // 요약 한 줄은 server-only(summarizePlanCost total → buildPlanSummaryLine) — 여기서 문자열로
  // 완성해 내림. 원 금액(costs·flight)은 안 내림(상세·plan-finder와 동일 공개 수준).
  const availablePlans = plans.map((p) => ({
    id: p.id,
    title: p.title,
    description: p.description,
    coverUrl: p.coverUrl,
    summaryLine: buildPlanSummaryLine({
      startDate: p.startDate,
      endDate: p.endDate,
      spotCount: p._count.spots,
      headcount: p.headcount,
      showCost: p.isPublic,
      total: summarizePlanCost(p.costs, p.flight, p.currency as 'KRW' | 'USD' | 'JPY').total,
      currency: p.currency as 'KRW' | 'USD' | 'JPY',
    }),
  }));
```

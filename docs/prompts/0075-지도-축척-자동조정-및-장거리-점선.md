## 1. 한 줄 요약

서울→제주처럼 멀리 떨어진 스팟이 한 화면에 들어오도록 지도 축척을 자동 조정(fitBounds)하고, 50km 초과 장거리 구간을 점선으로 구분해 그렸다. 작업 중 지도가 setBounds를 계속 되돌리는 잠복 버그를 발견해 수정했다.

---

## 2. 왜 / 목적 / 이유

### 장거리 구간을 점선으로 표시
- 왜: 장거리 구간(서울→제주)은 실제 도로 경로가 아니다(비행·배). 실선으로 이으면 바다 위에 도로가 있는 것처럼 오해된다.
- 목적: 단거리는 여정의 흐름(실선), 장거리는 건너뜀·이동(점선)으로 한눈에 구분되는 상태.
- 이유: 동선은 내비게이션이 아니라 기록이라 도로 스냅을 하지 않는다. 점선은 항공 노선도의 관례로 "이동했으나 이 선이 실제 경로는 아니다"를 뜻하고, 사용자가 다른 앱에서 학습한 코드(Jakob's law)라 설명 없이 읽힌다. haversine 거리 50km 초과를 장거리로 판정해 점선 처리했다.

### 축척 자동 조정(fitBounds)
- 왜: 스팟이 멀리 떨어지면 기본 줌으로는 일부만 보이거나 한쪽으로 치우친다.
- 목적: 모든 스팟이 한 화면에 들어오는 상태.
- 이유: 지도 생성 시 모든 마커의 경계를 계산해 setBounds로 맞췄다. 보기 전용(readOnly) 화면에서도 동작하도록 기존 게이트를 제거했다.

### 제어형 prop 충돌 수정 (잠복 버그)
- 왜: setBounds로 범위를 맞춰도 지도가 원래 자리·줌으로 되돌아갔다.
- 목적: 내 fitBounds 명령이 최종 화면에 유지되는 상태.
- 이유: center·level을 제어형(controlled) prop으로 넘겨서, 라이브러리 내부 useEffect가 setBounds 직후 prop 기준으로 재동기화하며 되돌렸다. 명령형(setBounds)과 선언형(prop)이 같은 화면을 두고 충돌했고, 마지막에 실행된 prop 동기화가 이긴 것이다. 게다가 center를 인라인 객체로 넘겨 매 렌더 새 참조가 되어 재동기화가 반복됐다. 해결: center 참조를 useState 초기화로 고정 + setBounds를 useEffect([mapInstance])에서 fitDoneRef로 한 번만 실행 + mapInstance를 state로 보유.

```tsx
// components/SpotMap.tsx — center 참조 고정 (매 렌더 새 객체 방지)
const [mapCenter] = useState(() => ({ lat: firstSpot.lat, lng: firstSpot.lng }));
const [mapInstance, setMapInstance] = useState<kakao.maps.Map | null>(null);
const fitDoneRef = useRef(false);

// setBounds를 mapInstance 준비 후 한 번만 실행 (prop 재동기화와 충돌 회피)
useEffect(() => {
  if (!mapInstance || fitDoneRef.current) return;
  const bounds = new kakao.maps.LatLngBounds();
  spots.forEach((s) => bounds.extend(new kakao.maps.LatLng(s.lat, s.lng)));
  mapInstance.setBounds(bounds);
  fitDoneRef.current = true;
}, [mapInstance, spots]);
```

## 5. 결과 / 배운점

- 명령형(setBounds)과 선언형(prop)이 같은 상태를 두고 충돌하면, 마지막에 실행된 쪽이 이긴다. 우선순위는 라이브러리가 아니라 내가 코드 구조로 정한다 — 선언형이 매 렌더 자기 말을 반복하지 못하게 하거나(참조 고정), 통제권을 한쪽에 몰아준다.
- 인라인 객체 prop(`center={{...}}`)은 매 렌더 새 참조가 되어, 참조 동등성에 의존하는 useEffect를 매번 깨운다. 값이 같아도 참조가 다르면 React는 변경으로 본다.
- 진단은 "반영이 안 됨(실패)"이 아니라 "반영됐다가 덮임(충돌)"으로 봐야 원인을 찾는다. 전자는 "내 코드가 왜 안 도나"를 찾다 미궁에 빠지고, 후자는 "또 누가, 언제 이 화면을 쓰나"를 찾아 라이브러리의 prop 동기화에 도달한다.
- 점선=이동은 사용자가 항공 노선도 등에서 학습한 관례(Jakob's law)다. 설명 없이 읽히는 시각 언어를 쓰면 UI가 스스로 설명한다.
- 동선은 기록이지 내비게이션이 아니다(도로 스냅 안 함). 이 전제가 단거리 실선 / 장거리 점선 구분의 근거다.

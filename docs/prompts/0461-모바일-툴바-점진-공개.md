## 1. 한 줄 요약

모바일(sm 미만)에서 3줄로 랩되던 에디터 툴바(버튼 15+구분선 4)를 점진 공개로 재편 — 한 줄 H2·B·I·목록·이미지+더보기(44px 터치 타겟), 나머지 9종+서식은 더보기 팝오버(신규 ToolbarMore)로. 데스크톱은 현행 유지, 분기는 CSS-only(`hidden sm:inline-flex`·`order-N sm:order-none`).

---

## 2. 왜 / 목적 / 이유

(초안 — 프롬프트 배경·확정 답변에서 추린 초안 수준)

- **왜**: 390px에서 툴바가 3줄 랩 + 구분선이 줄 끝에 걸려 어수선. 버튼 28px로 터치 타겟 44px 미달.
- **업계 기준(사용자 검색 확인)**: 가로 스크롤은 안티패턴(옵션 발견성 상실), 권장은 점진적 공개, 하단 고정 툴바는 iOS 키보드 시 fixed 이탈 위험.
- **한 줄 구성 근거(사용자 확정)**: 슬래시로 대체 가능한 블록(인용 등)은 접고, 진입점이 툴바·버블뿐인 마크(B·I)를 남긴다. 서식은 글 시작 시 1회성이라 더보기 안으로.

## 4. 코드 작성 & 수정

### 검수 핵심 수치
- 가용 행 폭: 390px→324px, 360px→294px. 44px 타겟 6개+gap 4px = 284px → 360px 한 줄 수용 (§5 권장 간격 8px은 304>294로 물리적 초과 — 4px 수용을 plan 승인으로 확정).
- 접었을 때 슬래시(7종)·버블(5종) 어디로도 접근 불가: **H3·취소선·인라인 코드** → 더보기가 유일 진입점.

### 1. FormatMenuContent 추출 (`FormatMenu.tsx`, 행동 불변)

양식 목록+확인 화면 전환·키보드 순회·포커스 관리를 `FormatMenuContent({ editor, onDone, onEscape })`로 추출. FormatMenu는 트리거+셸+위치+바깥클릭만 보유. 내부 상태는 마운트마다 초기화라 "열 때 항상 목록부터"가 리셋 코드 없이 성립.

### 2. 툴바 반응형 분기 (`TiptapEditor.tsx`)

```tsx
// ToolbarButton — 모바일 44px 타겟, sm 이상 기존 28px. 버블 메뉴 공유라 버블도 44px(§5 파급)
className={`inline-flex items-center justify-center px-2 py-1 min-h-[44px] min-w-[44px]
  sm:min-h-0 sm:min-w-0 ... ${className}`}
// 유지 6개: order-1~6 + sm:order-none (DOM은 데스크톱 그룹 순서 유지)
// 접힘 9개: max-sm:hidden / 구분선·서식 래퍼: max-sm:hidden
// ※ 0461 최초 커밋은 hidden sm:inline-flex였으나 v4 유틸 순서(알파벳 h<i)상 베이스
//   inline-flex가 hidden을 덮어 접힘이 무효 — 0462에서 max-sm:hidden으로 정정
<ToolbarMore editor={editor} active={active} onLink={handleLink} className="order-6 ml-auto sm:hidden" />
```

### 3. 신규 `ToolbarMore.tsx` (더보기 팝오버)

- FormatMenu 선례 복제: floating-ui `fixed`+autoUpdate(bottom-end, offset 8), 바깥클릭 닫기, ESC·화살표 선형 순회, aria-haspopup/menu, 셸 클래스 동일.
- 목록 뷰: 2열 그리드, 행 min-h-44 아이콘+라벨 10종(소제목·작게·인용·취소선·인라인 코드·링크·콜아웃 3종·서식). 활성 표시는 부모 useEditorState 맵 prop 공유(단일 소스). 링크는 handleLink prop 전달(프롬프트 로직 중복 금지).
- 서식 뷰: 같은 셸에서 FormatMenuContent 렌더(0359 내용 전환 패턴) + 터치용 "뒤로" 행(모바일엔 ESC 없음).

## 결정 (Decisions)
- 모바일 에디터 툴바는 점진 공개: 한 줄 H2·B·I·목록·이미지+더보기 — 선별 기준은 "슬래시로 대체 가능한 것은 접고, 진입점이 툴바·버블뿐인 마크를 남긴다"
- 모바일 툴바 버튼 간격 4px — §5 권장 8px의 확정 예외 (44px×6이 360px에 들어가는 물리적 조건, 동일 기능 군집이라 오터치 비용 낮음)
- 팝오버 신설 시 FormatMenu 메커니즘(floating-ui fixed+autoUpdate·바깥클릭·aria-menu)이 표준 선례, 다단 내용은 "같은 셸에서 내용만 전환"(0359)
- 반응형 분기는 CSS-only(max-sm:hidden/order + sm: 복원) — JS matchMedia 분기는 CSS로 불가할 때만. **베이스에 display 유틸이 있는 요소의 숨김에 무접두 hidden 금지**(v4 알파벳 순서 함정, 0462에서 실측 확정)

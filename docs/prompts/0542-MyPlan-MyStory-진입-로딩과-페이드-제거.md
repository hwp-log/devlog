## 1. 한 줄 요약

MyPlan·MyStory에 §11 기준(골격 전체 shimmer) 진입 로딩 신설 + appear-up/CardReveal 페이드 제거(스켈레톤과 이중 방지) + 기존 목록 스켈레톤 2벌에 페이저 자리 추가 + "2px 강조선 로딩 중 숨김"을 §11 규칙으로 승격(0538 상세에도 적용).

---

## 2. 왜 / 목적 / 이유

(초안 — 초안)

- **왜**: MyPlan·MyStory는 진입 로딩이 없고 페이드 등장 연출만 있어, 스켈레톤을 넣으면 등장 연출이 이중이 됨.
- **강조선 규칙 승격 근거**: 경계를 굵기가 아니라 역할로 — 진한 2px는 위계 강조 장치라 "뼈대 선행 표시" 기각 사유(0541)의 연장, 옅은 선(hairline·카드 테두리)은 면 분할이라 로딩 중에도 구조를 잡아줌.

## 4. 코드 작성 & 수정

### 조사 결과
- 기존 2벌(plan-finder/(list)·story/(list))은 §11 부합 — 실물은 크롬 예외인 헤더뿐. 누락은 페이저 자리(공용 Pagination = mt-10 + h-11, totalPages>1일 때 등장 → 하단 출렁임).
- MyPlan·MyStory는 전건 렌더라 페이지네이션 없음 → 신설분에 페이저 불필요.
- MyPlan 그리드 = PlanListClient와 클래스 동일, MyStory 그리드 = StoryCardList와 동일 → **공용 PlanSkeletonGrid/StorySkeletonGrid 재사용** (신규 그리드 코드 0).

### 주요 변경
- 페이저 자리: 두 목록 로딩에 `mt-10` 센터 h-11 바 (폭 332 = 7셀×44+gap 근사)
- 페이드 제거: appear-up 10곳 + CardReveal 래퍼 2곳 통째 제거 — 필터 전환 stagger도 함께 소멸하나 무연출 즉시 교체는 plan-finder 0430 확립 패턴. 공용 CardReveal·스토리 브라우저는 무접촉
- 신설 2벌: 헤더(아바타 56px·눈썹·타이틀·부제/버튼·검색바) 전부 shimmer + 공용 스켈레톤 그리드 count=8 (전건 렌더라 PAGE_SIZE 근거 불가 → 최대 밀도 4열 구간 2행 = 첫 뷰포트 채움)
- §11: "구조선 실색" 문장을 "진한 강조선 숨김(투명 보더) / 옅은 구조선 실색"으로 교체, 0538 SectionHeaderSkeleton에 적용

## 5. 결과 / 배운점

### 결과
- `npx tsc --noEmit` 전 커밋 통과. 커밋 5개 분리.
- **잔여 이슈**: `my-plan/loading.tsx`가 하위 `/my-plan/new`·`/my-plan/[id]`의 fallback으로도 적용됨(자체 loading 부재) — 목록 스켈레톤이 폼·상세 진입에서 잠깐 뜸. 0490→0491과 같은 유형, 하위 자체 loading 신설은 별도 사이클. 폴더 재배치((list) 그룹화)는 금지 규칙이라 미채택.
- 페이저 자리 폭 332는 근사(슬롯 수 반응형) — 높이·위치는 정확.

## 결정 (Decisions)

- 스켈레톤 선 처리 경계 = 역할(강조 vs 분할): 진한 2px 숨김(투명 보더로 자리 유지), 옅은 선 실색 (§11 정본)
- 목록 스켈레톤은 페이저 자리 포함 (대표형 = totalPages>1)
- 진입 페이드와 스켈레톤은 공존 금지 — 스켈레톤 있는 화면은 등장 연출 제거 (0430 무연출 즉시 교체 패턴으로 통일)
- 전건 렌더 목록의 스켈레톤 카드 수 = 최대 밀도 열 수 × 2행 (첫 뷰포트 채움 근거)

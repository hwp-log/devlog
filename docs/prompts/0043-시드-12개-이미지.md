## 결과·배운점

**잘 된 점**

- 4열 그리드가 12개 시드로 가득 차서 "포트폴리오" 느낌 한 번에 확보. 멘토에게 보여주기 부끄럽지 않은 상태.
- `findUnique` + `deleteMany` 멱등성 패턴 덕분에 `npx prisma db seed`를 여러 번 실행해도 안전.
- 0041에서 만든 `extractFirstImage`가 한 줄 갈음으로 로컬 이미지까지 지원 → 확장성 검증.

**알게 된 것 — 시드 멱등성의 의미**

처음에는 단순히 `create`만 적었다가 두 번째 실행에서 중복 에러. 멱등성(idempotency) = "여러 번 실행해도 같은 결과"는 시드의 기본 요건.

| 패턴 | 멱등성 | 문제점 |
|---|---|---|
| `create`만 | ❌ | 두 번째 실행에서 unique 충돌 |
| `upsert` | ✅ | 매번 모든 필드 갱신, 느림 |
| `deleteMany` + `create` | ✅ | 깔끔, 빠름 — 우리 선택 |

`deleteMany` 후 `create`가 가장 단순. 시드는 항상 "최신 상태로 리셋"이 자연스러우니까.

**작품 정보 검증의 중요성 — web_search 가치**

수리남을 광주로 잘못 적은 게 잡힌 게 시사적. 멘토나 면접관이 봤을 때 "이 사람 사실 확인 안 함" 인상을 줄 수 있는 부분.

- 시드는 데모용 = 면접에서 가장 먼저 보여줄 내용
- 잘못된 정보가 들어가면 "꼼꼼함" 신뢰도 무너짐
- web_search 한 번으로 막을 수 있는 부분

이건 메모리에 적힌 "기술·도구·라이브러리 web_search 필수" 규칙의 확장 적용. **실제 콘텐츠도 사실 확인 대상**.

**시드 본문 구조의 일관성**

12개 모두 같은 구조:
```html
<img src="/seed/{name}.png" alt=""/><p>4문장</p>
```

이게 일관되니까:
- 카드 썸네일 추출이 항상 동작 (모든 글에 첫 이미지가 있음)
- 미리보기 텍스트 길이가 비슷 (4문장이라 120자 부근)
- 카드 그리드가 균등하게 보임 (높이 차이 적음)

→ "데이터의 일관성이 UI 균형을 만든다". 만약 어떤 시드는 이미지 없고 어떤 건 본문이 한 줄이면 카드가 들쭉날쭉해짐.

## 1. 한 줄 요약

"여행동선 짜기" 메뉴의 [촬영지 직접검색]을 활성화해, Mapbox SearchBox로 장소를 검색하면 마커가 추가되고 편집 카드로 이어지게 했다. 검색 마커도 직접클릭 마커와 똑같이 "취소 시 삭제"가 작동하도록, 이름을 spot이 아니라 입력창 초기값으로만 채우는 방식을 택했다.

---

## 2. 왜 / 목적 / 이유

### 핵심 A — Mapbox SearchBox로 촬영지 검색

- **왜**: 지도를 직접 눌러 찍는 방식만으로는 장소 이름을 매번 손으로 적어야 했다. 이름으로 바로 찾는 길이 필요했다.
- **목적**: 검색 → 결과 선택 → 마커 자동 추가 + 편집 진입까지, 직접클릭과 같은 흐름에 "이름 자동 채움"만 더한 상태.
- **이유**: 공식 React SDK(`@mapbox/search-js-react`)의 `<SearchBox>`가 이미 쓰는 Mapbox 지도와 한 토큰으로 붙고, 결과 선택 시 카메라 이동·드롭다운까지 제공해 직접 만들 필요가 없었다.

### 핵심 B — 검색 마커도 "취소 시 삭제" 통일 (이번 작업의 핵심 결정)

- **왜**: 0055에서 만든 규칙은 "편집창을 이름 없이 닫으면(취소) 그 마커를 버린다"였고, 판단 기준이 `displayName`(저장된 이름)이 비었나였다. 그런데 검색은 이름을 *이미 안다*. 검색 이름을 spot에 바로 넣으면 `displayName`이 차서, 취소해도 그 삭제 규칙에 안 걸린다 → 검색은 취소해도 마커가 남고, 직접클릭(취소=삭제)과 동작이 갈린다.
- **목적**: 검색 마커도 취소하면 직접클릭처럼 깔끔하게 사라지는 상태. 사용자 눈엔 "추가했다 무르면 사라진다"가 일관.
- **이유**: 새 플래그를 만들거나 삭제 규칙을 고치는 대신, **이름을 "확정값(spot.name)"이 아니라 "입력 중인 값(입력창 초기값)"으로만 두기**로 했다. 그러면 `displayName`은 저장 전까지 빈 채라 기존 삭제 규칙이 *그대로* 작동한다. 즉 "displayName 비우기"는 목적이 아니라 "삭제 규칙 재사용"이라는 목적을 위한 수단이다.

> 면접용 한 문장: "취소 시 삭제 판단이 `displayName` 빔을 기준으로 도는데, 그 규칙을 안 깨려고 검색 이름을 spot이 아닌 입력창 초기값으로만 흘려보냈다."

### components/SpotMap.tsx — 검색 결과 → 마커 추가 (SSR 회피 dynamic import)

```tsx
const SearchBoxDynamic = dynamic(
  () => import('@mapbox/search-js-react').then((m) => ({ default: m.SearchBox })),
  { ssr: false }
);

function handleSearchRetrieve(res: import('@mapbox/search-js-core').SearchBoxRetrieveResponse) {
  const feature = res.features[0];
  if (!feature) return;
  const [lng, lat] = feature.geometry.coordinates as [number, number];
  const name = (feature.properties.name ?? '') as string;
  const id = addSpot('', lng, lat);   // spot.name은 빈 채 (삭제 규칙 재사용)
  setActiveSpot({ id, name: '', lat, lng, order: localSpots.length + 1 });
  setSearchedName(name);              // 이름은 입력창 초기값으로만
  setMode('edit');
}
```

```tsx
// 변경 전 — 2개 미만이면 그냥 빠져나가 기존 선이 남음
useEffect(() => {
  if (!mapRef.current || localSpots.length < 2 || !token) return;

      if (map.getSource('route')) map.removeSource('route');         // 소스 나중
    }
    return;
  }
  // ...기존 그리기 로직...
}, [localSpots, token]);
```

## 5. 결과 / 배운점

### 결과
- [촬영지 직접검색] 활성화 → 검색 → 마커 추가 → 편집 진입 정상.
- 검색 마커도 취소 시 삭제, 저장 후 재편집 시 보존 — 직접클릭과 동작 통일.
- 마커 2개 미만이면 폴리라인 제거, placeholder 예시 노출.

### 배운점
1. **삭제 규칙을 안 건드리려고 데이터 위치를 바꾼 설계.** "이름을 어디에 둘까(spot vs 입력창)"가 곧 "기존 규칙이 걸리나"를 결정했다. 새 플래그 없이 기존 로직을 재사용하는 길이 더 깔끔했다.
2. **`onRetrieve`는 콜백 ref가 불필요.** 지도 클릭은 마운트 1회 effect 안이라 stale 우회용 ref가 필요했지만, `<SearchBox onRetrieve>`는 매 렌더 최신값을 잡는 React 콜백이라 그 문제가 없다.
3. **공유 상태(searchedName)는 다른 경로로 샐 수 있다.** 검색용 이름이 직접클릭 마커 입력창에 새는 누수를 검수에서 잡았다 — 직클 경로에서 비우는 한 줄로 해결.
4. **환경 함정 (Prisma 7 + Node).** 패키지를 `--ignore-scripts`로 설치하면서 Prisma의 자동 client 생성이 건너뛰어졌고, Node 20.9가 Prisma 7 요구(20.19+)보다 낮아 `prisma generate`가 ERR_REQUIRE_ESM으로 막혔다. Node 22로 올린 뒤 `prisma generate`로 해결 → 라이브러리 메이저 버전은 Node 요구사항부터 확인.

### 남긴 것 (별도 작업)
- **한국 장소 검색 커버리지** — Mapbox Search Box가 광화문은 찾아도 서울시청 등은 못 찾음(Mapbox 한국 POI 데이터 한계, 코드 문제 아님). 지도는 Mapbox 유지, 검색만 Kakao/Naver 로컬 검색으로 교체 검토 → 0057 후보 (★★★★).
- **취소 외 경로 빈 마커** — 다른 마커 클릭/토글로 빠질 때 빈 마커가 남는 구멍 → 0058 청소 메모.

- 작성일: 2026-06-05
- 소요: 약 1시간
- 관련 커밋: `feat: 0072 마이플랜 계획리스트 순서변경 기능 추가(드래그 형식), 이외 수정, 삭제버튼 위치 정리`

## 한 줄 요약

편집기 Day 항목에 dnd-kit 드래그 재정렬을 추가하고(0049 사이드바 스팟 패턴 재사용), 마이플랜 3페이지(작성/상세/수정)의 이동 동선을 마이스토리 패턴(헤더 수정·삭제 버튼 + '← 목록으로' 하단 링크)으로 통일했다.

## 왜 / 목적 / 이유

### 1. Day 항목 드래그 재정렬

- 왜: 일정 항목의 순서를 바꿀 방법이 없어, 순서를 고치려면 항목을 지우고 다시 입력해야 했다.
- 목적: 핸들을 잡아 끌면 순서가 바뀌고, 저장하면 그 순서 그대로 상세 타임라인에 반영되는 상태.
- 이유: 사이드바 스팟 순서 변경(0049)에서 이미 dnd-kit 패턴을 검증했으므로 그대로 재사용했다. 새 라이브러리 검토도, 새 구조 설계도 필요 없었고 plan 검수도 "0049와 같은가"만 보면 됐다. 저장 로직은 손대지 않았다 — items 배열 순서가 곧 저장 순서라서, 드래그는 배열만 재정렬하면 된다(arrayMove).

### 2. 드래그 리스너는 행 전체가 아니라 핸들에만

- 왜: 항목 한 줄 안에 장소 이름 텍스트 입력, 카테고리 select, 금액 입력이 있다. 행 전체를 드래그 영역으로 만들면, 입력창을 클릭해 커서를 놓는 동작·텍스트를 드래그로 선택하는 동작이 전부 "누르고 끌기"라서 행 정렬 제스처와 충돌한다.
- 목적: 입력은 입력대로, 정렬은 정렬대로 — 한 제스처가 한 의미만 갖는 상태.
- 이유: 드래그라는 의미를 왼쪽 핸들 버튼(전용 영역)으로 분리했다. dnd-kit의 `{...listeners}`를 행이 아니라 핸들 버튼에만 달면, 입력 요소들은 드래그 시스템 밖에 있게 되어 충돌이 구조적으로 사라진다. 또 하나의 함정인 Day 전환 꼬임은, 재정렬 함수가 현재 선택된 Day의 items에만 작동하도록 범위를 한정해 차단했다.

### 3. 마이플랜 이동 동선 — 마이스토리 패턴 재사용

- 왜: 작성/상세/수정 3페이지에 뒤로 가는 동선이 없어 브라우저 뒤로가기에 의존했고, 상세 페이지의 하단 풀폭 수정/삭제 버튼은 마이스토리 상세(제목 옆 수정·삭제)와 문법이 달랐다.
- 목적: 마이스토리와 마이플랜이 같은 화면 문법을 쓰는 상태 — 상세는 제목 우측 수정·삭제, 모든 페이지 하단에 '← 목록으로'.
- 이유: 새 내비 스타일을 만들지 않고 마이스토리 상세의 구현을 기준으로 삼았다. 사용자는 한 번 익힌 문법을 앱 전체에서 재사용하게 되고, 우리는 검증된 스타일을 가져와 구현 비용을 줄인다. 저장 버튼은 페이지 우측 상단으로 이동해 헤더 버튼 문법과 맞췄다.

## 코드 작성 & 수정

드래그 가능한 항목 행 — 리스너는 핸들 버튼에만:

```tsx
// app/(protected)/my-plan/new/MyPlanNewForm.tsx
function SortablePlanItem({ item, onUpdate, onRemove }: { ... }) {
  const { attributes, listeners, setNodeRef, transform, transition, isDragging } =
    useSortable({ id: item.id });
  const style = { transform: CSS.Transform.toString(transform), transition };
  return (
    <div ref={setNodeRef} style={style}
      className={`grid grid-cols-[auto_auto_1fr_auto_auto_auto] gap-2 items-center${isDragging ? ' opacity-50' : ''}`}>
      {/* 드래그 리스너는 이 핸들 버튼에만 — 입력창·select는 드래그 시스템 밖 */}
      <button type="button" aria-label="순서 변경" {...attributes} {...listeners}
        className="text-slate-300 cursor-grab active:cursor-grabbing hover:text-slate-500">
        <GripVertical size={14} />
      </button>
      {/* 카테고리 배지 / 이름 입력 / 카테고리 select / 금액 입력 / 삭제 버튼 */}
    </div>
  );
}
```

재정렬은 현재 Day의 items에만 — Day 전환 꼬임 차단:

```typescript
function handleDragEnd(event: DragEndEvent) {
  const { active, over } = event;
  if (!over || active.id === over.id) return;
  setEditor((prev) =>
    updateDayItems(prev, clampedDay, (items) => {
      const oldIdx = items.findIndex((it) => it.id === active.id);
      const newIdx = items.findIndex((it) => it.id === over.id);
      return arrayMove(items, oldIdx, newIdx); // 배열 순서 = 저장 순서
    })
  );
}
```

## 결과 / 배운점

- 일정 순서를 끌어서 바꾸고 저장하면 상세 타임라인에 그대로 반영된다. 마이스토리와 마이플랜이 같은 화면 문법(헤더 수정·삭제, ← 목록으로)을 공유한다.
- **같은 제스처가 두 의미를 가지면 충돌한다 — 의미를 영역으로 분리한다.** 행 안에 입력 요소가 있으면 "누르고 끌기"가 정렬과 입력 조작 양쪽으로 해석된다. 드래그를 핸들 전용 영역으로 분리하면 충돌이 코드가 아니라 구조에서 사라진다.
- **검증된 패턴 재사용은 속도와 일관성을 동시에 산다.** 드래그는 0049 패턴, 내비는 마이스토리 패턴을 그대로 가져왔다. plan 검수가 "기준 패턴과 같은가" 한 가지 질문으로 줄었고, 사용자 입장에서는 앱 전체가 한 가지 문법으로 읽힌다.
- 기능을 붙일 때 저장까지 같이 고칠 필요가 있는지 먼저 본다. 배열 순서가 곧 저장 순서인 구조라서 드래그는 표시 계층의 일이었고, DB와 액션은 한 줄도 바뀌지 않았다.

### 1. 연속 기록일 계산 풀이

**목적**

사용자가 매일 기록을 작성했는지 한눈에 보여주기.
"오늘까지 며칠 연속 작성 중인지" + "역대 최장 연속 기록 며칠인지" 표시.

**고민 — 어떻게 풀까?**

각 날짜가 어느 시작점에 수렴하는지 확인 필요. 무슨 말이냐면...

[연속 케이스]
1. 5/12, 5/13 기록 (5/11이 시작점이라 가정).
2. 5/12에 순번 1, 5/13에 순번 2 부여.
3. 5/12 - 1 = 5/11. 5/13 - 2 = 5/11.
4. 둘 다 5/11로 수렴 = 같은 시작점 공유 = 연속 그룹.

[끊김 케이스]
5. 5/12, 5/13 기록 후 5/14 끊김. 그 다음 5/15에 다시 기록.
6. 5/12 - 1 = 5/11 (시작점 A). 5/13 - 2 = 5/11 (시작점 A).
7. 5/15 - 3 = 5/12 (시작점 B). 시작점이 달라짐.
8. 시작점이 다른 지점 = 끊김 발생.

[결론]
"같은 시작점에 수렴 = 같은 연속 그룹"이라는 본질.
SQL에서 이 시작점을 그룹 ID로 사용해서 GROUP BY로 묶음.

**방법 — 기술 적용**

이 풀이가 SQL의 "Gaps and Islands" 패턴.
- 순번 부여 → ROW_NUMBER WINDOW 함수
- 그룹화 → GROUP BY
- 그룹별 길이 / 마지막 날짜 → COUNT / MAX

> **Gaps and Islands**
> 순서있는 데이터에서 연속 구간(섬)과 끊긴 구간(틈)을 구분하는 SQL 패턴.
> 출석 기록, 사용자 세션, 주문 일자 등 "연속 데이터 여부"를 따지는 모든 영역에서 사용.

> **WINDOW 함수**
> 각 행마다 주변 행을 참고해 계산하는 SQL 함수.
> 일반 함수(SUM, COUNT)는 전체 묶어 1개 값 반환, WINDOW 함수는 행마다 1개씩 결과 반환.
> 예: ROW_NUMBER = 각 행에 순번 부여.

**배운점**: 트릭 자체("날짜 - 순번 = 같으면 연속")만 외우면 응용 어려움. 풀이 논리("같은 시작점에 수렴")까지 알면 응용 가능 영역 확장. 예: 사용자 세션 활동 시간 그룹화, 출석 기록 연속 구간 추출, 주문 연속 일자 분석.

### 2. SQL 작성 위치 선택 (Postgres 측 vs JS 측)

**목적**

연속 기록 그룹화 + 통계 계산. 결과는 같지만 어디서 계산할지 선택지 두 개.

**고민 — 어디서 계산할까?**

같은 결과를 만드는 두 가지 방법이 있을 때 어디서 처리할지 비교 필요.

[JS 측 계산]
1. DB에서 날짜 목록만 SELECT.
2. 클라이언트로 결과 전달.
3. JS에서 날짜 배열 순회하면서 연속성 판정.
4. 장점: 구현 단순 / 디버깅 쉬움 / DB 의존도 낮음.
5. 단점: DB 라운드트립 1회 + JS 로직 작성 / SQL 학습 X.

[Postgres 측 계산]
1. DB에 함수 작성 (CTE + WINDOW 함수).
2. 클라이언트는 RPC 호출만.
3. 결과(연속 일수 + 최고 일수) 바로 반환.
4. 장점: SQL 1회 호출로 결과 / 함수 재사용 / auth.uid() DB 측 처리.
5. 단점: SQL 복잡도 ↑ / 디버깅 어려움 / DB 의존도 ↑.

[결론]
0024는 학습 시점이라 Postgres 측 선택. WINDOW 함수, CTE, RPC 호출 패턴이 학습 본질.
production 환경에서는 단순성/유지보수 측면에서 JS 측이 적절할 수 있음. 멘토링 후 재검토.

**방법 — 기술 적용**

- CTE 3단계 (daily → numbered → groups) 로 단계별 SQL 작성
- ROW_NUMBER WINDOW 함수로 순번 부여
- RPC 호출로 클라이언트에서 함수 실행

> **CTE (Common Table Expression)**
> SQL의 `WITH name AS (...)` 구문.
> 임시 결과 집합을 이름 붙여 단계적으로 처리.
> 복잡한 쿼리를 작은 단계로 나누는 도구.

> **RPC (Remote Procedure Call)**
> Postgres에 작성된 함수를 클라이언트에서 호출하는 패턴.
> 형식: `supabase.rpc('함수명')`. 복잡한 SQL을 DB에 두고 클라이언트는 호출만.

**배운점**: 같은 결과를 두 방식으로 만들 수 있을 때 "어디서 처리할지" 선택이 의도성 드러냄. 학습 목적 / production 적합성 / 유지보수 비용 트레이드오프 인지 후 선택.

## 코드 변화 (실제 결과물)

### 1. get_til_streak() Postgres 함수 (신규)

```sql
-- supabase/migrations/20260513_get_til_streak_fn.sql
CREATE OR REPLACE FUNCTION get_til_streak()
RETURNS TABLE (current_streak bigint, best_streak bigint)
LANGUAGE sql
AS $$
  WITH daily AS (
    -- DATE_TRUNC: 같은 날 여러 TIL 작성 시 중복 제거
    SELECT DISTINCT DATE_TRUNC('day', created_at)::date AS entry_date
    FROM til_entries
    WHERE user_id = auth.uid()
  ),
  numbered AS (
    -- ROW_NUMBER WINDOW 함수: 날짜에 순번 부여
    -- (날짜 - 순번): 연속된 날짜는 같은 그룹값
    SELECT
      entry_date,
      (entry_date - (ROW_NUMBER() OVER (ORDER BY entry_date))::integer) AS grp
    FROM daily
  ),
  groups AS (
    SELECT
      grp,
      COUNT(*)::bigint AS streak_len,
      MAX(entry_date) AS last_day
    FROM numbered
    GROUP BY grp
  )
  SELECT
    -- 현재 연속 기록: 마지막 날이 오늘 또는 어제인 그룹
    COALESCE(
      (SELECT streak_len
       FROM groups
       WHERE last_day >= CURRENT_DATE - 1
         AND last_day <= CURRENT_DATE
       ORDER BY last_day DESC
       LIMIT 1),
      0
    ) AS current_streak,
    -- 최고 기록: 전체 그룹 중 최대
    COALESCE(MAX(streak_len), 0) AS best_streak
  FROM groups;
$$;
```

### 2. getTilStreak Server Action (lib/til/actions.ts에 추가)

```typescript
// lib/til/actions.ts
export async function getTilStreak() {
  const supabase = await createClient();
  const { data: { user } } = await supabase.auth.getUser();

  if (!user) {
    return { error: '로그인이 필요합니다' };
  }

  const { data, error } = await supabase.rpc('get_til_streak');

  if (error) {
    return { error: '통계를 불러오지 못했습니다' };
  }

  const row = data?.[0] ?? { current_streak: 0, best_streak: 0 };
  return {
    data: {
      currentStreak: Number(row.current_streak),
      bestStreak: Number(row.best_streak),
    },
  };
}
```

```typescript
import { getTilStreak } from '@/lib/til/actions';

export default async function StreakWidget() {

  if ('error' in result) {
    return (
      <div className="rounded-lg border border-slate-200 p-4">
        <p className="text-sm text-slate-500">통계를 불러오지 못했습니다</p>
      </div>
    );
  }

  const { currentStreak, bestStreak } = result.data;

  return (
    <div className="rounded-lg border border-slate-200 p-4">
      <h2 className="text-sm font-medium text-slate-500 mb-2">연속 기록일</h2>
      <p className="text-4xl font-bold text-slate-900">{currentStreak}일</p>
      <p className="text-sm text-slate-400 mt-1">최고 {bestStreak}일</p>
    </div>
  );
}
```

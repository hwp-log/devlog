Dotrip 양식 5종 — 프리필 최종본 + 구현 설명서

이 문서가 무엇인가

아래 카드 4장이 새 글 프리필의 원본 그 자체다. 2026-07-25 확정: placeholder 방식은 폐기됐고, 이 내용이 실제 텍스트(진짜 글자)로 본문에 통째로 들어간다 — 브런치 방식. 사용자는 이 글을 보존된 상태로 참고하면서 고치거나, 부분·전체를 자유롭게 지운다. 회색 placeholder·"예:" 접두어·StoryPlaceholder 확장은 모두 이 결정으로 불필요해졌다.

구조 (4양식 공통 골격)

도입 섹션(H2 + 인용 블록으로 감싼 첫 문단) → 본문 섹션들 → 구분선(hr) → 💡 팁 콜아웃 → ❓ FAQ 콜아웃. 팁·FAQ는 네 양식 모두 본문 맨 아래에 몰아 배치(본문 흐름을 끊지 않기 위해). 이모지는 콜아웃 종류 표시(💡/❓/⚠️ 최대 3종)에만 쓰고 제목·본문에는 금지. 본문 장치는 양식별로 다름 — ④목록+인용, ②③목록, ①인용만. 장소명 칩(서귀포 허니문하우스 류)은 코드 스타일이 아니라 장소 칩(향후 스팟 링크 연결 전제).

⑤ 자유형

섹션 0개 · 프리필 없음(완전히 빈 본문) · 서식 지우기 겸용. 이 문서에 카드가 없는 게 정상.

구현 순서와 의존성

① 콜아웃 블록 커밋이 선행 — Tiptap 커스텀 노드(종류 속성 + 제목 + 본문), 저장 HTML 구조 정의, 툴바·슬래시 배선. 프리필에 콜아웃이 들어가므로 이것 없이는 상수 개편 불가.
② 상수 개편 — 이 문서의 카드 HTML 구조를 template.ts 5양식 상수로 이관. 프리필(STORY_TEMPLATE_HTML)은 ④에서 파생, 정의 중복 금지.
③ StoryPlaceholder 제거 + 하단 안내 교체: "양식 내용은 자유롭게 고치거나 지워도 돼요. '/'를 입력하면 블록을 추가할 수 있어요."

반드시 풀어야 하는 문제 — 교체(survivor) 판정

기존 규칙은 "내용 있는 섹션은 보존"인데, 이제 모든 섹션에 예시 내용이 있다. 그대로 두면 양식 교체 시 아무것도 안 걷히고 덧붙기만 하는 중복 누적이 재발한다. 판정을 "섹션 내용이 예시 원문과 동일(정규화 비교)하면 빈 것으로 취급"으로 확장할 것. 같은 확장이 발행 시 정리(clean-empty-sections 서버판·empty-sections-doc 에디터판) 양쪽에 필요한지는 정책 판단 — 발행 시에도 원문 그대로인 섹션을 걷을지는 사용자에게 확인 후 결정 (미확인 상태에서는 발행 정리는 기존 "빈 섹션만" 유지가 안전). jsdom 기반 서버 코드의 클라이언트 import는 여전히 금지, 두 구현은 주석으로 짝 명시.

기타 제약

heading 텍스트는 5양식 전체에서 유일해야 함(교체 매칭이 heading 텍스트 기준). 현재 도입 heading 매핑 — ①여행의 시작 ②다녀온 곳 ③다녀온 코스정보 ④작품과 장소. ③의 일차는 1·2일차 고정, 3일차 이상은 사용자가 H2로 추가. 기본 프리필은 ④ 촬영지 순례형, 분기는 initialData?.content ?? STORY_TEMPLATE_HTML 유지. FormatMenu 설명 문구: ①감상 중심으로, 이야기하듯 / ②한 곳을 정보 위주로 꼼꼼하게 / ③여러 날 일정을 하루씩 / ④그 장면을 찾아간 기록 / ⑤서식 없이 자유롭게 — 빈 소제목은 정리돼요.

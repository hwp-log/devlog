## 1. 방향 한 줄

**미니멀 + 토큰 일관성 + 실사진 밀도.** 화면은 필요한 것만 담고, 밀도는 텍스트가 아니라 스틸컷(실사진)이 채우며, 일관성은 감각이 아니라 토큰이 강제한다. (레퍼런스 검증: 에어비앤비 — 카드 정보 4개(사진·제목·가격·별점), 광대한 여백, 화면 크기와 무관한 컴포넌트 동일성)

## 3. 타이포

| 역할 | 폰트 | 웨이트 |
|---|---|---|
| 헤드라인·카드 제목·로고 | **Noto Serif KR** | **500** |
| CTA 버튼 | Noto Sans KR | **500** |
| 본문·UI·강조 전부 | Noto Sans KR (Pretendard 대체 가능 — theme.ts에서 택1) | **400** |
| 숫자·날짜·EP·좌표 | DM Mono | 400 |

**웨이트 2단 원칙 (07-07 밤 확정, 에어비앤비 실측 대조 2회)**: 500은 명조 제목과 CTA에만. 600/700 사용 금지. **위계는 굵기가 아니라 크기·색(fg↔muted)·자간으로 만든다.** 정보값 vs 설명의 구분 = 색 대비 (예: "강릉역에서 15분" fg / "1.2km · 도보 가능" muted).

## 4. 규율 5 (에어비앤비 실측으로 확정)

1. **정보 상한**: 카드의 스캔 정보는 4±1개. Dotrip 카드 = 스틸컷 + 장소명 + 작품 배지 + 거리/별점. 그 이상은 상세로.
2. **카피 절제**: 헤더의 랜덤 헤드라인 1줄만 감성 카피 허용. 본문·카드·버튼은 기능어만 ("플랜에 담기", "코스 보기").
3. **모션 최소**: press(scale)·선택 글로우(ping)·상태 전환만. 장식 모션 금지. prefers-reduced-motion 존중.
4. **밀도는 사진이 채운다**: 여백이 허전해 보이면 텍스트·요소 추가가 아니라 스틸컷 크기/수로 해결. placeholder 상태의 허전함은 결함이 아님.
5. **일관성 = 컴포넌트 속성**: SpotCard·WorkChip·Marker·EmptyState는 단일 컴포넌트, 화면 폭은 그릇(바텀시트↔패널, 2열↔3열)만 바꾼다. 구현 기법: Tailwind v4 컨테이너 쿼리 우선 검토.

## 5. 화면별 테마 배정

| 화면 | 모드 | 근거 |
|---|---|---|
| SpotFinder | **다크** | 스틸컷이 어둠 위에서 상영 화면처럼 발광 (영화관 원리). 마커는 기본 점, 선택 시만 썸네일 확장 — 어둠의 여백 보존 |
| Story / my-story / PlanFinder / MyPlan / mypage / 인증 / admin | **라이트** | 읽기·작성·관리 화면. 실서비스 아이덴티티 연속 |
| 데탑 다크 지도 | 밀도 보정 | 도로·블록·그리드를 화면 폭 비례 증가 (모바일 밀도 그대로 확장 시 공허 — v2에 적용 완료) |

점(dot) 시그니처: 로고 점 · 내비 활성 점 · PlanFinder/MyPlan 점 타임라인 · SpotFinder 점 마커.
**점선 루트는 동선이 존재하는 화면 한정** (SpotFinder 제외 — 탐색 화면이지 동선 화면 아님. 07-07 정정).

## 7. 미결 — 멘토 피드백 이후 확정

1. **데탑 상세: 우측 고정 패널 vs 플로팅 카드** — 에어비앤비 실측(예약 패널 패턴)과 맨손 실험(3패널)이 모두 고정 패널을 지지 → **고정 패널 유력, v2 시안으로 구체화 완료**. 멘토링에서 v1(플로팅) vs v2(고정 패널) 비교 확인 후 확정.
2. **한 장소 = 복수 작품 표시 위치** — v2의 우측 패널 "이 장소의 작품" 목록으로 해소안 구체화. 상세 뷰 설계와 함께 확정.

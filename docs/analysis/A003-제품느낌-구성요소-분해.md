# A003 분석: 제품 느낌의 구성 요소 분해

> 배경: "앱 제품 같은 느낌은 어디서 나오는가"라는 질문에 대한 분해. 리뉴얼(A002 정의서)의 완성 판정 기준을 도출하는 과정.
> 작성일: 2026-07-07 / 근거: A001 현황조사(실측), 레퍼런스 서비스 실측 분해, 정의서 A002

---

## 1. 결론 먼저 — 제품 느낌의 구성 요소 3개

제품 느낌은 시각적 화려함이 아니라, 아래 3개가 있느냐 없느냐에서 나온다.

| # | 구성 요소 | 없을 때 증상 | Dotrip 실측 (A001) |
|---|---|---|---|
| 1 | **비-해피패스 설계** — 로딩/0건/실패 상태 | 데이터 오기 전 빈 화면, 실패 시 침묵 → "덜 만든 것" 느낌 | loading/error/not-found 파일 전 프로젝트 0개 |
| 2 | **터치 반응** — press 피드백 | 눌러도 무반응 → "웹페이지 보는" 느낌 (모바일엔 hover가 없음) | active: 사용 파일 3개, 나머지 전부 hover만 |
| 3 | **읽기 → 스캔** — 아이콘·위계·토큰 | 정보가 균질한 텍스트 → 훑을 수 없고 읽어야 함 | 라벨·카운트·날짜·금액 다수가 텍스트-only |

한 문장 압축: **잘 됐을 때만 설계된 화면은 앱이 아니라 데모다.** 제품 느낌 = 잘 안 됐을 때(1) + 만졌을 때(2) + 훑어볼 때(3)의 설계.

## 2. 왜 이 3개인가 — 도출 경로

1. Dotrip 화면들에서 "기능은 동작하는데 제품 느낌이 없다"는 문제 인식 → 원인 후보 분해
2. 지도 기반 커머스 레퍼런스 서비스 1곳을 브라우저 Network 탭과 DOM 검사로 실측 분해 → 제품 느낌이 있는 서비스에는 이 3개가 전부 존재함을 확인
3. A001 조사로 Dotrip에는 3개가 전부 부재함을 파일 단위 숫자로 확정 → 진단이 인상이 아니라 실측이 됨

## 3. 판정 도구화 — 느낌을 체크리스트로

"구리다/좋다"의 구분은 감각처럼 보이지만, 실제로는 위 3개의 유무를 빠르게 스캔하는 판정으로 환원 가능하다. 이를 1인 개발에서 판정 속도가 나오는 형태로 변환:

**5줄 체크 (화면 단위 완성 판정)**
1. 로딩: 콘텐츠 모양의 스켈레톤
2. 0건: 안내 문구 + 다음 행동
3. 실패: 안내 + 재시도
4. press: 터치 반응 (active:scale 등)
5. 정보: 읽기가 아니라 스캔 (아이콘·위계·토큰)

**화면 등급표 (앱 단위)**: S(간판, 5줄+시그니처 인터랙션) / A(주요, 5줄 전부) / B(보조, 5줄 전부·간소) / C(관리, 동작 우선)

## 4. 추가 발견 — 4번째 요소 후보: 상태의 질서

3분해 이후 SpotFinder 명세(A002 ③) 작성 중 발견한 것. 화면 요소들이 **하나의 원천 상태에서 파생**될 때, 동작이 "말이 되는" 느낌이 생긴다.

- SpotFinder 명세로 검증: 원천 상태 2개(selectedMovieId, selectedSpotId)에서 마커 스타일·카메라·카드·리스트 활성·투명도가 전부 파생 → 어떤 조작을 해도 화면 전체가 일관되게 반응
- 반례가 현재 SpotPopup: useState 16개가 각자 존재 → 요소들이 따로 노는 구조 (A004 상태 분류 분석으로 이어짐)
- 즉 1~3이 화면의 "표면" 요소라면, 4는 "동작"의 요소. 코드 레벨의 상태 응집("무슨 값 / 진입 시 행위 / 값 변경 시 상태 변화"가 한곳에 모임)이 UX 표면에서는 "일관된 반응"으로 나타난다는 가설. 검증은 SpotPopup 리팩토링 전후 비교로 예정.

## 5. 업계 판정 기준과의 대응

- 통용되는 사용성 휴리스틱과 겹치는 항목: 시스템 상태의 가시성(로딩·진행 표시 = 1번), 피드백 즉시성(= 2번), 인지 부하 최소화(스캔 가능성 = 3번)
- 실무 담론에서 "제품답다"는 표현은 대체로 마이크로 인터랙션(2번)과 상태 설계(1번)의 유무를 가리키는 경향
- 차이점: 본 분해는 체크 가능한 5줄로 좁혀져 있음 — 1인 개발에서는 판정의 정확도보다 판정 속도가 병목이기 때문

## 6. 적용 계획 (진행 중)

- 정의서 A002에 5줄 체크를 전 화면 완성 판정 기준으로 명문화 완료
- SpotFinder S급 구현에서 3+1 요소 전부 적용 → 전후 비교가 이 분석의 실증 자료
- 부산물로 Skeleton/EmptyState/ErrorState 공용 컴포넌트 제작 → 이후 화면 일괄 적용의 원형

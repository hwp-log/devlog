## ① 컨셉

Dotrip은 K-콘텐츠(영화·드라마)의 "한 장면"을 여행하는 서비스다. 화면 속 한 장면은 곧 실재하는 촬영지이고, 사용자는 그 장소를 지도에서 찾아(SpotFinder) 여행 계획으로 엮고(MyPlan) 실제로 다녀온 감정과 기억을 기록해(Story) 다른 여행자와 공유한다(PlanFinder). 즉 Dotrip의 한 사이클은 **발견 → 계획 → 경험 → 기록 → 공유**이며, 모든 화면은 이 사이클의 한 단계를 담당한다.

**경험 단계는 오프라인(실제 여행)에서 일어난다.** Dotrip이 대신 느껴주는 것이 아니다. Dotrip은 그 경험을 준비하고(발견·계획), 잘 보관하도록 돕는(기록·공유) 도구다.

- 브랜드 시그니처: **점(dot)** — 로고의 점, 점선 루트, 스틸컷 썸네일 마커, 점 타임라인. "화면 속 한 장면이, 지도 위의 한 점이 된다."

## ② 기능 인벤토리

| 사이클 단계 | 화면 | 핵심 기능 | 주요 데이터 |
|---|---|---|---|
| 발견 | `/spot-finder` | 촬영지 지도 탐색, 작품칩 필터, 스팟 상세 | Spot, Movie |
| 계획 | `/my-plan` + new / [id] / edit | 여행 계획 CRUD, 비용 카테고리, 항공 검색·연결 | MyPlan, Cost, Flight, Spot |
| (경험) | — 오프라인 단계, 화면 없음 | — | — |
| 기록 | `/story/new` + edit | 스토리 작성·수정, 플랜 연결, 태그 | Story, Tag, MyPlan(연결) |
| 기록 | `/my-story` (← `/my-dots`에서 변경) | 내 스토리 목록, 태그 검색 | Story(본인), Tag |
| 공유 | `/story` + [id] | 공개 스토리 피드·상세, 좋아요, 태그 검색 | Story, Like, Tag, Spot(지도) |
| 공유 | `/plan-finder` + [id] | 공개 플랜 탐색, 정렬·가격 필터, 플랜 좋아요 | MyPlan(공개), PlanLike |
| 지원 | `/` `/login` `/signup` | 랜딩, 인증 | User |
| 지원 | `/mypage` | 프로필·활동 대시보드·계정 삭제 | User, 집계 |
| 지원 | `/admin` | 작품 승인·거절·병합 | Movie, UserRole |
| 비범위 | `/til` 계열 | ⑤ 참조 | — |

**확정 결정**: `/my-dots` → `/my-story` 라우트명 변경 (커밋 0159 예정).
근거: 내부 컴포넌트(MyStoryCardGrid, fetchMyStoryTags)가 이미 my-story 명명 사용, 라우트만 불일치.
구분 유지: my-story = 기록(내 서랍) / story = 공유(광장). 리뉴얼 시 두 화면의 디자인 톤 차별화 근거.

## ④ 디자인 문법 7개 (라이트바겐 분해, 확정)

1. **마커 = 미리보기** — 썸네일 + 이름 칩
2. **탐색 루프** — 선택 → 좌우 페이저로 연속 탐색
3. **사용자 관점 정보** — 주소 대신 거리, 기능 대신 혜택
4. **정보 밀도의 규율** — 같은 항목·같은 순서·필요한 것만
5. **풀맵 + 바텀시트**(모바일) / **좌패널 + 풀맵**(데스크톱)
6. **전환의 의도성** — 컨텍스트 전환 = jump, 같은 맥락 = panTo
7. **단일 선택 상태의 다중 파생** — selectedSpotId → 마커·목록·카드·카메라

- Dotrip 고유 시그니처: 점(dot) 모티프 — 점선 루트, 스틸컷 썸네일 마커, 점 타임라인, 내비 활성 점.

**완성 판정 = 5줄 체크** (모든 화면 공통):
로딩(콘텐츠 모양 스켈레톤) / 0건(안내 + 다음 행동) / 실패(안내 + 재시도) / press(터치 반응) / 정보(읽기가 아니라 스캔).

3. **마이페이지 사용자 정보 변경의 페이지 위계 분리** — 기능 볼륨이 적은 현 단계에서는 현행(즉시 변경) 유지 (13회차 멘토 확인 사항).
